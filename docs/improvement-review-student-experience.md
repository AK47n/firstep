# 优化方向评审：学生体验与比赛成绩

> 评审日期：2026-08-18（工作区当前状态）
> 性质：改进机会盘点存档，非 spec、非工单。后续选定方向时按 `docs/agents/workflow.md` 流程立项（clarify → spec → 工单）。

## 一、现状概述

电赛工程生成器已具备完整链路：贴题面 → AI 预读 → 选平台 → 参考资料 → AI 推荐模块（功能需求层 + 收敛循环）→ 模块清单 → 多实例 → 板图引脚配置 → main.c 骨架 → 生成 → 自动编译 + AI 修复循环 → 交接提示词；另有模块库 / 参考文件库（154 条）/ PDF 资料库 / 赛题库（8 个年份）/ 母版提炼 / 更新记录 / 设置（LLM 观测、费用、本地路由、推荐缓存）共 8 个页面。双平台（stm32 / Keil5、mspm0 / CCS）24 个模块，70 个测试文件。

结论：**主线已闭环且质量较高**。剩余机会集中在「评分导向」（把评分表用起来）、「赛题覆盖面」（高频外设与题型模板）、「现场可靠性」（断网 / 刷新丢配置）三类。

## 二、A 类：直接提分（评分导向）——最高价值

### A1. 评分标准 → 可执行验收清单（优先级最高）

- **现状证据**：赛题库拆条时把「评分汇总」当作尾部杂项允许修剪（`topic_library.py:271`「每年最后一题含该年尾部杂项（评分汇总/页脚…）」）；步骤 1 的赛题文本也提示可修剪评分汇总（`index.html` 赛题库编辑框 placeholder）。评分表在生成链路中完全未被利用。
- **建议**：新增一个 LLM 结构化操作「评分点解析」：从题面提取 `评分点 → 分值 → 所属部分（基础/发挥）→ 对应题面句号 → 建议实现顺序（分/难度比）`。产物贯穿：推荐链路（功能需求层挂评分点）、README（验收清单章）、交接提示词、演示脚本。复用现有句子编号机制（`selection.py` 逐句对照）与收敛循环先例。
- **收益**：学生一眼看清分值分布与优先级，验收逐条对照，直接防丢分。

### A2. 一键生成设计报告草稿

- **现状证据**：电赛交物 = 作品 + 设计报告；工具生成时已掌握题面、平台、模块清单、引脚表、main.c 骨架（`readme.py` 确定性渲染，含引脚接线表与验证清单），但只产出工程说明 README，不产报告。
- **建议**：新增确定性模板 + 一次 LLM 调用，生成 `设计报告草稿.md`：系统框图（Mermaid/ASCII）、模块选型与理由、引脚分配表（直接复用 README 数据源）、软件流程、测试记录模板（勾选 + 数据表）。放工程根目录。
- **收益**：报告从零写变填空，省半天到一天，且数据与工程一致。

### A3. 演示脚本生成

- **现状证据**：评分靠现场演示，工具无演示流程产物。
- **建议**：基于 A1 评分点清单生成演示脚本：按评分点排序的 `步骤 → 操作 → 预期现象`，随工程产出。
- **收益**：现场演示不慌、不漏项（演示流程混乱是隐性丢分点）。

## 三、B 类：赛题覆盖面（模块库与骨架能力）

### B1. 高频外设模块缺口

- **现状证据**：24 个模块为 beep / config / coord_detect / debug_uart / delay / digit_uart / filter / huidu / imu_uart / k230 / key / led / led_beep / ml_mpu6050 / motor / ntb_time / oled / pid / step_motor / uart / uwb_uart / xunji / zigbee_uart / zigbee_uart_key。**缺 ADC（电位器/电压/光敏采样）、超声波测距（HC-SR04）、舵机、温湿度（DHT11/DS18B20）、数码管、红外遥控**。这些在历届题出现频率高，目前只能落「库外建议」（仅展示不进工程，`selection.py` OutOfLibrarySuggestion）。`wordlist.json` 已收录这些词条（推荐链路知道存在，库内无实现）。
- **建议**：按频率补录：adc（stm32 逐飞库 / mspm0 ADC12 有参考例程）、hc_sr04、servo（PWM 50Hz，可复用现有 pwm 类型级解锁）、dht11 / ds18b20、数码管（可先做 stm32）。
- **收益**：覆盖面提升 = 更多赛题可直接生成，学生少写驱动。

### B2. 题型决策骨架模板

- **现状证据**：ADR 0009 把决策层（路口检测 / 状态机 / 送药流程）从模块剥离后归档参考文件库，生成时靠 AI 读素材每次现写进 main.c 骨架，质量波动大。CONTEXT 已记「普适巡线逻辑为将来方向」。
- **建议**：为巡线小车、送药、视觉追踪、云台等常见题型做「决策框架模板」：状态机骨架 + 调度结构（复用现有 10ms/1ms 定时器调度先例），学生选题型 → 骨架直接带框架，AI 只填判定逻辑。
- **收益**：骨架可用性与一致性显著提升，减少反复修复轮次。

### B3. 可选配套落地

- **现状证据**：CONTEXT「可选配套」词条明确记录：`filter` 之于 `uwb_uart` 的代码层可选化（条件编译 + 生成器按选中定义宏）已立项未实现。
- **建议**：低挂果实，顺手收掉。

## 四、C 类：学生体验与现场可靠性

### C1. 断网 / 无 Key 现场模式

- **现状证据**：设置页强制「配置 API key 才能用 AI 功能」（`index.html:948`，`gen-banner`）；无 key 只能编译看结果。比赛封闭环境常断网。
- **建议**：① 本地模型路由（`local-llm-routing` 已存在，现仅 6 个纯文本摘要操作走本地）扩展到骨架 / 修复等；② 提供纯确定性离线生成路径（默认模块布局 + 模板骨架），保证现场断网也能开工。
- **收益**：现场可靠性与工具兜底能力。

### C2. 会话持久化 + 工程历史

- **现状证据**：步骤 1-9 全部配置在前端内存，刷新即丢；生成过的工程无历史列表。
- **建议**：配置存 localStorage；生成记录落「工程历史」页（重新打开、继续修复、一键打包 zip）。
- **收益**：比赛前夜浏览器崩溃不再重来；队友间分享工程更顺。

### C3. 工程问答助手

- **现状证据**：交接提示词是「复制出去给另一个 AI」（步骤 11），体验割裂。
- **建议**：工具内选择生成目录 → AI 基于工程文件 + 题面问答（「车为什么跑偏？」「发挥部分还能加什么？」），复用 fix 链路的文件上下文读取先例。
- **收益**：调试期持续获得增量帮助，体验闭环。

## 五、D 类：素材与内部闭环

- **题库补年份**：现有 2018C / 2019A / 2020C / 2021F / 2022C / 2022H / 2024H / 2026C，缺 2023 等年份，可补。
- **上板反馈回路**：学生真机发现模块 bug 目前只能人工补录；可加「一键反馈」（模块 + 现象 → 自动生成补录工单），模块质量随使用滚动提升。
- **参考素材扩充**：参考文件库 154 条已含 TI SDK 例程与小车底盘资料，可继续按赛题类型补决策层素材（配合 B2）。

## 六、优先级建议

第一梯队（改动可控、收益直接）：

1. A1 评分点 → 验收清单（复用句子编号与收敛循环，贯穿 README / 交接 / 演示）
2. A2 设计报告草稿（复用 README 数据源 + 一次 LLM 调用）
3. B1 高频模块补齐（adc / hc_sr04 / servo / dht11）
4. C2 会话持久化 + 工程历史（纯前端 + 少量后端，独立可交付）

第二梯队：A3 演示脚本（依赖 A1）、B2 题型骨架、C1 离线模式、C3 工程问答。

第三梯队（长期/内部）：B3 可选配套、题库补年份、上板反馈回路。
