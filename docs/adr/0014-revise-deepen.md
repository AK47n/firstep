# 修订与深化：两段式 API + 覆盖式重生成 + main.c 保全 + 编译验证硬门槛

生成后阶段「修订与深化」的架构决策（工单 revise-deepen/01-05）。原管线是单向
流水线：赛题 → 推荐 → 骨架 → 生成 → 编译修复 → 交接；赛事答疑 Q&A 只允许
在推荐前输入，专家答复迟到（工程生成后甚至隔天）时用户没有途径把新 Q&A 补
进流程，AI 精打磨也被推给下一个会话。决定：生成页新增生成后阶段，两个能力
共用一条流程——**修订**（补新 Q&A → AI 逐条影响分析 → 确定性 diff → 用户
确认 → 覆盖式重生成进同一输出目录，修订前整树备份可回滚）与**深化**（AI 按
功能需求逐条填充 main.c 的 TODO 预留区，强制走编译验证闭环）。

**关键决策：**

1. **两段式 API**（对照「推荐」与「生成」分离按钮的先例）：先 `分析`（耗时
   LLM：影响分析 + diff，返回待确认结果），用户确认后再 `执行`（重生成 /
   深化，SSE 进度流）。影响产物（impacts + suggested_slugs）随执行请求回传
   留痕，但执行的服务端**重新加载上下文**（清单直读 / 无清单反推，路由不
   信任前端回传的上下文），slugs / platform / problem_text 支持可选覆盖
   （用户手动调整 / 历史目录补题面）。

2. **确定性 diff**：新旧模块集差异 = 集合差（纯函数），AI 只负责解释"为什
   么"，不负责"算差异"；模块集判定用**依赖展开后的集合**（与生成产物同源
   ——确认集缺依赖时展开补回 = 实际没变，不误报 removed）。

3. **覆盖式重生成 + 备份回滚**：执行 = 整树备份到输出目录外（revise-backups/
   带编号，对照 fix-backups 先例）→ 清空输出目录 → 复用既有生成全链路（门禁
   / 绑定写侧 / 多实例 / 副产物 / README / 构建脚本）。备份成功但重生成失败
   → 备份保留（目录保持可回滚），报错中文。回滚 = 目录内容恢复为备份内容
   （修订残留全清）。

4. **main.c 保全策略**：模块集变化 → 重生成时骨架重生成（新 main.c 替换，
   旧版在备份里）；模块集不变 → **不重生成、main.c 原样保留**（用户手工编辑
   不丢），只把新 Q&A 并入上下文清单。深化读**现读磁盘**的 main.c（清单里
   的生成时快照只作参考，读侧 / 修订 / 深化一律现读——手工编辑天然保留）。

5. **深化编译验证硬门槛**：深化产物必须经编译验证——工具链探测（复用
   /api/compile 的 resolve_compile_toolchain 单源）→ 无工具链 = 大声降级
   （结果保留、状态 = 未验证，明确提示，不静默交付未验证逻辑）；有 → 编译 →
   失败自动进修复闭环（run_fix_round 复用）→ 重编译 → 绿 = 已验证。不设
   自动循环，用户可重复触发；修一轮仍红 = failed（结果保留可回滚）。

6. **上下文清单**（.contest_context.json）：生成尾部写纯新增隐藏文件（README
   先例，不触碰任何既有生成文件，逐字节契约不破），记录生成输入（题面 /
   平台 / slugs / 绑定 / 多实例 / 副产物模板 / Q&A / 功能需求清单 / 参考 /
   时间 / 工具版本）。读侧缺字段 / 旧版本向后兼容；无清单的历史目录自动反推
   （平台 = 工程配置文件后缀识别；模块 = modules/<slug>/ 目录名；绑定 = 写侧
   逆运算——stm32 pin_config.h 宏现值 / mspm0 syscfg $assign 落点值；main.c
   现读）；题面 / 需求清单反推不了 → missing 标记（前端提示用户补）。

**考虑过的方案**：单向流水线 + 交接提示词（现状）vs 工具内修订深化——修订
深化治本（交接提示词把精打磨推给下个会话，且无法补 Q&A）；单段 API vs 两段
式——两段（LLM 分钟级影响分析必须先确认再执行，对照推荐/生成分离先例）；
重生成覆盖 vs 新目录——覆盖（同目录保持工作流连续，备份可回滚兜底）；模块集
不变也重生成 vs 保全——保全（手工编辑是用户资产，无变化重生成纯破坏）；
深化免验证 vs 编译验证闭环——验证（守住"打开就能编译"承诺，无工具链大声
降级而非静默）；上下文清单 vs 纯反推——清单（生成时输入一次记全，反推只作
历史工程兜底，逐字节契约不破）。
