# 提炼进度：批边界事件 + 客户端计时器（SSE 推送）

Status: accepted

母版提炼单次 10-15 分钟（AI 两阶段分批判定，单批模型生成 2-5 分钟），期间前端只有静态转圈，用户无法判断卡死与否。决定：后端在阶段 / 批次 / 补问边界经 SSE 推进度事件（事件契约唯一出处；最后一个事件携带完整报告），前端显示阶段 stepper + 批进度 + 双计时器 + 可折叠日志。**模型单次调用期间后端产生不了任何事件，"没卡死"的证明 = 客户端每秒跳动的计时器**——不做调用内的假进度（假进度会验证一个真实系统给不出的节奏，把设计带偏）。

## 选型

- **SSE（fetch + ReadableStream 手动解析）**：EventSource 仅支持 GET，现状接口是 POST JSON；且不需要自动重连——断线 = 放弃本次（提炼确认前不落任何东西，刷新页面即安全放弃，无取消按钮）。
- **被否掉的候选**：轮询任务（后台任务 + 状态接口，多一套任务存储，本地单用户无断线续查需求）；token 级流式（把 DeepSeek 的 stream 透传到前端，调用内可见实时吐字——最细粒度但要改所有 LLM 调用共用的传输层，复杂度最高；事件 schema 预留扩展位，以后可加）。
