# 检测程序 = 确定性渲染 + 库内配方数据（硬件检测功能里唯一不靠 AI 的生成形态）

「硬件检测」栏目（工单 `module-hwcheck`）要给学生的东西是**一段能直接烧进板子、
跑完就告诉你这件器件通不通**的程序。按照本仓库既有的主线（骨架 / 自检冒烟都由
LLM 出稿、静态兜底把"接口里不存在的调用"改成注释占位），最省事的做法是再调一次
模型让它写 main.c。**决定：不这么做。**

检测程序 = **确定性框架**（`hwcheck.py` 渲染：LED 心跳、输出通道分节、逐件小节的
位置与顺序、结尾汇总）+ **库内配方数据**（`library/hwcheck_recipes.json` 说"每一件
怎么测"）+ **通用降级**（没有配方的器件：初始化 + I2C 类件总线地址扫描，并如实标
「未专精：只验总线和初始化」）。**渲染全程零 LLM**——这个功能里唯一一次 LLM 调用
发生在最后一步：学生把上板看到的现象填回来，AI 给排查方向。

**关键决策：**

1. **"看着测了其实没测"是本功能最大的失败模式，而它正是 LLM + 兜底的必然产物**。
   自检冒烟那条路的静态兜底会把不存在于接口清单的调用静默改写成注释占位——对
   骨架是保护（"你要自己填 TODO"），对检测程序就是灾难：学生会看到一片 "OK"，
   而那一节其实一行都没执行。所以检测程序里**没有兜底改写这一层**：配方引用的
   函数名必须能在该模块该平台的头文件接口清单里找到，找不到 = `HwCheckError`
   → 400 中文并点名 `slug × 平台 × 段 × 名字`（构建期大声失败）。
2. **配方是"怎么用这个模块"的元数据，不是模块逻辑**——这是与 ADR 0009（模块 =
   纯驱动切片）的边界所在。配方住在**库根的中央文件**里（跟随模块库根，不新增
   配置键、不往每个模块目录塞空壳文件），因此它不改变"目录即数据库"的审计面，
   也不把题逻辑搬回模块：检测顺序、输出通道、心跳这些**流程**仍然全在框架里。
3. **判据只认"可查表的事实"**。三处判据各有单源：配方文件（这件怎么测）、
   `readme.sort_verification_order` 的 bring-up 顺序（按什么次序测）、
   `pin_bindings._shared_groups` + 板定义 `BoardPin.notes`（哪两件 / 与板载资源
   撞脚）。检测页不自己发明第四套顺序或冲突判据。
4. **板端只判两层，第三层只回显**。① 编译绿（工具已验证）；② 通信 OK/FAIL ——
   **自证探头**（自己读一次 WHO_AM_I / 状态寄存器，**不信**驱动 `init` 的返回值：
   库内 stm32 的 `ml_mpu6050` 根本不校验通信，失败也照样往下写寄存器）；③ 数据
   合理性（静止时 |a|≈1g、角速度≈0）**只回显 + 给正常范围参考**，不在板上做阈值
   判决——阈值判决会把"读数不对"误判成"器件坏了"，而那通常是接线或用法问题。
5. **没配方的件如实说"未专精"**，且**不猜读函数**（猜出来的垃圾值比不测更坏）。
   通用降级能做的只有"初始化 + 总线地址扫描"，判据零新增知识：总线类型是
   manifest 已声明的事实。
6. **平台不对称如实呈现**（同一件 MPU6050：mspm0 走官方 DMP 出三维角度、stm32
   只有原始六轴且驱动不初始化总线），差异写在配方的 `note` 段里、直接印到检测页
   ——学生不该靠"显示不出角度"来反推"是不是我接错了"。
7. **检测工程与赛题工程互不干扰**：生成的工程走同一个生成内核（不新开第二条写盘
   路径），但**不进最近工程记录**、不被修订 / 深化误抓——上下文清单加 `kind`
   字段（`contest` / `hwcheck`，读侧缺字段 = 赛题工程，向后兼容）作为唯一判据。

**与既有机制的关系**：

* 与 ADR 0009（模块 = 纯驱动切片）：配方是**调用模块的数据**，不进模块源码、不
  改变模块边界；模块仍然只提供 init + 服务函数，检测流程不落模块。
* 与"自检冒烟"（`skeleton.generate_smoke_main`）：目标不同（做题前验通路 vs 我手上
  这件通不通），冒烟**原样不动**；两条路共用同一处"检测程序"生成缝，不各长一套。
* 与"模块库描述规范"（ADR 0005）：配方不新增 manifest 字段，库内模块条目的形状
  一个字节不改——它可以被删掉（删了就是全库走通用降级），不影响任何既有链路。
* 与生成门禁：配方校验用的接口清单与生成门禁**同一套提取**（模块头 ∪ 母版头），
  所以"配方过了校验"就等于"生成门禁认这些调用"。
