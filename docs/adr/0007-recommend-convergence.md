# 模块推荐：题面证据驱动的收敛循环 + 机械式实现覆盖检查 + 库外建议不进工程

选模块原为单次调用：提示词限定"在给定的模块库中选择合适的现成模块"，解析器对库外 slug 直接报错——推荐只能出自库内，对"送药小车显然需要视觉模块"这类题无解。决定：推荐改为题面证据驱动——**功能需求层**（能力/外设级：声光提示 → LED/蜂鸣器、识别数字 → 视觉）由**逐句对照**题面产出（题面按句编号，每句对应功能或"无功能"，找不对应句的功能即脑补、删）；逐条做**实现覆盖检查**（库内命中 → 可勾选进工程；无命中 → **库外建议**：类别名 + 常识举例，仅展示、不进工程、不参与生成）；AI 以题面为裁判**收敛循环**自检（删脑补 / 补遗漏 / 重查覆盖，连续两轮功能需求层一致即收敛，上限 4 轮防死循环），拿不准暂停向用户补问；库外建议的 name 只允许**硬件词表**条目（型号 K230 / 类别"视觉模块"），词表外型号降级为类别或拒收，examples 自由（用户自行核实），词表进 prompt 当科普素材、可手补。功能需求是"这题需要什么"的稳定描述，但**不是品类铁律**——推导只能出自题面证据（题面下次不要求识别数字就不需要视觉），同一题面（赛题条目）的收敛解可缓存复用（v2，库内命中每次现算，库会变）。

**考虑过的方案**：单次分析 vs 收敛循环——收敛，质量优先，成本为 2-4 轮 × 2-4K token（DeepSeek 可承受）；缓存固定结论防漂移 vs 收敛——收敛治本、缓存治标且固化"品类铁律"式脑补；库外建议靠 AI 主观判断 vs 实现覆盖检查机械产出——机械，可校验可单测，且"库内没有 LED/蜂鸣器怎么声光提示"这类缺口被显式暴露；库外建议 name 完全信任 vs 词表强约束——强约束（不懂不编、编造降级），与库内 slug 校验"宁可大声失败"同源；补问用户 vs 纯自检——拿不准必须问，题面证据不足以判定时用户是唯一裁判。
