# 提炼判定模型：判据是通用性与必需性，整合而非选来源

Status: accepted

提炼报告（保留 / 整合 / 剔除）的判定唯一判据是**读文件内容后判断它是否通用、是否基础建设必需**，不看重复次数或出现范围（旧的"公共自动保留、冲突强制合并"是按出现范围分类的，公共 ≠ 干净、冲突也可能是两份垃圾）。动作语义：保留 = 通用且必需；剔除 = 不通用（赛题逻辑）/ 残留 / 对生成无影响；整合 = 同路径多份内容不同时读多份、分析、产出通用版本（选一份只是特例），整合产物全文 + 说明进报告，用户审查后可改回选某份或剔除。已知残留（构建产物 / 备份 / 临时文件）机器识别、确定性剔除，但进报告可见并带规则化原因，不做黑盒消失。

当时否掉了两个候选：按重复次数判定（用户判定不精准）和 merge 只做"选定来源工程"（用户要求读多份后允许分析整合）。判定素材此前只有路径清单无文件内容，AI 判定须先读文件全文出摘要（两阶段），用户确认环节有最终否决权。

补充（请求体预算）："读全文"受请求体大小约束——DeepSeek 网关对请求体有硬性大小限制（超限返回 413），导入带标准外设库 / driverlib 的完整工程时，全部文件全文一次性发送必然超限。政策分三层：所有嵌内容调用（赛题 / 接口块 / 文件全文）超长（> 4000 字符）截断并带标注（TRUNCATION_NOTICE 措辞单源、注明原文长度——AI 明确知道读到的是截断内容、不脑补缺失部分）、摘要阶段多文件按预算（约 24000 字符/批）与文件数上限（25 个/批，防模型批量超载，判例 08）分批发送后合并摘要，单文件多版本合计超预算时按版本拆批（批内路径不重复）；_chat 发送前有序列化体积断言兜底（未截断的长输入在请求发出前大声失败，而非等网关 413）。截断与分批只影响发送素材，不改变判定判据；keep 落盘仍复制工程原文全文，不受截断影响。**已知风险**：merge 动作要求产出整合产物全文，而超大文件只见过截断摘要——整合产物可能是脑补代码。尚未用真实超长冲突工程验证；若出现，对超长 merge 候选应在报告中显式标记"截断，建议人工审查"或补发完整内容（预算内）。
