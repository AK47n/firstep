# 素材区：赛题库与参考文件库分设

输入素材是"整包"而非单份程序——2026C 一题带钥匙/锁两套程序、ALX 套件带通信例程与说明书——但录入只认"一套"，多出的部分无归属；spec 又曾把"赛题真题题库 / 知识库"划出范围。决定：新增两个独立素材区（均为磁盘目录即数据库，与模块库同风格）——**赛题库**：历年真题长 PDF 导入拆条（年份 / 编号 / 题面 `.md`，原 PDF 保留在条目目录），"几几年几题"编号可解析为题面、作生成入口之一（贴题面或选历史题），条目锚定附带完整程序（2026C 钥匙/锁两套）与关联模块（复用简介"XX 题专用"标注自动发现，不新造链接）；**参考文件库**：不编译进生成工程的配套资料（套件例程 / 说明书）与提炼残渣，条目锚定赛题或套件（套件锚点必须取模块库已有 kit 型号词表，保证 参考文件↔套件↔模块 链接可靠），生成时选模块阶段两级注入（先关联清单、需要时取全文），骨架生成阶段暂不注入。提炼报告动作表加"归档为该题参考文件"（复制入库、内容自持，源工程删除不丢）；构建残留 / 二进制仍确定性剔除，不配归档。两库存储与浏览入口分设——查题不看套件、查套件不看题。本决策推翻 spec Out of Scope 的"赛题真题题库 / 知识库"一条。

**考虑过的方案**：统一"素材库"单库两型 vs 两库分设——分设，浏览视角隔离，跨区只靠字段锚定；归档引用源工程 vs 复制入库——复制，内容自持；两级注入 vs 全量注入——两级，与选模块时"manifest 摘要喂 AI"的既有模式一致。
