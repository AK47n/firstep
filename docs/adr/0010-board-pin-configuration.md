# 板级引脚配置：模块引脚角色词表 + 生成前锁定 + 双平台接线单源

用户要"板上点引脚配功能"（CubeMX 类，但显示开发板本体而非芯片封装）：stm32 = 最小系统板，mspm0 = 地猛星。决策：配置词汇用**模块引脚角色**（manifest pins 声明，菜单标签 = `模块_用途`，如 `TB6612_STBY`），不用芯片 AF 复用词表——电赛用户想的是"电机驱动接哪些脚"，不是"PA2 的第几复用功能"。配置位置 v1 = **生成前锁定**（推荐选模块 → 板图配引脚 → 生成；锁定表随生成请求走 + 门禁校验），生成后编辑留 v2（复用同一套板定义与写侧）。**接线单源**：stm32 = 工程根 pin_config.h（模块只引用宏，硬编码全迁入），mspm0 = mspm0.syscfg（生成器只改 `$assign` 行，实例名/宏名不动）——兑现词表早已预留的"未来配置引脚只改此文件"。板定义（板图坐标/丝印/能力集）后端 boards/*.json 单源，门禁与前端同吃。默认布线 = 各角色声明默认值预填，未绑定按默认生成（"打开就能编译"不破）。

考虑过的替代方案：

- **AF 词表**（CubeMX 式逐脚列复用功能）——词表对用户陌生、全 AF 表录入苦工大、与模块代码对不上。
- **生成后编辑先行**——硬件是先接好线的，生成前锁定才是真实闭环；LLM 不服从锁定表的风险由门禁机械校验兜底，可接受。
- **实拍照片底图**——需正俯视照片 + 手工标坐标、换照片全废，且与深色主题冲突。
- **GUI 直接改模块代码硬编码引脚**——改错即编译错、无法校验，弃。

**Consequences**: stm32 能力集口径 v1 = ml_libs 支持表（UART/软 I2C/PWM 的"实例→引脚"在功能库里写死，选择受限；GPIO 任意；编码器 v1 限同 EXTI 线号——motor 的 EXTI2/EXTI4 handler 名绑定线号）；功能库映射扩展与生成后编辑、配置持久化同列遗留候选。同引脚多角色允许（xunji/huidu 共享灰度传感器先例），门禁不拦重复、前端叠加标注。前置依赖 = 母版 syscfg 地猛星化（工单 mspm0-master-dimx/01：现 syscfg 的 LED=PA3 是晶振脚、IMU=PA10/11 被 CH340E 占用，在地猛星真板上接线错误；step_motor/ml_mpu6050 孤儿实例补齐）。骨架不得内联引脚字面量由新门禁守住（现状性质，历史产物已验证）。工单 .scratch/pin-board-config/（01 数据 / 02 机制 / 03 前端）。
