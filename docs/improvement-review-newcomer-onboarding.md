# 优化方向评审：纯新人上手 firstep（新手向）

> 评审日期：2026-08-29（工作区当前状态）
> 性质：改进机会盘点存档，非 spec、非工单。后续选定方向时按 `docs/agents/workflow.md` 流程立项（clarify → spec → 工单）。
> 评审角度：**假想一个纯新人（第一次参赛、第一次用本工具）**，从"拿到 firstep"到"做完一道赛题并交付"，逐环节看提示语是否清晰、会不会卡住。上一份评审（`improvement-review-student-experience.md`，2026-08-18）的 A1 评分点 / A2 报告草稿 / A3 演示脚本 / B1 adc·servo 模块 / C2 会话持久化+工程历史 / C3 工程问答（任务商量、参数速调 AI 咨询）均已落地，本文不再重复；沿用其 C1（断网/无 key 离线路径）、B2（题型决策骨架）、B3（可选配套）为已知遗留。

## 〇、结论先行

主线质量高：12 步向导 + 就绪总览（关键路径/软建议）+ 一键补齐 + 卡片 details 兜底解释 + 中文错误映射 + 任务推进的上板自检清单 + 评分点核对 + 报告/演示草稿自动附带，这些对新手已经非常友好。

**但"拿到手"到"打开见到界面"这一段是空白**（安装、启动、前置条件、知道该先做什么），**"该先准备什么"没有一句话答案**（硬件/软件/API key 三件套），**8 个 tab 平铺无主次**（其中 5 个是库管理页，新手完全用不到）。这三块是本次评审的核心缺陷。

## 一、红色缺陷（会实实在在挡住新手完成第一题）

### R1. 仓库无 README，安装与前置条件全靠猜

- **证据**：仓库根目录只有 `start-app.bat/.vbs`、`stop-firstep.*`、`CLAUDE.md`、`CONTEXT.md`、`CHANGELOG.md` 和两份日志，**没有 README**；`docs/` 下全是给 agent 看的（`docs/agents/*`）和 ADR。
- **新人会问**：这是什么？需要装什么（Python ≥3.13，见 `pyproject.toml:5` `requires-python = ">=3.13"`、依赖 pypdf/fastapi/uvicorn/python-multipart/pillow/pymupdf）？怎么装（`pip install -e .`）？没有 DeepSeek key 能用吗？要买什么板子？——全部无答案。
- **建议**：根目录 `README.md`（面向人的安装/快速上手/常见问题）+ 可选 `install.bat`（装依赖 + 引导一次性把该配的配齐）。

### R2. 启动失败零反馈：双击后无声无息

- **证据**：`start-app.vbs` 无黑窗口静默跑 `start-app.bat`；bat 内 `python -m contest_generator.webapp` 若 **python 不在 PATH / 版本 <3.13 / 依赖未装**，日志落 `%USERPROFILE%\.contest_generator\webapp.log`，`tries>=20` 后 `:fail` 仅 `exit /b 1`——**没有任何对话框/提示**。新手的体验 = 双击 → 什么都没发生。
- **证据**：端口 8000 被占时 `netstat` 判定"已在运行"直接开浏览器，可能打开一个**别的程序的 8000 页面**（`start-app.bat` `netstat … findstr ":8000" LISTENING` 分支）。
- **建议**：bat 失败分支弹中文提示（用 `mshta`/`msg` 或写一个 `error.txt`+`start` 打开）；启动前探测 python 版本与依赖（`python -c "import fastapi..."`）；端口冲突时改用备用端口或明确报错。

### R3. 无「第一次该做什么」的引导 / onboarding

- **证据**：全站检索 `新手|教程|向导|入门|指南|欢迎|onboarding` 零命中（`index.html` 与 `static/js/**`）；「环境体检」是唯一一次性体检，但藏在「设置」tab 深处，首次打开不会主动出现。
- **新人会问**：我该从哪一步开始？哪些 tab 是给我用的、哪些是先别碰的？——现在要自己悟。
- **建议**：首次启动检测（localStorage 标记）→ 顶部显示一张「欢迎卡」：3 句话说明（这是什么 / 三步走：贴题→选平台→生成 / 两件事先去配：API key + 环境体检），或直接做"首次引导"浮层把第一步指到设置页安检。至少把 `gen-banner`（无 key 提示，`index.html:1870`，仅 `.hidden` 切换无按钮）升级为带「去设置」按钮的行动条。

## 二、黄色缺陷（不挡路，但让新手困惑、多走弯路）

### Y1. 所需东西没有一张"速查清单"：硬件 / 软件 / key

- **证据**：平台选择说明（`index.html:1947-1948`）只讲技术差异（模块库可用集/引脚板图/工具链），不回答"我要买哪块板、大概多少钱、装什么 IDE"；模块 manifest 有 `kit`（套件型号）+ `source_url`（购买链接），模块详情弹窗也展示了（`fx/module.js` 模块详情：套件/购买链接），但**没有汇聚成采购清单**（BOM），也没有"平台怎么选"的决策提示（价格/难度/学校已有板子/社区资料量）。
- **证据**：设置页「工具链」只有路径输入 + "留空自动探测"（`index.html:2807-2833`），Keil5/CCS Theia/MSPM0 SDK/SysConfig/烧录器驱动**没有任何安装指引或下载链接**；没有工具链时的降级文案（结果保留、状态=未验证）散在生成/修复链路里，新手第一次看到"未验证"不知道严重性。
- **建议**：「设置」页加一张**前置速查卡**（进入门槛 = ①Python → ②API key → ③IDE+工具链 → ④板子+传感器），每项带"怎么装/去哪买"链接；模块清单选中后自动生成**采购汇总**（kit × 数量，售价参考），生成 README 里也带一页。

### Y2. 8 个 tab 平铺，5 个库管理页对新手是噪音

- **证据**：顶部 tab = 生成/模块库/参考文件库/PDF 资料库/赛题库/母版/更新记录/设置（`index.html:1849-1858`）；其中模块库、参考文件库、PDF 资料库、赛题库、母版都是**内容管理页**（入库/编辑/删除），纯新人不需要，还可能误操作。
- **建议**：tab 做**分组**（生成/赛题库/设置为一组"使用"，其余收纳进一个"资料管理"组），或默认只展示"生成"+"赛题库"+"设置"三页，其余折叠。最小做法：tab 上加 `title` 说明"这个是给你管理资料用的，做题用不到"。

### Y3. 术语无词表，卡片标题是名词不是"为什么要做"

- **证据**：12 张卡的 h2 是"赛题原文/目标平台/AI 推荐模块/引脚配置/骨架/修复中心/修订与深化…"（`index.html:1894-2395`），对一个没接触过"母版/多实例/收敛循环/库外建议/平台警告 missing·unverified·hardware_bound/KIND_TEXT（`app.js:72`）"的新手而言，多数卡片要展开 details 才知其意；`details` 文案本身也有"模板 main.c/TODO 预留区/硬件绑定"这类行话。
- **建议**：在页面底部或帮助区放一个**迷你词表**（10 个词：母版=空工程底盘、模块=可复用驱动、多实例=同类器件装多个、平台警告=该模块在你板子上没验证过…）；卡片 h2 下方加一行"这步解决什么"的解释（防止只念标题）。

### Y4. 第 11 步四页签的主次与命名对新手不直观

- **证据**：`fx/revise-tabs.js:7-11` 四页签 = 修订 / 任务推进 / 参数速调 / 交付；默认激活「修订」（`ui/revise-tabs.js:11` `state.active="revise"`，仅"上下文加载后自动跳任务推进"）。但**真正的主路径是「任务推进」**（逐卡实现 main.c 逻辑 + 编译验证 + 上板自检），"修订"只是赛题答疑补录的二次操作，"参数速调"是调试期魔法，"交付"是收尾。
- **新人会问**：生成完工程后我去哪写逻辑？——答案藏在第 11 步的第 2 个页签里。
- **建议**：生成成功后的结果区直接给"下一步"指引（现在已有点：编译横幅、烧录按钮、任务卡引导）；把「任务推进」设为默认激活标签或在生成后强烈引导。同理第 12 步「交接提示词」是"复制给另一个 AI"，但工具内已有「和 AI 商量」（任务卡）与「参数速调 AI 咨询」，新手实际并不需要第二个 AI——应在这个入口说明清楚（"你已经不需要外部 AI 了"或反向指向任务推进）。

### Y5. 无 key / 无网时"哪些步骤需要 AI"边界不清

- **证据**：无 API key 时 `gen-banner` 提示（`index.html:1870`），但第 2、4、5、8、10、11、12 步哪些需要 AI、哪些是纯确定性步骤（1 上传抽字、3 平台、6 清单、7 引脚、9 生成）没有正面说明；前次评审 C1（断网/无 key 现场模式，仅 6 个纯文本摘要操作可走本地模型）仍是遗留。
- **建议**：设置页 AI API 卡加"我是否需要 key、没有 key 能做什么"的一段说明；把 C1 的本地路由扩展到骨架/修复（或给确定性兜底）。

## 三、绿色缺陷（锦上添花）

- **G1** 赛题库仅 8 个年份（2018C/2019A/2020C/2021F/2022C/2022H/2024H/2026C），缺 2023 等；"取题面"输入框的提示（`index.html:1926` `placeholder="历史赛题编号，如 2026C"`）对新人意味着"你是从题库挑真题练手的"，但题库页与生成页（第 1 步）没有互相引导的跳转。
- **G2** 上板自检清单（任务卡）与烧录按钮已具备，但"第一次怎么接线/怎么烧"（ST-Link 连法、DSLite 配置、板子供电）无一处聚合成一篇**上板五分钟教程**；参考文件库里散落着套件手册。
- **G3** `start-app.bat` 若在 python <3.13 环境会启动失败，而用户往往装有 3.10+，报错信息（日志）是英文 traceback——与全站"中文错误映射"（`errors.py`）的体验不一致。
- **G4** 首次打开时「生成」页默认激活（正确），但页面第一眼是 12 张卡片 + 就绪总览 chips，信息密度高；欢迎卡/引导（R3）落地时顺带做"首屏只露前 3 张卡"的渐进披露会更好。

## 四、优先级建议

第一梯队（直接决定"新手能不能走通第一题"，改动可控）：

1. **R1 README + 安装脚本**（仓库级，半天）
2. **R2 启动失败中文反馈 + 端口冲突处理**（bat/vbs 级，半天）
3. **R3 首次欢迎卡/引导 + gen-banner 行动化**（前端，1 天）
4. **Y1 前置速查卡 + 采购汇总**（设置页 + 模块清单聚合，1-2 天）

第二梯队：Y2 tab 分组、Y3 迷你词表、Y4 任务推进默认化与"不需要外部 AI"说明。

第三梯队（衔接前次评审遗留）：C1 离线兜底、B2 题型决策骨架、2023 等真题入库、上板五分钟教程（G2）。
