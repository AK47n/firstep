## 一、系统总体架构

## 二、ALX-AOA-FIT 套件通信协议

### 2.1 基站→STM32 主动上报（核心消息 0x2001）

**串口参数**：115200波特率、8位数据、1停止位、无校验

**消息格式（标签定位信息命令 0x2001）**：

```
帧头      包长度    流水号   命令码    版本     基站ID    标签ID     距离      方位角    仰角    标签状态  序号  预留   XOR校验
4B        2B        2B       2B       2B       4B        4B         4B        2B        2B      2B       2B    4B     1B
FF FF FF FF 00 25   00 0B    20 01    01 02    00 00 AA A2 00 00 AA A1 00 00 00 19 00 12   FF CA  12 34  00 0B 00 00 00 00 1E
```

| 字段 | 字节 | 类型 | 含义 | 示例值 |
|------|------|------|------|--------|
| MessageHeader | 4 | uint32 | 帧头 `0xFFFFFFFF` | — |
| PacketLength | 2 | uint16 | 消息体长度 | 37 |
| SequenceID | 2 | uint16 | 流水号 | 11 |
| RequestCommand | 2 | uint16 | `0x2001` 定位数据 | — |
| VersionID | 2 | uint16 | `0x0102` | — |
| **AnchorID** | 4 | uint32 | **基站ID** | 43682 |
| **TagID** | 4 | uint32 | **标签ID = 钥匙身份ID** | 43681 |
| **Distance** | 4 | uint32 | **距离，单位cm** ✅ | 25cm = 0.25m |
| **Azimuth** | 2 | int16 | **方位角，单位度** ✅ | 18° |
| Elevation | 2 | int16 | 仰角，单位度 | -54° |
| TagStatus | 2 | byte | 标签状态 | — |
| BatchSn | 2 | byte | 测距序号 | — |
| Reserve | 4 | byte | 预留 | — |
| XorByte | 1 | byte | 异或校验 | — |

### 2.2 心跳包（无标签时 0x2002）

当基站没有检测到标签时，每 **2秒** 发送一次心跳：
```
FF FF FF FF 00 10 00 08 20 02 01 01 00 00 AA A2
```

### 2.3 基站与信标绑定规则（单基站）

```
基站ID = 信标ID → 绑定通信
```

- 单基站模式下，基站和信标的ID必须**一致**才能通信
- 使用《PDOA定位软件》可以修改基站和信标ID
- 流程：打开配置模式 → 读取地址 → 设置新地址 → 关闭配置模式

### 2.4 卡尔曼滤波（基站内置）

基站支持内置卡尔曼滤波，可通过命令启用/禁用：
- 读取：`0x2084` / 响应：`0x2085`
- 设置：`0x2086` / 响应：`0x2087`

> **建议**：比赛时开启卡尔曼滤波，基站会自动对距离和角度做平滑处理。

### 2.5 Zigbee DL-20 无线ID通信协议 🆕

**模块参数**：
- 芯片：CC2530，2.4GHz Zigbee
- 串口：UART @115200bps，8N1
- 模式：透明传输（点对点），两模块配对后即串口透传
- 通信距离：空旷 ~100m

**钥匙端 → 门锁端 数据包格式（2字节）**：

```
Byte 0: 0xA5         同步头
Byte 1: KeyID        钥匙端 DIP-4 值 (0~15, 只取低4位)
```

- 发送周期：每 **200ms** 发送一次
- DIP 变化时立即发送（不等周期）
- 门锁端收到后更新 `g_key_id`，与本地 DIP-4 比对
- 门锁端超时 **1000ms** 未收到 → Zigbee超时 → ID不匹配

**DL-20 配置（AT命令）**：
- 两模块需配置为相同信道和波特率
- 默认波特率 115200（也可用 9600）
- 详见 DL-20 说明书 AT 命令章节

### 4.2 UART帧解析（关键代码框架）

```c
// UART接收缓冲区
#define UART_BUF_SIZE 64
uint8_t uart_buf[UART_BUF_SIZE];
uint8_t uart_idx = 0;

// 帧结构体
typedef struct {
    uint32_t header;
    uint16_t pkt_len;
    uint16_t seq_id;
    uint16_t cmd;
    uint16_t version;
    uint32_t anchor_id;
    uint32_t tag_id;
    uint32_t distance;    // cm
    int16_t  azimuth;     // degrees
    int16_t  elevation;   // degrees
    uint16_t tag_status;
    uint16_t batch_sn;
    uint32_t reserve;
    uint8_t  xor_byte;
} UWB_Frame;

// UART中断接收
void UART_IRQHandler(void) {
    uint8_t byte = USART_ReceiveData(USART1);
    
    // 检测帧头 0xFF 0xFF 0xFF 0xFF
    if (uart_idx >= 3 && 
        uart_buf[uart_idx-3] == 0xFF && 
        uart_buf[uart_idx-2] == 0xFF &&
        uart_buf[uart_idx-1] == 0xFF && 
        byte == 0xFF) {
        uart_idx = 0;
        uart_buf[uart_idx++] = byte;
        return;
    }
    
    uart_buf[uart_idx++] = byte;
    
    // 收到足够长度？PacketLength字段在byte[4:6]
    if (uart_idx >= 6) {
        uint16_t pkt_len = (uart_buf[4] << 8) | uart_buf[5];
        if (uart_idx >= pkt_len + 4 + 2 + 1) { // header + length field + xor
            parse_frame();
            uart_idx = 0;
        }
    }
}

void parse_frame(void) {
    UWB_Frame frame;
    frame.pkt_len   = (uart_buf[4] << 8) | uart_buf[5];
    frame.seq_id    = (uart_buf[6] << 8) | uart_buf[7];
    frame.cmd       = (uart_buf[8] << 8) | uart_buf[9];
    
    if (frame.cmd != 0x2001) return;  // 只处理定位帧
    
    frame.anchor_id = *(uint32_t*)(uart_buf + 12);
    frame.tag_id    = *(uint32_t*)(uart_buf + 16);
    frame.distance  = *(uint32_t*)(uart_buf + 20);  // cm
    frame.azimuth   = *(int16_t*)(uart_buf + 24);    // 度
    frame.elevation = *(int16_t*)(uart_buf + 26);    // 度
    
    // XOR校验
    uint8_t xor_calc = 0;
    for (int i = 0; i < frame.pkt_len + 6; i++)
        xor_calc ^= uart_buf[i];
    
    if (xor_calc == uart_buf[frame.pkt_len + 6]) {
        process_position(frame.tag_id, frame.distance, frame.azimuth);
    }
}
```

### 4.3 区域判定（带滞回）

```c
typedef enum {
    ZONE_NONE = 0,    // 无钥匙 / 超FOV
    ZONE_SENSING,     // 感应区 >2m
    ZONE_WELCOME,     // 迎宾区 1~2m
    ZONE_UNLOCK       // 开锁区 <1m
} Zone_t;

// 滞回阈值
#define THR_UNLOCK_ENTER   100   // cm, 进入开锁区
#define THR_UNLOCK_EXIT    110   // cm, 离开开锁区
#define THR_WELCOME_ENTER  200   // cm, 进入迎宾区
#define THR_WELCOME_EXIT   210   // cm, 离开迎宾区
#define FOV_HALF_ANGLE     45    // 度, 正前方±45°FOV

Zone_t current_zone = ZONE_NONE;

Zone_t determine_zone(uint32_t dist_cm, int16_t azimuth) {
    // FOV检查
    if (azimuth > FOV_HALF_ANGLE || azimuth < -FOV_HALF_ANGLE)
        return ZONE_NONE;
    
    if (dist_cm <= THR_UNLOCK_ENTER)
        return ZONE_UNLOCK;
    else if (dist_cm <= THR_WELCOME_ENTER)
        return ZONE_WELCOME;
    else
        return ZONE_SENSING;
}
```


### 4.5 ID验证机制 🆕 v2.0

**原方案 (v1.0)**：门锁端用 UWB TagID & 0x0F 与 DIP-4 比对。

**新方案 (v2.0)**：ID验证独立于UWB定位系统：
```
钥匙端: DIP-4 → STM32 → Zigbee DL-20 → 无线发送 [0xA5][KeyID]
门锁端: Zigbee DL-20 → USART3 → STM32 接收 KeyID
比对:   KeyID == LockDIP ?  授权 : 拒绝
```

- 钥匙端每 **200ms** 发送一次 2字节包（`0xA5` + KeyID）
- 门锁端超过 **1000ms** 未收到 → Zigbee超时 → 视为钥匙离开
- UWB 只负责测距/测角（定位），**TagID 不再用于身份识别**
- 两端 DIP-4 独立设置，只有值相同时才能开锁
- 钥匙端 DIP 变化 → 立即发送新ID（不等200ms周期）

## 五、关键优势总结

| 题目要求 | 传统方案 | ALX套件方案 |
|----------|----------|------------|
| 无线通信距离≥3m | 需要自行调试RF | ✅ UWB天然>10m，套件已调优 |
| 径向距离误差≤0.3m | 需要实现TOF算法 | ✅ 基站直接输出，精度±10cm |
| 方位角误差≤10° | 需要双天线+PDoA算法 | ✅ 基站直接输出，内置PDoA |
| 抗多径干扰 | 需要算法处理 | ✅ UWB物理层抗多径 |
| 迎宾/开锁区判定≤0.2m | 需要滤波 | ✅ 距离精度足够+基站内置卡尔曼 |
| ID验证 | 需要自定义协议 | ✅ TagID字段天然就是身份标识 |

### STM32只需要做：
1. ⬜ UART串口接收+帧解析
2. ⬜ ID比对（DIP开关 ↔ TagID低4位）
3. ⬜ 区域判定（if-else，带滞回）
4. ⬜ OLED显示驱动
5. ⬜ GPIO控制LED+蜂鸣器

> **不需要**：TOF测距、PDoA测角、天线阵列设计、卡尔曼滤波——全是基站硬件搞定的！
