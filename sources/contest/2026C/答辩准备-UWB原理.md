# UWB 测距测角原理 · 答辩准备

> 适用系统：ALX-AOA-FIT PDOA 跟随套件（单基站 + 信标），STM32F103C8T6
> 定位方案：**TOF 双向测距 + 4天线 PDoA 测角**（基站内置 MCU 完成，UART 主动上报）

---

## 0. 30 秒总纲（专家让你"讲讲你们系统原理"时先背这个）

> 我们的定位系统基于 UWB 超宽带技术，分测距和测角两步：
> 1. **测距用 TOF（飞行时间）**：基站和信标之间通过双向报文，测量电磁波在空中的飞行时间，乘以光速得到距离。用**双向测距**是因为两端时钟不同步，单向打时间戳测不准，双向可以把时钟偏差消掉。
> 2. **测角用 PDoA（相位差到达）**：基站有 4 根天线，同一个信号到达不同天线有**波程差**，产生载波**相位差**，相位差与来波角度一一对应，反解出方位角（还有仰角）。
> 3. 这两个算法都在**基站内置的 32 位 MCU** 里算好，通过串口 115200 主动上报距离（cm）和角度（度），我们的 STM32 只做协议解析、ID 验证、区域判定和门锁控制。

## 1. UWB 是什么（3 句话级别）

- **超宽带**：工作频段 3.1~10.6 GHz，单信号带宽 ≥ 500 MHz，比蓝牙/WiFi（几十 MHz）宽一个量级。
- 带宽极宽 → 脉冲极窄（纳秒级），**时间分辨率极高** → 测时间就能测出厘米级距离。
- 脉冲窄还有一个好处：**抗多径**。反射波和直达波在时间上分得开（路径差 > 约 30cm 就能分辨），接收机只认**最先到达的第一径（直达径）**，所以室内多径环境下精度不崩。这是 UWB 相对蓝牙 RSSI 测距的根本优势。

> 追问："为什么窄脉冲时间分辨率高？" → 信号带宽 B 的脉冲宽度约 1/B。B=500 MHz 时脉冲约 2ns，2ns 对应 60cm 的传播路径差。测时间测到亚纳秒级，距离就能到厘米级。

## 2. 测距原理：TOF 双向测距（重点，必问）

### 2.0 链路全景：信标 ↔ 基站 ↔ STM32（先说清楚谁和谁说话）

```
信标(Tag)           基站(Anchor)                门锁端 STM32
  │ UWB射频(Poll) ──▶│                            │
  │ ◀──(Response)    │ 内部计算:                  │
  │ ◀──(Final时间戳) │ TOF距离 + PDoA角度         │
  │                  │ ──UART 0x2001(115200)──▶ 解析→ID比对→区域判定→开锁
```

- **信标 ↔ 基站**：UWB 射频链路（3.1~10.6GHz 脉冲无线电，带宽 ≥500MHz）。信标上电自动周期性发起测距帧（Poll），基站应答（Response）并交换时间戳——这就是 2.2 节双向测距的"两次报文"；是否再有第三次 Final 帧回传时间戳（SS-TWR 还是 DS-TWR）由固件决定。同一帧到达 4 根天线的相位差用于 PDoA 测角。
- **基站 ↔ STM32**：TTL 串口 115200，基站算完主动上报 0x2001 帧。
- 空口对我们是**黑盒**：信标不用编程（上电即广播）、基站不用编程（自动应答计算），我们接触的唯一接口是 UART。注意 Zigbee 是钥匙端 STM32 ↔ 门锁端 STM32 的链路，与信标无关。
- 答辩话术：*"信标和基站之间是 UWB 脉冲射频，通过双向测距帧交换时间戳完成测距，同一帧到达 4 根天线的相位差完成测角；这些都在基站内置 MCU 里算好，我们通过串口拿到的是定位结果。"*

### 2.1 基本思想

电磁波速度是光速 c = 3×10⁸ m/s，恒定。**测出信号飞行时间 t，距离 = c × t ÷ 2**（除以 2 是往返路程）。

- 1m 距离，电磁波往返只要 **6.7ns** —— 所以时钟必须非常准、测量必须非常精细。
- 这也解释了为什么说"UWB 测距是测时间，不是测信号强度"：RSSI 受遮挡、多径、天线方向影响巨大，室内误差米级；TOF 直接测物理量，误差只取决于时间测量精度。

### 2.2 为什么必须"双向测距"（专家必问的坑）

如果直接测单向飞行时间，需要两个设备**时钟严格同步**——这几乎做不到。所以用**双向测距（TWR）**：

```
信标 ──发送请求──▶ 基站 ──回复──▶ 信标
      |_t1_|_处理延时(Treply)_|_t2_|
```

- 信标测出**总往返时间 Tround**（用信标自己的时钟）
- 处理延时 Treply 由基站测出（用基站的时钟）并随报文带回
- **TOF = (Tround − Treply) / 2**

这样两端**不需要绝对同步**，只要交换期间各自时钟频率足够准即可。这层逻辑一定要能讲出来："双向的目的是把两端不同步的**绝对时间偏差**消掉，只留下各自**频率偏差**的影响"。

> 追问："时钟频率偏差的影响有多大？" → 晶振精度典型 ±20ppm（百万分之 20）。Treply 越长、误差越大：误差 ≈ 频率偏差 × Treply / 2。Treply 取 1ms 时误差可达 1.5m，所以要么 Treply 做得短，要么用三次握手。

### 2.3 进阶：DS-TWR 三次握手（能答出来很加分）

- **SS-TWR（单边）**：一次来回，实现简单，但受时钟频率偏差影响大。
- **DS-TWR（双边）**：三次报文（请求→应答→最终），**两端各自测一次往返**，把两个往返结果组合，**一阶抵消时钟漂移**，抗时钟偏差能力提高一个量级。
- 答题模板：*"模块内部大概率用的是 DS-TWR 类方案，因为它在晶振精度一般的情况下也能保证厘米级；具体是双边还是单边由芯片固件决定，我们验证的是它输出的最终精度。"* —— 诚实 + 懂行。

### 2.4 为什么能测到厘米级（时间怎么测得这么细）

专家会问："6.7ns 才 1 米，你的时钟得多快才能测出厘米？"

回答要点：**不是靠单纯数高频时钟脉冲**，而是靠**脉冲相关 + 前沿检测 + 插值**：

- 接收机把收到的脉冲与本地模板做**相关运算**，找到相关峰；
- 在相关峰附近对采样点做**插值**，把时间戳精度提到皮秒量级（等效于极高分辨率）；
- 再配合多次测量取平均 / 卡尔曼滤波，最终输出精度典型 **±10cm**（规格书只写"厘米级精度"，±10cm 是行业典型值；实测后把实际误差补到 Q9 里）。

### 2.5 测距背诵卡

| 数字 | 含义 |
|---|---|
| c = 3×10⁸ m/s | 光速 |
| 1ns 电磁波走 30cm | 心算工具 |
| 1m 距离往返 = 6.7ns | 心算工具 |
| 带宽 ≥ 500MHz | UWB 定义之一，脉冲 ≤ 2ns |
| ±10cm | 典型测距精度（规格书称"厘米级"） |

## 3. 测角原理：PDoA 相位差测角（重点，必问）

### 3.1 基本思想：同一个波，先到近的天线

基站上有 **4 根天线**，间距很小（波长量级）。信标信号到达不同天线时，**路程长短不一样**（来波是斜着过来的），于是：

- 波程差 → 到达**时间差** → 等效为**载波相位差**
- 相位差由**来波方向唯一决定**，反解即得角度

### 3.2 公式（推导过程要会讲）

两根天线间距 d，来波与天线阵列法线的夹角 θ（方位角）：

- 波程差：**ΔL = d·sinθ**
- 相位差：**Δφ = 2π·ΔL / λ = 2π·d·sinθ / λ**
- 反解：**θ = arcsin( Δφ·λ / (2π·d) )**

推导要能现场做出来：画两根天线 + 一条斜着来的波前 → 直角三角形 → 斜边差就是 d·sinθ → 相位差和路程差差一个 2π/λ 的比例。这就是 **PDoA（Phase Difference of Arrival，相位差到达）**。

**ΔL → Δφ 那一步怎么讲（问答必讲的桥）**：波在空间上是正弦波，走一个波长 λ 相位正好转 2π，所以相位随路程的变化率 = 2π/λ。换算三步：ΔL ÷ λ = 波长数 → × 2π = 相位差，即 Δφ = 2π·ΔL/λ。心算工具：λ/4=90°、λ/2=180°、λ=360°。数字演示：λ=4.6cm、d=λ/2=2.3cm、θ=30° → ΔL=λ/4 → Δφ=90°（A 比 B 落后四分之一波长）。加分句：同样的路程差换成时间差只有 38 皮秒测不了，换成相位差 90° 一测一个准——**PDoA 的本质就是把皮秒级时间差"放大"成易测的相位量**。模块实际用 I/Q 采样恢复各天线相位再相减，那是固件的活，讲到 Δφ 为止。

λ 在 6.5GHz 附近约 4.6cm，在 8GHz 约 3.75cm —— 所以天线间距是厘米级的。

### 3.3 为什么用 4 根天线而不是 2 根

- **2 根天线只能测一个面内的角度**（一维）。
- **4 根天线组成面阵（2×2）**：横向天线对测**方位角**（Azimuth），纵向天线对测**仰角**（Elevation）——协议里两个字段都有，就是这个原因。

**关键加分点：测仰角是为了让方位角更准**（专家问"你们又不用仰角，为什么还要 4 根天线"就答这段）：

水平天线对的相位差实际是 **Δφ = 2π·d·sinθ·cosφ / λ**，里面混着仰角因子。如果只有 2 根天线，解算时只能假设 φ=0——但钥匙和基站高度不同（基站装门锁约 1.3m，钥匙在你手里随动作起伏），φ≠0 时方位角会被**低估**。纵向天线对把 φ 测出来，固件就能解掉 cosφ 项。所以"不需要仰角输出" ≠ "可以只用 2 根天线"——**4 天线恰恰是钥匙高度变化时方位角依然准确的原因**。

**cosφ 哪来的（一句话推导，防专家追问）**：设横对基线沿 X、法线沿 Z、竖直向上为 Y，来波方向单位矢量 u=(sinθ·cosφ, sinφ, cosθ·cosφ)。路程差 = 基线在来波方向上的投影 = d·u_x = **d·sinθ·cosφ**。§3.2 是水平面内 2D 简化推导（φ=0，cosφ=1），完整 3D 式就是这个。数值感受：θ=45°、φ=30° 时 sinθ·cosφ=0.612，按 2D 公式反解得 37.8°——**低估约 7°**。对称地，纵对天线（基线沿 Y）得 Δφ_v=2π·d·sinφ/λ：两个方程解两个未知数，先解 φ 再解 θ，这就是 4 天线解耦的数学本质。

**实物识别（答辩可直接指着基站讲）**：板上的 4 个黄铜色方形金属片就是 **2×2 贴片天线阵列**，尺寸约半个波长（厘米级），间距也是波长量级——正好对应 3.2 节 d≤λ/2 的无模糊条件。横对→方位角，纵对→仰角。演示注意：天线面阵正面朝向持钥匙的人，别用手/金属件遮挡基站正面，别握着基站演示。

### 3.4 为什么规格书说"120° 内最准、180° 内可用"（专家高频追问）

两个原因，都要会：

1. **相位模糊**：Δφ 只有 [−π, π] 区间内是单值映射。当 d·sinθ 超过 λ/2，相位会**绕圈**（2π 模），一个相位差可能对应多个角度。天线间距 d 和 λ/2 的关系决定了**无模糊角度范围**——这正是阵列设计的关键。
2. **灵敏度随角度变差**：θ 越接近 ±90°，同样的相位测量误差换算成角度误差被 **1/cosθ** 放大（因为 sin 曲线在 90° 处变平）。所以 ±60° 内精度好，边缘差。

所以系统 **FOV 只取 ±45°**：既满足题目 ≤10° 角误差，又留了裕量。

### 3.5 测角背诵卡

| 公式/数字 | 含义 |
|---|---|
| Δφ = 2π·d·sinθ / λ | 相位差核心公式 |
| d ≤ λ/2 | 无相位模糊条件 |
| ±60°（共120°） | 套件最佳测角范围 |
| 角度误差 ∝ 1/cosθ | 大角度误差放大 |

## 4. 高频追问 TOP 10（问答模板）

**Q1：为什么不用蓝牙/WiFi 测距，非要 UWB？**
→ 蓝牙/WiFi 只能靠 RSSI（信号强度）估距，强度受多径、遮挡、天线方向影响很大，室内误差米级；UWB 直接测飞行时间，物理量，误差只取决于时间测量精度，±10cm；而且 UWB 脉冲窄，多径环境下能锁定直达径，蓝牙做不到。

**Q2：多径干扰怎么办？**
→ 三层：① UWB 带宽 500MHz 起，反射径和直达径在时间上差几十 cm 以上就能分辨，接收机锁第一径；② 基站内置卡尔曼滤波（规格书明确"数据自带卡尔曼滤波"）；③ STM32 侧还有滑动平均滤波（距离窗口 8、角度窗口 5，config.h 可调）。

**Q3：定位算法是你们写的吗？**
→ 诚实 + 强调系统集成：物理层的 TOF 测距、PDoA 测角、卡尔曼滤波由基站内置 32 位 MCU 完成（相当于一个"定位传感器"）；我们完成的是 **0x2001 帧解析（帧同步 + XOR 校验 + 大端转换）、ID 验证系统（Zigbee + DIP-4）、带滞回的区域判定、锁状态机、人机交互**。模块作为标准件使用是允许的，关键是把原理讲透、把系统做稳。

**Q4：你们的区域判定原理是什么？**
→ 单基站给的是极坐标 (r, θ)：距离定半径、角度定方向。判定 = **半径阈值 + 角度门限联合判断**：|α|≤45° 才有效（FOV 门限），距离分档：**≤130cm 开锁、130~230cm 迎宾、230~430cm 感应、>430cm 无钥匙**（阈值在 config.h 可调），**档间带 10cm 滞回**防止在阈值边界来回抖动导致锁频繁动作。

**Q5：滞回值为什么取 10cm？**
→ 滤波后距离噪声约 ±2~3cm（预期值，实测后按实际噪声修正），10cm 滞回远大于噪声；开锁档进入 130cm、退出 140cm，迎宾档进入 230cm、退出 240cm，保证边界处不会"一帧开锁、一帧闭锁"反复跳变。这就是经典施密特触发思想。

**Q6：UWB 和 Zigbee 都在无线工作，会互相干扰吗？**
→ 不会。频段错开：Zigbee 在 2.4GHz，UWB 在 3.1~10.6GHz；而且 UWB 功率谱密度极低（限值 -41.3dBm/MHz 以下），对窄带系统几乎无干扰。另外 UWB 定位和 Zigbee 传 ID 职责分离、互不依赖。

**Q7：为什么身份识别不用 UWB 的 TagID，而是另加 Zigbee？**
→ v2.0 的改进：① 现场改 ID 方便——拨码开关即改即生效，而 UWB 信标改 ID 要连配置软件上位机；② 职责解耦——UWB 专心做定位（精度不能被身份需求绑架），Zigbee 专心传身份（2 字节透明传输，空旷 100m）；③ 两组 DIP 独立设置，只有两端一致才能开锁，安全性也更清晰。

**Q8：钥匙站在基站正后方（180°）怎么办？**
→ 单基站只覆盖正面 180°（四基站才是 360°）。正后方收不到定位数据，基站发心跳包（0x2002），我们 3 秒收不到定位帧就判定"钥匙离开"→ 闭锁。角度超 ±45° 的也一律视为无效区域。

**Q9：你们怎么保证/验证精度？**
→ ① 只在 ±60° 最佳测角范围内使用（FOV 取 ±45° 更保守）；② 距离用尺子实测对照 OLED 显示值记录误差；③ 基站开卡尔曼 + 我们侧滑动滤波；④ 滞回和超时参数可现场调（config.h 里全是宏）。

**Q10：卡尔曼滤波是干嘛的？**
→ 数据融合 + 平滑：用运动模型预测下一点，再用新测量修正，输出比单次测量更平滑、更准的估计，对噪声和跳变有抑制作用。基站输出的数据本身已过卡尔曼，STM32 侧再叠一层滑动平均是双保险。

## 5. 口径清单：哪些是我们的、哪些是模块的、哪些是通用原理（防说错）

专家最爱抓"你说的到底是不是你做的"。把每个知识点对号入座，主语说错一个词就可能穿帮：

**✅ 我们的系统（可以理直气壮说"我们做的/我们用的"）：**
- 0x2001 帧解析（帧同步 + XOR 校验 + 大端转换）
- ID 验证：DIP-4 拨码 + Zigbee DL-20（2.4GHz）传 ID，两端一致才开锁
- 区域判定：半径阈值分档 + FOV±45° + 10cm 滞回 + 3s 超时
- 锁状态机、OLED/LED/蜂鸣器、滑动平均滤波（距离窗口 8、角度窗口 5）

**🔧 模块内部的（说"由基站内置 MCU 完成/固件决定"，别说"我们实现/我们写"）：**
- TOF 测距、PDoA 测角、卡尔曼滤波、4 天线阵列与射频前端

**📖 通用原理（讲原理时说"UWB 技术普遍采用/理论上是"，别说"我们系统用了"）：**
- DS-TWR 三次握手、相关+前沿检测+插值测时、相位模糊 d≤λ/2、cosφ 仰角串扰

**❌ 禁句：**"我们用了三次握手""我们写了卡尔曼""我们的天线是自己做的"——测距、测角、天线全是模块的。想讲三次握手就按 §2.3 的模板：讲原理 → 承认模块内部由固件决定 → 落到"我们验证的是它输出的最终精度"。

## 6. 应对"专家追问到不会的地方"

- 先答原理层（上面这些），如果被问到芯片内部寄存器级的细节（比如"相位差是 I/Q 怎么采的"），诚实说：*"具体实现由模块固件完成，我们没有改动它内部，我们验证的是它输出的规格参数；如果需要调整，用厂商的配置命令（0x2086 配置卡尔曼使能——**出厂默认已开启**，读取状态用 0x2084 查 KalmanFlag；我们未改动过内部配置）。"* —— 把话题拉回到熟悉的部分。
- 关键心态：专家考的是**你懂不懂原理、知不知道自己在用什么**，不是考你会不会造芯片。原理讲透 + 系统逻辑闭环，就达标了。

## 7. 快速复习卡（上场前扫一遍）

```
UWB  = 超宽带(3.1~10.6GHz, ≥500MHz) → 纳秒级窄脉冲 → 高时间分辨率 → 厘米级
测距 = TOF: 距离 = c × t / 2，双向测距消除时钟不同步，DS-TWR 消时钟漂移
     ±10cm 精度靠：相关+前沿检测+插值+滤波
测角 = PDoA: Δφ = 2π·d·sinθ/λ → θ = arcsin(Δφ·λ/2πd)
     4 天线 = 方位角 + 仰角；d≤λ/2 无模糊；±60° 内最准(1/cosθ 放大)
分工 = 模块算好(TOF+PDoA+卡尔曼) → UART 0x2001 上报 → STM32 解析+判定+控制
区域 = 极坐标(r,θ)：半径三档阈值 + FOV±45° 门限 + 10cm 滞回
身份 = Zigbee 2.4GHz 传 DIP-4 ID，与 UWB(3.1~10.6GHz) 频段错开不干扰
```
