## 项目概述

2026 年全国大学生电子设计竞赛赛区赛（TI 杯）H 题：**车载平衡滚球运动控制系统**。STM32F103C8T6（Cortex-M3, 72MHz, 64KB Flash, 20KB RAM）为主控，驱动一辆沿黑色环形路线行驶的小车，行驶过程中通过舵机控制摆杆角度，使钢球在摆杆凹槽内保持稳定。

**⚠️ 关键约束：** 运行在裸机 10ms 定时中断（TIM3 ISR → `pid_control()`），无 RTOS，无动态内存分配。所有状态机运行在中断上下文，OLED I2C 刷新在主循环。

**⚠️ 当前状态：代码库刚从 2021F 智能送药小车项目拷贝过来，包含大量不再需要的旧代码（K230 数字识别、远端导航、路径记忆等）。需要逐步清理并重写为 H 题的控制逻辑。**

## 硬件架构

```
STM32F103C8T6
├── 8路灰度传感器      → 黑线巡线 + 启停线检测
├── MPU6050 (陀螺仪)    → 转弯角度控制（200Hz INT 中断 + 卡尔曼融合）
├── HMC5883L (磁力计)   → 偏航角观测（卡尔曼融合输入）
├── 2路编码器电机       → PID 速度闭环 + 差速转弯
├── 舵机（PWM）         → 摆杆角度控制（控制钢球在凹槽中的位置）
├── 球位置检测摄像头    → 安装在摆杆凹槽上方，检测钢球的实际位置
├── 图传发送模块        → 将摄像头画面无线传输到场外接收端
├── OLED 128x64 (I2C)  → 计时显示 + 状态信息（≤2英寸）
├── LED 红/绿 (PA11/12) → 状态指示
└── 按键 (PB5)          → 启动按键
```

**摆杆结构：**
- 4 分 PPR 水管改造，长度 25cm，外径 2cm × 壁厚 0.34cm
- 凹槽内壁表面光滑，放置直径约 1cm 的钢球
- 凹槽剖面边沿贴有刻度线（间距 0.1cm），不允许贴在凹槽内
- 左端用铰链/合页固定，高度 h ≥ 5cm，另一端连接至舵机
- 整个摆杆不超出车身

**车身尺寸限制：** ≤ 35cm（长） × 25cm（宽）

## 执行模型

```
main() 主循环:
  ├── 阶段1: 等待按键启动(PB5) — 每20ms调用 ball_detect_parse() + 每100ms刷新OLED
  │    ├── OLED显示: 有球→ X/Y坐标，丢球≥3帧→ NONE
  │    └── TIM3未启动，电机不转（安全调试模式）
  └── 阶段2: 启动后 OLED 刷新（检查 oled_dirty 标志，大字模式渲染）

TIM3 ISR（10ms 周期，硬实时）:
  └── pid_control():
      ├── ball_detect_parse() — 解析 K230 钢珠检测数据（消费 UART 环形缓冲区）
      ├── 编码器读数 + 速度 PID 计算
      ├── ★ 巡线控制（line_pid_track）
      ├── ★ 赛道圈数/路段状态机（启停线检测、路段计时）
      ├── ★ 摆杆平衡控制（球位置 PID → 舵机角度输出）
      ├── OLED 缓冲区更新（每200ms，写 oled_line1~2 各8字符，置 oled_dirty=1）
      └── 电机占空比输出（motorA_duty / motorB_duty）

USART1 ISR（每字节触发）:
  └── ball_detect_rx_handler() — 将 K230 发来的钢珠数据写入环形缓冲区
```

**⚠️ 关键：** 所有控制逻辑运行在 ISR 中，不能阻塞、不能 `delay_ms()`、不能用 `malloc()`。用状态机 + 计数器实现延时。

## K230 ↔ STM32 UART 协议（钢珠检测）

**物理层：** K230 Pin8(IO3/TX1)→STM32 UART1 RX, Pin10(IO4/RX1)→STM32 UART1 TX，115200-8N1（01Studio K230 UART1）

**协议格式（每帧一行，以 `\n` 结尾）：**

| 数据类型 | 格式 | 示例 |
|---------|------|------|
| 检测到钢珠 | `B,<cx>,<cy>,<confidence>,<x1>,<y1>,<x2>,<y2>\n` | `B,320,400,0.95,300,380,340,420\n` |
| 未检测到 | `N\n` | `N\n` |

**字段说明：**
- `B` / `N`：数据类型标识
- `cx`, `cy`：钢珠中心坐标（图像空间 1280×720）
- `confidence`：置信度（0.00~1.00）
- `x1`, `y1`, `x2`, `y2`：边界框左上/右下坐标

**STM32 接收端：**
- `ball_detect_rx_handler()`：USART1 ISR 中调用，将字节写入环形缓冲区（512 bytes）
- `ball_detect_parse()`：在 `pid_control()` 中每 10ms 调用，消费缓冲区并解析行
- `ball_result`：全局结构体，包含 `cx`, `cy`, `confidence`, `detected`, `updated`, `lost_frames`

**K230 发送端：**
- `det_ball_uart.py`：运行在 K230 上，加载钢珠检测模型，每帧发送一行数据
- 取置信度最高的检测结果（钢珠只有一个）
- **EMA 消抖**：对 cx/cy/x1/y1/x2/y2/confidence 共 7 个值做指数移动平均平滑，消除模型检测框的帧间抖动
  - `EMA_ALPHA = 0.40`（新帧权重），越小越平滑但响应越慢；建议静止场景 0.30，运动场景 0.50~0.70
  - 丢帧时自动重置 EMA 状态，下次检测到球时重新初始化，避免历史值污染
- 无检测时发送 `N\n` 告知 STM32

## 控制模型（★最重要★）

### 1. 巡线控制

沿用原有的边缘中点法巡线（`line_pid_track()`），配合 PD 控制 + 陀螺前馈阻尼。

- 8 路灰度传感器检测黑线位置
- `line_error_calc()` 返回偏差值（-7~+7，正值=线偏右）
- 死区 `LINE_DEADBAND` 过滤微小偏差
- PD 控制器输出左右轮速度差

### 2. 启停线检测（A 点）

A 点有垂直于环路的黑色启停线（长 5cm），需要与巡线黑线区分：

- 常规巡线：1 段连续黑传感器（黑线宽 ~1.8cm ≈ 1~2 个传感器）
- 启停线：横向黑胶带 + 纵向黑线交叉 → 更多传感器变黑（≥3 个相邻黑传感器）
- 或使用 `parking_block_detect()` 的黑色段数检测逻辑（≥2 段独立黑块）

### 3. 摆杆平衡控制（核心难点）

```
目标球位置 → [位置PID] → 目标舵机角度 → [舵机PWM] → 摆杆倾斜 → 球滚动
                                ↑
                        实际球位置 ← 摄像头检测
```

**控制回路：**
1. 摄像头实时检测钢球在摆杆凹槽中的位置（刻度线辅助定位）
2. 与目标位置比较 → 位置误差
3. PID 控制器计算所需舵机角度修正量
4. 舵机调整摆杆倾角 → 重力分量使球滚向目标位置

**关键参数：**
- 球位置 PID：P（比例）、D（微分阻尼，防止球在目标附近振荡）
- 舵机角度范围：由摆杆几何约束决定
- 前馈补偿：小车加减速/转弯时，惯性力会影响球的运动，需要加速度前馈

**转弯时的球平衡：**
- 小车转弯时产生离心力，球会向外侧滚动
- 需要提前向内侧倾斜摆杆来补偿
- 可以根据陀螺仪偏航角速度（gz）作为前馈量

### 4. 路段计时与速度控制

| 路段 | 距离 | 要求 |
|------|------|------|
| AB 段 | 1.5m 直线 | ≤ 8s（第4项） |
| 整圈 | ~4.6m（2×1.5m + π×1.0m） | ≤ 20s（第2项）/ ≤ 30s（第5/6项） |

**速度策略：**
- 直线段：可提速（但要保证球稳定）
- 圆弧段：降速（离心力小，球更容易稳定）
- 启停线前：降速确保精确停车

### 5. 球位置静态控制（第3项）

小车静止时，控制球在摆杆上往返运动：
- 从中心点 O 移动到 +5cm → 折返 → 移动到 -5cm → 稳定
- 运行时间 ≤ 5s，±5cm 处误差 ≤ 1cm
- 使用位置 PID 控制舵机角度实现

## 核心状态机（pid.c `pid_control()`）

### 1. 小车运行状态机

```
enum {
    CAR_IDLE,          // 等待按键启动
    CAR_RUNNING,       // 正常运行中
    CAR_STOPPING,      // 检测到启停线，减速停车中
    CAR_STOPPED,       // 已停车，显示总时间
};
```

### 2. 球控制状态机

```
enum {
    BALL_IDLE,         // 不控制（静止等待）
    BALL_CENTER,       // 稳定在中心点 O（第4/5项）
    BALL_POSITION,     // 稳定在指定位置（第6项）
    BALL_SWEEP,        // ±5cm 往返运动（第3项）
};
```

### 3. 十字路口/转弯控制（简化版）

H 题的赛道是简单的环形（无十字路口、T 字路口），但仍有两个 180° 半圆弧需要转弯：
- 圆弧段用巡线 PD 自然跟随即可（不检测路口）
- `cross_detect()` 仅用于检测启停线（A 点），而非十字路口

**⚠️ 旧代码清理计划：**
- ~~十字路口状态机（CROSS_NORMAL/STRAIGHT/TURN/COOLDOWN）~~ → 不需要，赛道为简单环形
- ~~K230 动态路口决策~~ → 不需要，无 K230 摄像头
- ~~远端导航（far_nav）~~ → 不需要，无复杂路口结构
- ~~路径记忆（path_memory）~~ → 不需要，无往返导航
- ~~药房/病房到达流程~~ → 不需要

### 4. 启停线检测（A 点）

- 第 1 次经过 A 点（第 2 项）：不做反应，仅开始计时
- 第 2 次经过 A 点（完成一圈）：减速停车，停止计时，显示总时间

**检测逻辑：**
```
启停线特征：横向黑胶带 + 纵向黑线交叉 →
  传感器看到的黑色段数或连续黑传感器数多于正常巡线
检测条件：parking_block_detect()（≥2段黑块）或连续 ≥N 个传感器为黑
消抖：连续 M 帧检测到启停线 → 确认
```

### 阶段1：等待启动（main.c 主循环，按键前）

上电后直接进入球检测调试模式，**TIM3 未启动，电机不转**，OLED 每 100ms 刷新：

| 场景 | L1 | L2 |
|------|-----|-----|
| 检测到钢珠 | `X:338   ` | `Y:47    ` |
| 短暂丢失（lost_frames < 3） | 保持上一个 X 坐标 | 保持上一个 Y 坐标 |
| 持续丢失（lost_frames ≥ 3） | `  NONE  ` | `  NONE  ` |

- `ball_detect_parse()` 在 `delay_ms(20)` 循环中调用，消费 UART 环形缓冲区
- 消抖阈值 `LOST_THRESHOLD = 3`（约 100ms@30fps），避免偶发丢帧闪烁
- 按 PB5 后进入阶段 2，启动 TIM3

### 阶段2：运行中（TIM3 ISR → pid_control）

| 场景 | L1 | L2 |
|------|-----|-----|
| 运行中（球在中心） | `TIME:XXs` | `BALL:OK` |
| 运行中（球偏移） | `TIME:XXs` | `X:<cx>` |
| 运行中（球丢失） | `TIME:XXs` | `BALL:ERR` |
| 到站停车 | `TIME:XXs` | `ARRIVED` |

**注意：** 球 X 中心阈值 = 590~690（图像宽 1280 的中心 ±50px）。此值根据摄像头安装位置可能需要调整。

**数据来源：**
- 时间：ISR 内按圈数/启停线检测计时

**OLED 缓冲区**（pid.c）：
- `oled_line1[32]`、`oled_line2[32]`：各存放 8 字符（`FMT8` 宏空格填充），供主循环大字渲染
- `oled_line3[32]`、`oled_line4[32]`：保留但不再使用（置空字符串）
- `oled_dirty`：ISR 每 200ms 置 1，主循环消费后清零

**主循环渲染**（main.c 阶段2）：
```c
OLED_ShowStringBig(1, 1, oled_line1);
OLED_ShowStringBig(2, 1, oled_line2);
```

## 修改指南

### 如果要修改球平衡 PID 参数
1. 球位置 PID 在当前代码中尚未实现，需要新增
2. 初始参数建议：P=2.0, D=0.5（先调 P 让球能动起来，再加 D 抑制振荡）
3. I 项在球平衡中通常不需要（摆杆倾斜后重力天然提供"复位力"）
4. 参数位置：pid.c 顶部宏定义区

### 如果要修改舵机控制
- 舵机角度范围：通常 0°~180°（对应 PWM 脉宽 0.5ms~2.5ms，周期 20ms）
- 摆杆物理约束：舵机实际可用角度由摆杆安装方式决定
- 舵机角度到球位置的映射：通过几何关系或实测标定

### 如果要修改转弯行为
- H 题的圆弧段直接用巡线 PD 跟随，无需特殊转弯逻辑
- 如果圆弧段巡线不稳定：调大 PD 的 D 项（当前 2.5）或降低速度
- 圆弧段速度可与直线段不同：在 `line_pid_track()` 中根据当前路段调整 `base_speed`

### 如果要修改启停线检测
- `parking_block_detect()`：检测 ≥2 段独立黑色段（当前阈值 2），可改为 ≥3
- 启停线消抖帧数：在启停线状态机中设置 `stable_cnt` 阈值
- 如果启停线误触发：增大黑色段数阈值或消抖帧数
- 如果启停线未触发：减小阈值，检查传感器安装位置是否覆盖启停线

### 如果要修改速度策略
- 基础速度 `BASE_SPEED`（当前 15.0）：全程默认速度
- 直线段可提速（如 `FAST_BASE_SPEED = 25.0`）
- 圆弧段可降速（如 `ARC_SPEED = 12.0`）
- 启停线前降速：在检测到启停线特征后减速到 `STOP_SPEED`

### 如果要调整巡线中心偏置（线不在传感器正中间）
- 先确认偏移方向：线在 D5-D6 之间（偏右）说明右轮偏强/左轮偏弱
- 线在 D3-D4 之间（偏左）说明左轮偏强/右轮偏弱
- **左右轮速度缩放**：`MOTOR_A_SCALE` / `MOTOR_B_SCALE`（pid.c `motor_target_set` 上方，当前 A=1.40f / B=0.70f）
  - 精细调整步长 0.01~0.02，观察线是否回到 D4-D5 之间
- 此缩放影响所有速度闭环巡线，不影响开环转弯

### 如果要调试巡线微摆
- **陀螺前馈增益**：`GYRO_DAMP_GAIN`（pid.c `line_pid_track` 顶部，当前 = 0 已关闭）
  - 如需启用：微摆不减 → 逐步增大到 0.03~0.08
  - 巡线反应变迟钝 → 减小到 0.01~0.02
- **PD参数**：`pid_init(&line_pid, ...)`（main.c），P=1.0, D=2.5
  - P 过大 → 过冲振荡 → 减小 P（可到 0.6~0.8）
  - D 过大 → 高频抖动 → 减小 D（可到 1.5~2.0）
- **死区**：`LINE_DEADBAND`（默认 0.5）
  - 中心附近仍微摆 → 增大到 0.8~1.0
  - 小偏差纠正太慢 → 减小到 0.2
- **⚠️ 已移除 EMA 滤波**：EMA 低通滤波与 D 项互相矛盾（EMA 抹平变化 → D 项失效），现在传感器偏差直接进 PD，D 项即时响应变化率。如传感器有偶发毛刺，可用死区过滤，不要加 EMA。

### 如果要调整舵机转角
- 修改 `servo_set_angle()` 中的角度到 PWM 映射
- 注意舵机死区：部分舵机在接近极限角度时线性度差
- 摆杆倾斜角与球位置的关系需实测标定

### 常用模式（遵循现有代码风格）
- 延时 = `static int cnt = N; if(--cnt <= 0) { ... }` (每周期减1, 10ms/周期)
- 新状态 = 在 enum 末尾添加，在 switch 中添加 case
- 新全局变量 = 在 pid.c 文件顶部用 `static` 声明
- OLED 显示 = 写 `oled_line1~2` 缓冲区（各8字符，`FMT8` 宏填充）+ `oled_dirty = 1`
