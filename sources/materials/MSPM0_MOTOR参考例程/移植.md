> 目标：将参考例程中的 IMU 陀螺仪模块（m0imu）移植到 MSPM0G3507 地猛星开发板

## 二、移植前必须逐项确认的检查清单

### ⚠️ 第1项：UART 引脚映射（最常见的问题）

参考例程中 IMU 使用的 UART 是 **UART3**，引脚为：

| 信号 | 引脚 | MSPM0 外设功能 |
|---|---|---|
| TX（MCU发→IMU收） | **PB2** | UART3_TX |
| RX（MCU收←IMU发） | **PB3** | UART3_RX |

**检查方法**：查阅地猛星开发板的原理图，确认 IMU 模块的 TX/RX 分别连接到 MCU 的哪两个引脚。

> **关键：** 如果地猛星板的 IMU 接到了不同的 UART 实例（如 UART0、UART1、UART2），必须同时修改：
> - `ti_msp_dl_config.h` 中 `MSPMotor_INST` 的宏定义
> - SysConfig 中 UART2 的 `peripheral.$assign`
> - 中断处理函数名称

---

### ⚠️ 第2项：时钟树 — MFCLK 必须等于 4MHz（最隐蔽的问题）

UART 的波特率时钟源是 **MFCLK**。参考例程中：

```
SYSOSC (32MHz)
  → PLL (rDivClk2x=3, qDiv=9, pDiv=2)
    → PLL_CLK2X (80MHz)
      → PLL_CLK2X_DIV (÷4 = 20MHz)
        → PLL_PDIV (÷2 = 10MHz)
          → UDIV (÷2 = 5MHz)
            → MFCLK = ??? 
```

实际上参考例程中 SysConfig 对 MFCLK 的配置路径需要看 `empty.syscfg`：

```js
// empty.syscfg 中的关键配置
divider6.divideValue = 4;   // PLL_CLK2X_DIV ÷4
divider7.divideValue = 2;   // PLL_PDIV ÷2
divider9.divideValue = 2;   // UDIV ÷2
multiplier2.multiplyValue = 10;  // PLL_QDIV ×10
```

最终 `ti_msp_dl_config.h` 中 MFCLK 通过以下方式确认为 **4MHz**：

```c
#define MSPMotor_INST_FREQUENCY  4000000   // UART时钟 = MFCLK = 4MHz
#define MSPMotor_IBRD_4_MHZ_115200_BAUD   (2)
#define MSPMotor_FBRD_4_MHZ_115200_BAUD   (11)
```

**验证方法**：
1. 打开你的 SysConfig 工程，确认 MFCLK 输出为 **4MHz**
2. 或者在 `ti_msp_dl_config.h` 中确认 `MSPMotor_INST_FREQUENCY` 宏的值
3. 如果 MFCLK 不是 4MHz（比如 8MHz、16MHz），必须重新计算 IBRD/FBRD

**波特率除数计算公式**（16x 过采样）：
```
IBRD = floor(F_UART_CLK / (16 × 目标波特率))
FBRD = round(64 × (F_UART_CLK / (16 × 目标波特率) - IBRD))
```

| MFCLK 频率 | IBRD | FBRD | 实际波特率 | 误差 |
|---|---|---|---|---|
| 4MHz | 2 | 11 | 115108 | 0.08% ✅ |
| 8MHz | 4 | 22 | 115108 | 0.08% ✅ |
| 12MHz | 6 | 33 | 115108 | 0.08% ✅ |
| 16MHz | 8 | 44 | 115108 | 0.08% ✅ |
| 32MHz（SYSOSC直接） | 17 | 23 | 115108 | 0.08% ✅ |
| 80MHz（MCLK直接） | 43 | 25 | 115108 | 0.08% ✅ |

> **注意：** 即使误差都标注为 0.08%，但内部 RC 振荡器（SYSOSC）本身有 ±1~3% 的温度漂移，如果叠加波特率误差和时钟漂移，可能导致通信间歇性失败。

### ⚠️ 第3项：UART 中断配置（容易遗漏）

参考例程中 UART3 的中断配置为：

```c
// ti_msp_dl_config.c 第258-261行
DL_UART_Main_enableInterrupt(MSPMotor_INST, DL_UART_MAIN_INTERRUPT_RX);
NVIC_SetPriority(MSPMotor_INST_INT_IRQN, 0);  // 最高优先级
```

**必须确认**：
1. **RX 中断已使能** — 只使能了 RX 中断，TX 不需要中断
2. **中断优先级为 0**（最高） — IMU 数据不能丢，UART RX 中断必须能抢占其他中断
3. **NVIC 总中断已开** — 确保初始化后没有 `__disable_irq()` 残留
4. **中断向量表正确** — 函数名必须严格匹配 `UARTx_IRQHandler`

**中断处理函数名称对照表**：

| UART 实例 | 中断处理函数名 |
|---|---|
| UART0 | `UART0_IRQHandler` |
| UART1 | `UART1_IRQHandler` |
| UART2 | `UART2_IRQHandler` |
| UART3 | `UART3_IRQHandler` |

---

### ⚠️ 第4项：GPIO 引脚配置 — 内部上下拉（极易被忽略）

参考例程中 GPIO 配置为**纯数字输入/输出，未开启内部上下拉电阻**：

```c
// empty.syscfg
UART2.txPinConfig.onlyInternalResistor = false;
UART2.rxPinConfig.onlyInternalResistor = false;
```

**⚠️ 但是**：IMU 模块在未上电或未初始化完成时，其 TX 引脚可能处于**高阻态（浮空）**。浮空的 RX 引脚会接收到随机噪声，产生虚假字节，导致解析状态机错乱。

**强烈建议**：
1. **在 SysConfig 中为 RX 引脚启用内部上拉**：将 `rxPinConfig.onlyInternalResistor` 设为 `true`，并选择 `Pull-up`
2. 或者在初始化代码中手动配置：
   ```c
   DL_GPIO_setPullResistor(GPIO_MSPMotor_RX_PORT, 
                           GPIO_MSPMotor_RX_PIN,
                           DL_GPIO_PULL_UP);
   ```

---

### ⚠️ 第5项：上电时序 — IMU 模块需要启动时间（间歇性失败的主要元凶）

参考例程的初始化时序：
```c
main() {
    SYSCFG_DL_init();        // 外设初始化（包括 GPIO、UART、时钟）
    delay_ms(3000);          // ⚠️ 等待3秒！IMU模块上电启动需要时间
    NVIC_EnableIRQ(...);     // 使能中断
    DL_TimerA_startCounter();// 启动1ms定时器
    Gyro_ConfigReportRateRx(); // ⚠️ 发送配置命令
    delay_ms(50);            // 等待IMU处理配置命令
    // ...进入主循环
}
```

**关键分析**：
- `delay_ms(3000)` — **3000ms 延迟**，给了 IMU 充分的上电和初始化时间
- 如果你的移植中这个延迟**太短**或**被删除**，IMU 可能还没准备好就收到了配置命令 → 配置失败 → 无数据输出
- `Gyro_ConfigReportRateRx()` 之后还有 `delay_ms(50)`，让 IMU 有时间处理配置命令

**建议**：
- 保持 3 秒的启动延迟不变
- 如果仍然间歇性失败，尝试延长到 5 秒
- 可以在配置命令发送后，加一个"等待 IMU 回复确认"的机制（参见第六章改进建议）

---

### ⚠️ 第6项：解析状态机无超时机制（间歇性失败的根因）

这是导致"有时候成功、有时候失败"的**最可能根因**。

IMU 数据解析状态机（`Gyro_ParseFrame`）有 4 个状态：

```
state 0 → 等待地址字节 0x0A
state 1 → 等待功能码 0x03
state 2 → 等待字节数 0x04
state 3 → 累积6字节数据（角度2B + 角速度2B + CRC2B）
         → 满9字节后校验CRC → state 0
```

**致命缺陷**：状态机**没有任何超时或帧头重同步机制**。一旦发生以下情况，状态机永久卡死：

1. **噪声干扰**：RX 引脚收到毛刺 → 产生一个垃圾字节 → 状态机从 state 0 进入 state 1/2/3，但后续字节不匹配 → 被 `else` 分支送回 state 0。但如果在 state 3 中，必须凑满 6 个字节才会回到 state 0（没有中间退出机制）。

2. **上电时 IMU 发送初始化数据**：IMU 上电后可能发送一些非标准的数据帧，打乱状态机。

3. **printf 阻塞**：主循环中 `printf()` 通过 UART0 发送数据。如果 UART0 TX FIFO 满了，`printf` 会阻塞（取决于重定向实现），此时 UART3 的 RX FIFO 可能溢出丢字节。

**为什么"偶尔成功"？**
- 当所有字节恰好正确到达 → 成功
- 当过程中有任意一个字节被干扰/丢失 → 失败（且不会自行恢复，直到复位）

---

### ⚠️ 第7项：CRC 校验

配置命令 `AA 06 01 01 01` 的 CRC16 值为 `0x00AD`（小端序：`AD 00`），已经在代码中**硬编码**：

```c
// imu.c 第129-130行
frame[idx++] = 0xad;
frame[idx++] = 0x00;
```

原始 CRC 计算代码（第126-128行）被**注释掉**了。这意味着：
- 如果你需要修改配置命令（比如修改上报频率的寄存器地址或值），硬编码的 CRC 会**失效**
- 建议恢复动态 CRC 计算，或每次修改后重新计算 CRC

**恢复动态 CRC 计算的方法**：
```c
void Gyro_ConfigReportRateRx(void)
{
    uint8_t idx = 0;
    uint8_t frame[20];

    frame[idx++] = 0xAA;
    frame[idx++] = 0x06;
    frame[idx++] = 0x01;
    frame[idx++] = 0x01;
    frame[idx++] = 0x01;

    uint16_t crc = CRC16(frame, idx);   // ← 恢复动态计算
    frame[idx++] = crc & 0xFF;
    frame[idx++] = (crc >> 8) & 0xFF;

    for (uint8_t i = 0; i < idx; i++)
    {
        while (DL_UART_isBusy(MSPMotor_INST));
        DL_UART_Main_transmitData(MSPMotor_INST, frame[i]);
    }
}
```

### ⚠️ 第8项：消除 test() 函数的副作用

`imu.c` 的 `Gyro_ParseFrame()` 开头调用了 `test()`：

```c
void Gyro_ParseFrame(uint8_t data)
{
    test();   // ← 每次收到一个字节都调用！
    // ...
}
```

`test()` 函数填充 `test_comm[]` 数组（计算另一个命令的 CRC），但结果从未使用。虽然不影响功能，但在中断服务程序中做无用计算是不良实践。

**移植时建议**：删除 `test()` 调用，或者删除整个 `test()` 函数。

## 三、移植步骤

### Step 1：复制文件

将以下 4 个文件复制到你的工程目录：
```
参考例程\m0imu\imu.c
参考例程\m0imu\imu.h
参考例程\MSP_Motor_Ctrl\motor_crc.c
参考例程\MSP_Motor_Ctrl\motor_crc.h
```

### Step 2：SysConfig 配置 UART

在 SysConfig 中（或手动编辑 `.syscfg` 文件）：

1. 添加一个 UART 实例，命名为 `MSPMotor`（或你自定义的名字）
2. 配置参数：
   - 外设：UART3（或地猛星板 IMU 实际连接的 UART）
   - RX 引脚：PB3（或实际引脚）
   - TX 引脚：PB2（或实际引脚）
   - 波特率：115200
   - 时钟源：MFCLK
   - 中断：勾选 RX 中断
   - 中断优先级：0（最高）
   - **RX 引脚内部上拉：建议开启**

3. 验证 `ti_msp_dl_config.h` 生成的内容中：
   - `MSPMotor_INST_FREQUENCY` = `4000000`
   - `MSPMotor_INST` = 你选择的 UART 实例（如 `UART3`）

### Step 3：手动确认/修改关键宏定义

如果 SysConfig 生成的文件名或宏名不同，需要在 `ti_msp_dl_config.h` 中确认以下宏存在且正确：

```c
#define MSPMotor_INST                UART3          // UART 实例
#define MSPMotor_INST_FREQUENCY      4000000        // UART 时钟 = 4MHz
#define MSPMotor_INST_IRQHandler     UART3_IRQHandler
#define MSPMotor_INST_INT_IRQN       UART3_INT_IRQn
#define GPIO_MSPMotor_RX_PORT        GPIOB
#define GPIO_MSPMotor_RX_PIN         DL_GPIO_PIN_3
#define GPIO_MSPMotor_TX_PORT        GPIOB
#define GPIO_MSPMotor_TX_PIN         DL_GPIO_PIN_2
#define MSPMotor_BAUD_RATE           115200
#define MSPMotor_IBRD_4_MHZ_115200_BAUD   (2)
#define MSPMotor_FBRD_4_MHZ_115200_BAUD   (11)
```

### Step 4：编写中断处理函数

在你的 `main.c`（或任意 `.c` 文件）中实现中断处理函数，函数名必须与宏 `MSPMotor_INST_IRQHandler` 展开后的名字完全一致：

```c
void MSPMotor_INST_IRQHandler(void)   // 即 UART3_IRQHandler
{
    switch (DL_UART_getPendingInterrupt(MSPMotor_INST))
    {
        case DL_UART_IIDX_RX:
            uint8_t data = DL_UART_Main_receiveData(MSPMotor_INST);
            Gyro_ParseFrame(data);        // IMU数据解析
            // Modbus_ParseFrame(data);   // 如果同时用电机，取消注释
            break;

        default:
            break;
    }
}
```

### Step 5：初始化时序（注意顺序！）

```c
#include "ti_msp_dl_config.h"
#include "imu.h"

int main(void)
{
    SYSCFG_DL_init();           // ① 先初始化所有外设

    delay_ms(3000);             // ② 等待3秒 — IMU上电启动

    NVIC_ClearPendingIRQ(MSPMotor_INST_INT_IRQN);
    NVIC_EnableIRQ(MSPMotor_INST_INT_IRQN);  // ③ 使能UART中断

    Gyro_ConfigReportRateRx();  // ④ 发送配置命令给IMU
    delay_ms(50);               // ⑤ 等待IMU处理配置

    while (1)
    {
        if (gyro_rx_done == 1)
        {
            gyro_rx_done = 0;
            float angle = (float)gyro_angle_raw * 0.1f;
            float dps   = (float)gyro_dps_raw * 0.1f;
            printf("%.1f,%.1f\n", angle, dps);
        }
    }
}
```

**⚠️ 特别注意初始化顺序**：
- `delay_ms(3000)` 必须在 `NVIC_EnableIRQ` 之前 → 否则干扰字节会被 ISR 处理，打乱状态机
- `Gyro_ConfigReportRateRx()` 必须在 `NVIC_EnableIRQ` 之后 → IMU 收到配置后会立即回复数据，中断必须就绪

### Step 6：确保 SysTick 正常工作

`delay_ms()` 依赖 SysTick 中断。确认 SysTick 配置正确：
- SysTick 中断优先级应低于 UART 中断（参考例程中 SysTick 优先级为 3）
- 在 `ti_msp_dl_config.c` 中确认 `SYSCFG_DL_SYSTICK_init()` 已被调用

## 四、调试诊断 — 如何判断问题出在哪

### 1. 用逻辑分析仪/示波器抓 UART 波形

这是**最可靠的诊断方法**。测量 IMU 的 TX 引脚：
- **无波形** → IMU 没有发送数据 → Step 5 初始化时序问题，或 IMU 没收到配置命令
- **有波形但不规律** → 波特率不匹配或引脚浮空
- **波形正常但 MCU 没收到** → 中断/引脚配置问题

### 2. 添加调试代码 — 回环测试

先用最简代码验证 UART 硬件通路是否正常：

```c
// 在主循环中添加：收到什么就原样发回（回环测试）
void UART3_IRQHandler(void)
{
    switch (DL_UART_getPendingInterrupt(MSPMotor_INST))
    {
        case DL_UART_IIDX_RX:
        {
            uint8_t data = DL_UART_Main_receiveData(MSPMotor_INST);
            // 回环：收到立即发回
            while (DL_UART_isBusy(MSPMotor_INST));
            DL_UART_Main_transmitData(MSPMotor_INST, data);
            break;
        }
        default:
            break;
    }
}
```

用一个 USB 转 UART 模块接到 MCU 的 PB2/PB3，发数据看是否回环正确。

### 3. 添加调试代码 — 观察状态机和原始字节

```c
// 临时添加调试代码
volatile uint8_t debug_rx_byte = 0;
volatile uint8_t debug_rx_count = 0;
volatile uint8_t debug_parse_state = 0;

void UART3_IRQHandler(void)
{
    switch (DL_UART_getPendingInterrupt(MSPMotor_INST))
    {
        case DL_UART_IIDX_RX:
        {
            debug_rx_byte = DL_UART_Main_receiveData(MSPMotor_INST);
            debug_rx_count++;
            Gyro_ParseFrame(debug_rx_byte);
            // 在主循环中 printf 输出 debug_rx_count，
            // 如果计数不增长 = 没有数据到达
            break;
        }
        default:
            break;
    }
}
```

### 4. 检查 printf 是否阻塞

如果你的 `printf` 重定向到了 UART0：
```c
// 确保 UART0 TX 采用非阻塞方式
// 或在关键代码段禁用 printf
```

### 5. 降低可能的电气干扰

- IMU 模块的 VCC 和 GND 连线要短而粗
- VCC 对 GND 加一个 100nF + 10μF 的去耦电容
- TX/RX 线远离电机驱动线、PWM 线

## 五、快速问题排查表

| 现象 | 最可能原因 | 检查项 |
|---|---|---|
| 完全没数据 | UART 引脚接错 | 第1项 |
| 完全没数据 | IMU 没收到配置命令 | 第5项、延时不够 |
| 偶尔有数据，偶尔没有 | 解析状态机卡死（无超时） | 第6项 |
| 偶尔有数据，偶尔没有 | RX 引脚浮空→噪声→虚拟字节 | 第4项 |
| 数据乱码 | 波特率不匹配 | 第2项 |
| 数据乱码 | 地线未接或接触不良 | 检查 GND 连接 |
| 同一代码有时行有时不行 | 内部 RC 振荡器温漂 | 第2项 |
| 上电后要复位几次才正常 | 上电时序/初始化顺序 | 第5项 |
| 数据帧 CRC 校验总失败 | 波特率误差过大 | 第2项 |

## 六、强烈推荐的改进（提升稳定性）

### 改进1：给解析状态机加超时机制

```c
void Gyro_ParseFrame(uint8_t data)
{
    static uint8_t state = 0;
    static uint8_t frame[9];
    static uint8_t idx = 0;
    static uint16_t timeout = 0;  // 新增：超时计数

    // 如果 50ms 内未完成一帧，重置状态机
    if (timeout > 50) {
        state = 0;
        idx = 0;
    }

    switch(state)
    {
        case 0:
            timeout = 0;          // 空闲状态，清超时计数
            if(data == 0x0A) {
                idx = 0;
                frame[idx++] = data;
                state = 1;
                timeout = 0;
            }
            break;

        case 1:
            timeout++;
            if(data == 0x03) {
                frame[idx++] = data;
                state = 2;
            } else {
                state = 0;
            }
            break;

        // ... case 2, 3 中也加 timeout++
    }
}
```

然后在 1ms 定时器中断中递增 `timeout`：
```c
void TIMER_0_INST_IRQHandler(void)
{
    // 每个1ms，超时计数+1
    extern uint16_t gyro_timeout;
    gyro_timeout++;
    // ...原有代码
}
```

### 改进2：加帧头搜索（更健壮）

在 state 0 中添加帧头搜索，而不是只匹配一次：

```c
case 0:
    if(data == 0x0A) {
        idx = 0;
        frame[idx++] = data;
        state = 1;
    }
    // 不是0x0A就忽略，继续等待
    break;
```

这个已经有实现，但要确保 `case 3` 中如果收集到一半，也能通过某种方式退出。

### 改进3：恢复动态 CRC 计算

不再硬编码配置命令的 CRC（见第七项），这样修改配置更灵活。

## 七、关键经验总结

1. **内部 RC 振荡器不是精确时钟源** — 如果 IMU 对波特率精度要求高（< ±1%），考虑使用外部晶振（HFXT）
2. **UART RX 引脚一定要处理浮空问题** — 内部上拉或外部上拉电阻（4.7kΩ~10kΩ）
3. **解析状态机必须有超时恢复机制** — 工程环境下电磁干扰是常态，帧不完整是预期内的
4. **上电时序很重要** — IMU 传感器需要毫秒到秒级别的启动时间
5. **中断优先级要合理** — 通信中断 > 定时器中断 > 主循环
6. **调试时先用回环测试验证硬件通路** — 再排查协议/软件问题
