## 系统框图

依赖树（缩进 = 依赖层级，依赖先于使用者）：
  - led：LED 指示灯驱动（双平台）：led_init/led_on/led_off/led_toggle + 通道宏 LED_RED/LED_YELLOW/LED_GREEN；拉电流 1=亮 细节已封装在模块内。
  - beep：蜂鸣器驱动（双平台）：beep_init/beep_on/beep_off/beep_toggle + beep_beep 响 N 声（阻塞式）。
  - delay：MSPM0 毫秒延时：delay_ms 基于 CPUCLK_FREQ 换算调用 delay_cycles，任何时钟频率自动适配。
    - oled：0.96 寸 OLED（SSD1306）I2C 显示驱动：硬件 I2C 显存式绘图（画点/字符/字符串/汉字，支持反色与 180° 旋转），带 16×8 ASCII 字库。（依赖：delay）
  - key：按键读取（双平台）：get_key_state 读取按键（上拉低电平按下）；stm32 默认 PB3（JTDO 复位后可用），mspm0 默认 PA2。
  - motor：TB6612 双路直流电机驱动（双平台统一 API）：motor_set_duty 调速 + motor_set_direction 方向 + motor_encoder_read 编码器读数（读后清零）。
  - ntb_time：系统毫秒时间戳（双平台统一 get_time_stamp_ms）：mspm0 用 NTB 定时器回绕累加，stm32 用 SysTick 1ms 节拍。

## 系统方案论证

本系统以STM32或MSPM0单片机为核心控制单元，利用其硬件定时器产生PWM信号驱动电机，通过编码器接口采集速度信息形成闭环控制，并借助I2C接口驱动OLED显示。选择双电机差速驱动方案，采用TB6612模块，具有体积小、效率高、PWM调速方便等优点。按键作为系统复位与启动触发，LED和蜂鸣器完成状态指示与报警。

循迹与数字识别是决定任务成败的关键。对比红外对管与灰度传感器，灰度传感器能稳定分辨红线与白色地面，且不易受环境光影响，故采用灰度传感器阵列。在数字识别上，采用摄像头模块直接识别纸质数字，相较于电磁感应或编码器预设方案，摄像头更具灵活性，能适应测试时随机设定的病房号。摄像头与灰度传感器作为外设，虽未在给定的模块清单与引脚分配中列出，但通过主控空闲GPIO或串口接入，系统设计时预留接口。此外，为支持发挥部分双车协同，采用无线通信模块实现小车间指令交互。综合以上选型，系统能够满足单个小车送药和双小车协同的要求。

## 软件流程设计

系统上电后初始化OLED、电机、LED、蜂鸣器等外设，进入待机状态。按下启动键后，小车首先通过摄像头识别药房处手持的数字标号纸张，获取病房号并将结果显示在OLED上。识别完成后，检测药品装载信号（如通过重力或光电检测，此处简化为外部触发），一旦检测到药品装载完成，立即启动电机，灰度循迹算法控制小车沿红线行驶。运行过程中，主循环不断读取编码器反馈和灰度传感器数值，通过PID调整左右电机PWM占空比，保持循迹稳定。到达目标病房后（通过编码器里程或识别到的病房号位置判断），小车停车并点亮红色LED，进入等待卸载状态。当检测到药品卸载后，红LED熄灭，小车自动掉头并沿红线返回药房，到达药房后点亮绿色LED，完成任务。若为发挥部分双车模式，则小车1完成送药后通过无线发送启动指令給小车2，小车2协同完成后续动作。整个过程中，OLED实时显示状态和距离信息，蜂鸣器在关键节点发出提示音。
