## 二、绿色结论（放心项）

1. **结构完整性**：93 个 manifest 全部可解析、字段齐全；所有平台条目 `files` 逐一存在；`pins` 角色 id 唯一、类型均在词表内；`dependencies` 全部有落点（基建件如 config/delay/filter/uart/k230 无 pins 属既有设计，被仓库门禁接受）。
2. **词表挂接**：两条线 100+ 件全部挂接 wordlist `lib_modules`（唯一例外 oled——收尾报告已记录方案级缺口，models 已含 OLED）。
3. **测试覆盖**：wiki 线每件都有专属 `test_module_<slug>.py`；5 个例外均为既有件且有结构性覆盖（motor→test_module_motor_parity.py、oled→oled_extra/oled_spi、huidu/xunji/ml_mpu6050→dep_cleanup/universality）。
4. **F4 嫌疑页已换算**：dkx 地图标注的 3 个 F4 嫌疑页（relay、mq-3、1.47 寸彩屏）——relay/lcd notes 明写 RCC_AHB1→APB2 等换算；mq-3 整段收敛到 ml_adc（零寄存器调用），notes 给 F1 口径。
5. **批次溯源**：dmx 线 52 件 notes 全部带 `wiki-modules-batchN/xx` 标记；dkx 线由 dkx-map.tsv 77 行单源（每行含匹配依据 + 备注）。
6. **零引脚字面量**：抽查最新 B 类 st7789_para（14 pins / 28 macros / 字体副本 static / 无 FSMC 无旧壳），注释剥离后代码内零引脚字面量；全库该红线由门禁/测试守（test_pin_bindings 的 PinLiteralInMainError 等）。
7. **双平台 API 差异均在 notes 有交代**：ml_mpu6050 DMP 族（结构测试豁免声明）、lcd/oled 新老壳、motor 命名族、fingerprint/hc05 的 `*_rx_handler`（stm32 isr.c 聚合件，设计如此）。

- **mspm0 线收尾快检脚本已失效**（最重要）：`.scratch/wiki-modules-batch13/sweep_52_modules.py` 第 85-87 行仍断言「mspm0 条目禁止混入 stm32 条目（批次 1 先例）」——stm32 线开建后该前提被设计推翻，现在跑出来 50/52 假 FAIL（仅 jy61p/open_mv4 幸存）。它作为「收尾门禁」已不可用；且除该断言外的其他检查（ADR 0009 / verified / hardware_bound / deps / wordlist / kit / source_url）本次实测全部通过。建议：重写为 mspm0 条目字段不变量（删混入断言）或明确退役，并在下一批收尾脚本上挂到与新 stm32 sweep 同级。

- **README 数字过期 + 整条 dkx 线缺文档**：README 称「56 个派生模块」（dmx 口径），实况 dmx 来源 58（多出 ili9341/ili9488 两件 B 类）；且 README 全文无「地阔星/dkx/stm32 线」字样——用户和代理读 README 会以为模块库只有 mspm0 一条线（77 页 / 74 件 ST 线条目完全未反映）。建议更新：数字 + 补「地阔星手册（77 页）→ ST 线模块」一节；顺带把口径说清（58 = 批 1-13 52 + wiki-materials 4 + B 类 2）。
