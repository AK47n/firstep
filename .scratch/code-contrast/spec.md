> 它把 `--tok-*` 语法高亮族记成「**只量不修**」的债（浅色 8/10 个令牌低于 4.5、
> 暗色掉线全在 accent 合成层上），本轮把这笔债还掉。

## 问题陈述

### 一、上一轮登记的「五层底」不是盘上真实的层数

上一轮 `CONTRAST_FAMILIES` 里那条族写的是「`--tok-*` × 代码底（含 4 层 accent 合成）」，
代码页上**文字真正会压到的底**却不止五层（`probe-00` §1 逐条认到出处）：

| 层 | 出处 | 上一轮 |
|---|---|---|
| 代码底 / `.07` 当前行 / `.12` 词命中 / `.18` 搜索命中 / `.32` 选区 | 五条规则 | ✅ 登记 |
| **`.38` 当前搜索命中**（`.code-mark-current`） | 六条 | ❌ **没登记** |
| **`--danger-dim` 编译错误行**（`.code-mark-error`） | 七条 | ❌ **没登记** |
| 括号彩虹 8 色（`.code-mark-bracket-depth-0..7`） | 只压括号字形，字色是 `--code-text` | ❌ 没登记（实测 6.6–7.4 ✅ 过） |

`.38` 那层比选区还狠（浅色现值 **2.07**、暗色 **2.57**）——只修五层等于修一半。

### 二、**口径错了**：高亮层压在字上，字形本身也被染色

上一轮把每一层都当「文字**压在**合成底上」算：`ratio = contrast(over(fg,bg), bg)`。
`probe-02-paint-order.mjs` 用真 Chromium 采了四条像素（浅/暗 × 注释/字符串 + 两主题的括号彩虹），
四条全部命中「**压在字上**」：

| 层 | 谁画的 | 实测字形像素 | over 预测 | behind 预测 |
|---|---|---|---|---|
| `.code-ta::selection`（α .32） | textarea（z-index 1） | `#1a7f37 → #118665` | `#128665` ✅ | `#1a7f37` ❌ |
| `.code-marks`（z-index 0） | 括号彩虹（暗） | `#e2e8f0 → #e9b6b9` | `#e9b6b9` ✅ 逐字节 | `#e2e8f0` ❌ |
| 同上（浅） | 括号彩虹 | `#1f2328 → #542229` | `#54232a` ✅ | `#1f2328` ❌ |

半透明色压在字上 ⇒ **字形 = `over(tint, fg)`、底 = `over(tint, code-bg)`**，两者被同一个 tint
往一处拉 ⇒ 真实比值**低于**旧算法。举例（浅色、`.38` 那层）：`--tok-com` 旧算 **3.10**、
按真渲染是 **2.69**。七个层的账全部要按新算法重算。

> 垫在字下的只有：代码底、`.code-pre-line.active`/`.code-hl-line.active`（`.07`，行元素自己）、
> `.flash`（`.12`，同上）。其余（标记层五类 + 选区）都是压字上。

### 三、高亮层会**互相叠**（本轮记为口径边界，不进判据）

双击选词 = 词命中（`.12`）+ 选区（`.32`）两层同时压；查找后拖选 = 搜索命中（`.18`）+ 选区。
同一 tint 的多个 over 层可按 `1-∏(1-α)` 合成一层，实测（令牌按单层解好之后）：

| 方案 | 单层 | 叠词命中 | 叠搜索命中 | 叠当前命中 |
|---|---|---|---|---|
| 现状层不动 | 4.65 ✅ | 4.11 | 3.79 | **2.67** |
| 降一档（本轮取值） | 4.66 ✅ | 3.91 | 3.57 | 3.23 |

**要把「叠当前命中」也做到 4.5，得让所有高亮淡到几乎看不见**（选区要到 α ≈ .12 量级）——
等于把代码页高亮废掉。用户拍板：**只保单层**（与上一轮口径一致），叠加态如实量出来当边界。

### 四、旧算法的账：十个令牌在七层上大面积掉线

| 主题 | 代码底原样 | 七层全栈 |
|---|---|---|
| 浅色 | 只有 `--tok-kw`/`--tok-tag` 不达标（3.19） | **10/10 全掉线**（最狠 `.38`） |
| 暗色 | 10/10 全过（6.29–13.69） | **9/10 掉线**（最狠 `.38`：`--tok-pre` 3.04） |

### 五、禁用态是全站最低，且本轮之前只记了债

`.scratch/light-contrast/issues/05-closeout.md` 人眼复核实测：hwcheck「带进生成页」**2.66**、
master「AI 提炼报告」**2.06**，根因是全局 `button:disabled { opacity: .45 }`
（另有多处组件级 `.5`/`.55`/`.6`/`.65` 覆盖）。用户拍板口径：**灰底灰字、去掉 opacity**。
本轮**有余力才做**（写在最后两张单里）。

## 方案

一句话：**把「代码页上文字会压到的底」补全到七层、把叠放几何按真渲染改正，然后一边降高亮强度
一边重排语法色，让十个 `--tok-*` 在两主题 × 七层上全部 ≥ 4.5（留 ≥ 0.15 余量）。**

1. **层补齐到七层**：五层 + `.38` 当前搜索命中 + `--danger-dim` 错误行；括号彩虹另立一条族
   （只与 `--code-text` 配对，实测全过，登记为覆盖）。
2. **几何进模型**：每层带 `behind` / `over` 两种几何，`over` 层按「字形 = over(tint, fg)」算。
   `probe_lib`（Python 口径单源）与守卫腿⑧（JS 闸门）两侧同源，镜像守卫钉住。
3. **新令牌 `--code-hl-rgb`**：代码页高亮色从此是**自己的旋钮**（本轮实测它就是语法色能有多亮的
   第一约束）——浅色 = 现值 `0, 150, 199`（渲染零变化），暗色 = `0, 190, 230`（略深一档）。
4. **高亮降一档**：选区 `.32 → .20`、当前命中 `.38 → .24`（层序保持：`.07 < .12 < .18 < .20 < .24`）。
   代价 = 选区/命中淡约三分之一；换来的是令牌改动从「浅色近墨 + 暗色荧光」回到「中等压暗」。
5. **落定二十个值**（下表）；浅色 8 个、暗色 2 个变，其余不动。
6. **判据与账**：守卫腿⑧ 的族表换七层 + 几何 + **族格数冻结**（防"表里少一层而腿照绿"）；
   例外表由生成器重算（`--tok-*` 那两条族债消失）；口径边界（叠加态、括号彩虹）写进守卫注释。
7. **禁用态（有余力）**：`button:disabled` 去掉 `opacity`，改 `--panel-2` 底 + `--muted` 字 +
   `--border` 描边；组件级那几处 `.5/.55/.6/.65` 一并收掉。

## 用户故事

1. 作为用户，我想要**代码页上十个语法色在每一种高亮状态下都读得清**（≥ 4.5:1），
   以便"浅色主题的代码"不是"选中就看不清"。
2. 作为用户，我想要**这一次把层补全**（当前搜索命中 `.38`、编译错误行），
   以便"修好了"覆盖的是我实际会看到的每一种底，而不是我恰好登记过的那五种。
3. 作为用户，我想要**判据按真渲染算**（高亮压在字上时字形也被染色），
   以便守卫说 4.6 的时候，屏幕上真的是 4.6。
4. 作为用户，我想要**选区/命中只好淡一档、语法色不必压成墨块**，
   以便两种代价都不吃满。
5. 作为用户（暗色），我想要**暗色语法色基本不变**（十个里只动两个、各 1–4%），
   以便我熟悉的暗色代码配色不被打散。
6. 作为用户，我想要**每一层都还在**（当前行 / 词命中 / 搜索命中 / 当前命中 / 选区 / 错误行），
   以便这轮不是靠"删掉高亮"过关。
7. 作为维护者，我想要**代码页高亮色有自己的令牌**（`--code-hl-rgb`），
   以便以后调高亮不必动全站 accent。
8. 作为维护者，我想要**族表按"层 + 几何 + alpha"的数据形状冻住格数**，
   以便有人从表里悄悄摘掉一层时腿会红（而不是"少算一层所以全绿"）。
9. 作为维护者，我想要**例外表由生成器重算**、`--tok-*` 的族债从表里消失，
   以便"还完了"是表上的事实。
10. 作为维护者，我想要**叠加态如实量出来写进口径边界**（不是假装它达标），
    以便下一轮要给"叠加也达标"定价时手上有数。
11. 作为下一轮的人，我想要**几何这件事有一支可复跑的像素探针**（probe-02），
    以便口径再被怀疑时不用重新发明验证方法。
12. 作为键盘/低视力用户，我想要**禁用按钮也读得清**（如果本轮有余力把它做完），
    以便"不可点"不等于"看不见"。

## 实现决策

### 一、层的数据模型（两侧同源）

层 = `[名字, alpha, 几何]`，名字带底的配方；新令牌承担"高亮色"：

```
["--code-bg",                      null, "behind"]
["--code-bg+hl.当前行",            0.07, "behind"]
["--code-bg+hl.词命中",            0.12, "over"]
["--code-bg+hl.搜索命中",          0.18, "over"]
["--code-bg+hl.选区",              0.20, "over"]
["--code-bg+hl.当前命中",          0.24, "over"]
["--code-bg+--danger-dim",         null, "over"]   # alpha 由令牌自带（rgba）
```

- 名字用**语义**（`hl.选区`）而不是 alpha 数字：以后调 alpha 不必改认人键、例外表不churn。
- 配方语法：`<底>+hl.<角色>` = `rgba(var(--code-hl-rgb), α)` 叠在底上；
  `<底>+--<rgba令牌>` = 该令牌按自带 alpha 叠在底上。两条都由 `layerColor`（JS）/
  `layer_color`（Python）实现，**镜面**。
- `over` 层的判据：`contrast(over(tint, fg), over(tint, base))`；`behind` 层：`contrast(fg, over(tint, base))`。
- **家族格数冻结** `CONTRAST_FAMILY_CELLS`（= 令牌数 × 层数 × 主题数的现算值）：
  与 `CONTRAST_PAIR_COUNT` 同一条纪律——判据不许在"表里少了一层"的情况下照绿。

### 二、产品面的接线（观感与值的改动分开做）

- 令牌：`:root` 加 `--code-hl-rgb`（暗色值）、`html[data-theme="light"]` 加浅色值。
- 代码页所有**高亮填充**改用 `rgba(var(--code-hl-rgb), α)`：
  `.code-pre-line.active` / `.code-hl-line.active` / `.code-pre-line.flash` / `.code-hl-line.flash` /
  `.code-gutter-line.flash` / `.code-mark-word` / `.code-mark-hit` / `.code-mark-current` /
  `.code-mark-bracket` 的淡底 / `.code-mark-guide` 的渐变 / `.code-ta::selection`。
  装饰（滚动条）与前景（caret、括号描边）保持 `--accent`。
- **先接线（值 = 现值、α 不变）再落值**：两张单分开，第一张可验证"观感逐像素不变"。

### 三、禁用态（有余力才做）

- 去掉三处 `opacity`（`button:disabled` .45 / `input,textarea,select:disabled` .6 / 组件级 .5–.65）。
- 统一口径：`background: var(--panel-2)` + `color: var(--muted)` + `border-color: var(--border)`，
  去掉 hover 态与外光（`box-shadow: none`）；主/危险/幽灵三类形态一视同仁。
- 判据：加进守卫腿⑧ 的族面（**不是**新腿）——「`--muted` × `--panel-2`」与
  「`--muted` × 面板底」两格，两主题各一条；另加一条"页面上不许再有 `opacity` 形式的禁用态"
  的结构判据（`button:disabled { opacity` 出现即红）。
- 渲染面：`probe-07` 的禁用态桶**实测是空的**（那两个按钮坐在渐变容器里被现有规则滤掉）——
  要么把该桶改成"祖先渐变也收"，要么另立一支小探针；**不许**把"扫描看不见"当成"已达标"。

### 四、文档与账

- `CONTEXT.md`「界面密度契约」那节补一条**对比度契约**（口径 + 现算命令 + 几何与边界的说明）。
- `docs/agents/local-environment.md` §0 追加本轮 📌 块（含"下一件事是发版 v1.4.1"）。
- `.scratch/backlog.md` 新增一节（本轮做了什么 + 仍开着的：叠加态定价、括号彩虹已覆盖）。
- `.scratch/light-contrast/README.md` 与 `issues/05` 的账**追加带日期的"已结清"**（不改历史记账）。

- **吃最高既有缝**（不新起文件）：
  1. `tests/js/css-tokens.test.mjs` 的**腿⑧**——族表七层 + 几何 + 格数冻结 + 例外表对账（闸门）；

- **渲染面**：`probe-02` 扩成"十个令牌 × 各状态的真像素采样"（浅/暗各一轮，.c 与 .syscfg 两种源，

  作回归对照。
- **人眼**：浅/暗各一轮整页截图（代码页含选中/查找态）——机器只能证"过线"，证不了"好看"。
- **读数纪律**：改完先冻结树再整套重跑（`readings.py`）；门禁一次只跑一道（浏览器门禁单独跑，
  跑完再 pytest）；每份落盘读数的时间戳必须晚于最后一次改产品面。

## 范围外

- **叠加态**（选区叠命中/词命中）不进口径：本轮的契约是**每个层单独** ≥ 4.5；叠加态的读数
  如实量出来写进「口径边界」，要收它得另开一轮（代价：高亮淡到几乎看不见）。
- **不把标记层挪到字下**（几何根因修复）：实测能把令牌改动压回"中等"，但要动代码页三层叠放
  （`.code-edit` isolation + z-index 重排 + 选区改由标记层自绘），风险与验收面都另算一轮。
- **不改字号 / 描边层级 / 布局 / 间距**；不碰 `BORDER_REGISTER` / `JS_BORDER_REGISTER`。
- **不碰**库数据 / 母版 / 发布包 / `sources/`；不引入 CSS 工具链。
- **不含发版**：v1.4.1 的版本同步、打包、tag、Release 另开一轮（用户拍板）。
- 上一轮留下的其它债（`--accent` 控件描边 2.70、`.pin-subtitle` 的 `var(--fg)` 未定义令牌、
  跨页前缀归属）不在本轮射程。

### 被否掉的方案（记下来，免得下一轮重走）

1. **层全不动、只压令牌**：浅色十色压到近墨（`--tok-kw #003648`）、暗色九色提亮成荧光
   （`--tok-str #ffd730`）——代码页观感变化最大，暗色尤其（它现在原样 10/10 全过）。
2. **降两档（选区/当前命中 → .16）**：暗色**零改动**，但选区弱于搜索命中（层序破了）；
   实测层序是有用的语义（当前命中必须比其它命中显眼）。
3. **全线换淡青（浅色 140,205,230）**：浅色令牌不必压那么深，代价是 `.07` 当前行那层
   只剩现在三分之一的淡底强度（**看不见当前行**）——等于拿一个功能换另一个功能。
