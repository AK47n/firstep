## 问题陈述

用户每次生成工程后都需要手动清理输出目录，多个赛题工程混在一起，查找和删除都很麻烦。

## 方案

生成页提供“生成到桌面赛题文件夹”选项，默认勾选。勾选后，系统根据赛题原文调用现有 AI 能力提取适合作为目录标题的赛题名称，在 Windows 桌面创建以该名称命名的文件夹，并把完整工程直接生成到该文件夹中。若目录重名，自动追加当前时间形成新目录，避免覆盖旧工程。不勾选时继续使用用户提供的输出目录，保持原有行为。

## 用户故事

1. 作为使用生成器的学生，我想默认把工程按赛题分别放进桌面文件夹，以便生成多个工程后可以按题目整体管理和清理。
2. 作为使用生成器的学生，我想看到由 AI 提取的赛题名称作为文件夹标题，以便桌面目录能直接表达工程对应的赛题。
3. 作为使用生成器的学生，我想在同名赛题重复生成时得到带时间标记的新文件夹，以便旧工程不被覆盖。
4. 作为不希望改变输出位置的用户，我想取消该选项后继续使用原输出目录，以便兼容已有工作流。
5. 作为用户，我想在生成成功结果中看到实际落盘路径，以便直接定位新工程。

## 实现决策

- 生成请求增加可选布尔字段，缺省按产品决策视为开启；显式关闭时完全走现有 `output_dir`。
- 桌面根目录由运行生成器的 Windows 用户目录推导，不由浏览器上传绝对路径；目录命名使用 AI 题名结果，并清洗 Windows 文件名非法字符、空白标题和保留名称。
- 同名目录不覆盖，按当前本地时间生成可读时间后缀；同一时间仍冲突时继续追加序号，确保落盘目标唯一。
- 题名提取复用现有 LLM 协议能力，不新增模型协议；提取失败按 AI 错误处理，不静默创建含糊目录。
- 路由负责解析请求和选择输出目标，核心生成仍只接收最终 `output_dir`，保证生成器职责不扩散。
- 生成响应继续返回 `output_dir`，其值为最终桌面工程目录或原请求目录。

## 测试决策

- 以 `POST /api/generate` 端到端测试作为最高现有 seam：给定请求、假 LLM 和临时桌面环境，断言最终目录、工程文件和响应路径。
- 覆盖默认开启、显式关闭、非法目录名清洗、重名时间后缀和 AI 题名失败的外部行为。
- 使用测试注入的桌面根目录与固定时间，避免测试写入真实用户桌面、依赖真实时钟或调用网络。
- 保留现有生成器测试，确认未带新字段的旧调用仍使用传入输出目录。

## 范围外

- 不实现桌面快捷方式、资源管理器自动打开或生成后自动删除。
- 不增加题名编辑输入框。
- 不改变现有用户手选输出目录的 API 语义。
- 不处理跨操作系统的桌面目录策略；本功能面向当前 Windows 本地应用。
