# Spec：推荐补问「蠢问题」根治——无规定即无限制 + 材料性门槛 + 上限 5 条

## 问题陈述

用户跑 2024H「自动行驶小车」AI 推荐，澄清阶段仍问出大量蠢问题：题面已写明「每经过一个点，
声光提示一次」「经过 A、B、C、D 点时必须有声光提示」，模型还问「是不是 A/B/C/D 每点都要
声光提示」之类的问题。用户的期望原则：「题目中没有提到那就是没有限制」——题面未提及的
细节（指示灯颜色/亮度、蜂鸣器音调、提示时长等）一律视为无限制，按合理默认实现，不提问；
题面已明确的细节绝不重复问。

上一轮工单 clarify-dumb-questions/01（题面预算 4000→12000 + 「已明确不重复问」加固）已落地，
但实测 2024H 仍复发，根因是提示词缺少「无规定即无限制」的默认宽松原则，且收敛阶段的
SELECT_SYSTEM_PROMPT 仍是「宁全勿漏、最多 10 条」——与澄清阶段「宁缺毋滥」自相矛盾，
补问兜底路径照样冒蠢问题。

第二波（2026-08 会话，工单 01 落地并重启后 2024H 复现）：模型仍问了三个「没限制」问题——
① 起始点摆放方向是否需要统一朝向（题面三(4) 明确写「摆放方向自定」，「自定」= 题面已给出
的答案，模型未识别为已明确）；② 声光提示具体形式（LED 颜色/蜂鸣器音调）是否有要求
（01 的「未提及的要求一律视为无限制」未守住）；③ 未明确灰度传感器数量是否用 8 路（未提及
的数量/规格参数未归入「无限制」，且模型把「几路」误判为影响选型）。

## 方案

把「无规定即无限制（默认宽松）」+「材料性门槛」+「上限 5 条」写进推荐流程的两个系统提示词，
并加代码层硬上限兜底：

1. **CLARIFY_SYSTEM_PROMPT**（澄清阶段）与 **SELECT_SYSTEM_PROMPT**（收敛阶段补问兜底）
   统一执行：
   - 题面已明确给出的细节（颜色/型号/数量/类型/位置点等）绝不重复问；
   - **题目中没有提到的细节就是没有限制**：题面未提及的要求（指示灯颜色与亮度、蜂鸣器
     音调、提示时长与方式、传感器具体型号等）一律视为无限制，按合理默认实现，不为此提问；
   - **材料性门槛**：只有题面缺失且会直接影响模块选择或方案核心结构的关键信息才补问；
     答案改变不了选型的问题不问；
   - 一次性列全、最多 5 条、不渐进追问（原「宁全勿漏、最多 10 条」删除，「宁缺毋滥」保留）。
2. **代码层硬上限**：`selection.MAX_QUESTIONS = 5` 作为单一出处——`selection._parse_questions`
   与 `llm.parse_clarify_questions` 解析时截尾兜底（模型被要求最多 5 条，超出即噪音，不轰炸
   用户）；提示词中「最多 N 条」由该常量插值生成，杜绝提示词与解析层漂移。
3. **select 用户消息 JSON 契约示例**同步收紧：「题面缺失且影响模块选择的关键补问」——
   用户消息尾句是模型的最后指令，系统提示词改了这里漏改会重演 ticket 06 双端漂移教训。
4. **第二波加固（工单 02）**：
   - 题面写明「自定/不限/自由选择」的条目（如「起始点摆放方向自定」）= 题面已给出的
     答案，绝不问；
   - 未提及的规格参数（传感器几路/数量、尺寸大小等）= 无限制实现细节，按合理默认实现，
     不为此提问；
   - 材料性门槛强化：规格参数（数量/路数/颜色/音调/时长）不构成补问理由。

## 用户故事

1. 作为用户，当我跑 AI 推荐时，我希望模型绝不问题面已明确给出的细节（如「每经过一个点
   声光提示一次」还要问是不是 A/B/C/D），以便不再被蠢问题打断。
2. 作为用户，我希望题目没有提到的细节（如指示灯颜色/亮度、蜂鸣器音调）被视为无限制、
   不提问，以便默认合理实现即可，不需要逐条回答规则细节。
3. 作为用户，我希望模型只问题面缺失且直接影响模块选择/方案核心结构的关键信息，以便
   提问数量自然收敛到个位数（0-3 条），一次答完。
4. 作为用户，我希望题面写明「自定/不限」的条目（如起始方向自定）不再被问、未提及的
   规格参数（传感器几路、尺寸大小）按无限制默认实现，以便推荐过程不再出现「没限制
   就是随便」类问题。
4. 作为用户，我希望即使模型不听话，解析层也有硬上限兜底，以便最多只看到 5 条问题。

## 实现决策

- 模块：`src/contest_generator/llm.py`（两阶段系统提示词 + `parse_clarify_questions` +
  select 用户消息 JSON 契约注解 + 注释同步）+ `src/contest_generator/selection.py`
  （`MAX_QUESTIONS = 5` 常量 + `_parse_questions` 截尾）。
- 常量单一出处：`selection.MAX_QUESTIONS = 5`（llm 运行时从 selection 导入，方向与现有
  依赖一致，无新环）；提示词里「最多 N 条」用 f-string 插值该常量。
- 截尾语义：解析层 `questions[:MAX_QUESTIONS]` 截尾保留前 5 条（超出即噪音），不报错。
- 不改：题面预算（CLARIFY_TOPIC_CAP）、澄清历史段、视觉问答层、webapp 编排、前端。
- 保留：已有「已答不重问」「一轮问全」「不要分批渐进追问」「图注推断」等条款与措辞。

## 测试决策

- 契约断言（tests/test_llm.py，参照 SKELETON_NO_UNUSED_RULE 双端断言先例）：
  - 两阶段提示词都含「就是没有限制 / 未提及 / 不为此提问 / 影响模块选择 / 绝不重复问」；
  - 「最多 N 条」由 `MAX_QUESTIONS` 插值（`f"最多 {MAX_QUESTIONS} 条"` in 两提示词），
    提示词与常量同步由测试钉死；
  - 既有「一次性把所有疑问全部列出」「不要分批渐进追问」「宁缺毋滥」等断言保持通过。
- 解析层上限（tests/test_llm.py `parse_clarify_questions` + tests/test_selection.py
  `_parse_questions`）：喂 7 条 → 返回前 5 条（参照私有助手直测先例 `_number_topic_sentences`）。
- 全量 pytest 绿 + mypy src 干净。

## 范围外

- 不改 select/骨架的题面预算（`_build_user_prompt` 仍 4000，select 带参考全文注入，
  预算联动需统一记账，另开）。
- 不做启发式问题过滤（易误伤）；不做提问质量评分。
- 不改前端问答交互、不改 webapp 编排、不改视觉问答自动消化逻辑。

## 补充说明

- 生效方式：改的是 Python 提示词常量，重启本地服务即生效（start-app.bat）。
- 用户确认（2026-08 会话）：① 澄清与收敛两处一起改；② 无规定即无限制；③ 加材料性门槛
  + 上限 5 条。
- 真机锚点：2024H 题面「每经过一个点，声光提示一次」「经过 A、B、C、D 点时必须有声光
  提示」——模型若再问「是不是 ABCD 每点都要声光提示」即回归失败。
