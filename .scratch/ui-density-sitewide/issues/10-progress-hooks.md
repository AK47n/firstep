## 结论（做了什么、账）

**这一单动了产品面**（`ui/master.js` / `ui/generate-recommend.js` 各加一个钩子块）——
是本轮第二张"非纯观感"的单（第一张是 08 的内联字号）。

1. **进度区的测试钩子**（`// [test-hook]` 标记成对）：
   · `ui/master.js` 的 `initMasterWorkflow()` 里挂 `masterProgressHooks`
     （`start` = 产品入口 `startProgress`，外加 `setStep` / `updateBatch` / `addLogLine` /
     `finish` / `state`）；
   · `ui/generate-recommend.js` 的 `renderModulePool()` 里挂 `recProgressHooks`
     （`start` / `stop` / `handleEvent` / `state`）——推荐进度区的 DOM 更新写在**事件表**里，
     所以暴露 `handleEvent`：探针喂合成事件，产品的事件→DOM 路径自己跑。
   · **挂在导出的 init / boot 会调用的函数里，不是模块顶层**：`tests/js/ui-dom-contract.test.mjs`
     钉着"ui 模块**求值期零接线**"——第一版挂顶层当场判红（1840 里红 1），这一条是那张单抓出来的。
2. **`probe-09` 换成走钩子**，并新增生成页 `#rec-progress` 的两张图：现在三个主体
   （参考详情弹层 / 提炼进度 / 推荐进度）× 浅暗 = **6 张**，且断言是量的：
   弹层外壳 1px、过滤框 1px（06 保留的例外）、两个进度区**整圈框 0px**、
   步骤名 14px、日志 13px、推荐文案走到"第 3/8 轮"。
3. **`probe-03` 2c 节**：用 `html.parser` 建"每个父节点下的子元素签名序列"，
   判据 = **改前的子序列在改后仍是子序列**（允许插入新兄弟，重排/搬走才判红）。
   签名 = `标签#id` + **该元素的直接文本前 20 字**（不带 class——本轮允许"只新增类名"，
   带 class 会把 05 单那种正当改动报成重排）。

**账（留给后面的人）。**

1. **2c 的两个已知限制**（都写在 `sibling_order_problems` 的 docstring 里）：
   ① 父路径**不带序号**（带序号的话，插一个元素会把后面所有路径移位 → 满屏假红，
   第一版实测 **249 处**）；代价是**同层的匿名兄弟被并进同一个桶**，桶内顺序仍然可比、
   但"某个匿名 div 自己的子元素"与"它兄弟的子元素"混在一起判；
   ② 签名相同的重复兄弟（连着一个空 `<div>` 又一个空 `<div>`）互相之间对调看不出来。
   **要连这两种也看住，得给它们加 id**（产品面）或上真 DOM 解析器。
2. **钩子是给探针/测试的，产品代码不调用**：用 `// [test-hook]` 成对标记包起来，
   `probe-03` 的 `strip_test_hooks()` 按标记剥掉整块再比 JS——**下一轮要加同类钩子照这个形状**，
   别用"允许这个函数名"当判据（那会让任意改动溜过去）。
3. **钩子必须挂在 init / boot 调用的函数里**：`ui-dom-contract.test.mjs` 的"求值期零接线"
   是硬判据（`ui/` 模块顶层不许有副作用语句）。新加钩子先想清楚"boot 哪一步会调到它"。
4. **票面日期按 git 提交时间写**（`git log -1 --format=%ci`）。
