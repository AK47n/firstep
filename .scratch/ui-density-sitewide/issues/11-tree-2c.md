## 结论（两条限制怎么消掉的、账）

**做法**（`_Node` / `_TreeBuilder` / `_align` / `sibling_order_problems`，都在 `probe-03-contract.py` 里）：

- **① 同层匿名兄弟并桶** → 不再按"路径字符串"分桶，而是**递归地逐父节点实例**做对齐：
  配上的父节点才往下走，匿名的兄弟各有各的 `_Node`，永远不会互相混。
- **② 相同签名兄弟对调** → 对齐键里带了**该元素的直接文本**（前 24 字），
  所以 `<th>文件名</th>` 与 `<th>批次</th>` 是可区分的；
  而**两个对齐键完全相同的兄弟，其子树必然逐字节相同**（否则在某一层 `_key` 就会不同）
  ——它们互换是**恒等变换**，不是"看不见"，是**没有可看的东西**。
  → 这条限制从"判据的洞"变成了"判据的性质"，写进 docstring。

**账（留给后面的人）。**

1. **判据从"子序列"升级成"LCS 对齐"**：这比 10 单那版**严**——
   那版只问"旧序列是不是新序列的子序列"（中间插新兄弟不算事），
   这版还会逐个父节点对齐、报出**具体哪一个既有元素**不见了（带路径），
   并且在配上的一对里**继续往下递归**（更深一层的顺序照样看）。
2. **LCS 是 O(n×m)/父节点**：`index.html` 里最大的父节点大约两百来个孩子，
   实测整支探针仍在秒级（解析两遍 + 逐层对齐）。**真到卡顿时**再考虑按 id 先切段。
3. **解析器是宽容版**（闭合标签对不上就往上找、找不到就忽略），**不追求 HTML5 级正确**：
   判据是"同一份文件的先后两版"、两侧同一把尺子，所以**稳定**比"正确"更要紧——
   这也是为什么自证必须随判据一起换（10 单那版的红证在这一版里已经不作数了）。
