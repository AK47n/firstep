# 02 — 文档实例令牌：旧文档迟到的告别不许注销新文档的登记

**要做什么：** 让「同一个标签里，上一个文档的告别」与「这一个文档的登记」**identity 上分开**。
`register` / `bye` 都带 `epoch = performance.timeOrigin`（同一文档内恒定、跨文档必然不同），
服务端记 `tab_id → 本次登记的 epoch`；**bye 的 epoch 与注册表里的不一致 ⇒ 忽略，不注销**。
修完这一张：`register` 与 `bye` 的到达顺序**怎么乱都不出错**（顺序反了也不会把刚登记的
新页面注销掉 —— 否则退出判据又回到"新页面必须再登记一次"，秒级竞态原样复现）。

**被谁阻塞：** 无——可立即开始（与 01 同文件不同区域；01 不 gate 它）。

**状态：** resolved

## Comments

### 2026-09-21 实现记录

#### ① 为什么是 `performance.timeOrigin`，不是另存一个随机令牌

同一个文档里它恒定、跨文档必不同；两侧（head 内联脚本那次 register、`app.js` 那次 bye）
各自从同一个文档读同一个值 ⇒ **不可能漂移**，客户端不需要存、也不需要第二条判据去对账。
另存一个随机令牌要多一个 sessionStorage 键、多一处"两侧必须读到同一个值"的隐性约定
（那正是本单在修的那类东西）。

不比较**时钟**语义：服务端只判"与注册表里记的那个值**相等吗**"，不与自己的时间做任何比较
（本地工具、同一台机器，但仍然不引入时钟假设）。

#### ② 判据 ④ 的假绿反例（服务端语义之外的客户端一半）

`epoch` 必须落在**该次 `fetch`/`sendBeacon` 调用的实参区间**里：第一版写成"调用点之后
400 字符窗口"，紧跟调用的一句 `window.__probeDecoy = { epoch: 1 }` 就能把它喂绿（评审实测）。
现在在掩码文本上数圆括号找配对，区间外一律不算，且**不留窗口魔数**。
