# spec — 启动器模式下 F5 重载会被应用自己关掉（`launcher-exit-race`）

## 问题陈述

启动器模式（`FIRSTEP_LAUNCHER=1`，也就是用户双击 `start-app.vbs` 的正常路径）下按 F5：

`pagehide` 先发 `/api/tabs/bye` → 服务端注册表变空 → 起 `_EXIT_GRACE = 1.5` 秒宽限 →
新页面要等 `index.html`（4,668 行 / 597 KB，含内联字体）**加 132 个模块**装载完，
`app.js` 求值时才发得出 `POST /api/tabs/register`；宽限内没到 → 后台线程 `os._exit(0)`
→ **应用把自己的服务关了**，用户看到死页面（后续请求 `ERR_CONNECTION_REFUSED`）。

- **现场记录**：`docs/agents/local-environment.md` L200-205（module-hwcheck/06 会话，浏览器
  验收连跑第 7 次 `goto` 命中）。当时只在**验收夹具侧**绕开（夹具不设 `FIRSTEP_LAUNCHER`），
  **产品侧那条竞态一直没修** —— 真实用户按 F5 仍会撞上。
- **本单第一步重量的（探针 `.scratch/launcher-exit-race/probe-00-order.mjs`，读数落
  `probe-00-order-before.txt`）**：启动器模式 + 真浏览器 + 真后端，连续 reload `--rounds 10`，
  **第 4 轮命中**：reload 后服务消失、`page.reload` 抛 `ERR_CONNECTION_REFUSED`、进程 `exit 0`
  （就是那条自杀路径）。服务端**处理顺序**逐轮如实记（uvicorn access log 的先后 = 处理先后）：

  | 轮 | 服务端处理顺序 | 结果 |
  |---|---|---|
  | 1 | `GET /` → `POST /api/tabs/bye` → `POST /api/tabs/register` | 活着（reload → 页面可用 **419ms**） |
  | 2 | 同上 | 活着（**511ms**） |
  | 3 | 同上 | 活着（**683ms**） |
  | 4 | `GET /` → `POST /api/tabs/bye`（**没有 register**） | **服务自杀**（页面等 register 等到 15.4s 超时） |

  ⚠ 这张表是**修复前**那一代源码的读数（探针在 `eae57b43` 的 git worktree 里跑）。修复后
  同一探针是 `probe-00-order-after.txt`：**10 / 10 轮全程活着**。两份证据都留在树里——
  第一版只留了一份、被修复后的复跑覆盖成"全绿"，"红侧证据"当场消失（双轴评审抓出）。

  三条读数直接定住了修法的形状：
  ① 「模块图装载时间」就是那个不可控的尾长（419 / 511 / 683ms → 第 4 轮越过 1.5 秒宽限）；
  ② **`GET /` 总在 `bye` 之前到达**（4/4 轮）——"新文档请求"这个信号**挡不住**它（见方案取舍）；
  ③ 旧实现里 `register` 排在 `bye` **之后**（它要等 132 个模块），**到达顺序本身就是晚的**；
     而"两个方向相反的操作在赛跑"意味着**顺序反过来也是可能的**——那一刻迟到的 `bye` 会把
     刚登记的新页面注销掉（第 2 层要挡的就是它）。

## 方案

一句话：**把"新页面自报家门"从"模块图装载完"提前到"页面 head 的第一段脚本"，并让旧文档
迟到的告别无权注销新文档的登记。**

三层，每层挡一个已实测 / 可测的失败模式：

1. **早注册**：`index.html` head 那段**已有的内联脚本**（主题防闪烁那几行之后）里直接
   `POST /api/tabs/register`。它在**装载标签之前**执行 —— 模块图（`boot.js` 及其 132 个模块）
   连**取**都还没开始。窗口从"HTML + 模块图装载"（实测 0.4–1.5s⁺ 的尾长）降到"浏览器为一个
   标签发起新导航 → head 执行 → 一个 POST 到达"（毫秒级）。
2. **文档实例令牌（`epoch`）**：`register` / `bye` 都带 `epoch = performance.timeOrigin`
   （同一个文档里恒定、跨文档必然不同，无需存任何东西、也不可能两侧漂移）。服务端记
   `tab_id → 本次登记的 epoch`；**bye 带的 epoch 与注册表里的不一致 = 那是旧文档的告别**
   → 忽略，不注销。
3. **在途退出显式化**：注册表里多一个"在途退出"标记 —— 注销后空 → **布防**；`register`
   或宽限到点前的任何一次布防撤销 → **撤防**；宽限到点仍布防且仍空 → **取走**（清零）并退出。
   旧实现是"睡 1.5 秒再查一次空集"，这一步同时消掉两件事：查空 → `os._exit` 之间的
   TOCTOU（回 200 然后服务没了），以及"重复 / 迟到的 bye 叠加第二个退出线程"。

### 先回答四个设计问题（结论 + 依据）

**Q1 宽限窗口该覆盖的到底是什么？register 能不能提前到模块图之前？**
→ 覆盖的应当是**「新页面宣告自己存在」这一个信号的到达延迟**，**不是**「新页面装载完」。
后者的尾长由资源体量与机器负载决定（实测 419/511/683ms，第 4 轮直接越过 1.5s），不可控；
前者由浏览器导航时序决定，毫秒级。
→ **能提前到模块图之前**，而且**只有一处**放得下：`index.html` head 的内联脚本。理由：
  · 装进 `boot.js` 没用 —— **ESM 静态 import 会先把整张图取完（fetch + 实例化）才开始求值**，
    所以"写在 `boot.js` 正文第一行"仍然发生在 132 个模块**全部取完**之后；
  · 另开一条 `<script src=…>`（经典脚本也能早于 defer 的模块执行）会变成**第三个脚本块**，
    直接撞 `tests/js/fx-guard.test.mjs` 判据③「index.html 脚本块恰好两处」——为了一个 6 行的
    登记去改那条判据，爆炸半径不合算（判据③守的是"HTML 不再是模块图的一部分"）；
  · 放进已有的内联块**零新增脚本块**，仍然受判据①②（零 import / 零顶层定义）约束。
→ **不必再调魔数**：`_EXIT_GRACE = 1.5` 保留原值。它不再承担"覆盖模块图装载"的职责，只覆盖
  "告别与新页面自报家门之间的时序抖动"（毫秒级）——余量两个数量级，既不调它也不新增常量。

**Q2 还是走"显式重载意图"（pagehide 带 reload 标记）？**
→ **做不到，别走**：浏览器没有这个信号。`pagehide` 对"关标签 / 关窗口"与"F5 重载"**同形**
（`event.persisted` 只区分 bfcache，不区分重载）；`PerformanceNavigationTiming.type === "reload"`
只有**新**页面才问得到，而新页面能告诉服务端这件事的方式，恰好就是 register；
`beforeunload` 会把 F5 变成弹框确认（本地工具里等于给用户加一道无意义的拦路虎）。
→ 它的失败模式是**二选一**：判不出来 ⇒ 要么漏关（服务不死，功能坏）、要么误关（F5 死页面，
  就是本单要修的那条）。等于把一条竞态换成一次猜谜。
→ **走"新页面 register 时撤销在途退出"这条路 —— 而且这条路今天已经成立**（`delayed()` 里
  再查 `len(registry)==0`）。缺的从来不是"撤销"，是"**到得太晚**"。所以本单 = 把 register
  提前（根因）+ 给告别配身份（乱序时别误伤）+ 把"在途退出"显式化（确定性可测、去掉 TOCTOU）。

**Q3 宽限期内 register 到达必须撤销在途退出 —— 今天真的不会退吗？多标签同时关呢？**
→ **今天确实不会退**（`delayed()` 睡醒后再查一次空集，注册表非空就不退）。但有两处必须补：
  · **TOCTOU**：`if len(registry)==0` 通过之后、`os._exit(0)` 之前到达的 register 会**拿到 200
    然后服务就没了**——用户看到的是"注册成功了，页面还是死的"；
  · **重复 / 迟到的 bye 会叠加第二个退出调度**（两个线程各调一次 `_EXIT`）。生产上第一个就
    把进程带走、看不出来，但它意味着"退出调度不幂等"这件事没人钉。
→ **多标签语义（显式化之后）**：
  · 关掉一个、还有别的 → `unregister` 返回"没空" → **根本不调度**；
  · 同时关 N 个 → 只有"注销后变空"的那一次布防；重复 / 迟到的 bye 撞上"已布防" → **不叠加**；
  · 布防之后任何 `register`（含**同一个 tab_id** 的 F5 回来）→ 撤防；
  · 撤防之后再关 → 重新布防（新的一轮，不是"一次布防永久有效"）；
  · 宽限到点**取走**布防（清零）→ 注入 `_EXIT` 的测试不会留下卡死的布防状态。

**Q4 真正"关掉浏览器"这条路径延迟会变大吗？可接受上限是多少？**
→ **不变**：宽限仍是 1.5 秒（既有常量、不动），关掉最后一个页面后 1.5s 布防到点 → 退出。
→ **用户可接受上限：最后一页关闭后 ≤ 2 秒服务停掉**（1.5s 宽限 + 进程退出；收尾给实测读数）。
  不缩短它：缩短只省 1 秒出头，却把余量砍掉数倍，换不来任何用户可见收益。

### 被否掉的候选（各自失败模式写清楚，免得下一个人重走）

| 候选 | 为什么否 |
|---|---|
| 只把宽限调大（2s / 3s / 5s） | 尾长不可控（第 4 轮 >1.5s，机器一忙会更长）；只是把中奖概率往下压，且**每次关浏览器都多等**。**不新增魔数**这条硬约束正是指它。 |
| `GET /`（文档请求）到达即撤销在途退出 | 实测顺序是 `GET /` → `bye`（4/4 轮）：**撤销发生在布防之前 = 白撤**。它只覆盖"bye 先到"的少数轮，挡不住本单要修的那条。 |
| "最近服务过文档 ⇒ 宽限内不退出"（全局规则） | 归因错：文档请求**不带标签身份**。双标签下 A 关闭、B 刚重载过 ⇒ A 的告别被吞 ⇒ A 变**幽灵条目** ⇒ 最后 B 关闭时注册表非空 ⇒ **"关浏览器 = 停服务"直接坏掉**。 |
| 每次加载用**全新** tab_id（不存 sessionStorage） | 乱序天然免疫（两侧操作不同的 id），但**丢掉"稳定 id 的自愈"**：页面登记完却没能装载完（模块图炸了 / 被中断）时，那条条目**再也没人来注销** ⇒ 服务永不自动停。稳定 id 下，同一个标签的下一次加载会复用同一个 id，它的 bye 顺手把幽灵清掉。 |
| 心跳 / 长轮询代替 bye | 要新增心跳周期（新魔数）、停服务延迟 ≥ 一个周期，且把"最后一个标签"变成"最后一次心跳"的推断——比现在更容易错。 |

## 用户故事

1. 作为**用启动器打开本工具的用户**，我想要按 F5 时页面能正常回来，以便刷新不会把工具自己关掉。
2. 作为**同一个用户**，我想要 F5 连按很多次（≥ 10 次）也不出事，以便"手贱多刷几下"不会踩雷。
3. 作为**同一台机器上编译大工程（UV4 占满 CPU）的用户**，我想要机器慢的时候 F5 也不自杀，
   以便"机器忙"不是我丢掉服务的理由。
4. 作为**开两个标签用的用户**，我想要关掉其中一个标签时服务继续活着，关掉最后一个才停，
   以便多标签的语义与直觉一致。
5. 作为**同一个用户**，我想要"复制标签页"（sessionStorage 被复制 ⇒ 两个标签同一个 tab_id）
   也不出错：关掉其中一个不该停服务，关掉最后一个才停。
6. 作为**普通用户**，我想要"关掉浏览器 = 服务停掉"这个既有功能**一字不变地保留**
   （延迟不变、行为不变），以便没人为了修竞态把它弄丢。
7. 作为**维护者**，我想要"最早的 register 在模块图之前"有**结构判据**钉住（不是靠注释约定），
   以便下一轮谁把那段登记挪进模块、或挪到装载标签之后，推之前就红。
8. 作为**维护者**，我想要那条结构判据**判事实不判写法**（能识别注释里的假登记、能识别
   顺序、能识别 tab 键字面量与 `app.js` 分叉），以便它不会因为一次无害的排版改动假红、
   也不会因为一次"看起来对了"的改动假绿。
9. 作为**维护者**，我想要这条判据有**合成红证**（内存注入：删登记 / 挪到注释里 / 挪到装载
   标签之后 / 改键名 / 去掉令牌）+ **真红证**（base **显式钉**修复前那个提交、带自校验），
   以便"判据有牙齿"和"判据在正确的那一代上真会红"都能被独立复算。
10. 作为**维护者**，我想要产品侧那条竞态有**pytest 用例**（注入 `_EXIT` / 假宽限），断言
    ①注册表空 → 调度退出 ②宽限内 register 到达 → 不退 ③非启动器模式 → 不调度 ④**乱序的
    旧告别不注销新登记** ⑤重复 / 迟到的 bye 不叠加第二次退出，以便竞态在毫秒级、不靠撞运气
    的层面被钉死。
11. 作为**维护者**，我想要"只有启动器模式才允许自动退出"这条判据保持唯一（`_launcher_managed`），
    以便测试 / 手动运行**永不自杀**这条硬约束不被这次改动稀释。
12. 作为**验收者**，我想要一条**真浏览器**的 spec 在**开启启动器模式**的夹具上连续 reload
    ≥ 8 次（覆盖现场第 7 次命中的量级）并断言"服务始终活着、页面每次都能用"，以便这条竞态

13. 作为**验收者**，我想要同一条 spec 里有一个**确定性**用例（把 `boot.js` 的响应拖到宽限
    之外）：修复前它必红、修复后必绿，以便"这条竞态会不会复发"不取决于当轮机器的运气。

15. 作为**维护者**，我想要新用例**自己起服务自己收**（含异常路径），以便浏览器门禁不留残留进程。

    L200-205 那条"产品侧本单没修"改成已修 + 新判据，以便下一轮读账的人不会以为它还在。

## 实现决策

### 客户端（`static/index.html` + `static/js/app.js`）

- **早注册放 head 那段已有的内联脚本**（`<script>` 块内、主题防闪烁那几行之后）：
  - 读到 / 建出 `sessionStorage` 里的 tab_id（**与 `app.js` 同一个键**，跨刷新稳定 ⇒ 幽灵
    条目能自愈，见被否候选表）；
  - `POST /api/tabs/register`，body `{tab_id, epoch: performance.timeOrigin}`，fire-and-forget；
  - 整段包 `try/catch`（存储 / 加密接口不可用的环境里，登记失败不该影响页面本身）。
  - **约束（既有判据，不是新规矩）**：内联脚本里**不许有顶层定义**（`const` / `let` / `var` /
    `function` / `class`，任意缩进；`tests/js/fx-guard.test.mjs` 判据①②）⇒ 这段只能用
    表达式与语句写；**不许 import**；**不新增脚本块**（判据③）。
- **`app.js` 只留「注销」一半**：读同一个 tab_id、`pagehide` 时 `sendBeacon("/api/tabs/bye",
  {tab_id, epoch})`。登记不再有第二处调用点（早注册是**唯一**的登记点，单源）；`tabId` 的
  "取不到就新建"兜底保留（内联脚本万一没跑成，注销至少不会拿一个 `null` 去发）。
  `epoch` 在同一个文档里恒等于 `performance.timeOrigin`，两侧**不可能漂移**（不需要存、
  也不需要另一条判据去对账）。
- **wire 契约**：`register` / `bye` 的 body 都是 `{tab_id: str(必填), epoch: number(可选)}`。
  `epoch` **缺省 = 旧语义**（不做实例比对，照旧注销）——向后兼容，也让 curl / 探针能用最小
  body 打这两个端点。

### 服务端（`src/contest_generator/webapp.py`）

- `TabRegistry` 从 `set[str]` 改成 **`dict[tab_id, epoch]` + 一个在途退出标记**，仍是一把锁：
  - `register(tab_id, epoch)` → 写 epoch，并**撤销在途退出**（不另设返回值：没人消费的信号
    不该出现在公开面上——判据是随后的 `exit_if_due` 返回 False）；
  - `unregister(tab_id, epoch)` → **epoch 与注册表里的不一致 ⇒ 忽略（返回 False，不是"空了"）**；
    否则摘掉，返回"是否空了"；
  - `arm_exit()`（注册表空且未布防 ⇒ 布防，返回 True）／`exit_if_due(exit_fn)`（仍布防且仍空 ⇒
    **取走布防并在同一把锁里 `exit_fn(0)`**，返回是否真退了）。
    **三个动作都在同一把锁里**：要么 register 先拿到锁（撤防 ⇒ 退出作废），要么退出先拿到锁
    （进程随即消失 ⇒ 那一发 register 拿不到 200）——**不存在"register 回了 200 但服务还是没了"**。
    退出动作是**注入的入参**（生产传 `_EXIT`）：它不返回（`os._exit`）或返回（测试桩），
    两者都不回调注册表，故锁内调用无死锁面。
- `_schedule_exit_if_idle(registry)`：非启动器模式直接返回（**`_launcher_managed()` 仍是唯一
  判据**）；`arm_exit()` 失败（还有标签在开 / 已布防）**不重复调度**；daemon 线程 `sleep`
  到点后调 `exit_if_due(_EXIT)` —— 它在锁内做最终判定并退出。`_EXIT` / `_EXIT_GRACE`
  保持**模块级、可注入**（既有先例：`tests/test_webapp.py` 里 monkeypatch）。
- 路由：`/api/tabs/register` 透传 `epoch`（新增 `_optional_number(payload, key)` 校验：
  缺省 / null → None；非数字 ⇒ 400，与既有 `_optional_*` 家族同款）；`/api/tabs/bye` 同款
  透传并照旧"空了才调度"。两个路由的 docstring 写清 epoch 的语义与"跨刷新稳定"的理由。
- **不加任何时间常量**；`_EXIT_GRACE = 1.5` 的注释改成它**现在**覆盖什么（时序抖动，不是
  模块图装载）。

### 判据（单源 + 守卫）

## 补充说明

- **为什么"稳定 tab_id + 实例令牌"而不是"每次加载新 id"**：稳定 id 是这个设计里唯一能挡住
  "幽灵条目"（登记了却没来得及注销）的机制 —— 同一个标签的下一次加载会复用同一个 id，
  它的 bye 顺手把上一次的条目清掉。换成每次加载新 id 就得把**注销**也搬进 head 内联脚本
  （否则半装载的页面永远留条目），等于把整段标签会话搬进 HTML，与仓库近期方向
  （`frontend-boot-module`：把接线搬出 HTML）相背。
- **本单的三层与"只调宽限"的区别**：三层各自对应一个**已实测 / 可确定性复现**的失败模式，
  且都不需要新的时间常量；只调宽限是把概率往下压。
- **读数基线（收尾按最终状态回填）**：前端门禁 **1702 passed / 0 fail / 10.1s**（1691 ＋ 判据⑥ 11 条）；
  pytest **5060 passed + 1 skipped / 131.1s**（5049 + 1 skip ＋ 本特性 11 条）；
  浏览器门禁 **29 passed / 0 fail / 94.2s**（26 ＋ 本特性 3）。修复前的现场读数
  （`probe-00-order-before.txt`）：10 轮里第 4 轮命中自杀；修复后（`-after.txt`）：10/10 全程活着。
  与"关浏览器"那条路径的实测延迟：**1525–1652ms**（宽限 1500ms + 进程退出；其中
  `probe-02-close-page.txt` 记的那次是 1638ms）——不变。
  三条与本特性同轮的环境事实（`-n auto` 下两条假红、worktree 残留会让 ps1 编码用例红）记在
  工单 05 的 Comments ② 与 `docs/agents/local-environment.md`。
- **工单边界的两次调整（都是实现时发现"原拆法要改两遍同一行"，如实记在这里）**：
