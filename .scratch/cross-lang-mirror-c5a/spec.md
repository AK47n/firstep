# spec — C5a 两条裸镜像补上（跨语言判据单源）

来源：架构评审报告 `%TEMP%\architecture-review-20260920-1745.html` 的 C5 卡「六条跨语言镜像判据 — 谁在守」
与复审结论第 **2.5 · C5a 两条裸镜像补上**；对应 `.scratch/backlog.md` 第 10 节末尾挂账的同向候选。
本条只做评审点名的两条，C5 的其余部分（ui 层测试缝、browser 用例接闸门）不在范围内。

## 问题陈述

这个仓库对 Python 侧的判断单源近乎苛刻，前端却留了两条**裸镜像**——判据有两份实现，注释写着
「与后端同口径」，但没有任何东西对账：

- **文件名校验规则**：后端 `codeview._CODE_NAME_ILLEGAL`（非法字符集）与 120 字符上限，前端
  `fx/code-tree-ops.js` 各写一份。改任一侧，另一侧静默失效——表现是前端弹窗放行、后端 400
  （用户填完名字才吃报错），或反过来前端把合法名字拦死。
- **同脚多角色的共享/冲突分类**：后端 `pin_bindings._shared_groups` 判定的结论，前端
  `fx/generate.js` 的 `pinShareClass` 自己再判一遍。`tests/js/pin-share.test.mjs` 覆盖了它，但
  断言的是**前端自己写的期望值**——两份实现一起漂也全绿。

第二条**已经漂了，而且今天就误导用户**：后端 `_role_resource_keys` 有 `adc` 分支（同一 ADC 实例的
模拟通道 = 合法共享），前端 `pinRoleResourceKeys` 只认 `gpio_out | gpio_in`，`adc` 类型落进「无键」
分支被判**冲突**。选 `adc` + `us016`（十几件薄封装按设计共读 `ADC12_0` 的 MEM0=PA24）时：

- 后端 `/api/bindings/auto` 判 `share`、不搬脚（`tests/test_pin_bindings.py` 已把这条钉成契约）；
- 前端在角色行打黄字「默认 PA24 与 … 冲突（同脚分属不同外设）—— 未绑定时生成会资源冲突，建议改线」。

于是页面在教学生**改一根不该改的线**——那根脚由 syscfg 单落点决定，改了就是另一条通路。

## 方案

两条镜像各走仓库**已有的两个成功先例**，不新增第三套做法：

- **文件名校验规则 → 后端下发模型**（先例：引脚可绑判据 `/api/bindings/matrix`，前端只求值）。
  后端在打开目录的响应里带上名称约束（非法字符集 + 上限），前端把它装进纯函数模块的运行时状态，
  校验按它执行；源码里的同名字面量退化为「后端没给规则时的启动兜底」，并由一条源码字面量守卫钉住。
- **同脚多角色分类 → 生成对拍 fixture**（先例：功能组「未选」判据 `tests/test_group_choice_mirror.py`
  ↔ `tests/js/group-choice-mirror.fixture.json`）。场景表只有一份（Python），期望值由后端判据**现算**
  写进 fixture，前端复算对拍；同时修掉已漂的 `adc` 分支，并把「板外脚不标注」的口径钉进场景表。

两条判据因此回到单源（运行时值只有后端一处；前端剩余的一份实现有对拍守卫在闸门内变红）。

## 用户故事

1. 作为使用者，我想要在代码栏改文件名时，前端拦下的规则和后端接受的规则**逐字相同**，以便不出现
   「弹窗放行、保存报 400」或「合法名字被拦住」。
2. 作为使用者，我想要这两条规则的唯一出处是后端，以便以后改规则只改一处、前端自动跟上。
3. 作为使用者，我想要选 `adc` + `us016` 这类共读同一路模拟量的模块时**不再看到「请改线」黄字**，
   以便不去改那根由 syscfg 决定的脚。
4. 作为使用者，我想要同一个引脚上两件真器件被判「合法共享」时，前端显示的说明与后端判定**结论一致**
   （前端说共享就不该同时说冲突，反之亦然）。
5. 作为使用者，我想要板外脚（排针没引出的默认脚）上的重叠**不被前端说成「合法共享」**，以便不误以为
   两件器件可以这样接。
6. 作为维护者，我想要改前端判据而忘了后端时**闸门内立刻变红**，以便在合并前就发现漂移，而不是上板才发现。
7. 作为维护者，我想要对拍失败时测试直接告诉我**是哪个场景、两侧各判了什么**，以便一眼定位漂移点。
8. 作为维护者，我想要这两条判据的出处与守卫在领域词表里有登记，以便下一个人不用读源码才知道谁守谁。

## 实现决策

### 一、文件名校验规则改由后端下发

- **判据单源**在 `contest_generator/codeview.py`：非法字符集与 120 上限改为模块级具名常量
  （现为 `_CODE_NAME_ILLEGAL` 字面量 + 硬编码 `len(name) > 120`），校验函数、400 文案与载荷投影
  **读同一个常量**。新增一个「名称规则」投影函数返回前端载荷形态：非法字符集拼成字符串 + 上限数字。
- **顺带补的两个既存缺口**（tdd 红证实测，用户可见契约变更，已记入工单与 `CONTEXT.md`）：
  ① `create_code_entry` 此前**完全不校验名称**（超长名静默建出、含 `* ? " < > |` 的名字把
  `os.open` 的 OSError 抛成 500）；② 补口必须**逐段**做——中间段是目录名，与末段同样直达 `mkdir`。
  路径安全那一层的拒绝面与文案（`非法路径`）保持原样：名称判定排在 `_resolve_in_root` 之后。
- **下发路径**：并入既有 `POST /api/code/open` 响应（`{root, files, name_rules}`）。选它而不是新增端点，
  因为前端每条进入代码栏的路径都经这个调用，页面一打开规则就在手，没有「规则未取到」的状态；
  载荷新增字段对既有断言（只查 `root` / `files` 逐条字段）无影响。
- **前端**：`fx/code-tree-ops.js` 增加一个装载入口，把后端下发的规则写进模块级运行时状态；
  `treeNameValidate` 读运行时状态，源码常量退化为**启动兜底**（后端尚未下发时仍可用）。
  常量名与类型不变（`CODE_TREE_NAME_ILLEGAL` 字符串 / `CODE_TREE_NAME_MAX` 数字），
  `tests/js/fx-guard.test.mjs` 的登记表与既有导入**零改动**。
- **UI 接线**：`ui/codeview.js` 在拿到 `/api/code/open` 响应后把规则交给纯函数模块；
  下发缺失或形状不对时保持兜底值（不抛错、不静默清空——空字符集会让校验形同虚设）。
- **兜底值的守卫**：Python 侧读 `fx/code-tree-ops.js` 真源码，抠出 `CODE_TREE_NAME_ILLEGAL` 字面量与
  `CODE_TREE_NAME_MAX`，与后端常量按**集合/整数**对账（不做字符串逐字比对——`\` 的 JS 转义写法
  与 Python 源码写法不同，逐字比对会把正确实现判红）。先例：`tests/test_hwcheck.py` 的
  `test_channel_vocabulary_mirrors_the_frontend`、`tests/test_library_invariants.py:624`。

### 二、同脚多角色分类补对拍，并修掉已漂的 adc 分支

- **修漂移**（`fx/generate.js`）两处，判据与后端逐一对应：
  - `pinRoleResourceKeys` 的资源键分支补上 `adc`（与 `gpio_out` / `gpio_in` 同路走实例映射，
    后端判据同源 = `INSTANCES_BY_SLUG`）；
  - `pinShareClass` 增加「引脚不在板内 → 不标注」的门控（后端 `_shared_groups` 对板外脚直接跳过）。
    今天库数据下（i2c/uart 角色的默认脚全在板内）该门控不可达，**为零行为变化**；它防的是
    「aht10 / hmc5883l 那类软 I2C 默认脚落到板外、两侧都判共享」这一类未来数据形态。
- **对拍契约**（照 `test_group_choice_mirror` 的形状，场景表单一出处 = Python）：
  - 每个场景提供：`name` / 平台 / **该场景涉及的模块（真实库内 slug + 平台）** / 期望分类所在的脚 /
    该场景的板（pin 名 + 能力 token + 板内与否）/ 实例映射。
  - Python 侧用**真实模块清单**喂后端判据现算，把 `_shared_groups` 的输出规范化成
    `(pin, 角色集, kind)` 写进 fixture；前端侧用同一份场景（真实 slug + 板 + 实例映射）
    构造角色对象、调 `pinShareClass`，把结论规范化成同一形状后逐场景比对。
  - 两侧规范化的键用**角色 key**（`slug.role_id`）——前端构造的角色对象本就有 key。
  - **只对账 kind**（`share` / `conflict` / `none`），reason 文案前端自有、不进对拍。
  - 场景表必须覆盖：`adc` 共读同槽（**本轮修漂移的证据场景**）、uart 家族同实例共享、i2c 总线多挂共享、
    gpio 同器件实例共享、混合同脚冲突、板外脚（两侧都不标注）、单角色不标注、pwm 等无键类型同脚冲突、
    多角色交集为空（不同器件实例）判冲突。
  - fixture 由 Python 侧脚本生成，**测试不自动重写**：漂移时红，操作者必须显式跑生成脚本、看清 diff
    再决定改动是有意的还是漏了另一侧。红证的判据是「停用前端修复后对拍必须变红」。
- **命名与落点**：fixture 与两侧测试文件名成对（`tests/test_pin_share_mirror.py` ↔
  `tests/js/pin-share-mirror.fixture.json` ↔ `tests/js/pin-share-mirror.test.mjs`）。
  既有 `tests/js/pin-share.test.mjs` 保留为纯函数单测（它测的是函数自身行为），对拍另立文件。

### 三、顺带更正既有口径

`CONTEXT.md` 的对应词表行（引脚绑定 / 代码查看器）补一句：这两条跨语言判据的单源在哪、由谁守
（代码查看器：规则由 `/api/code/open` 下发，前端只求值；引脚绑定：分类判据单源在 `pin_bindings`，
前端镜像由对拍 fixture 守卫）。**不留待办**——只记领域事实。

## 测试决策

- 测**外部行为**，不测实现细节：
  - 后端名称规则：端点载荷带规则 + 校验函数按同一常量拒绝/接受（既有 `tests/test_webapp.py`
    的 `/api/code/tree/*` 用例群是先在先例）。
  - 前端名称校验：`tests/js/code-tree-ops.test.mjs` 补「按后端下发的规则拒绝」的用例（含 `\`
    这类易漏字符与上限边界），断言的是**校验结论**，不是常量从哪来。
  - 前端装载接线：`ui/codeview.js` 依赖 DOM 与 fetch，进不了 `node:test`（该层只有 2 个测试文件
    import 它），故用**源码守卫**（`tests/js/code-tree-ops.test.mjs`，先例
    `tests/js/overlay-confirm.test.mjs:82`）只回答「每个 `/api/code/open` 调用点附近都调了装载
    函数」——形态无关（改名变量 / 两步走都算通过），漏装即红。它**不**放在 pytest 面：那是前端
    测试面的守卫，且 pytest 不该为它 shell 出 node。
  - 跨语言对账：Python 侧的源码字面量守卫（抠出 JS 常量值再与后端常量比，先例
    `test_hwcheck.py` 的正则抠字面量——**不起 node 子进程**）与 fixture 守卫（引脚分类）。
  - 引脚分类修正：`tests/js/pin-share.test.mjs` 补 `adc` 共享与板外脚两例（函数自身行为）。
- **测试缝**（沿用既有，不新造）：
  - `POST /api/code/open` 的响应契约（FastAPI TestClient，既有 `client` fixture）；
  - `tests/js/*.test.mjs` 纯函数对拍（既有 `node --test` 前端门禁）；
  - 跨语言对账的既有两处先例（正则抠前端字面量 / fixture 现算对拍）。
- 前端门禁会自动跑：`tools/prepush.py` 对 `static/` 与 `tests/js/` 的改动跑 `node --test`，
  `ci.yml` 同一条。

## 补充说明

- 两条镜像彼此独立，可并行；工单顺序按「先易后难」排（名称规则改动小、结构简单）。
- 评审原文对这两条只有一行（`2.5 · C5a`），本 spec 是按仓库 workflow 步骤 1 与用户逐条确认后的展开：
  下发路径、兜底常量去留、工单切法、漂移处理范围四项均已拍板。
- 本轮**不**把 C5a 之外的同向候选顺手带上——第 10 节末尾列的其余几件各自另立。
