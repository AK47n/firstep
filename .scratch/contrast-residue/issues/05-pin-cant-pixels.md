**要做什么：** 引脚菜单里"这根脚接不了这个角色"那一行，从"**从没量到过真像素**、只靠同一对色的
静态推算背书"变成"**有可复现配方 + 两主题真像素读数**"。配方已侦察定案（零预备绑定）：

> **MSPM0 → 模块 `step_motor` → 点板图第一根脚 PA0** ⇒ 弹出菜单里 **4 行 `li.cant`**

## 一、配方（写清楚"为什么"，别只写"点什么"）

- [x] 步骤与**等待点**逐条写进工单 Comments（平台卡 `status==="ready"`、模块加入之后再等
      `/api/bindings/matrix` 判据模型到位、`#pin-board-caption` 不含"正在核对可绑引脚…"）。
      **判据模型未到时 `pinCanHost` 降级成类型级 ⇒ 一行 `cant` 都不会出**——这是最容易假红的一步。
- [x] 硬前提写清：① 零预备 `cant` **只在 mspm0**（port/slot 谓词是 mspm0 专属）；② 先选平台再选模块；
      ③ 菜单只能从板图圆点开（`circle[data-pin]`），且多实例卡点过「选择引脚」后点圆点会转成绑实例；
      ④ 模块须有 ≥2 个同类型且**默认同端口**的角色（跨口的模块后端故意不给约束，出不了 `cant`）；
      ⑤ reload 会从草稿恢复平台与模块，而**已选模块不再出现在网格**里（每主题开跑前清 localStorage）。
- [x] **STM32 版配方**作为对照记录（它必须两步预备：先占住同实例的对脚，再点另一脚）——
      并写清为什么 STM32 逃不掉这两步（uart 是纯类型级 + 对脚可跟随；i2c 在 STM32 无实例 token，
      **永远不出 `cant`**——这解释了账本里"先绑 OLED_SCL 再扫"为什么失败）。
