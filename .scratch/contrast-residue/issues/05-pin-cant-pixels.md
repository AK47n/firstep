# 05 — `.pin-menu-list li.cant` 的真像素取证（造前提 + 扩量具口径）

**要做什么：** 引脚菜单里"这根脚接不了这个角色"那一行，从"**从没量到过真像素**、只靠同一对色的
静态推算背书"变成"**有可复现配方 + 两主题真像素读数**"。配方已侦察定案（零预备绑定）：

> **MSPM0 → 模块 `step_motor` → 点板图第一根脚 PA0** ⇒ 弹出菜单里 **4 行 `li.cant`**
> （`STEP_MOTOR_RST2/SLP2/DIR2/DCY2`），原因是这组角色走单端口宏、而 PA0 在 A 口。
> 等价备选：MSPM0 + `nrf24l01` → 点任意 B 口脚 ⇒ 6 行 `cant`。

**用户可见变化：无**（只补取证；若读数低于 AA 才转产品改动——**预期不会**：它上一轮已改成
`--muted` × `--panel-2` = 浅 5.25 / 暗 5.67）。

**被谁阻塞：** 无——可立即开始。

**状态：** ready-for-agent

## 一、配方（写清楚"为什么"，别只写"点什么"）

- [ ] 步骤与**等待点**逐条写进工单 Comments（平台卡 `status==="ready"`、模块加入之后再等
      `/api/bindings/matrix` 判据模型到位、`#pin-board-caption` 不含"正在核对可绑引脚…"）。
      **判据模型未到时 `pinCanHost` 降级成类型级 ⇒ 一行 `cant` 都不会出**——这是最容易假红的一步。
- [ ] 硬前提写清：① 零预备 `cant` **只在 mspm0**（port/slot 谓词是 mspm0 专属）；② 先选平台再选模块；
      ③ 菜单只能从板图圆点开（`circle[data-pin]`），且多实例卡点过「选择引脚」后点圆点会转成绑实例；
      ④ 模块须有 ≥2 个同类型且**默认同端口**的角色（跨口的模块后端故意不给约束，出不了 `cant`）；
      ⑤ reload 会从草稿恢复平台与模块，而**已选模块不再出现在网格**里（每主题开跑前清 localStorage）。
- [ ] **STM32 版配方**作为对照记录（它必须两步预备：先占住同实例的对脚，再点另一脚）——
      并写清为什么 STM32 逃不掉这两步（uart 是纯类型级 + 对脚可跟随；i2c 在 STM32 无实例 token，
      **永远不出 `cant`**——这解释了账本里"先绑 OLED_SCL 再扫"为什么失败）。

## 三、读数与判据

- [ ] **两主题各一份真像素读数**：量到的行数（≥1）、每行的前景 / 底 / 比值；
      与静态族面同一格（`--muted` × `--panel-2`）**对得上**。
- [ ] **"没量到"必须落盘**（既有口径）：量具要有"这一次没量到 X"的逐条记账，不许静默变绿
      （本轮最可能的形态：判据模型没等到 → 一行 `cant` 都没有 → 读数必须说清是"没造出前提"
      而不是"产品没问题"）。
- [ ] **判据强度自证**：把"等判据模型"那一步去掉（或把平台换回 STM32 不预备）→ 量具报"没量到"
      且**不当成通过**（这一发要留下读数）。
- [ ] 读数与 PNG 落 `contrast-residue/`；浏览器门禁**单独跑**（量具与门禁抢端口/CPU）。
