# 03 — 两个图例色点的令牌归属落定 + 亮色补 `--pin-fixed-pad`

**要做什么：** 引脚图例里那两个色点（「空闲 IO」「固定/电源（不可点）」）不再挂在"静态判不了"
这一档上——它们的令牌现在解得出来了（01 单），归类到**描边承担分层**那一档并写清理由；
同时把浅色主题下"固定/电源"焊盘的配色补上（亮色块从来没覆盖过 `--pin-fixed-pad`，它一直沿用暗色值
`#171b21`，在浅色板图里是**近黑的点**，而旁边"空闲 IO"焊盘是浅灰 `#d0d7de`——两块焊盘不是一套）。

**用户可见变化：有**（浅色主题的板图里，"固定/电源"焊盘从近黑变成与空闲焊盘一套的浅灰）。

**被谁阻塞：** 01（解析面扩到全部定义块——那两个色点的令牌正是第二块 `:root` 里定义的）。

**状态：** ready-for-agent

## 一、登记项归类（渲染方面）

- [ ] `ui/generate-pins.js` 的两条内联取色登记（`background:var(--pin-pad)` /
      `background:var(--pin-fixed-pad)`）从 `skip` → **`surface-bordered`**；理由写清：
      **色点自带描边**（`1px solid var(--border-strong)` / `var(--border)`）承担"看得出分层"，
      填充是**色样**（它的信息是"这个颜色代表什么"，不是"它比底亮多少"）。
- [ ] **`skip` 档位退场**：两条改完之后 `JS_CONTRAST_KINDS` 里 `skip` 零实例 ⇒ 删掉它，
      并把那段"零实例的档位 = Speculative Generality"的注释同批回改（**别留一个没有实例的档**）。
      两侧（JS 守卫 / Python 口径）同步；镜像腿跟着改。
- [ ] 确认**解得出值**：两主题四个格（两个令牌 × 两主题）都要现算成功；把值落进读数
      （`--pin-pad` 亮 `#d0d7de` / 暗 `#21262d`；`--pin-fixed-pad` 修前两主题 `#171b21`）。

## 二、浅色补值（产品面）

- [ ] `:root` 的 `--pin-pad` / `--pin-fixed-pad` / `--pin-pcb` 那一族在**亮色块**里成套：
      补 `--pin-fixed-pad`，候选值 **`--border-strong` 的亮色值**（浅灰），与 `--pin-pad`
      同一族语言（"浅灰 = 板上的焊盘"）。
- [ ] **边界（写进注释）**：本单**不立**"亮色块必须成套覆盖某些令牌族"的判据——那要先定
      "哪些令牌族必须两主题成套"，属另一件事。**只做这一处补值 + 写清为什么**，别让下一个人
      以为这条线有守卫。若实施时觉得该立，先开单，不要顺手加。
- [ ] 检查连带：`--pin-fixed-pad` 还用在板图（`fill`）、接线图焊盘（`fill`）、资源总览板图
      （`fx/resource-board.js`）——三处一起变；逐处真像素取证（下一条）。
