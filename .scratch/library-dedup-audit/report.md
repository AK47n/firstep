# 各库重复项盘点（2026-09-13，只读扫描 + 一次定向回收）

**请求**：「看一下各个库里面有没有重复的，重复就删掉」。
**结论先说**：**注册层面零重复**；文件层面共 **507 MB 冗余，但其中 300 MB 是结构性重复，删了会坏东西**——
真正的"同一份文件被存了两遍"只有 **7 个文件 / 208 MB**，已回收（可恢复）。

## 一、注册层面：干净

| 检查项 | 结果 |
|---|---|
| 模块库 95 个模块目录 | 无重名目录；**无 slug 与目录名不一致**；无重复 slug |
| 参考库 171 个条目目录 | 无重名 |
| 赛题库 20 个目录 / 母版库 2 个 | 无重名 |
| 词表 `models` 127 项 / `solutions` 87 项 | **零完全重复** |

## 二、文件层面：507 MB 冗余的构成

扫描口径：同一库内 SHA256 相同即算一组（`probe-01-scan.py`，只读）。

| 库 | 文件 | 重复组 | 冗余 | 判定 |
|---|---|---|---|---|
| `library/modules` | 454 | 0 | 0 | 干净 |
| `library/masters` | 54 | 0 | 0 | 干净 |
| `library/references` | 1294 | 38 | 0.25 MB | **结构性**：策展合集目录本就包含单器件条目正文（如 `at24c02` 同时出现在"存储-编码/温度/气体-温度"三个合集里） |

| `sources/car` | 603 | 179 | 4.72 MB | 同类工程结构 |

### 为什么不能按"重复就删"一刀切

三类重复各有各的理由，删了都会坏：

1. **原厂 SDK/demo 树**：同一份 `stm32f10x.h` 存在于 8 个 demo 工程里是原文资料的形态；
   删掉任意一份都会让那个工程缺少依赖（`SKIP_DIR_NAMES` 里也没有"删原厂文件"的先例）。
2. **共享真题 PDF**：见上表 `library/topics`——代码**依赖它在每个题录目录下都在**。
3. **策展合集**：参考资料库的"合集"条目按设计就是若干单器件条目的再组织。
