## 问题陈述

mspm0 地猛星板卡包型号与排针事实此前没有闭环：文档里仍写“疑 LQFP-48 / syscfg 仍声明 LQFP-64(PM) / 留待核实”，容易让后续代理误把 `PA13` / `PA14` 当作不确定或不可用脚，也容易误动 `PA19` / `PA20` 的 SWD 锁脚口径。

## 方案

以 2026-08-20 用户实物核验为准收口：主控芯片表面可见 `42WG4`、`ABDL` 字样，芯片外周为 48 脚；板上 2×20P 排针分布确认正确；`A13`、`A14` 在板上；用户没有在板上找到 `A19`、`A20`。因此生成器继续把 `PA13` / `PA14` 作为地猛星 2×20P 上的普通可用脚，把 `PA19` / `PA20` 作为 SWD/DEBUG 固定资源，不进入普通模块默认分配。TI 封装命名中 `LQFP(PT)` 是 48 脚、`LQFP(PM)` 是 64 脚；SysConfig 仍沿用现有可工作的 `LQFP-64(PM)` / LP-MSPM0G3507 模型，但不以该模型反推实物脚数，实际板上引出范围由 `mspm0-dimx` 板定义约束。

## 用户故事

1. 作为学生，我想让 `PA13` / `PA14` 明确出现在地猛星可用脚口径里，以便给 PWM/GPIO/串口等角色绑定时不再被错误灰显。
2. 作为学生，我想让 `PA19` / `PA20` 明确保持 SWD/DEBUG 锁脚，以便不会把调试口分配给普通模块导致下载/调试风险。
3. 作为维护者，我想把旧的“包型号悬案”改成已核验事实，以便后续代理不会重复追问或误改板定义。
4. 作为维护者，我想用测试钉住 `PA13` / `PA14` 在 2×20P、`PA19` / `PA20` 不在 2×20P 的事实，以便板定义回退时立刻红灯。

## 实现决策

- 修改 ADR 0012 的包型号条目：从“悬案”改为 2026-08-20 实物核验结论。
- 修改 mspm0 母版 syscfg 顶部说明：删除“疑 LQFP-48 / 留待核实”的未闭环表述，改为“SysConfig 模型沿用 LQFP-64(PM)，板定义约束实际 2×20P 引出”。
- 不改 `mspm0-dimx` 板定义数据：当前数据已经包含 `PA13` / `PA14`，且没有把 `PA19` / `PA20` 放进 2×20P 排针。
- 不改 SysConfig `--package "LQFP-64(PM)"`：现有母版、真实来源样本和 TI/LP-MSPM0G3507 工具链路径均以该模型工作；虽然实物芯片外周为 48 脚（TI 封装 `PT` 口径），生成器用板定义限制实际 2×20P 引出范围，而不是把 SysConfig 模型切到更小封装。

## 测试决策

- 在 `tests/test_boards.py` 增加板定义不变量测试：`PA13` / `PA14` 必须可由 `board_pin` 找到，`PA19` / `PA20` 必须找不到且只出现在 SWD 固定资源中。
- 复用既有 `boards` fixture 与 `board_pin` 入口，只测试外部板定义行为，不测试 JSON 内部排版。

## 范围外

- 不新增地猛星板卡图片/丝印解析能力。
- 不改前端板图 UI。
- 不更换 SysConfig 设备/package 参数。
- 不处理 PB4/PB5 的 LaunchPad 遗留模型脚；它们仍不在地猛星 2×20P 排针上。

## 补充说明

TI 的 MSPM0G3507 确实有多个封装选项；本项目生成器的板级事实以用户手上地猛星实物和 `mspm0-dimx` 板定义为准，SysConfig package 仅作为代码生成模型入口。
