# Spec：main.c 与代码查看器融合（不割裂）

## 问题陈述

生成页步骤 8 的 main.c 编辑框与「代码」tab 的代码查看器呈现**同一个 main.c 的两份互不感知的视图**，用户在实际使用中感到割裂：

1. **事实分裂**：生成时把步骤 8 编辑框内容写入磁盘 main.c 之后，任务推进（第 11 步）、深化、修订、参数修改都会改写**磁盘上的** main.c，但步骤 8 编辑框从不回读——用户做完几步任务回到步骤 8，看到的还是生成那一刻的快照，与磁盘（也是代码查看器里看到的）不一致。
2. **入口割裂**：生成成功结果区没有直达代码查看器的入口（只能去最近生成卡片找「查看代码」）；代码查看器打开目录后也不知道自己与生成上下文的联系。
3. **上下文缺失（生成前）**：步骤 8 的骨架里出现 `led_init(LED_RED)`、`adc_init()` 之类调用，但用户看不到每个调用来自哪个模块、模块源码长什么样——只能凭空信任 AI。代码查看器此时没有工程可看，模块库详情弹窗也只能看到元数据与文件名，看不到内容。

## 方案

把「main.c 的编辑视图（步骤 8）」与「工程的只读视图（代码查看器）」变成同一事实的两面，可互相跳转、互相看见：

1. **磁盘同步状态行**：生成成功后，步骤 8 常驻一行状态：「已生成到 <dir> · main.c 已写入磁盘」，右侧带「从磁盘重新加载」按钮。任务推进每步成功 / 深化完成 / 修订应用后，自动对磁盘 main.c 与编辑框做一次差异检测：一致则静默；不一致则在状态行提示「磁盘 main.c 已更新 → [加载]」，**绝不自动覆盖**用户未保存的手动编辑。
2. **双向跳转**：生成成功结果区「下一步」、步骤 8 工具栏各加「在代码查看器中打开工程」→ 切到代码 tab 并打开该目录；代码查看器打开目录且与最近生成上下文一致时，顶栏显示「去生成页编辑 main.c」→ 切回生成页、滚动到步骤 8、按用户主动点击加载磁盘内容到编辑框（代码查看器维持只读契约，编辑唯一入口仍在步骤 8）。
3. **骨架引用模块锚定**：骨架生成（或编辑框内容变化）后，在步骤 8 编辑框下方显示「骨架引用的模块」chips——从骨架文本静态提取模块风格调用（`<slug>_init` / `<slug>_read` / `<slug>_update` 等），与已选模块匹配，click 打开模块详情弹窗；无法识别不显示（宁少标不错标，best-effort）。
4. **模块源码速查**：模块详情弹窗的清单文件行可点击查看源码（复用代码查看器的渲染观感：行号 + 高亮 + 大纲），通过新增的只读端点读取模块库内文件。这一条既服务生成前上下文（痛点 3 的轻量完整版——每个骨架调用的实现都能点进去看），也是将来「生成前虚拟工程树」的地基。

## 用户故事

1. 作为用户，我生成完工程后能看到步骤 8 提示「main.c 已写入磁盘 <dir>」，以便确认编辑框与磁盘一致。
2. 作为用户，我做完第 11 步任务后回到步骤 8，能看到「磁盘 main.c 已更新 → 加载」，以便不再对着旧骨架做后续判断。
3. 作为用户，我点「加载」后编辑框内容刷新为磁盘版本（行号 / 高亮 / 草稿保存同步），以便继续在步骤 8 编辑真实文件。
4. 作为用户，我在生成成功结果区点「在代码查看器中打开工程」，即可在 IDE 式视图里核对整个工程，以便确认模块文件 / 引脚头 / syscfg 与骨架的对应关系。
5. 作为用户，我在代码查看器打开生成过的工程时能看到「去生成页编辑 main.c」入口，点回即在步骤 8 编辑磁盘版本，以便编辑与浏览互不割裂。
6. 作为用户，我生成骨架后能在步骤 8 看到「骨架引用的模块」chips，点任意 chip 查看该模块详情（元数据 + 源码），以便理解每个调用来自哪里、实现长什么样。
7. 作为用户，代码查看器保持只读（无编辑按钮），避免双编辑入口造成状态混乱。

## 实现决策

- **差异检测机制**：事件驱动，不轮询。事件 = 生成成功 / 任务执行成功（status ≠ failed）/ 深化完成 / 修订应用完成；动作 = 读取磁盘 main.c（复用现成只读端点，`dir` = 该事件的输出目录）与步骤 8 编辑框比较，逐字节相等 = 静默（或状态行维持「已同步」），不等 = 提示 + 「加载」按钮。加载 = 覆盖编辑框 + 触发行号/高亮重同步 + 保存草稿（编程赋值不触发 input 事件，需显式走保存路径）。
- **上下文目录**：生成成功后把 `output_dir` 记为「生成上下文目录」（内存 + 草稿持久化），供三处消费：步骤 8 状态行展示、结果区「打开工程」、代码查看器「去生成页编辑」的匹配判断（打开目录 === 生成上下文目录才显示）。
- **骨架引用锚定**：纯函数提取（可单测）——扫描骨架文本中的 `ident(` 调用形态（复用/借鉴 C 词法层思路，不带 include 与字符串），ident 以某个已选模块 slug 为前缀即命中该模块；重复去重、按出现顺序展示；无命中 = 该区隐藏。打开的详情弹窗复用既有模块详情弹窗（不改其元数据部分）。
- **模块源码只读端点**：新增 `GET /api/modules/{slug}/files/{path:path}`，安全拒绝面与母版文件树 / 代码查看器同口径（`..` 任意层级 / 空段 / 首字符 `/` / 反斜杠 / 冒号 / resolve 后必须落在该模块目录内 / NUL 二进制拒绝 / 大小上限），中文错误 400；模块不存在 400。前端弹窗文件行懒加载 + memo（业务 400 缓存可重试，网络 / ≥500 不缓存），渲染复用代码查看器同款行号 + 高亮视图。
- **代码查看器保持只读**（既有契约不破）：只新增「去生成页编辑 main.c」跳转桥，不新增任何编辑能力。

## 测试决策

- **只测外部行为**：JS 纯函数（骨架引用提取、差异判定文案、目录匹配）进 `tests/js/*.test.mjs`（node 直跑现有框架）；Python 侧新增模块文件端点走既有 webapp / 库测试先例（测试安全拒绝面：穿越 / 越界 / NUL / 超限 / 模块不存在 / 平台存在性，全部 400 中文）。
- 前端胶水（状态行显隐、跳转）按仓库惯例不进自动化，靠真机走查验收。
- 差异检测与「加载」的既有行为回归：生成 / 任务执行后步骤 8 内容不因静默同步被覆盖（不注册自动写回路径）。

## 范围外

- **生成前虚拟工程树**（main.c + 全部模块源码 + 母版承继文件并排浏览的 IDE 式预览）：本次只做「单模块源码速查」的地基（端点 + 弹窗源码区），整树装配留作下一步。
- 代码查看器编辑能力、差异三向合并、文件状态轮询 / 监听（用户在外用 IDE 改文件后的自动感知）。
- 模块库文件端点扩展为目录列表端点（本次只需单文件读取）。

## 补充说明

- 步骤 8 编辑框与代码查看器目前已是两套 UI（textarea 三明治 vs 只读 gutter 视图），本次**不合并渲染**，只做事实同步与跳转桥——合并渲染是更大的 UI 重构，收益待定。
- 用户已确认：代码查看器维持只读；本次先做层次 1+2 与骨架锚定，虚拟工程树后置。
