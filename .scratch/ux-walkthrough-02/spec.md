# spec — 用户体验优化一期（走查合并整改，A–Q 全包）

## 问题陈述

电赛工程生成器功能已完整，但三份只读走查（生成主流程 23 条 / 库管理与设置 14 条 / 反馈机制与一致性 25 条）与历史「范围外」候选、CSS 审计剩余项共同指向四类体验问题：

1. **数据丢失风险**：覆盖式「重生成」无确认直接整树重建输出目录；平台切换静默清空已选模块/实例/引脚；「全部还原默认」一键清空全部绑定；覆盖重生成的 `.bak` 备份在界面无恢复入口，二次覆盖会静默删掉上一份备份。
2. **主流程发现性死角**：多实例配置卡（6.5）游离于 12 步步骤体系之外，无编号、不进导航、不计入完成度，用户跳过实例配置而不自知。
3. **首次使用与配置摩擦**：设置页十余张卡但「保存设置」在最底部且成功反馈同在底部；「体检」只查 UV4/gmake 而「工具链」卡暴露的是 CCS 三件套，言行不一且叫法混乱（gmake 工具链 / CCS 三件套 / 装 CCS）；录入模块/参考条目要跨 3 个折叠区，提交按钮在最远区；参考条目改文件内容被强制成「先删再加」两步；模块编辑弹窗「保存身份」与「推送新文件」两套语义并存。
4. **等待与错误体验**：推荐/修订/参数/编译修复/商量等分钟级长任务只有一行状态文字或跳动秒数，无「已等待多久 + 当前阶段」，无取消；生成端点用「每 2s 轮播 5 个假阶段名」假装进度；500/长错误只走 2.5s 即消失的 toast，用户无法复制反馈；文件系统失败直接透出 Windows 英文原文（WinError 32）；500 兜底暴露 Python 异常类型名；SSE 终态裸串「请求失败」。
5. **一致性打磨**：删除确认弹窗五种形态三种外观；「已验证」一词三处含义不同但都绿色；顶栏页签无 ARIA tabs/方向键；大量输入无 label；圆角/间距/字号无令牌（8/10/12/999/6px、5/7/9px、13/13.5/14/15 混用）；库列表默认按标题排序而非最近更新；部分库读取失败残留「正在读取」占位；PDF 库只能删疑似重复文件。

## 方案

按「先修数据丢失与发现性死角（P0）→ 再修首配/等待/错误体验（P1）→ 最后一致性打磨（P2）」分批实施，全部为小步快跑的前端为主改动 + 少量后端小改（均不触碰真实 LLM 推荐路径）：

- **A 危险操作确认补齐**：覆盖式重生成前 danger 确认弹窗（展示模块集变更摘要 + 覆盖重建与整树备份说明）；平台切换前确认（提示将清空已选模块/实例/引脚）；「全部还原默认」确认并 toast 提示还原数量。
- **B 6.5 多实例卡纳入步骤体系**：步骤系统支持非整数步骤标识；步骤 6 卡在存在多实例模块时顶部显示「还差 N 个实例」徽章；实例的配/清/删操作同步步骤 7 就绪判定与徽章。
- **C `.bak` 应用内恢复**：覆盖确认框补「如需找回旧工程，把桌面 X.bak 改回 X」说明；生成结果区新增「恢复覆盖前备份」按钮（后端新增安全重命名端点，同款路径安全校验）。
- **D 设置页保存体验**：顶部 sticky 保存条（任意滚动位置可见与保存）；成功/失败提示改 toast；AI API 卡内提供「保存并连接」直达。
- **E 体检与工具链言行一致**：环境体检扩展对 CCS 三件套（SDK/编译器/SysConfig）与赛题/参考/PDF 库目录的探测并逐行展示；工具链叫法统一「Keil UV4（stm32）/ CCS+MSPM0 SDK（mspm0）」；体检未就绪项提供「去设置填」一键跳转（切页签 + 展开对应折叠区 + 聚焦输入框）；设置页工具链卡内联展示探测回显。
- **F 录入/编辑绕路**：模块/参考录入把「AI 出简介草稿」按钮挪到简介输入框同一行；提交按钮紧贴最后一区；参考录入三个折叠区默认全展开；参考编辑「同名新增 = 覆盖原文件」一次 PUT 完成（不再要求先删再加）；模块编辑弹窗合并为一个「保存」（身份 + 文件顺序提交，未推送文件加计数角标）。
- **G 错误人话化 + 可复制**：后端文件系统错误按 errno/winerror 分派中文与修复步骤（WinError 32 关闭 Keil、磁盘满、只读/无权限）；500 兜底去掉异常类型名；backup_id 术语人话化并给下一步；前端 500/长错误改常驻内联块（可选中复制）并给 toast 加复制按钮与更长停留；所有 SSE 流终态统一走共享错误解析。
- **H 长任务可感知进度 + 取消**：统一「已等待 X 分 Y 秒 + 当前阶段名」秒表（复用既有计时格式）覆盖推荐/修订/参数/编译修复/商量/预读；推荐端点补发带中文阶段标签的 start 事件，进度面板立即显示「AI 正在选模块…（可能要几分钟）」；推荐收敛态进度条停在约 85% 并注明「正在出最终结果」；生成端点去掉与真实管线无关的假阶段轮播，改「正在生成工程（约几分钟）」；分钟级长任务增加「取消本次等待」（客户端中止 + 明确「可安全重试」语义）。
- **I 删除类确认与撤销**：最近生成记录、想法草稿删除接确认弹窗（说明影响范围）且确认后 toast 带撤销；母版库与 PDF 库删除确认迁移到共享确认弹窗工厂；工厂默认确认文案加告警防漏传。
- **J PDF 任意删除**：非「疑似重复」的普通 PDF 也提供「回收」删除（复用既有回收目录策略，可恢复；被参考条目引用时确认框说明影响）。
- **K 生成页状态按钮一致性**：「检查能否生成」忙碌态（拉取时禁用 + 转圈）；面板顶部加「硬判据就绪 → 点生成工程即可」绿色总结、软性警告改中性「可选项」措辞；步骤 8 两个主色按钮降级一个为次按钮并各加一行短说明；生成成功不再自动抢滚屏跳到修复中心；「展开依赖并检查平台」加进行中反馈；预读失败按钮复位；上传抽取加加载反馈。
- **L 术语与文案对齐**：桌面选项「同名目录自动加时间」改为与实际行为一致的文案（同名完整工程先确认并备份 .bak 覆盖 / 同题换平台自动带平台后缀新目录）；术语表补 自备/词表/重推/选型/补问；「深化」三入口统一命名与定位说明；「已验证」词汇表统一（模块=已验证/待验证、步骤=已完成/未完成、任务=上板通过/待上板）；新手指引「右上角设置」改「顶部导航」。
- **M 键盘与可达性**：顶栏页签遵循 ARIA tabs（role=tablist/tab、aria-selected、roving tabindex、左右方向键切换）；大量裸输入补 aria-label；确认弹窗打开移焦、焦点陷阱、关闭还焦。
- **N CSS 令牌化**：补 `--radius-sm/md/lg/full` 与 `--space-*` 令牌与少量工具类（.mt-2/4/6/8 等）；圆角收敛四档（胶囊 full / 卡片 md / 控件 sm）；按钮收敛三类；字号归并（13.5→13 或 14、10/10.5→11）；语法高亮/紫色族/青 rgba 裸值/绿完成族裸色改令牌；主题相关裸色值改令牌（扫描件白底保留则加注释说明）。
- **O 库页面小修**：参考/PDF 库默认按「最近更新」降序；失败时清空加载占位并同位置展示错误；赛题库加载占位延迟 ~150ms；库目录卡列出 5 个目录（派生值只读展示 + 跟随说明），切换模块库目录时提示联动。
- **P 「和 AI 聊」入口收敛**：多入口（全局商量 / 每卡问这里 / 买件商量 / 参数速调问 AI / 第 12 步交接提示词）命名与定位统一；长跑屏幕（母版提炼 / 编译修复 / 修订深化）加「有问题？去问 AI」直达链接；推荐结果区与任务推进区的商量语义边界说清楚。
- **Q 欢迎卡与响应式**：欢迎卡 compact 态补主行动入口；基础窄屏响应式（顶部导航与生成区关键断点不溢出）。

## 用户故事

1. 作为新手用户，我想在点「确认并执行修订」前看到一个明确警告（将覆盖重建输出目录并已整树备份），以便不会误毁旧工程。
2. 作为用户，我想在切换平台前被提示会清空已选模块/引脚/实例，以便不丢配置。
3. 作为用户，我想在点「全部还原默认」前被确认，以便误点时能反悔。
4. 作为用户，我想在配置多实例模块时看到它在步骤体系中的位置与「还差几个」提示，以便不会漏配实例。
5. 作为用户，我想在覆盖生成后能从界面一键恢复覆盖前的备份，以便不依赖手动改文件夹名。
6. 作为用户，我想在设置页任何滚动位置都能保存并马上看到结果，以便配置 key 不用滚到页尾。
7. 作为用户，我想在体检里看到 CCS 三件套的真实状态并能点一下就跳到设置对应输入框，以便「填了却不知有没有生效」的困惑消失。
8. 作为用户，我想录入条目时草稿按钮、简介框、提交按钮在同一条线上，以便少绕路。
9. 作为用户，我想编辑参考条目时直接替换同名文件内容，以便不用「先删再加」两步。
10. 作为用户，我想模块编辑弹窗一个「保存」就把身份和文件都存了，以便不会以为存了其实没存。
11. 作为用户，我想看到文件系统错误的中文原因和修复步骤，以便知道该关掉 Keil 还是清磁盘。
12. 作为用户，我想在长错误出现时能复制完整信息反馈给开发者，以便问题能被修。
13. 作为用户，我想在等待 AI 的任何长任务时看到「已等待多久 + 正在做什么」，以便判断卡没卡。
14. 作为用户，我想在等太久时能取消本次等待并安全重试，以便不干等。
15. 作为用户，我想删除最近记录/草稿时有确认与撤销，以便误删可恢复。
16. 作为用户，我想删除任何一份 PDF 都能在界面完成（进回收目录），以便不靠磁盘操作。
17. 作为用户，我想「检查能否生成」在拉取数据时有忙碌反馈并告诉我「都就绪了就点生成」，以便不困惑。
18. 作为用户，我想界面术语与教程一致（顶部导航、CCS、深化、已验证），以便学得会。
19. 作为键盘用户，我想用方向键切顶部页签、Tab 能进弹窗且不逃逸，以便无障碍使用。
20. 作为用户，我想界面圆角/间距/字号一致，以便观感统一。
21. 作为用户，我想库列表默认看到最近更新的资料，以便快速找到在用的那份。
22. 作为用户，我想在长跑屏幕也能一问直达「和 AI 商量」，以便不白等。
23. 作为首次访问用户，我想欢迎卡精简态也有主入口，窄屏下界面不溢出。

## 实现决策

- **批次与顺序**：A/B/C（P0）→ D/E/F/G/H（P1）→ I—Q（P2），每批内按依赖排序；每包一个或多个工单（vertical slice）。
- **测试缝**：沿用仓库既有最大复用缝——前端纯函数放 `static/js/fx/*.js`、测试为 `tests/js/*.test.mjs`（node:test）；后端改动补 `tests/` pytest 用例；DOM 胶水（ui/*.js）不单测，由工单验收标准 + 现有全量回归（node --test tests/js、pytest）保障。新增可测纯函数一律进 fx/（如：步骤完成度与实例缺口计算、警告文案生成、备份恢复端点前端状态、错误解析 parseError、秒表格式化复用）。
- **交互原则**：危险操作（覆盖/清空/删除）必须有确认；破坏性确认统一走既有共享确认弹窗工厂（危险红主钮）；长任务等待必须有「已等待 + 阶段」；错误信息必须中文人话 + 可复制 + 有下一步；所有文案变化以不改变功能语义为前提（术语统一按词汇表）。
- **后端边界**：新增端点仅两个方向——备份恢复（安全 rename）与环境探测扩展（CCS 三件套 + 派生目录存在性）；`sse.py/events.py` 仅增发 start 事件，不改既有事件语义与 LLM 调用链；`fix_errors.py/revision.py` 仅改面向用户的 message 文案。
- **范围收敛**：「和 AI 聊」入口收敛（P）只做文案/定位/链接统一，不合并后端会话端点；窄屏响应式只做关键断点不重排整页；CSS 令牌化只收敛可感知项，不做全文件重写。

## 测试决策

- 纯函数新测：实例缺口/完成度判定、警告文案、错误解析 parseError、秒表格式、备份恢复前后端契约（pytest）、CCS 探测解析（pytest）、文件系统错误分派（pytest，按 errno/winerror 分支）。
- 回归：`node --test tests/js`（前端 fx）、`pytest tests`（后端）。改动涉及的既有测试若因文案变化需同步（如断言错误 message 的用例）。
- 手工验收：起 webapp + 走查关键路径（覆盖确认、平台切换确认、6.5 徽章、保存 sticky、体检跳转、参考覆盖、.bak 恢复按钮、长任务秒表、删除确认、PDF 回收、顶栏方向键、窄屏无溢出）。

## 范围外

- 不合并/重构后端会话与 SSE 端点（仅增 start 事件与 message 文案）。
- 不做库列表虚拟滚动/分页（154 条全量渲染实测可接受）。
- 不做真实 LLM 推荐路径的行为变更（选模/推荐/深化等算法与提示词不动）。
- 不做整页视觉重设计；CSS 令牌化仅收敛既有样式不重新设计。
- 不做移动端完整适配（仅关键断点不溢出）。
