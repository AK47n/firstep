# 硬件检测·库外器件（陌生器件 + 资料辅助）——功能规格

> 2026-09-22 grilling 三轮定稿（用户逐轮「按你推荐」，仅两处按实测事实更正）。逐条决策见「实现决策」。

## 问题陈述

学生手上新到一件器件，它**不在模块库里**（典型：卖家常卖的某个传感器模块、别人给的模块、小厂模块）。今天这条路是死的：

- 检测页的器件池 = 模块库全量。库里没有 manifest 的东西**在页面上根本不存在**——选不到、看不见、也没有任何"我手上这件不在这里"的出口。
- 通用降级（未专精件：初始化 + 总线扫描）只服务**库内有 manifest 但没有配方**的件。库外件连通用降级都没有资格。
- 学生手上的**资料**（卖家页、数据手册、模块实物照片）与工具之间没有入口。他自己知道的那点关键事实——"地址 0x76""WHO_AM_I 寄存器 0xD0 应该读回 0x58"——工具一个字都拿不到，也就无法替他判"通没通"。
- 结果是学生只能退回手写裸 I2C 调试代码、盯着串口猜。**这段活正是本工具存在的意义所在**（赛题工程的学生手写调试代码属于同一类痛点）。

## 方案

检测页器件区新增一块「我的器件」（库外件），与库内器件**同页、同流程**：

1. **填事实**：结构化表单——名称 / 总线 / 7 位地址 / 身份寄存器 + 期望值 / 备注。件本身**与平台无关**（同一件在两个平台上都能测）。
2. **资料可选**：可以贴一段文字、传 PDF 手册、传模块照片或手册截图 → AI 把手册里的关键事实抽成**草稿**填进表单 → **用户逐字段确认/修改**（AI 只填草稿，永远不写代码、不生成判据）。没有资料就纯手填，一样能测。
3. **参与检测**：确认后的自建件与库内器件一起出现在检测页——接线（这一趟要接的那一对脚）、上板清单、可复测的串口命令。
4. **生成探测程序**：确定性渲染一段**裸总线探测**：ping 器件地址（板上判应答）+ 读一个身份寄存器（有期望值就判 OK/FAIL；没有就**只回显读到的字节**，页面与串口都明说"没有期望值可比"）。**不写寄存器、不读数据**——猜出来的读法比不测更坏。
5. **上板 → 回填 → AI 排障**：编译 / 烧录复用既有能力；把实际现象填回去，AI 排障的上下文里**带上自建件的事实**（地址、身份寄存器、期望值），否则它连"你这件该怎么查"都无从说起。

支撑这一切的**支点是一件新的库内模块 `i2c_probe`**（总线原语：ping 地址 / 读一个寄存器）。它不是驱动、不含任何器件语义，纯粹是"借一对脚 + 一条总线给我们用"；有了它，探测代码才进得了既有生成门禁（mspm0 上 `main.c` 只准调"所选模块头里真实存在的函数"）。

**非 I2C 的陌生器件**（SPI / UART / 单总线 / 模拟）：这一版**不生成探测程序**，只给「应看到什么 / 不对先查哪里」清单 + AI 排障，并在页面上如实说明为什么只到这里——不假装测过。

## 用户故事

1. 作为学生，我想要**把我手上这件库里没有的器件**告诉工具（名称 + 地址就够了），以便它出现在检测计划里，而不是被无声拒绝。
2. 作为学生，我想要**传手册 / 贴网页文字 / 传模块照片**，以便我不必自己从几十页手册里翻出地址与身份寄存器。
3. 作为学生，我想要 AI 抽出来的事实**只是草稿、由我逐字段确认**，以便我不会把一个模型猜出来的地址烧进板子。
4. 作为学生，我想要**没有资料也能测**（纯手填），以便手上只有一块裸模块时也不被挡在门外。
5. 作为学生，我想要页面告诉我**这两根线接到板子的哪两个脚**，以便我照着插线。
6. 作为学生，我想要板上**直接给应答 / 不符的判定**，以便我区分"器件没应答（线 / 供电）"与"应答了但身份寄存器不对（型号不对 / 寄存器填错）"。
7. 作为学生，我想要**没有期望值时它如实说"只回显、不判"**，以便我不把"读到一个数"当成"这件是好的"。
8. 作为学生，我想要自建件在结果里**有自己的标记、跟库内 [专精] 件分开**，以便我知道哪些结论是库内验证过的、哪些只是"按我给的地址试了一下"。
9. 作为学生，我想要同一件**下次不用重填**（存在工具的数据目录里、可再选），以便我第二次测它时直接勾上。
10. 作为学生，我想要自建件也能**不重烧复测**（串口命令），以便我一边动线一边看应答。
11. 作为学生，我想要**这一次用的定义 + 资料留在这个检测工程目录里**，以便过几天回头看还知道当时凭什么填了那个地址。
12. 作为学生，我想要**资料会被送到 AI 抽取**这件事在页面上被明说，以便我不在不知情的情况下把手册传出去。
13. 作为学生，我想要自建件能与库内器件**同时测**（比如"地猛星 + 库内 OLED + 我这件"），以便一次上板把该验的都验了。
14. 作为学生，我想要**非 I2C 的自建件也被如实处理**（给清单与排障、明说不生成探测程序），以便我不去期待一个不存在的能力。
15. 作为维护者，我想要渲染出的探测代码**只调用 `i2c_probe` 头里真实存在的函数**（构建期守卫），以便它不会像幻觉调用那样在编译期才炸。
16. 作为维护者，我想要探测代码**不出现引脚字面量**（一律走宏名），以便它与既有的引脚配置/改绑机制不脱钩。
17. 作为维护者，我想要新模块满足库内既有不变量（内部件身份、参考关联豁免、默认布局共享白名单、真编译矩阵），以便它不会让既有守卫变红或悄悄绕开。
18. 作为维护者，我想要两平台的探测程序**真编译 0 error / 0 warning**，以便"能生成"与"能编译"不是两件事。

## 实现决策

**支点模块 `i2c_probe`（库内新增，纯总线原语）**

- 职责只有三件：`i2c_probe_init()`（按需初始化总线）、`i2c_probe_ping(addr7)`、`i2c_probe_read_reg(addr7, reg8)` → 读回一个字节（失败有明确返回值）。**不含任何器件语义**（不知道 WHO_AM_I 是什么），符合「模块 = 纯驱动切片」的既定边界。
- stm32 实现 = **位操作软 I2C**（照 aht10 / sht20 先例自实现，不依赖母版 ml_i2c），引脚用**自己的一组宏**，默认 **PA6/PA7**——库内六件软 I2C 已共挂这条总线，不同地址可共存。母版 `pin_config.h` 加一组宏（库内每个软 I2C 件都有自己那组，属常规；**不用母版 ml_i2c 的 PA11/PA12：那两个脚在蓝药丸上是 USB DM/DP**，库内已有明确先例写着"不用母版 ml_i2c：引脚硬绑 I2C_GPIO=PA11/PA12（USB 共用脚）"）。
- mspm0 实现 = **硬件 I2C**（`I2C_0_INST` + SDK 的 `DL_I2C_*`，照 ml_mpu6050 的 `mpu_port.c` 先例），脚 = 母版 syscfg 已定的 **PA0(SDA)/PA1(SCL)**。该实例的裁剪判据是"消费者 ∩ 选中集"，所以**必须把 `i2c_probe` 登记成 `I2C_0` 的消费模块**，否则它会被裁剪掉、`I2C_0_INST` 不存在。
- 引脚在 manifest 里如实声明（stm32 带宏、mspm0 走 SysConfig 不带宏），因此**接线表/工程 README 的接线行照既有推导自然出现**——页面与工程同源这条不变量不破。
- 平台已知代价如实写在模块说明与检测页：mspm0 的 PA0/PA1 与**板载 LED 共用**（通信期间 LED 微闪，板定义已注明），且 PA0 的板载上拉位未焊（依赖模块板自带）。

**自建件的定义（数据目录，目录即数据库）**

- 落点 = **工具数据目录**（`<配置目录>/hwcheck_devices/<id>/`）：`device.json` + `materials/`（用户提供的资料副本）。**不进 `library/`**（那是产品库：会 git 提交、随发布包分发，用户自建的东西不该混进去，也不该被别人下载到）。
- 字段（全部是**事实**，没有一项是推导）：`id`（`mine_` 前缀的 slug 形；与库内 slug 冲突时**页面当场拦下并要求改名**）、`name`（人读名）、`bus`（词表：`i2c` / `spi` / `uart` / `onewire` / `analog` / `gpio` / `other`）、`address`（**7 位**地址，0x08–0x77；`bus=i2c` 必填）、`register`（身份寄存器地址，8 位，可选）、`expect`（期望读回值，8 位，可选；填了它才谈得上"判定"）、`notes`（可选，进清单与 AI 排障上下文）、`created_at` / `updated_at`。
- 页面对地址做**双向显示**（7 位 + 派生的 8 位读/写形式），因为手册里两种写法都常见（0x68 与 0xD0）——这是填错地址最常见的一处坑。
- 件**与平台无关**：同一件在两个平台上都能测（总线脚由平台决定，地址与寄存器是器件的事实）。
- 库里官方模块的默认总线脚是平台事实，页面直接抄（stm32 = `i2c_probe` 声明的 PA6/PA7；mspm0 = PA0/PA1）。

**资料 → 事实草稿（AI 的唯一新增用途）**

- 入口：贴文字 / 传文件（PDF / 图片），文件走**既有的抽取通道**（文本抽取 + 视觉描述），拿回来的文本再交给一次 LLM 调用抽成**草稿 JSON**。
- 草稿形状严格限定在自建件字段 + 每条事实的**原文出处片段**；抽不到的字段**留空并说明"手册里没找到"**，绝不编。**草稿一律不落盘生效**：用户确认/修改后保存的才是定义。
- AI **不写代码、不生成判据、不决定探测动作**——探测程序永远由确定性渲染器按确认后的事实产出。
- AI 不可用 / 抽取失败 = **降级为纯手填**，流程不阻断（照既有"建议不可用不阻断"的口径）。
- 页面上明说：**资料会被送到 AI 通道**做抽取（本机不训练、不外传是模型服务方的事，但用户有权知道这件事会发生）。

**探测程序怎么渲染（确定性，零 LLM）**

- 新的域模块 `hwcheck_custom.py` 拥有这一半：自建件定义 → 探测小节（C 语句）+ 上板清单 + 页面文案。渲染输入**只有确认后的字段**。
- 每件的小节形态：
  - 有输出通道才渲染（与既有"没有通道就不假装测过"的口径一致）；
  - 小节头 + `hwcheck_detail`「自建件：按你确认的事实探测」；
  - ping 地址 → `hwcheck_verdict(...)`：板上判定 + 失败时给排查话术（供电 / 上拉 / 线序 / 地址写法）；
  - 有 `register` + `expect` → 读寄存器并与期望值比较 → 判定；
  - 有 `register` 无 `expect` → **读回值只回显**（十六进制），并明说"没有期望值可比，只回显"；
  - 无 `register` → 只 ping，并明说"这一趟只验了应答"。
- **只读**：渲染器不产生任何写寄存器调用；这条用结构守卫钉住（渲染出的调用集 ⊆ `i2c_probe` 接口里的读侧函数）。
- **无引脚字面量**：所有脚一律走宏名 / 模块参数，绝不出现 `PA0` / `Pin_11` 这类字面量（生成门禁明文拒绝引脚字面量）。
- **按需渲染**：与既有 04/05/07 三张口径一致——没有判定项时不留死函数、没有探头时不留"未判定"档，验收线是两平台真编译 **0 error / 0 warning**。
- 顺序：库内件（bring-up 件在前）→ 自建件排最后；标注用**单独一个词**（「自建件：按你确认的事实探测」），**不冒充 [专精]**。
- 复测：自建件也进串口命令台（字符分配与冲突判据沿用既有单源；页面显示该敲哪个字符）。
- 生成主程序时的模块集：有自建件则自动带上 `i2c_probe`（框架 led/delay + 通道 + 库内器件 + `i2c_probe`）。**自建件本身不是模块、不进 slugs**（它没有 manifest；库外 slug 会在生成链上游被 `UnknownModuleError` 拒），它是数据 + 一段渲染出来的代码。

**落档与回读（自解释 + 可复现）**

- 生成时把**本次用到的自建件定义快照 + 资料副本 + 抽取草稿**写进检测工程目录（`custom_device/<id>/`）：过几天回头看，清楚知道当时凭什么填了那个地址。
- 上下文清单记下本次用到的自建件 id；**回读以工程内的快照为准**（用户之后改了或删了"我的器件"不影响已生成的工程），页面同时标出它来自哪一个「我的器件」条目。

**AI 排障（既有能力的扩展，不是新链路）**

- 排障上下文新增一段「自建器件事实」（id / 名称 / 地址 / 寄存器 / 期望值 / 备注 / 本次是否与库内件共总线）。
- **事实白名单同步扩容**：自建件的 id / 名称 / 地址必须进白名单，否则模型一提它们就会被"说了本次上下文里没有的东西"当场拒收（既有事实约束查表的必然要求）。
- 兜底建议与"检测没过是正常结果"的出口照旧。

**端点与载荷**

- 「我的器件」CRUD：列出 / 新增（按 id 幂等更新）/ 删除。
- 资料草稿：一段文本（或既有抽取通道的结果）→ 草稿 JSON（形状校验在域层，模型输出不合契约即拒收重问，仍不行则降级为"手填"）。
- 既有的预览 / 生成 / 回读 / 排障端点载荷新增自建件字段（缺字段 = 没有自建件，向后兼容）。

**测试决策**

- **最高既有缝 = 域层纯函数**（自建件定义校验、探测小节渲染、清单文案、标注词），内存直测、零 LLM——照 `hwcheck*.py` 既有先例。
- **端点**：TestClient + 假 LLM 桩（草稿抽取、生成、回读、排障四条）。
- **守卫（构建期大声失败的那几条）**：① 渲染出的调用 ⊆ `i2c_probe` 接口清单；② 渲染产物里**没有写寄存器调用**、没有引脚字面量；③ 自建件标注与 [专精] 标注不互串；④ 自建件 id 与库内 slug 的冲突判据。
- **真编译**：两平台各跑真编译矩阵（stm32 走 UV4、mspm0 走 gmake），验收线 0 error / 0 warning——照既有编译矩阵口径。
- **前端**：fx 纯件单测进前端门禁；检测页的真实浏览器验收（新卡片、表单、资料上传、生成后面板）进浏览器门禁。
- **反证要求**：每条新守卫都要有一次"停用后用例必须变红"的实测（本仓库既有纪律）。
- **真机口径**：编译绿 + 用户照清单上板跑一轮并把现象回填；**没跑过就写"未上板"，不假装**。

## 范围外

- **写寄存器 / 读数据 / 自动生成驱动**（AI 依资料写驱动入库那条路 = 先前的选项 D，另立条目）。
- **非 I2C 的探测程序**（SPI / UART / 单总线 / 模拟类）：这一版只有清单 + AI 排障。
- **自建件的引脚配置**（不能改绑：固定走平台既有总线），以及 16 位寄存器地址 / 多字节寄存器 / 页切换类器件。
- 自建件与官方模块库之间的同步（"转正入库"）。
- 检测结果云端同步 / 跨机迁移。
- mspm0 `I2C_0` 之外的第二条硬件 I2C 总线。

## 补充说明

- **命名**：新模块 `i2c_probe`；数据目录布局 `hwcheck_devices/<id>/`；标注词「自建件」。**不与「自检」（自检冒烟）重名**，也不碰「预算」这类已占用词。
- **与既有 ADR 的关系**：检测程序 = 确定性渲染 + 库内数据（ADR 0016）不变——本特性把"库内配方数据"这一半扩成"库内配方数据 **或** 用户确认的事实"，AI 仍然不产出一个字节的检测程序。`i2c_probe` 不持器件语义，符合「模块 = 纯驱动切片」（ADR 0009）。这条扩展值得在 ADR 0016 上补一笔（另开工单或在实施工单里落）。
- **库内新增模块要满足的既有不变量**（实施时逐条核）：身份字段判据（内部件，不做购买链接要求）、参考关联映射或显式豁免、默认布局共享白名单（与六件软 I2C 共挂 PA6/PA7）、真编译矩阵、版面/来源守卫。
- **一条与既有决策相反的事实**（已按实测更正）：母版 `ml_i2c` 的 PA11/PA12 在蓝药丸上是 USB DM/DP，库内软 I2C 件明确不用它——所以探测支点也不用它，改自己一组宏 + PA6/PA7。
- **一条被后续工单推翻的决定（工单 12 更正）**：本 spec「实现决策」里"id（`mine_` 前缀的 slug 形）"沿用了 02 的 id 文法（`entry_store.SLUG_PATTERN`，允许连字符）。工单 12 实测发现 id 会被原样拼进检测程序的 C 函数名（`hwcheck_custom_<id>`），连字符拼出来整份工程编不过——id 文法已收紧为 `mine_` 前缀 + C 标识符可用字符（`my_devices.DEVICE_ID_PATTERN`，判据单源），不再复用库内键文法。上文"id（`mine_` 前缀的 slug 形）"按此文法读。
