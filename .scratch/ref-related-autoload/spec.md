# 参考例程相关性自动利用（ref-related-autoload）

## 问题陈述

用户在参考文件库录入了 152 条资料（含约 130 条 TI MSPM0 SDK 官方例程：ADC12-* / UART-* / SPI-* / I2C-* / CAN-* / GPIO-* / DMA-* / Flash-* / 定时器-* / 比较器-* / 运放-* / 低功耗-* / RTC-* / NVIC-* / SysTick-* / 塔克R3-* 等），但生成工程时 AI 几乎从不利用这些资料：推荐阶段 AI 每次只点名 0-1 条参考，TI 例程从未被选中过。

根因：AI 可见的候选清单只由「题面编号锚定 ∪ 选中模块套件（kit）锚定」装配，全库 152 条中仅 6 条被锚定（4 条题面锚定 + 2 条 kit 锚定），其余 146 条（含全部 TI 官方例程）永不进候选——除非用户手动勾选 reference_ids。未锚定条目成为「死库」；用户直觉正确，资料利用率约 0。当年录入时「保持未锚定」的审计决策语义合理（通用外设例程不绑定某道赛题），问题不在锚定本身，而在系统没有任何通道让未锚定条目自动进入候选。

## 方案

1. **推荐阶段候选扩容**：按题面文本 + 外设关键词词表做相关性匹配，把命中的未锚定参考文件（标题 + 一句话简介）加入 AI 候选清单（新增来源标注「与题面相关」）。模型照旧点名才回读全文——两级注入机制不变，无新增全文成本；每轮成本增量约 2-5K token，候选上限 15 条。
2. **骨架阶段自动注入**：按选中模块 slugs 自动关联 top-N 条相关例程，作为参考实现注入骨架提示词（与手动选参考同一通道，受既有 40KB 参考段预算按篇均分截断），骨架主函数可直接参照官方写法；上限 4 条。
3. **相关性 = 确定性纯函数**：单源词表（英文外设名/缩写 + 中文外设词 + 模块 slug 映射）、条目标题 token 化、得分 > 0 才入选、降序截断、平台过滤沿用。词表不命中 = 零增量（与现状逐字节一致）。
4. **不动锚定语义与审计**：相关性候选是「锚定 ∪ 相关」的补充项，不是替换项；锚定命中优先，按 id 去重。

## 用户故事

1. 作为参赛学生，我生成未锚定赛题（如 2026A~H 非配套题、粘贴题面 no-topic）时，AI 的候选清单里能看到与题面外设相关的 TI 官方例程，以便 AI 点名利用——此前这些赛题候选为 0 条。
2. 作为参赛学生，我生成骨架时，与所选模块相关的官方例程全文自动注入，以便 main.c 参照官方写法而非从零开写。
3. 作为参赛学生，我在推荐结果里能看到 AI 点名的多条参考文件，以便了解 AI 利用了哪些资料并做增删（沿用既有 reference_ids 勾选交互）。
4. 作为参赛学生，no-topic 场景（粘贴题面未识别出赛题编号）同样生效——相关性基于题面文本，不依赖编号识别。
5. 作为维护者，相关性判定是纯函数、词表单源、确定性排序，便于测试与扩展，保证不会把无关例程灌进上下文（得分 0 不进）。
6. 作为维护者，成本可控：推荐 15 条上限、骨架 4 条上限、词表不命中零增量；generate 阶段行为不变（缺省关闭，向后兼容）。
7. 作为维护者，最坏形态请求预算仍有确定性上界：候选清单段新增 wire 预算兜底（与全文段同款截断机制 + 标注），结构测试同步核算。

## 实现决策

- **构建模块**：
  - 参考库域新增相关性匹配纯函数：词表（PERIPHERAL_TERMS 英文/中文词项 + MODULE_PERIPHERAL_TERMS 模块 slug → 词表项映射）+ 条目标题 token 化 + 计分排序 + 平台过滤 + limit 截断。
  - 装配域（赛题上下文解析）把相关候选并入既有候选装配（锚定 ∪ 相关，锚定优先、按 id 去重），新增 `related_limit` 参数（缺省 0 = 关闭）。
  - 推荐提示词段：候选清单来源标注新增 related 值（沿用既有 auto/manual 的 note 机制），清单段新增 wire 字节预算兜底（沿用全文段 `_fit` 同款截断 + 标注）。
- **接口契约**：
  - 匹配函数：`related_references(reference_root, *, topic_text, slugs=(), platform="", limit=0)` → 按得分降序的参考条目列表；limit 0 = 返回空（缺省关闭）；topic_text 为候选来源（识别到历史赛题用库内题面全文，no-topic 用粘贴题面）。
  - 装配函数新增 `related_limit` 参数透传：recommend 传 15（仅进候选清单，模型点名才回读全文）、skeleton 传 4（自动全文注入）、generate 不传（0 = 不注入，与现状一致）。
  - 候选清单来源标注：`related` = 「与题面/所选模块相关，自动列出」（沿用 note 机制，prompt 清单行按 source 区分）。
- **匹配规则**（决策性细节）：
  - 词表项分两类：英文外设名/缩写（全小写，如 adc/uart/spi/i2c/can/gpio/dma/flash/rtc/nvic/systick/timer/pwm/比较器/运放/lcd/oled/key 等）与中文外设词（定时器/串口/按键/蜂鸣器/舵机/电机/循迹/摄像头/视觉 等）。
  - 题面命中：小写子串扫描 + 英文词表项按字母数字边界独立出现（`[^a-z0-9]` 前后边界，防 canmv 命中 can、serial 粘连等误报）；中文词表项子串直接命中。
  - 条目侧：标题按 `[-_\s()（）]` 拆分 token，数字字母连体为单 token（adc12 是一个 token）。
  - 得分：题面命中的词表项 ∩ 条目 token 集合——term 为 token 前缀也算命中（adc → adc12）；得分 > 0 才入选；无 slug 映射的外设（spi/i2c/can/timx/gpio/dma/comp——库里无对应模块 slug）自然只能靠题面词命中。
  - 排序：得分降序 → 平台匹配优先 → id 稳定序；limit 截断。平台过滤沿用既有规则（非 any 平台只收匹配/any 条目）。
- **骨架全文注入**：自动关联条目并入 topic.references 后，走既有「references 全量回读 + 40KB 均分截断」通道，无需新通道。
- **架构决策**：保持两级注入不变（候选清单 → AI 点名 → 回读全文），只扩候选来源、不扩注入深度；generate 阶段不注入参考（沿用既有决定，本特性不改）。

## 测试决策

- 只测外部行为：词表命中/不命中、边界反例（canmv 不命中 can）、platform 过滤、limit 截断、slug 映射命中、排序与去重、候选清单来源标注、recommend 与 skeleton 传入不同 limit、清单段 wire 兜底截断标注。
- 既有 seam（不再新增）：
  - 参考库域单测（纯函数：词表/计分/排序/过滤/limit）。
  - 装配域单测（related 并入、去重、anchored 优先、related_limit 透传）。
  - prompt/预算结构测试：worst-case 结构测试以「15 条最坏清单 + 64KB 全文 + 历史 20 条 + 题面 4000」为新最坏形态重新核算（**2026-08 定案：余量由 ≥ 6KB 收紧为 ≥ 2KB**——真实库简介 194-348 字/条，15 条清单段实测 4.7-5.1KB，6KB 边界保不住；清单段加段级预算 REFERENCE_SUGGESTIONS_MAX_WIRE_BYTES=4096 整段截断，新最坏 ≈128.2KB 距 2KB 边界余 ~830B。详细推导见工单 02「预算定案」）；骨架侧以「4 篇全文」核算。
- 领域回归：词表不命中场景与现状逐字节一致（断言零增量）。

## 范围外

- 不改锚定语义与「保持未锚定」审计决策。
- 不改 generate 阶段（不注入参考文件）。
- 不新增 UI 结构：候选清单/参考展示跟随既有渲染；来源标注跟随既有样式。
- 不做语义/向量检索与模型依赖（词表匹配足够，避免新依赖与新模型调用）。
- 不动既有预算常量设定（40KB/64KB 沿用；15 条清单经清单段 wire 兜底封顶）。
- 不重写/扩充库内条目标题与 description 内容（token 化按现状标题工作）。

## 补充说明

- 用户已确认：方向 = 「完整方案：推荐清单扩容 + 骨架自动关联」；预算 = 「可接受，控制条数上限」（每轮成本增量约 2-5K token）。
- 预算核算：候选清单段现状无任何截断上限（逐行 `- id: title —— description`），15 条最坏形态约 +4.7-5.1KB wire（真实库简介 194-348 字/条，远超 80 字/条的初始估算）；既有 worst-case 结构测试余量仅 785B（最坏实测 124143B vs 124928B 触发点），故清单段必须新增 wire 预算兜底（带截断标注），新最坏形态重新核算。**2026-08 修订 4 定案：余量 ≥ 6KB 不可维持，收紧为 ≥ 2KB**（红证先行实测校准，见工单 02「预算定案」）。
- **实现期巡检补丁（合并入工单 02，详见其「巡检补丁」节）**：词表补「巡线」「cam」；新增同义词组机制 PERIPHERAL_SYNONYM_GROUPS（题面命中组内任一词 → 整组激活 → 条目侧组内任一词命中计 1 分，按语义组计分）：（循迹，巡线）、（摄像头，camera，cam）；英文词项粘连中文尾巴的 token 内独立出现规则。这些解决了真实库三个巡线条目标题用「巡线」、题面写「循迹」的桥接失败与「C7-3-4L ESP32-CAM开发板资料」的 cam 命中。
- 模块库现况：无 spi/i2c/can/timx/gpio/dma/comp 模块 slug，这些外设的 TI 例程只能靠题面关键词命中——词表覆盖这些术语是本特性价值主体。
