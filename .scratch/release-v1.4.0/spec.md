## 问题陈述

线上最新仍是 **v1.3.1（2026-09-27）**，而 `main` 领先 `origin/main` **75 笔**（其中实质提交 38 笔，
其余是 post-commit 自动补的 CHANGELOG）。这四批改动**任何发布包里都没有**，用户在 v1.3.1 上仍会遇到：

1. **观感是"各页一套"**（`ui-density` 检测页轮 + `ui-density-sitewide` 全站推广轮要解决的）：
   `index.html` 样式块里 **387 处裸 px 字号 / 13 种取值**、**209 处完整整圈描边**、351 处裸令牌间距——
   检测页之外那十三个页签各写各的，同一个"正文"在 A 页 13px、B 页 14px。
2. **更新面板里的体量数字与实测不符**（`backlog-closeout/01`）：页面写着「6.2 GB」「5 GB+」「约 1 GB」，
   实测是**约 800 MB / 约 0.7 GB / 约 800 MB**。
3. **MQ 系九件模块的说明里有一句手册上没有的「预热 3-5 分钟」**（`backlog-closeout/02`）。
4. **记录写并发不稳**（`record-write-hardening`，用户看不见）：四个域的"固定临时名 + 无锁记录写"
   在并发/强杀下可能留半截 JSON 或互相盖掉。

## 方案

**发 v1.4.0（次版本 +1：界面大改），两件套都发**（小发版四件套 + 完整包四件套，同一个 Release）。

用户可观察的结果：打开工具（已装用户点「设置 → 软件更新 → 检查更新 → 一键更新」）之后——

- **全站一套字号档位（20/16/14/13/12/22 六档角色）、一屏一层完整描边、间距走令牌**：
  十四个页面观感统一，重点靠"左条 + 字重"跳出来，而不是靠框套框；
- 更新面板里的体积数字改成实测值；
- MQ 系九件模块的说明退回有据措辞。

新用户走完整包拿到同一份内容。**不带资料库变更**（不发资料库增量包）。

## 用户故事

1. 作为学生，我想十四个页面看起来像同一个工具（同一套字号档位与间距），而不是每页一个样。
2. 作为学生，我想一屏只有一层完整描边，重点（分组、警示、当前项）一眼看得见，而不是框套框。
3. 作为学生，我想页面上的体积数字是真的（我按它判断要下多久）。
4. 作为学生，我不想在模块说明里读到手册上没有的参数（"预热 3-5 分钟"）。
5. 作为同时开两个窗口操作用户，我不想因为并发写把记录写成半截 JSON。
6. 作为维护者，我想这一版的发布产物可核对（zip 实算 sha256 = `sha256.txt`、`00-START-HERE.txt` 在场、
   `removed.txt` 非空），且发完当场把第 0/3 节的账改对。
7. 作为维护者，我想这一版**先在沙箱「模拟用户机」上真机验收过**（真进程 + 真浏览器 + 真数据目录），
   而不是只拿"本机测试全绿"当发货依据。

## 实现决策

- **版本号 `v1.4.0`**（用户拍板；`docs/agents/releasing.md` 的 SemVer 表：界面大改 → 次版本 +1）。
- **两件套都发**：完整包是新用户唯一的安装入口（README 只指它一个文件），必须在场。
- **本版不带新代码**：只做「版本号同步 + 门禁与读数复核 + 沙箱真机验收 + 打包发布 + 账本」，
  四张单见本目录 `issues/`。
- **读数每轮重跑**（`ui-density-sitewide` 轮固化的纪律第 1 条）：发版前的三套门禁与全站读数
  **一律本轮现跑**，不引用上一单的照片。
- **浏览器门禁单独跑**（同一轮纪律第 2 条）：`node --test --test-concurrency=1 "tests/browser/*.spec.mjs"`
  先跑，再跑全量 `pytest -n auto`。
- **沙箱真机验收**（第 1 节）：从**当前工作树**造一份干净「模拟用户机」（`make_sim_sandbox.py`，
  工具根 `Desktop\firstep-sim` / 数据目录 `~\.contest_generator_sim`）、**8020** 起真进程
  （`sim-run.py`），用真浏览器按计算样式核对本轮定的档位与间距、并核对更新面板的体量文案；
  收尾收 8020、查残留进程，**结论当场回写 `local-environment.md`**。
- **工作树必须干净**：两个打包器都拒绝脏工作树，而「工单标 claimed / resolved」与读数落盘
  本身就是 tracked / 新增文件变更——所以**先打包打 tag，再落发布后的账本**
  （账本提交跟在 tag 之后，与 v1.2.2 / v1.3.0 / v1.3.1 三轮同款）。
- **推送必须钉 IP**：本机 hosts + 本地代理会冒充 github 域名（`curl` 200 也不算数）。
  按第 0 节「本机网络事实」用**有效键** `-c http.curloptResolve=github.com:443:<验过的 IP>`
  **并加** `-c http.postBuffer=524288000`（默认 1 MiB 之上走 chunked，中间人更容易掐）。
- **不重跑真机 drill**（`drill-01` 起点 v1.1.1 的那支是 v1.2.2 那一轮的验收）：本版以
  **沙箱真机验收 + 发布产物自洽**为准，如实记账。
