## 问题陈述

### 一、上一轮记的那三个对比度数字，口径就是错的

`ui-density-sitewide/12`（浅色人眼复核）量过三档徽章：`.ref-none` **6.11** / `.ref-kit` **5.19** /
`.ref-topic` **3.39**。量具 `probe-12-measure-light.mjs` 的 `bgOf()` 会**跳过半透明背景**、
沿祖先链找第一个不透明底——可徽章**自己那层 `--accent-dim` 淡底是画在元素身上的**。
按真实合成底重算：`.ref-topic` = **2.95**、`.ref-kit` = **4.38**、`.ref-none` = **4.50**（正好压线）。
**三个数全部偏乐观**，而"浅色下只有 accent 小字越线"这个结论正是从它们来的。

### 二、不是一处，是六族、99 处（浅色）；暗色也有 16 处

机械清单（同一条规则里既有 `color:` 又有 `background:`，两主题各算一遍；共 **376** 对）——
浅色 **188 对里 99 对低于 AA**，形状全部一样：**语义色压在自己的淡底上**。

| 族 | 现比值 | 处数 | 暗色同族 |
|---|---|---|---|
| `--ok-bright` #2da44e on `--ok-dim` | **2.74** | 12 | —— |
| `--accent` #0096c7 on `--accent-dim` | **2.95** | 25 | 9.77 ✅ |
| `--accent` on 淡底 `#eef1f4` | 2.99 | 6 | ✅ |
| `--accent` on 白 / 白字 on `--accent` 实心 | 3.39 | 11 | **1.77** ❌（两处硬写 `#fff`） |
| `--on-accent` on `--accent-dark`（hover 实心底） | 3.59 | 3 | ✅ |
| `--warn` 4.17(19) / `--danger` 4.40(13) / `--info` 4.38(13) / `--ok` 4.33(3) / `--purple` 4.29(1) | 4.17–4.40 | 49 | `--danger` 4.35(13) ❌ |

暗色不达标 **16** 处：两处 `#fff` 压在 accent 实心按钮上（**1.77**，代码页发消息钮与选区浮标）、
`.stepper .step.done .dot` 2.54、`button.danger:hover` 3.35、`.rel-tag.tag-perf` 3.60、
以及 danger 族 13 处 **4.35**（差 0.15 过线）。

### 三、这条线也没有机器守卫（与描边那条线一模一样的病）

守卫 `tests/js/css-tokens.test.mjs` 管的是"**裸色必须令牌化**"——它保证颜色来自令牌，
**一个比值都不算**。于是今天任何人往样式块里写一条 `color: var(--warn)` 压在自己的淡底上，
没有任何东西会红；`--accent` 换一个更浅的值也一样。

### 四、"去框留淡底"在浅色下只有 ×1.065（暗色是 ×1.17）

`.recent-wf-summary` / `.update-result` / `.materials-progress` / `.distill-progress` / `.release-body`
这几处**没有左条**，浅色下与页面底只差 ×1.065，属"盯着看才分得出"；**107 条规则**用 `--panel-2` 当底。

### 五、渲染方与代码配色族各有一笔没人看的账

- `static/js/**` 里 **19 处内联令牌取色**（`fx/task.js` 的"已完成 N 步"用 `--ok-bright` 压卡片底
  ≈ 3.3 ❌、`fx/flash.js` / `ui/generate-pins.js` 的状态文字等）+ 5 处含裸值/transparent 的。
  样式块面干净**不代表**渲染方干净（描边那轮的 10 处内联框就是先例）。
- `--tok-*` 语法高亮族：浅色代码底上 **8 / 10 个令牌低于 4.5**（`--tok-kw` / `--tok-tag` 仅 **3.19**），
  叠上搜索命中 / 选区那几层 accent 合成底后**只剩 `--tok-fn` / `--tok-const` 还在 4.8 一线**。
  **改它 = 改代码长什么样**，是另一件事，本轮**只量不修**。

## 方案

一句话：**一边把浅色调色板修到过 AA，一边把"过不过 AA"变成可对账的数据**——
守卫按令牌现值**现算**每一对的 WCAG 比值，达标的必须达标、记账的必须与冻结值一致。

1. **引入 `--accent-text`**（浅色压暗一档、暗色 = `--accent` 同值 ⇒ **暗色零变化**）：
   `--accent` 继续用于描边 / 淡底 / 图标 / 实心按钮底，**当文字色的地方一律改走 `--accent-text`**
   （85 处 `color: var(--accent)`）。
2. **六族一起修**：每族的"文字色 × 自己的淡底"在**四种底**（页面底 / 卡片 / 加深后的淡底 /
   dim 合成底）上全部 ≥ 4.5，且留 **≥ 0.15 余量**；淡底 alpha 与文字令牌都可以动，取改动小的一侧。
3. **`--panel-2` 加深**（浅色 ×1.065 → **×1.18**，与暗色 ×1.17 同水平）：
   `--muted` 压上去仍 ≥ 4.5，且不碰字号 / 描边层级（那是上一轮定过的）。
4. **暗色 16 处顺手修掉**：两处硬写 `#fff` 改走 `--on-accent`；danger 族微调过线。
5. **守卫加两条腿 + 一张例外表 + 跨语言镜像 + 合成红证**（住在既有 `tests/js/css-tokens.test.mjs`，
   **不另起文件**）：
   - **腿⑧（样式块面）**：机械抽取所有「同规则 color × background」对（两主题）→ 现算比值 →
     **不达标的每一条都必须在例外表里登记过**（`debt` / `nontext` / `skip` 三类，各带理由）；
     外加一张**显式补充表**管机械抽不到的已知对（`--tok-*` × 代码底、焦点环 / 语义左条 × 淡底）。
   - **腿⑨（渲染方面）**：`static/js/**` 里 19 处内联令牌取色逐条登记（`[文件, 锚点, 令牌, 假定底, 类别]`），
     双向对账 + 同一套比值判据。
   - **跨语言镜像守卫**（`tests/test_contrast_mirror.py`）：Python 探针与 JS 守卫的常量与公式必须同源
     （阈值 4.5/3.0、大字判据 24px / 18.66px+bold、亮度公式、合成公式）——照
     `test_border_register_mirror.py` 先例：两侧漂移会造出"**腿绿而读数红**"这类最难查的假账。
6. **读数是可复算的照片**：静态清单（本目录 `probe-01`）+ **渲染量具**（沿用
   `ui-density-sitewide/probe-12-measure-light.mjs` 的框架，跨十四页量**真元素**）+ 浅暗两套整页截图。

### 二、守卫的数据模型（腿⑧，**三面**）

> **实施期修正（01 单，2026-09-30）**：下面这三面是 01 单**实施 + 双轴评审**之后的最终形状。
> 与 spec 初稿的两处差异，都在「补充说明 · 实施期口径修正」里写清了为什么。

- **机械面**（不登记，现算）：`<style>` 块里同一条规则同时声明 `color:` 与 `background:` 的，
  取两侧令牌 → 两主题各算一遍 → 按该规则的 `font-size` / `font-weight` 定阈值
  （≥24px，或 ≥18.66px 且 bold ⇒ 3.0；否则 4.5；未声明 = 继承 14px = 小字）。
  配对数**冻结**成 `CONTRAST_PAIR_COUNT`（376）：改令牌值不动它，增删这类规则才动。
- **族面**（`CONTRAST_FAMILIES`）：机械抽不到的**族**——底来自祖先或图形属性。
  每族取**最坏格**参与判据（逐格矩阵在读数里）。两张：`--tok-* × 代码底（含 4 层 accent 合成）`、
  `--accent 焦点环 / 语义左条`。族表的第三格是**阈值档位**（`text` 4.5 / `nontext` 3.0）。
- **令牌面**（`CONTRAST_TOKEN_BASES`）：**无底规则里的文字令牌**（`color:` 有、底在基类或祖先）。
  584 条含 `color:` 的规则里 **390 条**是这样——给其中任何一条新加 `color: var(--warn)`，
  前两面都不会红（01 单双轴评审实测的缺口）。做法：把"当文字色用的令牌"逐个登记
  （令牌字面 + **人判的假定底** + 档位 + 理由），表外的令牌出现即红；
  空底列表 = 静态判不了（`inherit` / 未定义令牌 / 已由族面覆盖），登记理由后跳过判据。
  ⚠ 这一面是**令牌级**、不是选择器级（同一个令牌在不同选择器上可能压在不同底上）——
  选择器级的精确配对归前两面。
- **底的口径**（**本轮更正的那一条**）：底 = **元素自己那层背景合成后的颜色**
  （`rgba` 淡底要叠到祖先不透明底上），**不是**祖先底。合成基色 = `--panel`（卡片）。
- **例外表**（`CONTRAST_EXCEPTIONS`，**只增不减要审批**）：`[主题, 认人键, 类别, 理由, 冻结比值]`，
  **两类**：`debt`（明确记账的不达标，比值必须与冻结值一致）、`skip`（静态口径不适用：
  `::selection` 这类反白块、`inherit`、未定义令牌）；
  认人键三形态：选择器（机械面）/ `族：<标签>`（族面）/ `令牌：<字面>`（令牌面）。
- **双向对账**：盘上每个不达标项 ⊆ 例外表；例外表每条 ⊆ 盘上（三面各按自己的认人键）。
  形状自检同描边那轮（类别在表里、每类至少一条、档位词表合法）。

### 三、守卫的腿⑨（渲染方面）

`JS_CONTRAST_REGISTER` = `[文件, 锚点, 前景令牌, 假定底, 类别]`，**19 条**（`probe-02` 清单）。
锚点取**该声明所在行的可认片段**（令牌名 + 附近类名），**不取行号**（描边那轮 02 单的纪律）；
假定底 = 该内联块被插进的那层卡片底（`--panel`），明写成假设。
反向：盘上每处内联令牌取色 ⊆ 登记表。

### 四、跨语言镜像与红证

- `tests/test_contrast_mirror.py`（照 `test_border_register_mirror.py` 先例）**九组**判据：
  两档阈值、大字判据、亮度公式九个数、`+0.05` 与合成基色、**十三条解析正则**、
  `CODE_LAYERS`、`CONTRAST_FAMILIES`、两套档位词表、`CONTRAST_TOKEN_BASES`；
  外加一条 **`--check` 同源断言**（守卫那张例外表必须等于生成器**现在**算出来的那张）——
  生成器与表之间的漂移**任何一面腿都看不见**（表与盘上仍自洽，只是表不再是生成物的样子）。
- **合成红证**（腿⑧ 的判据是"吃源码文本 → 返回问题清单"的纯函数，故走**内存注入**，
  比"就地改盘 + `finally` 复原"更干净）：令牌改浅 / 新增不达标规则 / 摘掉 debt 登记 /
  债务静默恶化 / 过线仍挂账 / 未知类别 / 掏空类别 / 形状不对 / 重复登记 / 族定义写错 /
  族档位写错 / **令牌面四条**（未登记令牌 / 死条 / 债务恶化 / 档位写错）/ **大字分档四态**
  （小字必红、24px 放行、19px+bold 放行、19px 非 bold 仍红）。
- **反证探针** `.scratch/light-contrast/probe-05-mirror-and-check-red.py`：
  镜像守卫与生成器 `--check` **判不判得红**——八处注入（换基色令牌 / 改切规则正则 /
  改亮度系数 / 改档位词表 / 改令牌表 / 改族表底列表 / 表里多一条假登记 / 改坏冻结值），
  每处"真改盘上文件 → 跑判据 → 断言红 → `finally` 复原 → sha256 校验逐字节相同"。

  1. `tests/js/css-tokens.test.mjs` —— 腿⑧腿⑨ + 例外表 + 合成红证（本 spec 唯一的新缝就在这，
     与 `FROZEN_FONT_SIZES` / `PAGE_SCOPES` / `BORDER_REGISTER` 同一处）；
  2. **前端门禁** `node --test "tests/js/*.test.mjs"` —— 改守卫的主证据；
  3. **全量 pytest** `python -m pytest -n auto -q` —— 收口一次（含新的镜像守卫）；
  4. **浏览器门禁** `node --test --test-concurrency=1 "tests/browser/*.spec.mjs"` ——
     本轮改了产品面（`index.html` 令牌块与选择器），**必须单独跑**（那轮纪律 2）。
- **读数**：静态清单探针（本目录，一条命令复算）+ 渲染量具（跨十四页量真元素的计算样式）。
  提交前**每份落盘读数的时间戳必须晚于最后一次改产品面**（那轮纪律 1）。
- **人眼复核**：浅色 + 暗色各一轮整页截图（十四页 + 内容态），逐张 `read_image` 看——
  颜色这类改动**机器只能证"过线"，证不了"好看/不刺眼"**。
- **不许退化的既有读数**：描边那轮的三支探针（14 作用域 0/0、页面尺 0 条、`fullBoxes` 115）
  与本轮的量具基线，改完后重跑对照。

## 范围外

- **`--tok-*` 语法高亮族的配色不改值**（本轮只量 + 登记为 `debt`）：改它 = 改代码长什么样，
  是另一件事、另一轮。
- **不动字号档位 / 描边层级 / 布局 / 间距**：那是 `ui-density-sitewide` 定过的，本轮只动颜色。
- **不动 `BORDER_REGISTER` / `JS_BORDER_REGISTER`**（描边那两张表）：本轮只加腿⑧腿⑨，
  描边两表的读数不许变（`fullBoxes` 115 必须逐字相同）。
- **`.pdf-*` / `.lib-*` 跨页前缀的谓词归属**：sitewide 08 账第 8 条判过"按第一命名页保留现状"，不碰。
- **不碰库数据 / 母版 / 发布包 / `sources/`**：纯前端面。
- **不做暗色主题的重新设计**：只修那 16 处越线，不改暗色调色板。
- **不引入构建期 CSS 检查工具**（stylelint 之类）：判据住在既有守卫里，不新增依赖。

### 三种被否掉的方案（记下来，免得下一轮重走）

1. **只修 accent 一族，其余五族登记为债**：改动最小，但浅色下仍有 60+ 处不达标，
   而"修"的形状与 accent 完全相同——分开做等于把同一件事付两遍复核成本。
2. **靠"减淡底 alpha"修一切**（不动文字色）：淡底会淡到看不见，
   与"一屏一层"的语义相冲（那正是「去框留淡底」这条线本身要解决的问题）；
   而且 01 单的选值探针实测：浅色下**光减 alpha 救不了**（同一个令牌还被当纯文字压在卡片底上，
   降到 α0.02 也不过线）——所以走的是"换文字令牌"。
3. **引入 stylelint / axe 之类的现成工具**：判据离开既有守卫、新增依赖、且它们判的是
   "渲染后的 DOM"——与"令牌表即数据、探针从守卫源码解析"这条既有架构不合。

### 与上一轮（border-guard）的关系

- 两条线**同构**：那边是"哪些框算例外"，这边是"哪些颜色对算达标"——都是把散文清单变成
  可对账的数据 + 双向对账 + 合成红证。
- **本轮的腿编号从⑧起**（描边那轮占了⑥⑦），住在**同一个守卫文件**里（sitewide 轮定的"不另起文件"）。
- 描边那两张表的读数**必须不变**：`fullBoxes` 115 是本轮"只动颜色"的机器证明。
- 本轮**会**动产品面（令牌值），所以与描边那轮的"产品面零改动"不同——
  读数纪律照旧，但基线的含义从"没退化"变成"改前 / 改后两张照片"。
