# 工单：desktop-platform-suffix（桌面同题双平台目录隔离）

## 问题陈述

桌面输出模式下目录名只按赛题命名（历史赛题 = 编号 + 英文短名，如 `2024H_Auto_Car`；粘贴题面 = AI 起的英文短名，如 `Auto_Car`），不携带平台信息。同一赛题常做 STM32 与 MSPM0 两版：换平台重新生成同一题时，同名完整工程触发「请先删除该目录或修改题名」400——用户既不想删旧版，也不应被逼改题名；即使手工改名绕过，桌面也会出现两个看不出平台的近似目录。

## 方案

桌面输出模式下，目录名自动追加平台后缀（`_STM32` / `_MSPM0`）：历史赛题 → `2024H_Auto_Car_STM32` / `2024H_Auto_Car_MSPM0`，AI 题名 → `Auto_Car_STM32`。同题双平台各得其所、互不冲突；同平台同题再次生成仍走既有 400 护栏（generate-conflict-guard 语义不变）。历史已生成的无后缀目录不迁移、不写入——由用户自行删除/改名。

该方案已与用户确认：**一律带后缀，旧目录不管**。

## 用户故事

1. 作为同时做 STM32 与 MSPM0 两个版本的参赛学生，我想要桌面目录名带平台后缀，以便双平台同题目录分开且一眼可辨。
2. 作为换平台生成同一题的用户，我想要不再被「请先删除或改题名」卡住，以便两版并存。
3. 作为手动指定输出目录的用户，我想要目录名不受影响，以便维持既有工作流。
4. 作为同平台再次生成的用户，我想要同名完整工程仍被安全拒绝，以便护栏不破。

## 实现决策

- 平台 → 目录后缀映射单源：新增常量表（照 `PLATFORM_CONFIG_FILE_SUFFIXES` 先例），`stm32 → _STM32`、`mspm0 → _MSPM0`；未知平台大声失败（生成平台只有两值，暴漏漂移优于静默无后缀）。
- 装配点 = 桌面输出目录解析（`_resolve_generation_output_dir`）：历史赛题（`topic_dir_title`）与 AI 题名（`name_topic_english`）两条路径的标题在交给目录裁决（`desktop_topic_dir_verdict`）前拼接平台后缀。目录裁决、互斥锁键（`desktop:<目录名>`）、失败清理、成功聚焦全部自动跟随目录名变化，零额外改动。
- 后缀为纯 ASCII：目录名依旧全 ASCII（不破坏工具链中文路径乱码的既有约束）。
- 400 文案补充一句：同一赛题换平台会自动生成带平台后缀的新目录（提示卡在「请先删除或改题名」的用户）。
- 前端零改动：生成请求已带 platform；结果面板展示的 output_dir 自动为新名。

## 测试决策

- 端到端 seam 照 generate-conflict-guard / desktop-topic-output 先例：注入测试桌面根 + 假 LLM，POST /api/generate 断言最终目录名与响应 output_dir。
- 覆盖：
  - 同题 stm32 与 mspm0 两次生成 → 两个目录（`<题名>_STM32` / `<题名>_MSPM0`），互不冲突、无 400。
  - 同题同平台第二次生成 → 400，目录内容原样。
  - 历史赛题（topic_id）与粘贴题面（无 topic_id）两条路径均带后缀。
  - 手动模式（未勾选桌面输出）→ output_dir 原样使用、无后缀。
- 后缀映射纯函数单测。

## 范围外

- 旧无后缀目录的迁移 / 删除 / 改名。
- 后缀可配置、可自定义。
- 手动输出目录模式的任何变化。
- recent.json / 历史记录的迁移。

## 补充说明

- 升级后桌面出现旧目录（无后缀）与新目录（带后缀）并存属预期行为；同平台同题首次再用无后缀目录名生成时不再命中旧目录（旧目录与新生成目录名不同），旧目录由用户自行清理。
