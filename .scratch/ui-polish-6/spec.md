# Spec：内容区加宽（ui-polish-6）

> 用户反馈：页面左右两侧留白太多（1440 屏内容 980px、两侧各 230px；1920 屏各 470px），中间内容区太窄，希望加宽让显示更美观。用户选定方案 B：生成页特宽。

## 问题陈述

- `main { max-width: 980px }` 全站统一，生成页 12 步流程（信息最密）也被限制在 ~790px 内容宽度（减步骤导航后）；
- 宽屏下两侧留白浪费，内容区文字/表格/代码行被迫换行。

## 方案（用户选定 B）

1. **main 容器**：`max-width: 980px → 1400px`，`padding: 0 16px → 0 24px`；
2. **其它页收窄**：`main > section.page:not(#tab-generate) { max-width: 1280px; margin: 0 auto }`——设置/赛题库/模块库等表格页 1280 居中，避免过宽空旷；
3. **生成页特宽**：`#tab-generate` 吃满 main 1400px（12 步卡片、板图、代码区受益 ~50%）；
4. **响应式回退**：视口 <1400px 时 main 自然全宽（-48px padding）；<1180px 步骤导航照旧隐藏（现有规则不动）；任何宽度无横向滚动条。

## 配套微调

- 生成页卡片 padding 由 `16px 20px` 微调为 `18px 24px`（加宽后避免内容贴边）；
- 步骤导航 158px 不动；板图、模块清单、参考表格随宽自然舒展，不做结构性改动。

## 实现决策

- 只改 `src/contest_generator/static/index.html` 的 CSS（main 规则 + 新 section 规则 + 生成页卡片 padding）；
- 零 JS 改动、零测试缝改动（纯 CSS，不影响 84 个 JS 测试与契约钉）。

## 验证

- CDP 无头 Edge 截图：1440 视口（生成页全宽 1392px / 设置页 1280 居中 + 80px 留白）与 1920 视口（生成页 1400 居中 / 设置页 1280 居中）；
- 断言：无横向滚动条（`document.documentElement.scrollWidth <= innerWidth`）、步骤导航位置正确、卡片不溢出；
- js 84/84 + 契约 50/50 全绿。

## 范围外

- 不改布局结构（flex/grid 骨架）、不做双栏内容、不动步骤导航宽度；
- 不做移动端专项（<820px 的体验不属于本轮）。
