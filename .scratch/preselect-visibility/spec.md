## 问题陈述

用户用 AI 推荐模块时，提示词里的「模块库可用模块」清单被题面预筛截断成子集：真实库 stm32 86 条 / mspm0 84 条，实际只送进 33–41 条。2024H（智能小车）这类题上，可见的 35 条几乎全是传感器/显示件，而 `motor`、`pid`、`servo`、`xunji`、`key`、`oled` 一条都看不见——模型没读过它们的简介，自然选不出来。上一批已修好「模型推荐子集外模块被当成幻觉而中断推荐」，但**模型看不见正解**这一层没修。

同一根因还连带两处：

1. 骨架阶段的「模块 → 参考例程」自动关联只覆盖 18/93 个模块，其中 9 个映射（beep/key/led/oled/servo/step_motor/led_beep×2/zigbee_uart_key）的词项在参考库 148 条标题里 0 命中——选中这些模块时一条例程都关联不到，等于没写。
2. 参考库内容本身只覆盖芯片外设例程（MSPM0 SDK 例程 124 条 + 厂商套件资料 + car 1.1 + 21F/26H 决策例程），**器件级例程一条没有**；而器件级移植手册早已在 Markdown 资料库里躺着（70 篇 lckfb 移植手册）。

## 方案

1. **一级清单行瘦身**：把喂给模型的模块清单行从「slug + 全简介 + 套件段 + 采购链接 + 各类标记」压成「slug + 有界首句 + 依赖 + 多实例 + 副产物/互斥标记」。实测 stm32 全库 29.6KB / mspm0 29.7KB（预算 40000B）——**全库可装、截断彻底消失**，86/86 条全部可见，关键模块不再靠排名挤位置。
2. **预筛继续存在、但不再截断**：预筛保留「排序 + 预算截断 + 保底」机制（库继续长大时仍需兜底），只是瘦身后全库装得下，`truncated` 恒为 False，「按题面初筛 N/M」注记不再出现。
3. **骨架映射判据归位**：映射的验收线从「每个词项都必须命中参考条目标题」改为「每个有映射的模块至少有一个词项命中参考条目标题」（关联是按模块算的，只要有一个词项能关联到例程，这条映射就不是死的）；全库模块必须**显式**声明映射或豁免，不再靠测试文件里的常量名单兜底。
4. **参考内容补录**：把 Markdown 资料库里已有的器件级移植手册做成参考条目（oled/led/key/beep/servo/step_motor 等），死映射随之复活；补不到手册的模块进显式豁免名单。

## 用户故事

1. 作为使用者，我想要小车、循迹、PID 这类题的推荐提示词里能看见 `motor`/`pid`/`servo`/`led`/`key`，以便模型能选中正解而不是凭常识瞎猜。
2. 作为使用者，我想要模块清单不再被截断，以便任何赛题的任何库内模块都有机会被推荐。
3. 作为使用者，我想要清单行仍然带依赖、多实例能力、副产物模板与互斥组这些决策信息，以便模型选中后配实例不再二次失败。
4. 作为使用者，我想要选中 `oled`/`led`/`key`/`beep`/`servo` 时骨架能关联到对应的移植手册，以便生成的 main.c 有真实例程可参照。
5. 作为维护者，我想要「全库模块都能装进预筛预算」这条不变量进测试，以便模块库继续长大时截断回潮会被立刻抓住。
6. 作为维护者，我想要「每个模块要么有映射、要么显式豁免」这条契约由库内数据保证，以便新增模块时不会静默变成「关联不到例程」。
7. 作为维护者，我想要预算账本（`budget.py` 记账注释）与真实库回归测试同步更新，以便瘦身带来的余量是记账过的、不是意外。
8. 作为维护者，我想要既有截断语义的测试用例（小预算直造）继续绿，以便瘦身没有顺手破坏预筛机制本身。

## 实现决策

- **瘦身行形态**：`- <slug>: <有界首句>（依赖: …）（多实例：上限 N，变体 = X）（副产物模板可选：…）（互斥组：…）`。有界首句 = 按「。」「；」切出第一句，再按 **100 字符**硬上限截断；切分不切「，」「：」（否则 `motor` 会只剩「TB6612 双路直流电机驱动（双平台统一 API）」丢掉能力句）。套件段与采购链接**不进一级行**（实测套件段占 23.5% 字节，且含淘宝/天猫链接噪声）。
- **形态归属**：行形态仍归 `manifest` 层（`ManifestSummary`），新增「瘦身行」渲染方法；`to_line()` 语义不变（完整行，供其它消费方与既有测试）。**预筛装配点取瘦身行**——瘦身行在装配点就替换 `TopicContext.manifest_summaries`，因此提示词、库指纹、设计报告草稿、修订影响分析四条下游链路自动一致（单一取源）。
- **100 字符上限的依据**：实测 60 字上限 20.7KB / 100 字 29.6KB / 120 字 33.4KB / 150 字 39.7KB（预算 40000B）。取 100 字留 ≈10KB 余量，同时把 `pid`（207 字）这类能力密集简介的核心能力句完整保留到「+ 左右轮目标速度输出」。
- **预算与账本**：`MODULE_SUMMARY_BYTES` 保持 40000（仍作上界，库长大时截断机制仍在）；`budget.py` 的摘要段记账注释更新为瘦身后的真实值，最坏形态回归测试（`test_recommend_real_library_budget`）按新形态复测并保持 ≥2KB 边界余量。
- **预筛契约**：`preselect_module_summaries` 的排序/截断/保底语义与 `PreselectResult` 形状**不变**；只是瘦身后真实库 `truncated` 为 False。既有「小预算直造截断」的用例继续有效（它们自造摘要与预算）。
- **骨架映射判据**：`MODULE_PERIPHERAL_TERMS` 的硬契约收紧为「每个映射至少一个词项（含同义词组）命中至少一条参考条目标题」；豁免名单从测试文件常量升为库内数据（模块 manifest 或映射模块旁的显式声明），使「新模块漏声明」在结构测试里红。
- **参考内容来源**：器件级参考条目从 `sources/materials/lckfb-地猛星移植手册/`（70 篇，含 0.96 寸 OLED、LED 数码管/WS2812、按键摇杆、舵机、TB6612、灰度、超声波等）提取，按参考库既有入库路径（锚定 kit 或 none）落条目；补不到的模块进豁免名单并写明理由。

## 测试决策

- **测试接缝（全部沿用既有最高接缝，不新建）**：
  - 预筛可见性 → `tests/test_preselect_coverage.py`（真实题库 × 真实库，6 条 xfail strict 即本批验收，修好自动 XPASS，摘标记转常规守卫）。
  - 瘦身行形态与字节账 → `tests/test_manifest.py`（行渲染先例）+ `tests/test_selection.py`（预筛层）+ `tests/test_llm.py::test_recommend_real_library_budget`（真实库最坏形态）。
  - 骨架映射 → `tests/test_skeleton_mapping_coverage.py`（2 条 xfail strict）+ `tests/test_reference_library.py`（词表单源断言）。
- **只测外部行为**：断言「全库 86 条都能进预算」「6 组题面下关键模块可见」「瘦身行含依赖/多实例/副产物/互斥信息」「每个映射至少一个词项命中标题」「每个模块有映射或显式豁免」；不钉具体排名、不钉首句切出来的字面值。
- **红证先行**：瘦身行未接入前，覆盖率 6 条仍红；接入后自动转绿（strict xfail 转 XPASS 即证明）。映射判据与豁免机制同理。
- **既有先例**：`tests/test_preselect_coverage.py`（真实库覆盖率）、`tests/test_manifest.py::test_summary_line_*`（行渲染）、`tests/test_llm.py::test_recommend_real_library_budget`（真实库预算回归）、`tests/test_library_invariants.py`（全库不变量进 pytest）。
