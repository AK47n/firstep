# 04 — 检测页 → 生成页的衔接入口（含页头陈旧文案）

**要做什么：** 学生在硬件检测栏目里验通了一件器件之后，能**一键把它带进赛题工程**（生成页选中同名模块），
不用回生成页再找一遍。同时把检测页头那句陈旧副标题改掉——它还写着
「本版先做「板子活着」最小自检」，会让人以为这一栏测不了器件（功能早就扩到器件选择 / 配方 /
串口命令台 / 库外件了）。

**被谁阻塞：** 无——可立即开始（与 01、02、03 互不阻塞，可并行）

**状态：** ready-for-agent

- [ ] 检测页能把当前选中的**库内器件**带进生成页，并在生成页把对应模块置为选中态
- [ ] **只带器件、不带引脚**：检测页没有引脚配置入口，页面上必须说清"引脚到生成页再配"
      （含生成前自动消解动过的那几根线——那些是检测页的本地裁决，不是用户的选择）
- [ ] **库外自建件不带过去**，且页面上说明为什么（它不走生成链，没有 manifest、不进 `slugs`）
- [ ] 带入前逐个过**库内 slug 词表校验**：词表里没有的拒收并给中文理由，不许把坏 slug 塞进生成载荷
      （防"点了没反应"与"生成时才 400"两种分家）
- [ ] 检测页头副标题改成如实说明这一栏能做什么（选平台 + 选器件 → 接线表 / 冲突预警 / 逐件判通断 / 复测 / 排障）。
      现状现场：`src/contest_generator/static/index.html` 第 4016 行
- [ ] fx 纯函数单测（带入的载荷与拒绝理由）+ 既有导航 / DOM 守卫同步 + 浏览器人工验收一次

## Comments

### 2026-09-24 立项依据

- 核查报告第 7 条：验完器件后没有任何"带回生成"的入口，学生只能凭记忆回生成页重选。
- 副标题现状（HEAD 实测）：`<h2>硬件检测 <span class="muted">（手上这件器件通不通——不用赛题、不用先选模块；
  **本版先做「板子活着」最小自检**）</span></h2>`——那是工单 `module-hwcheck/02` 的文案，之后 7 张工单
  （器件选择 / 配方 / 串口命令台 / 通用降级 / 排障 / 库外件）都没回头更新它。
- 带入范围的口径依据：检测页与生成页共用同一份模块库（`/api/modules`），所以"同名模块"是可靠的对应物；
  而引脚不行——检测页的引脚出口是"生成前自动解冲突"，与赛题页的绑定模型不是同一套输入。
