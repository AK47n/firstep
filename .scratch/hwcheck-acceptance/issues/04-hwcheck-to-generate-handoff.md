# 04 — 检测页 → 生成页的衔接入口（含页头陈旧文案）

**要做什么：** 学生在硬件检测栏目里验通了一件器件之后，能**一键把它带进赛题工程**（生成页选中同名模块），
不用回生成页再找一遍。同时把检测页头那句陈旧副标题改掉——它还写着
「本版先做「板子活着」最小自检」，会让人以为这一栏测不了器件（功能早就扩到器件选择 / 配方 /
串口命令台 / 库外件了）。

**被谁阻塞：** 无——可立即开始（与 01、02、03 互不阻塞，可并行）

**状态：** resolved

- [x] 检测页能把当前选中的**库内器件**带进生成页，并在生成页把对应模块置为选中态
- [x] **只带器件、不带引脚**：检测页没有引脚配置入口，页面上必须说清"引脚到生成页再配"
      （含生成前自动消解动过的那几根线——那些是检测页的本地裁决，不是用户的选择）
- [x] **库外自建件不带过去**，且页面上说明为什么（它不走生成链，没有 manifest、不进 `slugs`）
- [x] 带入前逐个过**库内 slug 词表校验**：词表里没有的拒收并给中文理由，不许把坏 slug 塞进生成载荷
      （防"点了没反应"与"生成时才 400"两种分家）
- [x] 检测页头副标题改成如实说明这一栏能做什么（选平台 + 选器件 → 接线表 / 冲突预警 / 逐件判通断 / 复测 / 排障）。
      现状现场：`src/contest_generator/static/index.html` 第 4016 行
- [x] fx 纯函数单测（带入的载荷与拒绝理由）+ 既有导航 / DOM 守卫同步 + 浏览器人工验收一次

### 2026-09-24 立项依据

- 核查报告第 7 条：验完器件后没有任何"带回生成"的入口，学生只能凭记忆回生成页重选。
- 副标题现状（HEAD 实测）：`<h2>硬件检测 <span class="muted">（手上这件器件通不通——不用赛题、不用先选模块；
  **本版先做「板子活着」最小自检**）</span></h2>`——那是工单 `module-hwcheck/02` 的文案，之后 7 张工单
  （器件选择 / 配方 / 串口命令台 / 通用降级 / 排障 / 库外件）都没回头更新它。
- 带入范围的口径依据：检测页与生成页共用同一份模块库（`/api/modules`），所以"同名模块"是可靠的对应物；
  而引脚不行——检测页的引脚出口是"生成前自动解冲突"，与赛题页的绑定模型不是同一套输入。

### 2026-09-25 结论

**一句话**：检测页「3. 要测的器件」下面多了一块带入区（`#hwcheck-handoff`）——它**点之前**就把三件事
写清楚（带哪几件 / 哪几件带不过去、为什么 / 引脚不带），点下去把这几件并进生成页的已选清单并
**立刻展开依赖**，然后切到生成页、滚到已选清单上；一件都带不过去时按钮置灰、**留在本页**并把理由
摆在旁边（没有"点了没反应"这条路）。检测页头副标题换成这一栏真正能做的事，
导航 tab 的 title 里那句同源的陈旧假设（「后续可选器件」）一并改掉。

**判据落在哪一层**（照仓库既有分工）：

| 判据 | 住在哪 | 为什么 |
|---|---|---|
| 该带哪几件 / 不该带哪几件 + 逐条中文理由 | `fx/hwcheck.js` 的 `hwcheckHandoffPlan`（纯函数） | 字符串数组进出、零 DOM 零请求，可直测；"库外件"的判据 = `/api/my-devices` 清单，**不写成 `mine_` 前缀**（前缀是 `my_devices.DEVICE_ID_PATTERN` 的事，再判一遍就是第二份实现） |
| 并入生成页的规则（不重复加 / 保序 / 哪几件本来就在） | `fx/hwcheck.js` 的 `hwcheckHandoffMerge`（纯函数） | `selectedSlugs` 的唯一写者是推荐簇 A，本函数只算"并进去之后长什么样"，于是这三条规则可直测 |
| 文案（引脚那一句 / 回报那一句） | `fx/hwcheck.js` 的 `hwcheckHandoffPinNote` / `hwcheckHandoffResultText` | 单源：块里那句与 toast 那句同源，ui 一个字都不拼（结构钉断言 ui 里不出现这些句子） |
| 写状态 + 切页签 | `ui/hwcheck.js`（`handoffToGenerate`）+ `ui/generate-recommend.js` 的 `addModulesFromHandoff` | 本模块是 `selectedSlugs` 的唯一写者；批量并入**只展开一次**（逐件 `addModule` 会连打 N 次 `/api/selection/expand`），重绘三块收敛成一个 `refreshSelectionViews()`（与 `addModule` 共用） |

**库内词表取哪一份**：`/api/modules` 载荷（生成页模块池与检测页器件网格吃的是同一份）。
**刻意不用** `/api/my-devices` 的 `known_slugs`——那份读不到时是空集，会把所有器件都判成"带不过去"。
