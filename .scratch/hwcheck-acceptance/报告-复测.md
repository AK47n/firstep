## 本轮新发现（2 条，都**不是**本批引入的回归）

### N1 `key` 的配方说明还在叫学生「把那一行的注释去掉」——工单 01 漏改了一处

- 现场：`library/hwcheck_recipes.json:384`（`key` × `mspm0` 的 `note.lines` 第 3 条）：
  「⚠ **上板前先把 main.c 里 SYSCFG_DL_init() 那一行的注释去掉**（它现在是注释状态——本平台生成链的已知限制…）」
- **它真的会印到页面上**：`recheck-page.txt:219`（场景 D：地猛星 + LED + OLED + 按键）的平台差异里原样出现。
- 为什么是漏改：工单 01 改了检测页清单那一项 + 两处配方文案（`xunji`、`adc`，见 `git show bb7c3816 -- library/hwcheck_recipes.json`），
  这条 `key` 是第三处，没在射程里。
- 影响：那一行**已经是活代码**，学生照这句话去 main.c 找注释会找不到；而且它与清单里已删掉的同名提示自相矛盾。
- 建议改法：文案改成与 xunji / adc 同口径（「检测程序开头已经调了它，不需要你改 main.c」），
  并把 `tests/test_hwcheck.py` 已有的「配方/清单不得出现『取消注释』」断言扩到 `library/hwcheck_recipes.json` 全文——这类残留下次当场红。

### N2 `.sysmem` 链接器告警：`ml_mpu6050` 那一格 + 编译面板看不见链接器诊断

- 现象：本轮新增的一格（检测页 `OLED + ml_mpu6050`）编译**通过**（exit=0、0 error），但带 1 条
  `warning #10210-D: creating ".sysmem" section with default size of 0x800; use the -heap option to change the default size`。
- **隔离测量**（`recheck-isolate-sysmem.txt`，五格同轮对照）：与 OLED 无关——关掉 OLED 通道照样 1 条；
  `jy61p` / `aht10` / 空选都是 0 条。根因在件本身：`library/modules/ml_mpu6050/ml_libs/inv_mpu.c:60-61`
  把 `log_i` / `log_e` 定义成 `printf`，TI 运行时的 stdio 要堆 → 链接器建 `.sysmem` 时告警。
- 定性：**既有、非本批引入**——该文件最后改动是 2026-09-08；自建件那批的编译矩阵
  （`.scratch/hwcheck-unknown-device/probe-*-compile-matrix.txt`）早就把同一条标成「（已知工具链）」。
- 顺带量到一条**口径漏洞**（比告警本身更值得留意）：`parse_compile_errors` 认不出链接器形态的告警
  （`warning #10210-D:` 里 `warning` 后面是 `#` 不是 `:`）。把真原文喂进去，解析出 **0 条**
  （`recheck-parser-sees-linker-warning.py`，同轮编译器形态的 warning / error 都正常解析出 1 条）。
  两个后果：① **编译面板会对这条告警报「0 warning」**；② 工单 09 的矩阵按 `"warning:" in message`
  计数，因此把这一格记成 0 warning——「0 error / 0 warning」这条验收线在链接器诊断上是漏的。
- 建议另开单（两条都不在 hwcheck 射程内）：① 面板解析器补链接器形态诊断；
  ② 想让 mpu6050 那格真到 0 warning，得动驱动里的 `log_i/log_e`（或换非 stdio 实现）。
