# 硬件检测验收补齐（让「拿到的硬件能不能用 / 不会用能不能上手」真的成立）——功能规格

> 2026-09-24 立项。起因 = 一次对原始目标的实测核查（`.scratch/hwcheck-acceptance/报告.md` +
> `probe-page.py` 的五个场景读数）。核查结论是「方向对、工程在，但差几步」，
> 本 spec 只收那几步，不重做已经 resolved 的那两块（`module-hwcheck` 01–09、
> `hwcheck-unknown-device` 01–12）。

## 问题陈述

「硬件检测」栏目当初是为两件事建的：**① 拿到一件硬件，看看它能不能正常用；② 不会用的时候，能辅助我把它用起来。**
功能本身做完了（配方机制、通用降级、串口命令台、现象回填 + AI 排障、库外件探测），但按这两个目标实测，还有四处没到：

- **地猛星上生成的检测工程开箱跑不起来。** 渲染出的 `main.c` 里 SysConfig 初始化那一行是**注释占位**，
  必须手动取消注释、重新编译才生效；不取消就是"灯不闪、串口一个字没有"——**这恰好是最像板子坏掉的失败形态**。
  根因不在检测页：生成门禁不认识 `SYSCFG_DL_init`（它由 SysConfig 构建期生成），
  于是把它判成"未定义调用"并注释掉——**这条限制对骨架工程、赛题工程同样成立**，
  硬件检测只是第一个把它暴露到台面上的功能。
- **地猛星上「OLED 屏 + 任意 I2C 器件」生成前必被拦下。** 母版把 OLED SPI 变体的两个脚也叫 `SCL`/`SDA`，
  与库内 17 件 I2C 传感器实例**逐字同名**；SysConfig 的 Duplicate name 判据不吃引脚改绑（实测换四种绑定恒为 2）。
  而"勾着屏幕看结果 + 我新买的那件传感器"是学生最自然的一次上板组合——现在这条路是死的。
- **配方全部未上板。** 编译矩阵是绿的（16 种形态 × 两平台 0 error / 0 warning），
  但没有任何一块真板跑过检测程序。"板上现象"这一层从未被验证过——而目标 ① 的字面要求就是"看它能不能正常用"。
- **验完一件器件，没有把它带回赛题工程的路。** 检测页与生成页是两个独立栏目，学生验通了还得回生成页
  把同名模块再选一遍；页面上也没有一句话说明"验通了之后怎么用它"。

另有一件不属于本 spec、但必须同时发生的：**这一栏还没进任何发布包**（v1.2.2 用户完全看不到它）。
那是发版动作（版本号 / 打包 / Release），见 `docs/agents/releasing.md` 与
`docs/agents/local-environment.md` §0，本 spec 不重复管。

## 方案

给上面四处各配一条端到端可验证的切片，**不改已经 resolved 的配方机制与库外件设计**：

1. **让 mspm0 生成链真的注入 SysConfig 初始化**——骨架 / 赛题 / 检测三条路一起吃：
   生成的 mspm0 工程烧进板子后外设真的被初始化，检测页清单里那条"上板前先取消注释"消失。
2. **解开母版引脚符号重名**——地猛星上「OLED 屏 + 任意库内 I2C 器件」能同选、能生成、能编译；
   撞名这一类的判据从此不再由"用户去掉一件"来兜。
3. **拦下时的出路文案点名页面上真实存在的动作**——即使根因修了，将来仍可能出现别的重名组合；
   被拦下时说的必须是学生这一页上做得到的动作（取消勾选某个输出通道 / 去掉某件器件），
   不是 SysConfig 的实例名。
4. **检测页 → 生成页的衔接入口**——验完的器件能带进赛题工程；顺带修掉检测页上那句陈旧的副标题
   （它还写着"本版先做「板子活着」最小自检"，会让人以为这一栏测不了器件）。
5. **真机上板一轮**——按检测页清单在两块板子上各走一遍，把现象回填；没跑过的照旧写"未上板"。

## 用户故事

1. 作为学生，我想要**地猛星上生成的检测工程不用我改任何一行代码就能编译烧录跑起来**，以便我的第一次上板不会以"灯不闪、串口没字"开场。
2. 作为学生，我想要**"OLED 看结果 + 我新买的 I2C 器件"这个组合能直接生成**，以便我不必在两者之间二选一。
3. 作为学生，当我选的组合真的装不下时，我想要**出路文案说的是我这一页上做得到的动作**（取消勾选哪个通道 / 去掉哪件器件），以便我不用去猜 SysConfig 实例名对应屏幕上的什么。
4. 作为学生，我想要**验通一件器件之后能把它一键带进赛题工程**，以便我不用回生成页再找一遍同名模块。
5. 作为学生，我想要检测页的头一句话**如实说明这一栏能做到什么**（能选器件、能逐件判通断），以便我不会因为一句旧文案就以为它只能验板子。
6. 作为维护者，我想要**mspm0 的 SysConfig 初始化注入有单一判据**（不靠某个页面各写一遍特例），以便骨架 / 赛题 / 检测三条路不会再各自踩同一个坑。
7. 作为维护者，我想要**母版引脚符号唯一性有守卫**（新加实例时撞名当场红），以便这不只是这一次的一次性修补。
8. 作为维护者，我想要**每一条改动都有真编译证据**（stm32 不回归 + mspm0 0 error / 0 warning），以便"能生成"与"能编译"不脱钩。
9. 作为维护者，我想要**真机上板有落盘读数**（跑过的写现象、没跑的写未上板），以便这批结论不靠自述。
10. 作为维护者，我想要**这批改动不碰已 resolved 的配方机制与库外件设计**，以便回归面收在本 spec 的射程内。

## 实现决策

**射程与边界**

- 本 spec 只收「核查报告」里排在前面的四条（生成链初始化 / 引脚符号重名 / 出路文案 / 衔接入口）与它们的验收（上板）。
  配方覆盖面的扩张（全库回填）、stm32 侧 DMP 移植、发版动作都不在射程内。
- 已 resolved 的两块（`module-hwcheck`、`hwcheck-unknown-device`）**只允许被动适配**（例如初始化那一行从注释变成活的），
  不允许借这批单重构它们的机制。

**① mspm0 的 SysConfig 初始化注入（产品级，不是检测页特例）**

- 这是**生成链**的问题，不是硬件检测的问题：根因是生成门禁对 mspm0 的接口认知（`SYSCFG_DL_init` 由构建期头声明，
  门禁按"头文件里有没有这个名字"判，于是判成未定义并注释掉）。修在检测页 = 同一个坑换个页面继续踩。
- 两条候选修法交由工单**先量后定**（不许不量就选）：把该符号纳入 mspm0 的已知接口面；或在渲染母版 main.c 时把它作为模板的一部分而不是"main.c 里的调用"进产物。
  判据是同一个：骨架 / 赛题 / 检测三条路生成的 mspm0 工程，那一行都是**活的**，且真编译绿。
- 影响面覆盖全产品的 mspm0 生成，故**必须带真编译矩阵**（stm32 不回归 + mspm0 编译绿），
  并且要保留"这门禁本来要防什么"的判据（不许为了放行一个名字把门禁削弱）。

**② 母版引脚符号重名（根因）**

- 根因已定位：母版 mspm0 的 SysConfig 里，OLED 的 SPI 变体把两个脚 `$name` 起成 `SCL`/`SDA`，
  而库内每一件 I2C 传感器实例也都叫 `SCL`/`SDA`——SysConfig 要求同工程的引脚符号名唯一。
- 两条候选修法（工单内先量影响面再选）：改 OLED SPI 那两个符号名；或给每个传感器实例的引脚符号带上实例前缀。
  选面窄的那条——但**改名会改掉生成的宏名**，引用了旧宏的模块代码必须同批改，且要真编译矩阵兜底。
  > **口径更正（2026-09-24，工单 02 实测，账见 `.scratch/hwcheck-acceptance/issues/02-*.md`）**：
  > 实测把"窄修"否掉了——12 格组合里 **10 格**在生成前就被拦下（不止"OLED + 传感器"，
  > 还有 `aht10 + bh1750` 环境站、`oled + lcd`、`led_beep + gp2y1014au`、`rc522 + nrf24l01` …），
  > 而 SysConfig 的判据是 `$name` **全局唯一**（`SCL`/`SDA` 一组 18 个实例里只能留 1 个裸名）。
  > 于是取"14 组 / 68 个符号全部改成 `<实例名>_<原符号>`"：母版从此满足**引脚符号全局唯一**
  > 这一条单一不变量，守卫才写得成 `name_count == 0`；边际成本比窄修只多 ~70 处模块引用
  > （`SCL`/`SDA` 那一组本身就占 373 处里的约 300 处）。
  > 用户故事 7 的"母版引脚符号唯一性守卫"据此落地为
  > `tests/test_syscfg_prune.py::test_master_pin_symbols_are_globally_unique`。
- 「不改名、只把出路说清楚」是 ③ 的内容，**两条不互相阻塞**：③ 立刻改善体验，② 才真正解开组合。
- 这一类缺陷要有**构建期守卫**：母版 syscfg 里新增实例时再次撞名，当场红（判据复用既有的落盘冲突报告，
  不另造一套）。

**③ 被拦下时的出路文案**

- 文案由域层产出（前端只渲染，沿用既有出口文案单源），因此可以纯函数直测。
- 硬要求：**点名的必须是页面上真实存在的控件动作**——检出"重名来自某个输出通道"时，就说"取消勾选那个通道"；
  来自器件选择时才说"去掉那一件"。SysConfig 实例名只作括号里的补充信息，不能是唯一线索。

**④ 检测页 → 生成页衔接入口**

- 只能搬**器件集**：检测页没有引脚配置入口，引脚（含自动消解动过的那几根）进不了赛题工程，
  页面上必须说清"只带器件、引脚到生成页再配"。
- 带入的 slug 必须逐个再过一遍库内词表校验（检测页允许的库外自建件**不在**可带入之列——它不走生成链）。
- 副标题文案属于同一切片（同一处页头，同一批改动一起验收）。

**⑤ 真机上板**

- 口径沿用 `real-acceptance` A 组：真板、按检测页清单逐条看、现象回填；
  **没跑过就写"未上板"**，不拿编译绿代替。
- 至少覆盖：地猛星一件专精件 + 一件未专精件（看通用降级怎么说话）、stm32 一件专精件。
- 证据落 `.scratch/hwcheck-acceptance/`（探针脚本 + 读数文本），沿用本目录已有的核查证据风格。

## 测试决策

- **最高既有缝 = 域层纯函数**（字符串进 / 字符串出，内存直测，零 LLM）：
  出口文案（③）、衔接入口要带的器件集与拒绝理由（④）、初始化那一行在渲染结果里的形态（①）都在这一层测。
- **生成门禁**：沿用既有的内存语料 + 门禁谓词测试，不另读盘；同时用产物树语料复核（既有的
  `build_output_tree_corpus` 一路），保证"门禁过了"与"产物真的对"是同一件事。
- **引脚符号唯一性**：判据复用既有的落盘冲突报告（检测页与生成门禁同源那一份），
  新增守卫用例 + **反证探针**（把改名撤回、或再塞一个撞名实例，用例必须变红——本仓库既有纪律）。
- **真机口径**：stm32 走 UV4、mspm0 走 gmake，编译矩阵 **0 error / 0 warning**；
  ① 另加一条文本断言：渲染出的 `main.c` 里那一行**不是注释**。
- **前端**：fx 纯函数单测（衔接入口的载荷与文案）+ 既有导航 / DOM 守卫同步；浏览器人工验收。
- **上板（⑤）不做自动化**，落地形式为脚本 + 读数文本 + 现象回填。

## 范围外

- 全库配方回填（本期仍只认已有的 10 件 / 17 格）。
- 发版动作本身（版本号 / 打包 / Release / 线上发布包）——另行按 `releasing.md` 走。
- stm32 侧 DMP 姿态解算移植。
- 改「模块 = 纯驱动切片」的边界、给模块 manifest 加字段、给配方加段。
- 检测工程与赛题工程的合并（两者仍然互不干扰，只是多一个单向的"带器件过去"入口）。
- 引脚配置入口搬进检测页（本批不做；动过的线仍如实进载荷与接线表）。
