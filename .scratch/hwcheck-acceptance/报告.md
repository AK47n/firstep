# 硬件检测栏目「是否达成原始目标」核查（2026-09-24）

> 原始目标（用户原话）：**① 看看拿到的硬件能否正常使用；② 不会使用的时候能够辅助完成使用。**
> 本报告只回答这两条，不重复 spec 的承诺——看的是**今天这套代码实际会给出什么**。
> 证据全部是本机现跑（`.scratch/hwcheck-acceptance/probe-page.{py,txt}`、`main-{mspm0,stm32}.c`、`exit-aht10.txt`）。

## 一句话结论

**方向对了，工程也真做出来了，但「达成」还差三步：它没发到用户手上、地猛星上生成的程序开箱跑不起来、而且它的核心路径（屏幕 + I2C 器件）在地猛星上会被自己拦下。**

目标 ① 判定：**部分达成**（stm32 侧基本可用，mspm0 侧有两个硬伤，且全库没有任何一格真的上过板）。
目标 ② 判定：**基本达成**（接线表 / 应看到什么 / 不对先查哪里 / 串口复测 / 模块说明弹窗 / 新手引导 / 库外件资料→草稿，这一整条链都在）。

## 差距清单（按「挡住用户的严重度」排序）

### 1. 这一栏还没发到用户手上（最严重，也最好修）

`VERSIONS.md` 最新是 v1.2.2（2026-09-19），`__version__ = "1.2.2"`；
`docs/agents/local-environment.md` §0 写明：硬件检测栏目本身 + 检测页引脚出口 + 库外件探测，
**五批改动都只在 main 上，任何发布包里都没有**。
→ 对**装发布版的学生**来说，① 和 ② 的达成度此刻都是 0。要真达成，得发 v1.3.0（建议版本号已在 local-environment 里拍过）。

### 2. mspm0 生成的检测工程不能开箱即跑

`SYSCFG_DL_init();` 被渲染成注释（成因：该符号由 SysConfig 构建期生成，
生成门禁"main.c 不许调不存在的接口"会判它未定义）。代码里**如实标注**了
（文件头 + 清单第 6 条都写着"上板前先取消注释"），但这与「打开就能编译烧录跑」的目标直接冲突：
学生第一次拿到地猛星，最容易看到的现象是"灯不闪、串口一个字没有"，而**这恰恰是最像板子坏的失败形态**。
stm32 侧无此问题（`SystemInit()` 正常输出）。

### 3. mspm0 上「OLED + 任意 I2C 器件」这条路是堵的

实测：`oled=True` 时 `aht10` / `bh1750` / `sht30` / `jy61p`(pilot 件) → 生成前 400；
`oled=False` 时全部通过。而页面上「OLED 屏」**默认就是勾选的**，指南也建议"至少勾一个输出通道"。
出路文案的问题更具体：它让用户"回到器件选择去掉一件"或"显示屏换一路不挂 I2C 的"，
但**页面上的真实动作是取消勾选「OLED 屏」这个输出通道**——OLED 根本不在器件列表里，指路指错了地方。
（根因是母版 syscfg 给这些实例起的引脚符号同名，工单 11 已把它从"编不过"改成"生成前如实拦下"，
但拦下之后用户仍然测不了"屏幕 + 传感器"这个最常见的组合。）

### 4. 全部未上板

编译绿已证（16 种形态 × 两平台 0 error / 0 warning），但**没有任何一块真板跑过检测程序**，
"板上现象"这一层从未被验证。目标 ① 的字面要求就是"看看能不能正常用"，这一步不能由编译代替。
（spec 的验收口径本来就要求用户照清单上板跑一轮并回填——这一轮还没发生。）

### 5. 专精面窄

10 件 / 17 格有配方；库内其余（含 17 件共用 SCL/SDA 的 I2C 器件）只有"初始化 + 总线扫描"级别。
自 09/24 起 `adc×mspm0` / `xunji×mspm0` 两格已随引脚出口修复可以生成（实测通过），
但总体上"你手上这一件"落到"未专精"的概率仍然很高——那档是**如实但很浅**的。

### 6. 页面副标题是旧的（小，但会误导）

`index.html:4016` 还写着「**本版先做「板子活着」最小自检**」——那是工单 02 的文案，
功能早已扩到器件选择 / 配方 / 命令台 / 库外件。学生读这句会以为这一栏只能验板子、测不了器件。

### 7. 检测页 → 赛题工程没有衔接（小）

验完一件器件后，页面上没有"把它带进生成流程"的动作；学生得自己回「生成」页再选一遍同名模块。
（模块说明弹窗里能看到"怎么用（接口）"，信息不缺，缺的是一步跳转。）

## 建议的下一步（按投入产出比）

1. **发 v1.3.0**——把这五批（含硬件检测）送出去，否则一切讨论对用户都是零。
2. **修 mspm0 的 `SYSCFG_DL_init`**——这是"打开就能烧"的唯一硬伤，且失败现象最像硬件坏。
3. **给 mspm0 的重名冲突补一条真正的出路**——至少在 400 文案里点名「取消勾选「OLED 屏」通道」这个页面动作；
   更彻底的是改母版 syscfg 的引脚符号名（工单 11 记着"改绑解不开"）。
4. **真板跑一轮**：地猛星 + stm32 各一次，按清单走完并把现象回填——这才是目标 ① 的验收。
5. 顺手：更新页面副标题；加一个"把这些器件带进生成页"的入口。
