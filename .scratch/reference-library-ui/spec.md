# 参考文件库页 UI 提升（信息查看 + 编辑体验 + 数据健康 + 美感）

> 会话/系列 slug：reference-library-ui。本 spec 描述「第三个栏目 = 参考文件库
> （tab-reference）」整轮提升的共同方向；实施按竖切工单逐张落地（见 issues/）。
> 与上一轮「第二个栏目 = 模块库」（module-library-ui，已完成 7 张工单）对偶。

## 问题陈述

「参考文件库」栏目是全站管理第二原始的的面板：浏览靠 4 个服务端筛选输入框
（标题 / 类型 / 锚定 / 文件名）+ 搜索按钮，库大了以后无法即时定位，无排序、
无统计；「查看」弹层只有 `id · N 个文件` 与文件清单，条目的元数据（简介全文、
锚定、平台、体量）一律看不到；**条目入库后没有任何编辑能力**——后端没有
update 端点，改标题 / 类型 / 简介 / 锚定 / 平台或增删文件只能整条删除重录
（全部文件重新上传一遍），对 160+ 条目的库是不可接受的维护成本；锚定列是
纯文本、平台 chip 裸样式、按钮风格割裂，视觉上落后于生成页与模块库页；录入
表单 12+ 字段一屏堆叠无折叠。此外，锚定数据健康不可见：锚定值不命中任何库内
赛题 / 套件词表的条目永远不会被生成链路自动关联注入，但没有任何警示。

## 方案

把「参考文件库」页提升为信息完整、可检索、可编辑、风格统一的管理面板，四个主轴：

1. **信息与查看**：表格精修 + 全新「详情」弹窗（元数据 + 文件清单合并一窗）+
   客户端即时过滤 / 排序 / 统计条，替换现有服务端四框筛选区。
2. **编辑体验**：新增「编辑」弹窗（全字段元数据 + 文件增删），经新后端端点
   `PUT /api/references/{id}` 一次事务提交；校验与录入（add_reference）同源。
3. **数据健康**：悬空锚定警示——topic 锚定值 × 赛题库 key 清单、kit 锚定值 ×
   模块库 kit 词表，不命中 = 该条目永远不会被自动关联注入 → 行内警示 + 统计条
   红色计数（可点击过滤）；警示为提示语义，不拦截编辑。
4. **美感**：与生成页 / 模块库页同一套令牌体系（表头底纹、行 hover、徽章、
   按钮、空态），录入表单分区折叠。

主体形态维持**表格**（管理场景信息密度优先），不做卡片网格、不做双视图。

## 实现决策

### API 契约（新增 1 个端点，其余全复用）

- `PUT /api/references/{entry_id}`，body：
  `{title, type, description, anchor_kind, anchor_value, platform, add_files?: {文件名: 内容}, remove_files?: [相对路径, ...]}`
  ——元数据全量必填（前端表单总是一次提交完整值）；`add_files` / `remove_files`
  可选（缺省 = 不增不减）。成功返回 `entry.to_dict()`（含磁盘实况 file_count /
  size_bytes）。
- 校验与 `add_reference` 同源：标题 / 类型 / 简介非空；锚定——topic 过
  validate_topic_anchor 格式校验、kit 必须在模块库已有 kit 词表（词表外拒绝，
  与录入同语义）、none 强制空值；platform 取自词表；`add_files` 路径安全 +
  不与 reference.json 冲突；`remove_files` 路径安全 + 必须实际存在于条目目录 /
  清单中（不存在 = 400 报错，防错删数据漂移）。
- **全部校验在第一次落盘前完成**：任何校验失败抛 ReferenceError（错误映射表已
  有登记，错误文案中文），磁盘零变化；落盘顺序对偶先例（先改引用再删实体 +
  先写新文件再写元数据），成功一次 `commit_after_write` 自动 git 提交
  （`lib: update reference {entry_id}`）。
- **标题编辑不改条目 id / 目录名**（目录名 = 身份不变量；重命名目录有 materials
  镜像 / 路径引用 / git 历史风险）。
- 文件管理范围：加文件 = 文本内容写入（与录入同款 picker 同读法，UTF-8）；
  删文件 = 按路径 unlink（含提炼归档的二进制文件）；**不支持修改文件内容**
  （删除后重新添加即是改写，本轮不做内联编辑）。
- 文件清单元数据字段 `files` 更新为增删后的结果（保序、去重）。
- 既有端点零改动：`GET /api/references`（无参全量）继续作为列表数据源；
  `GET /api/references/{id}/files`（磁盘实况）作详情 / 编辑弹窗文件清单源；
  `POST /api/references/draft`、`POST /api/references`、`DELETE /api/references/{id}`
  不动。

### 前端（交互逻辑继续下沉纯函数，DOM 层只转发）

- 纯函数组（挂 window，供冒烟直接调用，对偶 module-library-ui 的 lib-* 系列）：
  `refFilterEntries`（四合一关键字 + 平台 + 锚定类型过滤）、`refSortEntries`
  （标题 / 类型 / 体量 / 文件数 / 平台，稳定排序）、`refStats`（总数、平台分布、
  锚定类型分布、未锚定数、总体积、悬空数）、`refDanglingAnchors`（悬空判定：
  topic = 不存在任何库内赛题 key 是锚定值子串；kit = 锚定值不在 kit 词表）、
  `refRowHTML`（行渲染：标题 + 命中文件直出链接、简介截断 + tooltip、锚定徽章、
  平台 chip、体量、操作按钮）、`refMatchFiles`（文件名命中清单，从条目 files
  清单计算，替代原服务端 matched_files 的客户端版本）、`refAnchorBadge`、
  `refChipRowHTML`（过滤 chips 渲染与置态）。
- 数据源：`GET /api/references`（无参，全量在手）→ 客户端即时过滤排序统计；
  悬空检查另取 `GET /api/topics`（key 清单）与 kitVocabulary（沿用
  loadKitVocabulary 从 `/api/modules` 派生，已随 tab 切换加载）。
- **悬空检查降级**：`/api/topics` 返回空 = 赛题库未录入，跳过 topic 锚定检查
  （避免全库误报）；kit 词表为空 = 跳过 kit 锚定检查。
- 详情弹窗：复用既有 `.ref-files-overlay` / `.ref-files-close` 遮罩与关闭模式
  （module-info-dialog 先例），内容分两段——元数据段（标题 / 类型 / 锚定徽章 +
  值 / 平台 chip / 简介全文 / 体量 / 悬空 ⚠）+ 文件段（过滤输入 + 清单 + 打开，
  数据走磁盘实况端点）。
- 编辑弹窗：全字段表单（标题 / 类型 / 简介多行 / 锚定三态切换 / 平台三选一）+
  文件管理区（现有文件勾选批量删除 + 添加文本文件行，pick 样式同录入表单）+
  一次「保存」调用 PUT；保存中 / 成功 / 失败三态反馈；编辑简介不做 AI 校验
  （参考简介是说明性素材、由人确认，与录入流程同一哲学）。
- 统计条：条目总数、锚定类型分布（赛题 / 套件 / 未锚定）、平台分布（any /
  stm32 / mspm0）、未锚定数、总体积（formatSize 求和）、悬空锚定红色计数段
  （点击 = 过滤只显示悬空条目，再点取消）。
- 旧筛选区替换：4 个服务端输入框 + 搜索按钮移除；改为关键字即时输入（防抖）
  + 平台 chips + 锚定类型 chips + 排序下拉；「文件名命中直出链接」特性保留，
  客户端从条目 files 清单计算（不含清单外磁盘散文件——接受，详情弹窗有磁盘
  实况兜底）。
- 录入表单分区折叠（基本信息 / 素材与锚定 / 平台属性），对偶
  add-section.collapsed 先例；锚定与平台校验提示文案保留中文。

### 模式变更 / 架构决策

- 不引入新依赖、不改 manifest 模型、不动模块库 / 赛题库 / 生成链路。
- 后端新增仅 `update_reference`（reference_library.py）+ 1 条路由（webapp.py）；
  错误类型复用 ReferenceError（已在 error_to_http 表登记），零新错误类。
- 交互逻辑继续下沉纯函数（先例：score-points-format、libFilterModules 系列），
  DOM 事件层只做转发，保持 tests/js node:test 可测。

## 测试决策

- 前端主 seam = `tests/js` 的 node:test 纯函数单测（extract 范式：
  module-library.test.mjs / module-info-dialog.test.mjs 同款）。覆盖：过滤匹配
  规则（含四合一、平台、锚定类型）、排序稳定性、统计汇总、悬空判定（含空库
  降级、子串方向）、文件名命中计算、行渲染子串断言（徽章 / 悬空 ⚠ / 命中链接）。
- 后端新函数 `update_reference` + `PUT` 路由 → pytest：成功改元数据 / 改锚定
  （三态各一例）/ 加删文件组合 / 各校验失败（非空、词表外 kit、非法平台、
  非法路径、reference.json 冲突、remove 未命中）且磁盘零变化 / 不存在条目
  报错 / 标题改后 id 与目录名不变 / 元数据 files 字段保序去重更新 / 自动 git
  提交触发（沿用既有 autocommit 测试模式）。
- 交互层（弹窗开合、折叠、编辑流转、悬空过滤）延续浏览器级验证先例
  （.scratch/reference-library-ui/smoke.mjs + 截图 + 冒烟清单，对偶
  module-library-ui/smoke.mjs 范式：CDP 9251 连接、check 计数、假条目注入还原）。
- 全量回归：pytest 全量（现状 2365 绿）+ tests/js 全量（现状 305 绿）+
  冒烟清单保持全绿。

- 深色主题。
- 生成页的参考资料选择器（loadReferencePicker，属第一栏目）。
