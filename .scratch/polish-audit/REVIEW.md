# 电赛工程生成器 UI 视觉评审

> 评审对象：`.scratch/polish-audit/` 下 10 张全页截图（深色 8 张、浅色 2 张）。
> 方法：逐张 `read_image`。`audit-03-reference-dark`(1440x9110) 与 `audit-07-changelog-dark`(1440x15724) 超 8192px 限制，先经 System.Drawing 降采样为副本（1113x7040 / 645x7040）再读。
> 诚实声明：这两张超长页与生成页(1440x5451)为整页缩略，**字号/极细边框/局部对比度是按缩略图估算**，涉及精确像素的判断建议在原生分辨率复核。布局级、色系统一性、节奏类结论置信度较高。

## 一、按严重度排序的问题清单

### 高（明显影响观感 / 一致性）

**H1. 浅色主题辅助文字对比度不足（尤其 muted 文字）。**
- 页面/位置：`audit-01-generate-light`（各步卡描述行、placeholder、按钮下方提示）；`audit-08-settings-light`（「应用设置」说明、卡片描述、「最近 LLM 工作流」底部 note、输入框 label）。
- 问题：主题令牌全局 `--muted #8b949e` 在深色 `#0d1117` 上成立，但直接落到浅色白底上，`#8b949e`（约 2.7:1）用于正文级辅助文字会明显发灰、难于阅读。截图里这些辅助文字在浅色下已接近「隐形」。
- 建议：给 `data-theme=light` 单独定义一档更深的 muted（GitHub 亮色默认 ~`#57606a`），并同步一档更深的边框令牌；浅色下 placeholder/说明/表头小字统一用它。同样检查浅色下 step 卡片与输入框的边框（`#30363d` 在亮色应换成 ~`#d0d7de`，否则输入框边界发虚）。

**H2. 生成页首屏信息过密、顶部层级重叠。**
- 页面/位置：`audit-01-generate-dark` 顶部（上）。
- 问题：同一屏叠了「品牌行 + 产品名 + 一行看似面包屑的说明（赛题原文→AI 推荐→…→交接提示词）」+「顶部导航 tab」+「左侧 步骤导航 栏」+「前 3 张步卡」。产品名旁那行说明读起来像「流程面包屑」却放在品牌位，语义错位；首屏的导航/说明/侧栏三套横向元素挤在第 1 屏，观感杂乱。
- 建议：把那行流程说明从品牌行拆走（放成步骤区上方的小标签，或并入导航下）；「步骤导航」侧栏改成纯数字进度轨（自动高亮当前步、默认收起），避免和左侧另一套「用法」说明再次重复；移动端隐藏侧栏。

**H3. 数据列表行内「删除」红色按钮大面积重复，破坏列表节奏。**
- 页面/位置：`audit-03-reference-dark`、`audit-04-pdf-dark` 每行右侧（右）；`audit-06-master-dark` 操作列（右）。
- 问题：参考文件库 / PDF 库 / 母版表格里**几乎每一行**都配一个红边红字「删除」按钮（外加一个深色「详情」）。整列红色反复出现，视觉上像一直被「告警」，与深色页沉稳基调冲突；且列表越长（参考库 ~200 行）越刺眼。
- 建议：行级删除降级为「hover 才出现的 icon 垃圾桶 + 确认弹窗」，或把危险感收敛成 muted 色、只在 hover/聚焦时变红；保留「正式删除」主操作的红色。同时统一这三张表的操作列：列对齐、按钮规格、间距一致。

**H4. 同元素在「库」页与「母版」页表头样式漂移。**
- 页面/位置：`audit-03-reference-dark`、`audit-04-pdf-dark`（表头行）vs `audit-06-master-dark`（母版表头）。
- 问题：参考/PDF 用深色表头条 + 细分隔列；母版是「平台/提炼来源/入库告警/健康/操作」多列，但表头更弱、字号更小，列与列之间没有同款分隔。三张表格都是「列表式」，表头强度却不一致，读表时跳跃。
- 建议：统一三张表的表头背景、字重（semibold）、padding 与列分隔线做法；母版表头对齐参考/PDF 的强度。

### 中（细节质感）

**M1. 空态处理不统一：部分卡片空态直接是空白输入区，缺引导。**
- 页面/位置：`audit-01-generate-dark` 中段的「调试/编译修复」等长文本步卡（中大块空 textarea）；vs `audit-08-settings-dark`「最近 LLM 工作流」的空态（已有 icon +「暂无已保存的工作流」+ 引导文案）。
- 问题：同一套 UI 里，设置页空态图文协调，生成页几个大 textarea 却近乎空白、无 placeholder/无引导，显得「没做完」。
- 建议：给生成页大输入区加统一 placeholder（如「等待运行…」「此处将显示输出」），空态与设置页同规格（icon + 主文案 + 次文案）。

**M2. 生成页芯片配置表（`⑩ 引脚配置`）单元格拥挤。**
- 页面/位置：`audit-01-generate-dark` 中下部大表格；`audit-01-generate-light` 同区域。
- 问题：表格每个小格里同时塞「芯片外设名 + 已选/× 小标签」，格子小、标签与格子边界贴近（浅色下尤其粘连），hover 命中区也很小，密集且易误点。
- 建议：增大 cell 间距或行高；「已选」态改为更轻的描边/淡色而非强边框图标；给「× 移除」留独立可点区。

**M3. 设置页「计费 •」行符号语义不明。**
- 页面/位置：`audit-08-settings-dark`/`audit-08-settings-light` 的「AI API」卡片底部「计费 •」。
- 问题：一个孤立的 `•` 无说明，看不出是「按量计费」还是「状态点」。这类小符号容易被忽略成排版瑕疵。
- 建议：改为「计费：按量 / 每条请求计 tokens」或加 tooltip/角标。

**M4. 浅色导航/侧栏 active 态文字对比需复核。**
- 页面/位置：`audit-01-generate-light` 顶部「生成」tab、左侧「AI 调试(推荐)」高亮 pill。
- 问题：浅色下 active 是青色/teal 实心 pill。若 pill 内文字用白字，teal 背景 + 白字对比往往偏低；需确认两主题下 active 文字都达 AA。
- 建议：浅色 active pill 用深青底白字或浅青底深字，统一深/浅两套实装值。

### 低（可做可不做）

**L1. 更新记录页（`audit-07`）是超长单列时间线，滚动成本高。**
- 页面/位置：整页（1440x15724）。
- 问题：每一条版本「标题 + 大段正文」单列铺开，行高很大、文字稀疏，翻到最新版要滚很久；版本号标题与正文层级区分度在缩略下不明显。
- 建议：版本标题加粗并配「最新」角标；默认只展开最近 N 条，其余折叠；或用两列卡片。

**L2. 每页顶部「引导句」存在性不一致。**
- 页面/位置：`audit-08` 顶部「点击卡片标题可折叠/展开，状态自动保存。」vs `audit-01` 侧栏的「用法」帮助面板。
- 问题：不同页面用不同方式「自我介绍」——设置页是顶部一句说明，生成页是侧栏面板。形态不统一。
- 建议：统一成「页面顶部一条说明」或「右上角帮助入口」，避免各页自由发挥。

**L3. 品牌行产品说明语义错位（见 H2 超集）。**
- 页面/位置：`audit-01` 品牌行「电赛工程生成器」右侧小字。
- 问题：那串「赛题原文→…→交接提示词」更像流程而非产品描述，放品牌行易被读成面包屑。
- 建议：改为更自然的短描述，或移到步骤区上方。

## 二、三个最高价值改进

1. **浅色主题补齐专属 muted/边框令牌**（对应 H1）。这是当前浅色页最扎眼的问题：辅助文字与输入框边界在亮色下偏灰、发虚，只需要在 `data-theme=light` 增补 1~2 档更深的灰（~`#57606a`）与亮色边框（~`#d0d7de`），就能显著提升两处浅色页的可读性与精致度。

2. **收敛数据列表里的行级「删除」红按钮**（对应 H3 + H4 表头）。把参考库 / PDF 库 / 母版的操作列做统一、把红「删除」降为 hover 态危险图标，是覆盖面最广的一致性修复——三张表、总计数百行都会因此安静下来，与深色沉稳基调契合。

3. **统一空态与首屏引导**（对应 M1 + H2）。收紧生成页顶部三层横向元素（品牌/流程说明/导航/侧栏），给大输入区补统一 placeholder，让空态与设置页同规格。这条直接改善「第一眼印象」和最长的生成页观感。
