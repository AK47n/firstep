# spec — 前端装载清单去化石（frontend-import-fossils）

## 问题陈述

前端页面的**模块装载清单写在 HTML 里**：页面的唯一 `<script type="module">` 用 69 条 `import`
把 337 个名字从 130 个模块里拉进来，其中 **259 个名字宿主正文里一次都没用过**。

这批名字是「纯函数迁进 fx/」与「tab 逐个迁进 ui/」两轮模块化留下的**冻结产物**（迁移期间
每条 `import` 一行地长大，迁完没人回头删）。它们不干活，但**保留着全局失败模式**：
删掉/改名其中任何一个导出，浏览器解析 import 就抛 `SyntaxError`，**整页脚本全灭**——
服务端 `/api/*` 与静态资源全 200，看起来像"卡住"（2026-09-12 真机现场）。
为了防这次已经发生过的坑，仓库养了两条守卫 + 一张 337 行的手工名字登记表，
而"一个导出的存在性"仍写在**三处**（模块 / 登记表 / HTML import），错一处就整页死。

## 方案

把装载清单缩到**只剩宿主真正调用 / 页面真正依赖的名字**（337 → 78 个具名 + 5 条纯装载）：

- **没有页面依赖副作用、且已被别的模块 import 的整条装载删掉**（24 条 / 193 个名字）——
  其中 22 条是纯 fx 域（纯函数，消费者是各自 import 它们的 ui 模块）；
  另 2 条（共享进度面板工厂、文件选择工具件）是纯声明模块，同样由消费者自己 import。
  *（评审整改：原先按目录一刀切"fx 删 / ui 转裸"，把这 2 条也当成了"加载即接线"，判据错了。）*
- **有页面依赖副作用（加载即绑监听器 / 加载即写 DOM）的转裸装载**（5 条 / 14 个名字）——
  `import "/js/ui/x.js"`：照旧执行模块，但不再声明用不到的名字，**把今天只写在注释里的
  "加载即接线"这条边显式化**。
- **部分在用的只删未用的名字**（11 条 / 52 个名字），保留在用的 78 个。
- 迁移墓碑注释**原样保留**（那是历史记录，本 spec 不动文档），标记与样式一个字节不动。

并新增一条结构守卫把这个不变量钉住：**页面不许导入它不使用的名字；零具名使用的装载
必须是裸装载**。守卫先写、先红、再清理、转绿——它是本次改动的测试面。

## 用户故事

1. 作为维护者，我想在改一个 fx 导出的名字时只改一处，以便不再因为"忘了同步 HTML"把整页搞死。
2. 作为维护者，我想让页面装载清单只列真正在用的名字，以便读 HTML 时不被 259 个没用的名字淹没。
3. 作为维护者，我想让"这个 ui 模块是靠被加载才接线"这件事写成代码（裸装载），
   以便不必读注释才知道它的存在意义。
4. 作为维护者，我想让"导入了却没用"在测试里直接变红，以便同类化石不会再长回来。
5. 作为维护者，我想让这次改动不改变任何页面行为，以便可以放心地当天合入。
6. 作为维护者，我想让既有两条守卫（import↔export 对账、防双源回退）继续有效，
   以便不因本次清理削弱原有保护。
7. 作为探针/浏览器用例的作者，我想让 fx 模块底部的 window 探针桥照旧可用，
   以便既有 CDP 探针不必因为这次清理改写法。
8. 作为用户，我想让页面照旧打开就能用，以便感觉不到这次改动发生过。

## 实现决策

- **改的是**：页面唯一 `<script type="module">` 里的 import 清单（69 条语句 → 24 条删除、
  5 条转裸装载、11 条瘦身、29 条不动）。改动可机械判定：`git diff -U0` 的每一行增删
  **都必须是 import 行**（本次实测 16 增 / 40 删，全部命中）。
- **不改**：任何 fx / ui 模块的内容、任何 CSS、任何标记（555 个 id 不动）、任何后端。
- **判据单源**：`tests/js/import-usage.mjs` 的 `unusedImports`——「import 语句里具名的符号，
  必须在宿主脚本**正文**里出现」，正文 = 宿主脚本块（`<script type="module">` … `</script>`）
  去掉 import 语句与整行注释。守卫（`import-usage-guard.test.mjs`）与红证脚本共用它，
  Python 探针是它的镜像且口径逐字对齐（*评审整改：探针早先取到文件尾，被 `</script>` 之后的
  标记骗过，与守卫不同源*）。
- **标识符引用不能用 `\b`**：`$` 不是 word 字符，`\b$\b` 恒假——会把真正在用的 `$`
  （app.js 的 getElementById 别名，宿主 startup 里就在用）误判成未使用。用
  `(?<![\w$])名(?![\w$])`（本次实测踩到，两个独立解析器都判错）。
- **"要不要保留装载"的判据**：剥掉字符串与注释后，模块是否有**列 0 的可执行语句**
  （DOM 接线 / 首帧 DOM 写）——但**排除探针桥**（`if (typeof window !== "undefined")
  Object.assign(window, {...})`）：那是给 CDP 探针调纯函数用的，且模块本身会被它的 ui
  消费者加载，所以它不是"装载必须保留"的理由。
- **裸装载的语义**：`import "/js/ui/x.js"` 与具名 import 一样执行模块顶层代码——
  对这批模块是逐字节等价的行为（它们靠顶层监听器接线）。
- **新守卫的落点**：与既有两条前端结构守卫同层（`tests/js/`），由前端门禁
  `node --test "tests/js/*.test.mjs"` 执行，prepush 与 CI 都跑它。
- **不做**：不给 ui 模块加显式 `init()`、不引入 `js/boot.js`（那是把接线搬出 HTML 的下一步，
  见范围外）；不删 fx 模块本身；不动迁移墓碑注释；不动 `ui/delivery.js` 既有的 window 挂桥
  （与 app.js 的"不挂 window 桥"规则相抵，属既有事实，另立）。

## 测试决策

- **测试面就是这个功能的 interface**：页面装载清单的行为面 = "浏览器能否把这张模块图连起来
  ＋ 那些靠加载接线的模块是否真的接上了"。
  1. **结构守卫（新增）**：判据单源作用在当前文件上，断言"零未使用名字"。先写它 →
     变红（40 条语句 / 259 个名字）→ 清理 → 变绿。先例：`static-import-guard.test.mjs`。
  2. **红证**：真失败日志（把 HEAD 版落到盘上跑守卫的原始输出，退出码 1）＋ 复用守卫判据的
     复放（`guard-red-proof.mjs`），两份都在 `.scratch/frontend-import-fossils/`。
  3. **真浏览器冒烟**：真后端 + chromium，断言 ① 0 个 pageerror / 模块图链接错误；
     ② 被删装载的 fx 探针桥仍在；③ **加载期监听器记账**（加载前钩住 `addEventListener`）
     里必须出现 5 个转裸模块各自的绑定 → 直接证明"顶层接线真的执行了"；④ delivery 的
     加载即写 DOM；⑤ 一次真点击的行为证据。改前/改后跑同一条冒烟，输出**逐行相同**。
     先例：`tests/browser/server.mjs` 夹具（端口 8791）。
- **不测**：不写"某个名字被删掉了"这类实现细节断言（那只阻碍以后的改动）。
- **回归**：前端门禁全量 + pytest 全套各跑一次。

## 范围外

- **把接线搬出 HTML**（`js/boot.js` + 给 import 时接线的 ui 模块补显式 `init()`）——
  本 spec 只做"清单去化石"，搬运是下一步；今天先把地雷拆掉。
- **`tests/browser/` 接进闸门**（先要修掉 HEAD 上已知的 6 绿 3 红）。
- **删迁移墓碑注释**（历史记录，另立）。
- **`ui/delivery.js` 的 window 挂桥与 app.js 规则相抵**（既有事实，另立）。
- **前端其它候选**（ui 层测试缝、跨语言镜像裸奔）——不在本 spec。

## 补充说明

- 工具与证据都在 `.scratch/frontend-import-fossils/`：`probe-imports.py`（plan/check 镜像）、
  `apply-cleanup.py`（按判据重写清单；含"有页面依赖副作用"判定）、`smoke-page.mjs`（浏览器冒烟）、
  `guard-red-proof.mjs` + `guard-run-before.txt`（红证）、`smoke-before.txt` / `smoke-after.txt`（前后对照）、
  `check-reachability.mjs`（22 个 fx 是否仍被模块图引用）。
- 命名纪律：本仓库「装载清单」特指 HTML 里这张 import 表；「登记表」指 `fx-guard` 的
  `DOMAINS` 名字表——两者不是一回事，本 spec 只动前者。
