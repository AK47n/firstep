# 工单：compile-error-jump（编译错误行定位 main.c）

## 问题陈述

修复中心的编译错误列表已有结构化行号（`path:line` + 消息，工单 compile-experience-ui/01），点击行为是展开该行源码片段（`/api/compile/source-line`）。当错误出在 main.c 时，用户更需要在 main.c 预览里看上下文——但现在得自己找到第 8 步的 main.c 卡、手动滚动到对应行、再凭行号核对。行号层与语法高亮层、滚动三同步机制都已存在（ui-polish-8/10 系列 + code-zoom），缺的只是「点一下 → 预览滚动到该行并高亮」这一条联动。

## 方案

错误列表里 main.c 的错误行：整行点击 = 滚动页面到 main.c 预览卡（必要时自动展开折叠卡）+ 预览内选中该行文本（浏览器原生滚动定位，软换行/折行场景同样精确）+ 选区样式 = 持续高亮（再点其他错误行即切换；点击页面别处由浏览器自然清选）。非 main.c 文件的错误行维持现状（展开源码行片段）。

该方案已与用户确认：**main.c 错误行整行点击 = 跳转定位**（替换展开源码行）；**持续高亮，点其他行切换**。

## 用户故事

1. 作为编译失败后看错误的用户，我想要点一下 main.c 错误行就直接跳到预览对应行，以便不用来回滚动对行号。
2. 作为修复循环中的用户，我想要定位行持续高亮，以便修一轮后再看新错误列表时不丢当前位置。
3. 作为错误在其他 .c/.h 文件的用户，我想要既有的源码行展开行为不变，以便已有的排查路径不受影响。

## 实现决策

- 错误行点击分派：错误条目路径 basename 为 `main.c` → 跳转定位；其他文件 → 现状 `fixToggleSource`（展开源码行）。路径先归一 POSIX（照既有的 `fixKeyOf` 归一先例），`./main.c` / 绝对路径 / `main.c` 均命中。
- 行号 → 字符偏移：纯函数（按 `\n` 前缀和计算第 N 行行首偏移与行尾偏移，行尾不含换行符；空行 = 首尾同点）。定位用 `setSelectionRange(off, off+len)`——浏览器原生滚动到选区，textarea 自身处理折行，不依赖像素级行高公式（软换行开启下像素公式会漂移，已确认 `.code-wrap textarea` 为 `white-space: pre-wrap`）。
- 高亮 = 选区样式：`#main-c` 加 `::selection` 强调背景（半透明高亮色）；选区保持即持续高亮，无额外状态内存。
- 页面滚动：main.c 卡 `scrollIntoView`（block 居中，平滑滚动）；卡片若折叠则先展开；预览为空（未生成骨架）→ toast 提示不跳转。
- 列表重建（新一轮编译结果 / 修复后重编译）不清选区——选区状态即是「当前定位」，浏览器行为兜底；新列表的行号对应当前预览内容，行号对应关系成立。

## 测试决策

- tests/js 纯函数单测（正则抽取先例，纯函数不引用模块级常量）：
  - 行偏移计算：多行、超长行（折行不影响偏移——偏移是逻辑行，与视觉折行无关）、空行、末行无换行符、文本含 `\r\n`（C 代码按 `\n` 视之，`\r` 计入行尾长度与 textarea 值一致）。
  - main.c 路径判定：`main.c` / `./main.c` / 绝对路径 / 非 main.c（如 `isr.c`、`modules/led/code/led.c`）。
- headless 冒烟：渲染带错误列表 → 点击 main.c 错误行 → 探针断言 `#main-c` 的 selectionStart/End 等于预期偏移、`#main-c` 所在卡可见（已滚动/展开）。
- 回归：非 main.c 错误行点击仍展开源码行（既有行为不变）。

## 范围外

- 其他文件（模块 .c / isr.c 等）的预览跳转。
- 行号层行号加粗 / 变色（行号列与代码层在折行场景的既有近似对齐，本工单不动）。
- 错误行号与预览内容漂移的根治（用户手工编辑 main.c 后旧列表行号不再对应——重新编译刷新列表即可，属预期）。
- 错误条目的「展开源码行」能力移除（保留，与跳转并存）。

## 补充说明

- 行号对应关系成立的原因：错误列表总是伴随最新一次编译结果，而预览内容 = 该次编译时的 main.c（AI 修复后重编译会刷新列表与预览，行号同步更新）；仅用户手工编辑后旧列表漂移，属预期。
