# spec — 设计报告草稿 + 演示脚本（A2/A3）

> 日期：2026-08-23。来源：`docs/improvement-feasibility-analysis.md` 方向 A2/A3；用户拍板：
> **生成时自动附带**（每次生成自动产出，不做开关、不做手动触发）；**演示脚本纯确定性渲染**
> （零 LLM 调用）。设计报告草稿 = 确定性模板层 + LLM 输出层（一次额外 LLM 调用）。

## 问题陈述

电赛交付物不止工程本身：设计报告与现场演示也是评分硬项。当前工具生成工程后，学生要
**手动另写**设计报告（方案论证、框图、引脚表、测试记录）与演示脚本（评分点 → 操作步骤/
预期现象）——重复劳动且与工程数据容易脱节（报告里的引脚表/模块清单和工程对不上）。

## 方案

生成工程时，工程根自动多出两个纯新增文件（README 先例，逐字节契约不破）：

1. **`设计报告草稿.md`**：报告框架 + 与工程逐字节一致的数据章节。
   - 确定性模板层（不吃 LLM）：工程概览（平台/开发板）、系统框图（文本层次图：
     模块依赖树 + 引脚连接，纯函数渲染，不做 Mermaid）、模块选型表（slug / 简介 /
     依赖）、引脚分配表（与 README 同源同数据）、测试记录模板（验证顺序清单驱动）。
   - LLM 输出层：方案论证（为什么这套架构/选型）+ 软件流程（主循环/关键流程），
     一次调用、结构化输出；失败降级 = 该节中文占位提示，生成不阻断。
2. **`演示脚本.md`**：纯确定性渲染，零 LLM 调用。
   - 演示前准备（编译烧录 + 接线提示）+ 演示步骤表。
   - 有评分点（A1 已落地）→ 按评分点分区组织，每条 = 操作 + 预期现象 + 对应
     功能需求/模块；评分点与功能需求经题面句子编号桥接（score sentence_refs ↔
     requirement sentence_index）。
   - 无评分点 → 降级为功能需求驱动；两者皆无 → 按模块清单列验证演示项。
   - 操作/预期现象 = 结构化模板文字（基于需求描述 + 命中模块能力方向），尾部注明
     「请按实物调整」——诚实定位为脚本框架，不是现场剧本。

两个文件均为纯新增，缺省路径（无 LLM 文本 / 无评分点 / 无需求）下不触碰任何既有
生成文件；LLM 失败只影响报告 LLM 节，不影响生成成败。

## 用户故事

1. 作为参赛学生，我想要生成工程时自动得到设计报告草稿，以便直接把精力花在补充方案
   论证与实验数据上，而不是从零搭报告框架。
2. 作为参赛学生，我想要报告里的框图/选型表/引脚表与工程数据逐字节一致，以便报告与
   代码不打架。
3. 作为参赛学生，我想要演示脚本按评分点逐条列出操作与预期现象，以便现场演示不丢分。
4. 作为参赛学生，我想要演示脚本在没有评分点或需求时也有可用降级，以便任何题面都能
   拿到脚本框架。
5. 作为参赛学生，我想要 AI 写方案论证失败时生成不被阻断，以便主流程永远可用。
6. 作为维护者，我想要两个产物都保持「缺省路径逐字节不变」的回归护栏，以便旧生成
   结果与测试不回归。
7. 作为维护者，我想要演示脚本零 LLM 调用，以便离线/低成本场景可用、测试确定。

## 实现决策

- **新模块 `report_draft.py`**：`render_report_draft(...) -> str` 纯函数——确定性章节
  渲染 + LLM 文本注入（LLM 文本是入参，不是渲染器自己调）。幂等：同输入两次调用
  逐字节一致，恒以单个尾部换行收尾（README 先例）。
- **新模块 `demo_script.py`**：`render_demo_script(...) -> str` 纯函数，同上幂等契约。
- **`llm.py` 新操作 `generate_report_draft`**：输入 = 题面 + 功能需求清单 + 模块摘要 +
  引脚表摘要；结构化输出 `{rationale: 方案论证, workflow: 软件流程}`；走既有
  `_retry_parse` / 预算底座；LLMError 由调用方捕获降级（空文本 + 占位），不抛到生成
  主链。
- **`generator.generate()` 加参数 `report_draft_text: str = ""`**：缺省空 = 不写报告
  文件（旧行为逐字节不变）；非空 = 写 `设计报告草稿.md`（README 之后、上下文清单
  之前）。演示脚本数据（score_points / requirements / manifests）已在 generate 参数
  里，零新参数，写盘同段。两个文件写失败走既有 rmtree 兜底（生成原子性不破）。
- **引脚表单一出处**：报告草稿与 README 的引脚行同源（复用 readme 的 `_pin_rows`
  数据源，同包内共享或提取公共函数，实施时以结构测试钉住防漂移）。
- **评分点 ↔ 需求桥接**：评分点 `sentence_refs`（题面句号）与功能需求
  `sentence_index`（题面句号）同编号体系，演示步骤按此关联归组；关联不上的评分点
  独立成条（不丢弃）。
- **报告文件名**：`设计报告草稿.md`；**演示脚本文件名**：`演示脚本.md`（工程根，
  与 README.md 同级）。
- **失败策略**：LLM 方案段失败 → 报告仍写盘，LLM 节显示中文提示「本节 AI 生成失败，
  请手动补充」；生成摘要照常返回，不新增失败面。
- **摘要展示**：生成摘要结构清单（structure）自然包含两个新文件；后续工单在前端
  摘要卡显式标注并给打开/复制入口。

## 测试决策

- 好测试 = 只测外部行为：渲染函数吃结构化输入 → 断言输出文本的章节/表格/降级分支/
  幂等（同输入两次调用逐字节一致）/ 尾部换行。
- 新 seam：`tests/test_demo_script.py`、`tests/test_report_draft.py`（纯函数，
  参照 `test_readme.py` 先例）。
- `tests/test_generator.py` 扩展：缺省路径逐字节不变（report_draft_text="" 不写新
  文件）+ 有文本时两个文件落盘 + 内容与渲染函数一致。
- `tests/test_llm.py` 扩展：generate_report_draft 协议 / 结构化解析 / 重试兜底
  （照 select_modules 先例）。
- `tests/test_webapp.py` 扩展：生成路由接线（LLM 文本 → generate）+ LLM 失败降级
  （生成仍成功、报告含占位）。
- 全量回归 + mypy 干净是每张工单的收尾门槛。

## 范围外

- 不做 Mermaid 框图（文本层次图，可行性分析决策点 2 已定）。
- 不做报告/演示的「打开即导出 Word/PDF」（纯 Markdown 落盘）。
- 不做设置页开关（用户拍板：生成时自动附带，无开关）。
- 不做演示脚本的 LLM 润色（用户拍板：纯确定性渲染）。
- 不持久化工程历史（C2 已否决）。
- 不写 .contest_context.json 反推侧的报告/脚本恢复（报告/脚本是生成产物不是输入，
  修订重生成时由新流程重新生成）。

## 补充说明

- LLM 调用发生在 webapp 生成路由（薄壳层），generator 保持纯逻辑核心（骨架先例：
  LLM 文本先产出、作为参数传入 generate）。
- 报告的「测试记录模板」与 README「验证顺序清单」同源（sort_verification_order
  复用），避免两套验证顺序漂移。
- 演示脚本尾部统一注明「请按实物调整」，明确定位为脚本框架。
