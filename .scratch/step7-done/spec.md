# 步骤 7「引脚配置」完成判定修正 — spec

## 问题陈述（用户报告）

步骤 7 从来就没有显示完成过：`syncStep7()` 只在 `pinBindings` 非空（用户显式绑过引脚）时才标完成。两条常见路径都被漏掉：① 所选模块在此平台**没有可配置引脚角色**（提示"按默认布线生成，无需配置"）——应视为完成，却永不勾；② 有角色但用户**按默认布线直接生成**——生成成功后步骤 7 仍显示未完成。这是逻辑失误。

## 根因

- `syncStep7()` 判定条件过窄（只有"已绑定"一种完成态），且**只在 `bindRole`/`unbindRole` 中被调用**——`renderPinCard()` 重算角色/展开后从不触发它，无角色与默认布线两条路径没有任何入口会把步骤 7 标完成。

## 方案

完成判定改为四个完成态之一（平台已选且已展开模块为前提）：

1. **无引脚角色**（展开后 `pinRoles()` 为空）→ 完成（无需配置）
2. **有角色已显式绑定**（`pinBindings` 中存在当前角色键）→ 完成
3. **多实例已配引脚**（`instances` 任一实例带 `pin`）→ 完成
4. **已按默认布线生成成功**（`stepDoneSet.has(9)`）→ 完成（隐式接受默认）

前提不满足（未选平台 / 未展开模块）→ 未完成（避免"平台都没选就勾 7"）。

判定抽纯函数 `step7DoneState(state)`（node:test 直抽直测）；`syncStep7()` 变薄壳。调用点补全：`renderPinCard()` 三个出口（未选平台 / 板定义未就绪 / 正常末尾）各调一次——覆盖展开、移除、平台变更、绑定、重置全部路径；生成成功处理器的 `markStepDone(9)` 后追加 `syncStep7()`。

## 测试决策

`tests/js/step7-done.test.mjs` 8 用例：未选平台 ✗ / 未展开 ✗ / 无角色 ✓ / 有角色未绑未生成 ✗ / 已绑定 ✓ / 未绑定但已生成 ✓ / 多实例已配 ✓ / 多实例未配 ✗。

## 范围外

- 不改第 7 步的警告态（`#pin-warn-list` 板载共用警示仍走总览 ⚠）。
- 不改多实例配置卡（6.5）本身；仅把它已配引脚纳入判定。
- 不新增"确认默认布线"按钮（生成成功即隐式确认，满足当前交互）。
