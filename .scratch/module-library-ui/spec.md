# 模块库页 UI 提升（信息查看 + 编辑体验 + 美感）

> 会话/系列 slug：module-library-ui。本 spec 描述「第二个栏目 = 模块库」整轮提升的
> 共同方向；实施按竖切工单逐张落地（见 issues/）。

## 问题陈述

「模块库」栏目是全站管理最原始的面板：表格只有 4 列（模块 / 简介 / 依赖 / 平台版本），
manifest 里丰富的字段（套件、购买链接、备注、引脚声明、文件清单、多实例能力、
Python 副产物模板、功能组互斥）一律看不到；「改简介」用浏览器原生 window.prompt，
无校验反馈、无对照；库大了以后没有搜索、过滤、排序与统计，找不到模块；
「添加模块」表单 12+ 字段一屏堆叠无折叠；视觉上落后于生成页（无令牌化阴影、
无行 hover、按钮裸奔、无统一徽章语言），与近期 ui-polish 系列的整体风格脱节。

## 方案

把「模块库」页提升为信息完整、可检索、可编辑、风格统一的管理面板，分三个主轴：

1. **信息与查看**：表格精修 + 新增全字段「详情」弹窗（复用生成页模块卡已有的
   全量信息渲染与弹窗交互模式）+ 客户端搜索 / 平台过滤 / 排序 / 统计条。
2. **编辑体验**：「改简介」从原生 prompt 升级为模态编辑器（多行输入 + AI 校验
   反馈三态 + 原简介对照）；新增「编辑」弹窗承载套件 / 购买链接编辑与平台版本
   文件增删。全部复用现有后端端点，零新端点。
3. **美感**：与生成页同一套令牌体系（阴影、圆角、行 hover、斑马纹、焦点态、
   徽章配色对齐模块选择卡），危险操作视觉强化，空态 / 加载态打磨，
   添加模块表单分区折叠。

主体形态维持**表格**（管理场景信息密度优先），不做卡片网格、不做双视图。

## 用户故事

1. 作为模块库管理者，我想要在每行看到「详情」入口，以便一键查看该模块的全量
   信息（依赖 / 多实例 / 副产物模板 / 互斥组 / 各平台备注 / 套件 / 购买链接 /
   文件清单 / 引脚声明表）。
2. 作为模块库管理者，我想要详情弹窗的字段与生成页模块卡详情一致，以便两处看到
   的信息互相印证、不产生两套认知。
3. 作为模块库管理者，我想要在表格上方输入关键字即可过滤行（匹配 slug / 简介 /
   依赖 / 套件 / 备注），以便库大了以后快速定位模块。
4. 作为模块库管理者，我想要按平台、按验证状态（已验证 / 未验证 / 硬件绑定）过滤，
   以便分别看到「我没验证过的模块」或「只给 STM32 用的模块」。
5. 作为模块库管理者，我想要按 slug / 平台数 / 依赖数排序，以便按我关心的维度浏览。
6. 作为模块库管理者，我想要一个统计条（模块总数、各平台覆盖数、已验证数、
   硬件绑定数、互斥组数），以便对库的规模与健康度一目了然。
7. 作为模块库管理者，我想要悬空依赖被显式标注（模块声明依赖了库中不存在的 slug），
   以便及时发现库的数据质量问题并在详情弹窗里核对。
8. 作为模块库管理者，我想要「改简介」在一个模态里完成（多行文本、保存中 / 
   AI 校验中 / 校验通过 / 校验驳回都有明确反馈），以便不再依赖浏览器原生弹窗。
9. 作为模块库管理者，我想要「编辑」弹窗里能改套件型号与购买链接（平台级），
   以便录入硬件身份字段不再需要手动编辑磁盘 manifest。
10. 作为模块库管理者，我想要「编辑」弹窗里能增删各平台版本的文件（从磁盘选择或
    直接输入），以便补录 / 清理平台版本都在 UI 内完成。
11. 作为模块库管理者，我想要「添加模块」表单按「基本信息 / 平台版本与文件 /
    进阶能力」分区折叠，以便长表单不挡视线、默认只展开第一步。
12. 作为模块库管理者，我想要表格、徽章、按钮、空态的视觉与生成页一致，以便整个
    工具观感统一、减少割裂感。
13. 作为模块库管理者，我想要删除等危险操作有明确的一次确认与视觉警示，以便防误触。

## 实现决策

### 模块与复用

- 前端新增一组**纯函数**（搜索过滤、排序、统计汇总、悬空依赖检测、摘要行格式化），
  与现有纯函数层（moduleGridHTML / moduleInfoHTML / score 系列 / groupOfSlug 系列）
  同范式：不碰 DOM、可独立喂 node:test。
- 详情弹窗**复用**生成页已有的全量信息渲染（moduleInfoHTML 及其平台分段）与弹窗
  交互模式（遮罩 / ✕ / Esc 关闭）；模块库调用时不给平台上下文（展示全部平台，
  不显示「某平台无此版本」提示）。
- 徽章统一样式复用模块选择卡的平台徽章（已验证 / 未验证 / 硬件绑定 / 内嵌母版），
  `title` 提示保留。
- 表格视觉复用 ui-polish 系列已令牌化的卡片 / 表格样式变量，不再新造令牌。

### API 契约（全部复用现有端点，零新后端）

- `GET /api/modules`：全量模块（to_dict）；搜索过滤排序在客户端做（列表数据已全量
  在手，不为检索新增服务端参数）。
- `PUT /api/modules/{slug}/description`：body `{description}`；AI 校验不一致时后端
  返回错误 → 模态保持「校验驳回」态并展示原因；成功返回新 manifest → 重渲染表格。
- `PUT /api/modules/{slug}/platform-identity`：body `{platform, kit?, source_url?}`；
  空值 = 保留原值（补填语义），成功返回新 manifest。
- `POST /api/modules/{slug}/platform-files`：body `{platform, files:{文件名:内容},
  hardware_bound, kit?, source_url?}`；成功返回新 manifest。
- `DELETE /api/modules/{slug}/platform-files`：body `{platform, filenames:[...]}`；
  成功返回新 manifest。

### 具体交互

- 表格列调整为：模块（slug + 悬空依赖警示标）/ 简介（截断 + 全文 tooltip）/
  依赖（含副产物摘要，现状保留）/ 平台版本（徽章组 + 文件数 / 套件摘要）/
  操作（详情 · 改简介 · 编辑 · 删除）。
- 详情 / 改简介 / 编辑各自独立弹窗；删除保留一次确认（确认文案含模块目录语义）。
- 统计条：模块总数、按平台计数、已验证数、硬件绑定数、互斥组数（组数取
  exclusive_group 去重 id）；有悬空依赖时统计条显示红色警示计数。
- 添加模块表单：折叠卡分区，默认展开「基本信息」，平台版本与文件、进阶能力
  折叠；折叠样式沿用设置页整卡折叠的先例。
- 空态、加载态文案沿用现有「📦」风格并在视觉上对齐。

### 模式变更 / 架构决策

- 不引入新依赖、不改后端、不动 manifest 模型。
- 交互逻辑继续下沉纯函数（先例：score-points-format、groupOfSlug 系列），
  DOM 事件层只做转发，保持 node:test 可测。

## 测试决策

- 主 seam = `tests/js` 的 node:test 纯函数单测（先例：moduleGridHTML /
  moduleInfoHTML / score-points-format / groupConflicts）。覆盖：过滤匹配规则、
  排序稳定性、统计汇总、悬空依赖判定、摘要格式化、简介校验状态机（若实现为
  纯状态函数）。
- 交互层（弹窗开合、折叠、模态编辑流转）延续现有浏览器级验证先例
  （probe-*.mjs + 截图 + 冒烟清单），不新增单元测试面。
- 后端零改动 → pytest 不新增业务测试；现有端点测试作回归保障。
- 全量回归：pytest 全量 + tests/js 全量 + 冒烟清单保持全绿。

## 范围外

- 全量 manifest 可视化编辑（备注 / 引脚声明 / 依赖 / 多实例 / 互斥组）——
  后端无对应端点，本轮不做（备注等通过详情弹窗只读展示）。
- 服务端搜索过滤参数（/api/modules 查询参数）——客户端过滤已够用。
- 卡片网格视图 / 表格-卡片双视图切换。
- 移动端 / 窄屏专项适配（表格维持水平滚动即可）。
- 深色主题（若有独立工单系列，另行处理）。
