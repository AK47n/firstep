# 01 — 模块库表格视觉令牌化

**要做什么：** 模块库页表格从「裸表格」升级为与生成页同一质感的管理面板：行 hover、
斑马纹、圆角、焦点态、统一样式的操作按钮与平台徽章；空态 / 错误态打磨。纯视觉纵切，
不改任何交互逻辑与数据流。

**被谁阻塞：** 无——可立即开始。

**状态：** resolved

- [x] 表格行 hover 与生成页 / 参考库表格一致（沿用全局 `tbody tr:hover`，不新增底纹与新令牌值；参考库表无斑马纹则本表亦无）

## 第十轮：目视验收的机器化替代（2026-09-09 同会话 · 按第九轮「下一轮建议」第 2 项）

**为什么不是「看一眼截图」**：本轮执行 agent 的模型不声明图像输入（`read_image` 直接报
`model ... does not declare image input`），「人工目视」这一半无法由 agent 兑现。因此改为
**两条独立证据链交叉**，并顺带修出目视才看得见的缺陷：

| 证据链 | 做法 | 结果 |
|---|---|---|
| ① 像素级（看**产物本身**） | 自解 `.scratch/module-library-ui/01-table-shot.png`（1418×802）：逐行/逐列底色众数、相邻行带均值差、纯色长条与色族分类 | 无斑马纹（相邻行 ΔRGB < 0.6 色阶）、表头 `#1c2128` 底纹、行内**裸文字徽章**、红色只出现在删除钮、四钮几何一致 |
| ② 渲染态（看**页面实况**） | headless Chrome（CDP 9251）+ webapp 8000，视口设 1418×802 复现同一滚动态，量 93 行几何与计算样式 | 与 ① 坐标逐项对齐（卡片 / 表格 / 表头 / 四列 / 四钮 x 坐标一致），断言面同源 |

**目视查出的两个缺陷（均已修 + 已加机器判据，故 6 项机器判据不因此失效）**：

1. **「内嵌母版」是裸文字徽章**（`fx/module.js` 两处 `<span class="badge">` 无颜色变体）
   ——只有形状（padding/圆角/字号）没有底色，夹在彩色平台胶囊之间像没套样式。
   修：新增 `.badge.neutral`（中性底 `rgba(139,148,158,.15)` + `--muted` 字，写法同
   `.badge.ref-none`），两处标注改挂该变体；守卫 `tests/js/module-library.test.mjs`
   「「内嵌母版」徽章必带颜色变体类」（双向：渲染侧带类 + index.html 真有该变体规则 + 防回退）。
2. **截图取景把标题切了一半**：原取景 `#tab-library.scrollIntoView({block:'start'})` 使
   `scrollTop` 落在 68，而 header 是 `position:sticky; top:0`（高 48px）→ 标题 h2 被吸顶栏盖住，
   第一眼像渲染故障。修：冒烟改为**滚回页顶**再截（不隐藏任何 chrome），并新增收尾截图
   `01-table-shot-final.png`（干净页重载后重截）。

**冒烟脚本本轮 +4 项断言**（71 → 75）：简介列截断从「title 非空」升级为
「DOM 文本 = 纯件现算截断（26 字符 + …）且 ≠ title 全文」；新增「每枚徽章都带颜色变体类」
与「『内嵌母版』徽章有中性底色」。实跑 **75/75 PASS**（见盘点第十轮收口）。

**结论**：机器可判的 6 项验收 + 冒烟/回归两项已全部勾（第九轮已勾，本轮补强判据后复跑仍全绿）；
**「人工目视」一项保持未勾**——本轮提供的是可复现的像素级 + 渲染态证据，
人眼确认那一下仍留给人（若接受机器判据口径，可在评审时改判）。

**目视结论（视觉通道，1418×802 深色主题）**：页面标题「模块库」**完整可见、未被吸顶栏遮挡**

（`STM32 / 已验证`、`MSPM0 / 已验证`）+ 灰色 `内嵌母版`；操作列四钮同套、**仅「删除」为红字**；

总评「正常渲染、样式统一的界面」。

**一处需要说清的判读（已定量核对，不是缺陷）**：视觉通道把 `内嵌母版` 读作「几乎没有明显底色 / 近裸文字」。
像素核对给出的结论是**底确实画了**——该徽章是 60×19 圆角块、内部 `(43,48,56)` 命中 **631 px**
（占该框 1140 px 的 55%，其余为文字与抗锯齿），而行底为 `(26,31,38)`，**Δ=(+17,+18,+18)**：

```
期望值 = rgba(139,148,158,.15) 叠在行底 (26,31,38) 上 = (43,49,56)   ← 与实测 (43,48,56) 逐通道 ≤1 吻合
```

即第十轮新增的 `.badge.neutral` 在图上是成立的；它「看着弱」是因为这是**刻意的最弱中性变体**
（写法与 `.badge.ref-none` 同源），夹在彩色平台胶囊之间本就该最轻。**不判为缺陷**；
若要让它在视觉上更明确，属设计调值（改 alpha），需设计裁决，不在本单范围。
