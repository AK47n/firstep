# 硬件检测栏目工程卫生（评审 P2 七项 + 前端守卫补洞 + 两个大文件按职责拆分）

**来源**：`docs/improvement-review-hwcheck.md` 的 **P2 七项（建议 8–14）**，加上本轮立项前**实测新发现的两条**
（见「补充说明」的立项读数）——它们不是评审漏写的建议，是评审那条建议（P2-12 的守卫口径）**照字面做会炸**、
以及评审没看见的一个**守卫盲区**。

**上一批的关系**：P0+P1 七项已由 `.scratch/hwcheck-hardening/`（`01`–`07`、`09`–`11`）落地并全绿；
本批是它的**后续清尾**，做完即进发版（v1.3.1）。

## 问题陈述

**对学生（用户）**：这一批里有五处是"页面说了不实的话或说了等于没说"，其中三处在学生最容易撞上的路径上：

1. 几处提示把 markdown 粗体标记**原样吐进页面**——学生看到的是字面星号（`**…**`），
   而其中一条（默认引脚撞脚后的修法说明）在双通道平台上**几乎必现**。
   **实测 5 处、跨 3 个文件**（评审点名 3 处都在检测栏目；另 2 处在代码编辑器与向导，
   其中一处走 `textContent`，所以不是"只有 innerHTML 才有这个问题"）。
2. 检测记录文件**读失败**时，页面把"读不到"说成"这份记录坏了"，并建议**把它删掉重填**——
   文件被别的程序占用或权限不足时，照做就是**删掉自己的检测记录**。
3. 板级事实（板载 LED 在哪几个引脚）在后端**硬编码**了一份，改板定义不会改这句话，
   页面上就会出现"照着它接是错的"；而排障侧又把"清单文案里出现过的脚"当作引脚白名单的**来源**——
   文案与判据互为因果，谁都不以数据为源。
   （**实测更正**：板库 JSON 里**没有** LED 的结构化事实，只有自由文本 `notes`；
   平台级真源是选型数据里那两个常量。）
4. 母版配置**存在但读不出来**（被占用 / 权限 / IO 错）时，容量判定**整段静默消失**——
   预览放行、生成才 400，而学生在页面上看不到任何"判不了"的提示。
   （**实测更正**：评审说这里"与自述矛盾"不成立——该文件的 docstring 本就写着"判不了就不判"；
   真问题不是自相矛盾，是**把判不了伪装成判过了**。）
5. 多实例器件（LED / 按键，声明最多 8 路）**只验第一路**，页面上却回显通道数——
   学生装了 4 个 LED，只看见 1 个被验过，且没有任何地方告诉他"只验了首路"。

**对维护者（这轮的主要受益人）**：地基有三处塌陷，且都不是"再写点用例"能补的：

6. **ui 层的 156 条覆盖全是源码串匹配**（`readFileSync` + `includes`）——断言"源码里有这行"，
   而不是"点下去会怎样"。上面第 1、3 条的盲区正是这一层：串匹配看见 `**` 也照样绿。
7. **"用了没 import"这个方向没有任何守卫**：全仓前端有 609 个名字经 `Object.assign(window, …)`
   挂在 `window` 上（66 个模块），而现有守卫只管反方向（"import 了没用"）。
   实测**已经有 4 处**调用位靠这条老式全局桥侥幸解析——其中一处正是上一批 `hwcheck-hardening/07`
   声称"让 `hwcheckErrorHTML` 有了产品侧消费者"的那一行：**浏览器用例真的绿**（桥兜住了），
   但它没有 import 边，所以在导出面守卫眼里它**仍然是只被测试消费的死导出**——
   "改一处、守一处"的账在两处同时对不上。
8. **两个 1300+ 行的单文件把八类职责混在一起**：纯函数层一个文件里住着状态归一 / 生成与编译降级 /
   器件与接线 / 逐件计划 / 命令台 / 排障 / 自建件 / 跨页衔接；DOM 层一个文件里住着状态、渲染编排、
   "我的器件"增删改查、以及全部动作与请求。后果不是"不好看"，而是**每次改动都要在一个大文件里
   重新建立上下文**，评审列举的那批缺陷有一半正是这样漏出来的（`initHwcheck` 一人 272 行、
   绑 15 处事件委托）。
9. 账本与自述漂移（`module-hwcheck/09` 正文写"16 形态"而其读数文件已是 18；两份核查报告已过期；
   用户可见的 400 文案里印着内部工单号；同一段 docstring 逐字重复且条数与标题不符）；
   浏览器用例跑完留一条 `[afterEach]` 告警——**成因已定位**：`clearDevices()` 连续 5 轮派发移除
   都没等到器件集清空（真实成因待诊断，**不许用"告警无害"结案**：它也可能是"移除按钮在某个状态下
   真的不生效"这条产品缺陷）。

## 方案

一句话：**先把"页面说的和事实对上"（5 条学生可见），再把"守卫闭不上眼"（测试缝与一条新守卫），
最后把两个大文件按职责拆开（纯搬迁、零行为变化）**。

顺序是有理由的：前两条改的是**行为**，必须在拆分之前落地——拆完再改，diff 会散在六个新文件里，
评审与回滚都变难；拆分放在最后，是因为它是"零行为变化"的机械搬迁，验收判据就是**既有的全部门禁**，
而它带来的风险（2600 行移动）不该和发版要带的行为修复混在同一批 diff 里。

拆分的做法：**先展开、后收口**。第一步把纯函数层按职责段整段搬进若干新模块（旧文件暂转再导出，
保证一次提交内门禁全绿）；第二步迁移全部消费者（DOM 层、前端用例、浏览器用例）并删掉旧文件。
DOM 层同理（入口只保留对外那两个导出，其余按"核心渲染 / 我的器件 / 动作与请求"三片搬走）。
**拆完必须同时满足既有四条结构守卫**：每个模块从装载根可达、全图 import↔export 逐名对账、
导出面每条导出都有消费者、ui 模块之间无环——这四条既是约束，也是这次拆分的验收。

## 用户故事

**学生视角**

1. 作为参赛学生，我想要页面上的提示**只显示它要显示的话**（不出现字面星号），以便我不必猜"这星号是什么意思"。
2. 作为参赛学生，我想要检测记录**读不出来**时页面说的是"读不到、可能被占用"，而不是"记录坏了、删掉重填"，
   以便我不会照着提示删掉自己填过的检测记录。
3. 作为参赛学生，我想要页面上写的板载 LED 引脚与这块板子的**定义一致**，以便我照它接线不会接错。
4. 作为参赛学生，我想要母版配置读不到时**当场收到一句中文理由**（而不是"预览通过、生成 400"），
   以便我知道该去修什么，而不是以为程序有问题。
5. 作为参赛学生，我想要多实例器件（LED / 按键）的检测**如实说明"只验第一路"**，
   以便我装了 4 个 LED 时不会以为另外 3 个也被验过了。
6. 作为参赛学生，我想要勾选器件 / 勾选上板清单之后**光标还在我刚勾的那一项上**，
   并且能用键盘完成同样的操作，以便我连续勾十几项时不用重新用鼠标找位置。
7. 作为参赛学生，我想要编译 / 烧录这类**要等**的动作有可被读屏念出的状态与忙碌态，
   以便我不用靠猜"它到底在跑没有"。
8. 作为参赛学生，我想要**看得见的失败**（预览失败、记录读失败、配置读失败）说法各不相同，
   以便我照着提示走就能修好，而不是被引到不相干的地方。

**维护者视角**

9. 作为维护者，我想要"任何模块的正文里**用了却没 import** 的名字"当场被守卫拦下，
   以便下一次再有人靠 `window` 全局桥写代码时，**在提交前**就红，而不是等到线上某天才炸。
10. 作为维护者，我想要 ui 层的关键行为（焦点、忙碌态、"点了会怎样"）由**真浏览器用例**作证，
    以便评审里那类"串匹配看不见的缺陷"下次能被自动抓住。
11. 作为维护者，我想要"导出只被测试消费"这件事**不再可能悄悄发生**（桥依赖归零之后，
    判据 D 的产品侧消费者口径才真的成立），以便"改一处、守一处"的账能对上。
12. 作为维护者，我想要纯函数层与 DOM 层各按职责分居**小而专**的模块（每件一眼能读完），
    以便我在改一个功能时不必先读完 1300 行、也不必担心碰坏另一类职责。
13. 作为维护者，我想要账本、自述与读数**互相对得上**（形态数、报告时效、用户可见文案里不出现工单号），
    以便下一轮接手的人不必再花时间分辨"哪句是过期的"。
14. 作为维护者，我想要浏览器门禁跑完**零告警**，以便下次的真红不会被既有噪声掩盖。

## 实现决策

- **纯函数层（fx）按职责拆成六件**：状态归一与载荷/平台卡/提示文案、生成与编译降级/上板清单/最近检测、
  器件选择与接线表/撞脚/建议顺序、逐件计划与未专精与自建件计划与命令台、现象回填与 AI 排障、
  跨页衔接。拆分**只搬不改**：函数体与注释逐字保留（包括各自的 `window` 桥条目与 `eslint` 无关的注释块），
  唯一允许的变化是 import/export 语句与文件头说明。
- **DOM 层（ui）拆成四件**：入口（对外两个导出：面板渲染与初始化，含事件委托接线）、核心渲染、
  「我的器件」增删改查与草稿、动作与请求（预览/生成/采纳/恢复/编译/烧录/清单同步/排障提交）。
  **约束**：ui 模块之间只允许单向依赖（无环守卫），跨件调用方向在实现时定死，必要时把共享状态
  下移到核心件、或以回调注入，**不许**用 `window` 桥绕过。
- **新增一条守卫（判据本体与既有守卫同源）**：模块正文（**注释/字符串已掩码**）里处于**调用位**的
  自由标识符，不得命中「`window` 桥发布的名字」；本模块 import 的本地名、本模块自身声明与自身导出除外。
  守卫必须自带正向对照（注入一处依赖 → 必须报），并保留一条"掩码/边界"自检（注释里出现同名词不算）。
- **桥本身不删**：`Object.assign(window, …)` 是浏览器探针与页面内联脚本的既有出口，本轮**只禁止模块正文依赖它**，
  不改它的发布清单。
- **导出面守卫的消费者集合不动**，并在其文件头用本轮实测数字（消费者 169 → 排除 `tests/js` 后 11、
  零消费者导出 0 → 171）钉住"为什么不能照 P2-12 字面做"。
- **板级事实单源（已拍板：以选型数据的平台默认为源）**：页面上凡出现"这块板子的 LED 在哪几个引脚"，
  都从选型数据里的平台默认（平台 → LED 通道映射 / 首引脚）取；**不动板库 JSON**（里面没有 LED 的
  结构化事实，只有自由文本 `notes`）。排障侧的引脚白名单同样改以同一数据为源
  （不再以"清单文案里出现过"为源）。取不到时的行为必须**明说**。**"母版没导入"与"母版读不出来"
  要分开**：前者是平台不可用（页面已有状态可依），后者是**失败**，必须给中文理由。
- **记录写的正确性形状**：唯一临时名 + 原子替换 + **短临界区**。明确**不照** `_generation_guard`
  （那是"每键互斥 + 冲突 409"，用在记录写上会让学生"生成期间连勾选都存不了"）；
  跨 LLM 时延的那条路径要把调用移出临界区，临界区内只做"重读 → 合并 → 写"。
- **记录写**：唯一临时名 + 原子替换，并把"读-改-写"整段纳入一把锁（与仓内既有锁原语同款）；
  并发两处入口（清单勾选 / 排障回填）都不许丢更新。
- **多实例口径**：本轮**只做如实说明**（页面与配方自述"多实例只验首路"），不按实例展开
  （展开要动配方 schema，属新 spec）。
- **无障碍**：勾选类重绘后恢复焦点（记住 id → 重绘 → 聚焦回去）；三个只有 placeholder 的输入
  进既有的无障碍标签表；编译/烧录状态行加 `aria-live` 与忙碌态禁用；器件卡若与生成页共用渲染件，
  则**只补该页需要的键盘/语义**，改动同时受生成页与库页用例约束。

## 测试决策

- **好测试 = 外部行为**：断言"点了会怎样"（DOM 状态、请求体、文件内容），不断言"源码里有这行"。
  既有 ui 断言是源码串匹配，本轮**不再新增**这类断言；新增的 ui 行为断言一律进真浏览器门禁。
- **测试缝（已与用户确认）**：
  - **真浏览器门禁**（真浏览器 + 真后端，本机一条 spec 约 35–80 秒）——焦点恢复、键盘可达、
    `aria-live`/忙碌态、"点了会怎样"这类运行时行为；
  - **前端门禁**（`tests/js`，秒级）——纯函数行为、以及**新守卫**（全局桥、字面星号、导入对账）；
  - **pytest**——服务端行为：配置读失败的中文 400、记录读失败与坏 JSON 分开话术、板级事实单源、
    并发写不丢更新；反证一律"注入旧形态 → 必须红 → 复原逐字节相同"。
- **拆分怎么验**：不新增判据，跑**既有的全部门禁**（全套 pytest + 前端门禁 + 浏览器门禁），
  加一条"搬迁完整性"自检——按导出名集合与函数体逐字比对搬迁前后（名字集合必须相等，
  函数体除 import/export 行外逐字相同）。这条自检是本轮唯一为拆分新造的判据。
- **既有先例**：结构守卫四条（装载根可达 / 全图对账 / 导出面 / ui 无环）、纯件不回流守卫、
  `import-usage-guard`（反方向）、以及反证脚本 + 读数落盘的记账习惯。
