# 14 — 库数据里的 markdown 粗体标记：渲染层支持 `**粗**`（12 号单发现的既有缺陷）

**要做什么：** 学生在检测页与模块库里**看到的是字面星号**：`**本件必须接个已知电压才有意义**`
而不是加粗的"本件必须接个已知电压才有意义"。让渲染层把库数据里成对的 `**…**` 渲染成
`<strong>…</strong>`——**先转义、后替换**，覆盖三处库数据来源：配方说明（`note.lines`）、
模块简介（`description`）、模块的平台备注（`platforms.*.notes`）。

**被谁阻塞：** 无——可立即开始（12 号单已把那条判据面收窄到产品文案，本单把它放宽回库数据）。

**状态：** resolved

**来源**：12 号单新增的「页面上零字面星号」判据当场抓到（第一版判的是整栏可见文本）。
**实测规模**（只读量具，命令在票尾）：

## 为什么是"渲染层支持"而不是"扫数据去掉星号"

两条路都是"页面不再出现字面星号"：扫数据要改 **75 个库文件 / 约 4300 处**（还丢掉作者写的
强调），渲染层是**一处代码 + 若干渲染点**且保住本意；库数据本来就是按 markdown 写的
（仓库里 `fx/markdown.js` 是 .md 素材的现成先例）。**用户 2026-09-27 拍板走渲染层。**

## 约束

- **先转义、后替换**（顺序不许反）：`esc(text)` 之后再做 `**x**` → `<strong>`。库里/用户填的
  `<script>` 照样是文本，替换出来的 `<strong>` 才是标签。
- **两个入口，各管一处**（单源在 `fx/core.js`）：
  · `escRich(text)`——**正文**用（成对标记转 `<strong>`）；
  · `escPlain(text)`——**属性**用（`title="…"` / 输入框 value：那里 `<strong>` 只会被当字面量
    显示，所以只把标记剥掉）。
- **孤立标记不许漏到页面上**：成对替换之后仍残留的 `**` 一律剥掉。理由是真实的：行级截断
  （`hwcheckOrderDesc` 60 字、模块卡简介 26 字）**会从成对标记中间切开**，只做成对替换的话
  截断处会留下半截星号——那正是本单要消灭的东西。
- **属性里的正文**（模块卡 `title`）用 `escPlain`，别把标签塞进属性。
- **不动库数据**（`library/**` 一个字节不改；生成链与配方数据不受影响）。

## 范围外

- `library/**` 的任何内容修改。
- 其它栏目的库数据渲染（参考文件库简介 / 赛题库题面）——本单只覆盖检测页与模块库这两处

## 结论（读数与账）

**做了什么。** 库数据里的成对 `**…**` 现在渲染成 `<strong>`，学生看到的是加粗的那句话。

| 落点 | 文件 | 输入是什么 |
|---|---|---|
| `escRich(text)` / `escPlain(text)`（**单源**） | `fx/core.js` | 先 `esc` 再替换；孤立标记一律剥掉 |
| 配方说明行 `hwcheckSectionNoteHTML` | `fx/hwcheck-plan.js` | 配方 `note.lines`（2434 处） |
| 建议顺序说明行 `hwcheckOrderHTML` | `fx/hwcheck-wiring.js` | 模块 `description`（截断切开的标记也剥干净） |
| 说明弹窗四问正文 `moduleIntroHTML` | `fx/module.js` | `intro` 分段（来自 `description`） |
| 说明弹窗「备注」行 | `fx/module.js` | `platforms.*.notes`（1844 处） |
| 说明弹窗正文回落（无 intro 时） | `fx/module.js` | `description` |
| 模块卡简介（正文 / title） | `fx/module.js` | `escRich`（正文）/ `escPlain`（属性） |
| 模块库表简介列（正文 / title） | `fx/module.js` | 同上 |

两个入口按**去处**分是刻意的：`title="…"` / 输入框 value 里标签只会被当字面量显示，所以那条路
只剥标记（`escPlain`）——**属性里塞标签**是比字面星号更难查的一类错。

**判据（两层）。**

| 层 | 判据 |
|---|---|
| 前端门禁 | `tests/js/rich-text.test.mjs` 5 条：成对转换、**先转义后替换**（`<script>` 仍是文本）、孤立/半截标记剥掉（**行级截断**的真实形态）、属性路径不产生标签、无标记时与 `esc` 的关系 |
| 浏览器门禁 | `库数据里的说明文字零字面星号`（**库数据**这一半，12 号单那条只判产品模板文案）：配方说明行 + 说明弹窗 + 模块卡（正文与 title 两条路）四条腿，并断言成对标记真的变成了 `<strong>`（不是被剥掉） |

**反证（`probe-14-red.txt`，3/3 成立）**：① 配方说明行退回 `esc()`；② 弹窗备注行退回 `escHtml()`；
③ 帮助函数退回"只转义不转换"——每段都是"注入即红、复原 sha256 逐字节相同"。

**跟着动的一处旧判据（口径收窄，记账）**：09/10 的搬迁完整性自检 ② 判"与搬前快照逐字相同"，
而搬迁完成不等于这些函数从此不许改——本单动了两个声明就会被它判红。于是给它加了一张
**逐条记账**的豁免表 `LATER_EDITS`（名字 → 改它的工单；本单两条：`hwcheckSectionNoteHTML` /
`hwcheckOrderHTML`），并补一条体检：**没登记进表的改动照旧报**（正向对照钉着）+ 表里的每条
都必须在快照与六件/四件里找得到（防表腐烂）。**不是"谁都别判我"的挡箭牌。**
