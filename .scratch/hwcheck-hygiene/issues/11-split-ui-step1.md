**要做什么：** DOM 层那一个 1312 行的大文件按职责拆成四件：**入口**（对外仍只有两个导出：

## 约束（拆完必须同时成立）

- **ui 模块之间单向依赖、无环**（`ui-cycle.test.mjs`）：入口 → 三件 → 核心渲染，
  不许出现核心 → 动作/器件的反向边。跨件调用方向在实施时**定死并写进文件头**；
  若某处非要有反向调用，改由**入口注入回调**或**把共享状态留在核心件**，
  **不许**用 `window` 桥绕（这正是 01 号单要消灭的形态）。
- **每个模块从装载根可达**（`fx-guard` 判据④）、**全图 import↔export 逐名对账**、
  **零未使用具名 import**。
- **对外契约不变**：`ui/hwcheck.js` 仍导出 `initHwcheck` 与 `renderHwcheckPanel`
  （`boot.js` 的装载清单与既有用例都指着它们）；`INDEX`/DOM 契约（`ui-dom-contract`）不变。

## 结论（读数与账）

**这笔做了什么。** `ui/hwcheck.js`（1401 行 / **59 个顶层声明** / 零 window 桥条目）按职责拆成四件：

| 文件 | 行数 / 字节 | 内容 |
|---|---|---|
| `ui/hwcheck.js`（入口） | **184 行** / 8866 B | 两个导出（`initHwcheck` ＋ 转出的 `renderHwcheckPanel`）＋ 23 处事件委托接线（与搬前同数） |
| `ui/hwcheck-core.js` | 540 行 / 27075 B | 栏目状态 + 小工具 + 各区块渲染 + 面板编排（含 `renderMyDevices`） |
| `ui/hwcheck-devices.js` | 355 行 / 15198 B | 「我的器件」增删改查与草稿 + 4 段下沉的委托处理分支 |
| `ui/hwcheck-actions.js` | 575 行 / 27523 B | 动作与请求 + 11 段下沉的委托处理分支 |

对外契约一个字没动：`boot.js` 仍 `import { renderHwcheckPanel, initHwcheck } from "/js/ui/hwcheck.js"`
（**再导出**，形态 A `export { … } from "…"`——形态 B `import …; export { x };` 过不了导出面判据 T，
09 号单实测过）。入口 184 行 ≤ 250 ✓，且**票面"现状"表的一处归属做了实测调整**（见下）。

**一处实测调整（要记账）：`renderMyDevices` 归核心件，不归器件件。** 票面现状表把 333–585
整段划给器件件，但面板编排 `renderHwcheckPanel` 要调 `renderMyDevices`，而核心件不许反向
import 器件件。把"渲染"留在核心件、"增删改查与草稿"放进器件件，换来的是一条**零回调、
零反向边**的依赖链（入口 → 器件/动作/核心；器件 → 动作/核心；动作 → 核心；核心不 import ui）。
这正对上票面那句"必要时把共享状态下移到核心件、或以回调注入"——本单选了前者，一条回调都没有。

这一处就是它的实证。
