工单 hwcheck-hygiene/14：库数据里的 markdown 粗体标记改在渲染层转 <strong>

一、问题（12 号单新增的判据当场抓到，不是本单引入）
- 库数据按 markdown 写，成对 `**…**` 经 esc() 原样进页面 → 学生看到
  `**本件必须接个已知电压才有意义**`
- 实测规模：配方 note.lines 2434 处、74 个 manifest 的 platforms.*.notes 1844 处、
  description 6 处；02 号单的判据 ⑨ 只扫 JS 产品串，这一层一直没判据看着

二、做法（用户拍板：渲染层支持，不扫数据）
- fx/core.js 出两个纯函数（单源）：escRich（正文：先 esc 再把成对 `**x**` 转 <strong>）、
  escPlain（属性：只剥标记——title/输入框里标签只会被当字面量显示）
- **孤立标记一律剥掉**：行级截断（建议顺序 60 字 / 模块卡简介 26 字）会从成对标记中间切开，
  只做成对替换会在截断处留半截星号
- 渲染点：配方说明行 / 建议顺序说明 / 说明弹窗四问正文与备注与简介回落 /
  模块卡简介（正文 escRich、title escPlain）/ 模块库表简介列；library/ 一个字节没动

三、判据（两层）
- 前端门禁 tests/js/rich-text.test.mjs 5 条：成对转换、**先转义后替换**（<script> 仍是文本）、
  孤立/半截标记剥掉、属性路径不产生标签、无标记时与 esc 的关系
- 浏览器门禁「库数据里的说明文字零字面星号」：配方说明行 + 说明弹窗 + 模块卡正文与 title
  四条腿，并断言成对标记真的变成 <strong>（不是被剥掉）

四、反证 probe-14-red.py 3/3：配方说明行退回 esc() / 弹窗备注行退回 escHtml() /
帮助函数退回"只转义不转换"——每段注入即红、复原逐字节相同

五、跟着动的一处旧判据（口径收窄，记账）：09/10 的搬迁完整性自检 ② 判"与搬前快照逐字相同"，
搬迁后合法修改会误红 → 加逐条记账的豁免表 LATER_EDITS（本单两条）＋ 体检「没登记的改动
照旧报」（正向对照钉着）＋「表里每条都能在快照与六件/四件里找到」（防表腐烂）
