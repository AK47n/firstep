# 09 — 输入窗口化 + 高亮阈值调整

**要做什么：** 大文件输入时只重绘窗口（复用 08 的窗口计算），击键不再 O(全量行数) 重绘；同时调整/分片超大文件高亮回退阈值（现状 >128KB 纯文本回退，窗口化后放宽或按窗口行数分片），5000 行合成 .c 文件输入流畅。

**被谁阻塞：** 08（窗口计算/渲染共用）。

**Type:** task
## Answer

已实现并验证：

- 输入窗口化强化（承接 08）：输入同步路径**零强制布局**——
  ① 尺寸缓存 winSize（行数/行高/最长列数未变不碰样式；列数增长按实测 ch
  宽估算加宽，无 DOM 读）；
  ② winView 缓存（scrollTop/viewportH 只在滚动/resize/跳行事件时刷新——
  值变更后首次读 scrollTop/clientHeight 实测 50-60ms/次，是此前 150-220ms
  逐键延迟的主要根因）；
  ③ 行数变化（内容高度变化）才读写滚动位置（罕见）；
  ④ 已聚焦不重复 focus、选区未变不 setSelectionRange（输入后读取同样触发
  布局）；
  ⑤ editJumpToLine 设置 scrollTop 后先 winReadView 再 winRender。
- 阈值放宽：HIGHLIGHT_MAX_BYTES 128KB → 1MB（窗口化后高亮按窗口渲染、
  highlightText O(n) 线性实测 267KB ≈ 0.3ms；5000 行 .c 保持真彩色）。
- 实测：5000 行 .c 逐键输入同步 150-220ms → 均值 36.8ms / 峰值 60.8ms
  （CDP 冒烟 smoke-09.mjs 5/5 PASS：真彩色、<50ms 均值、DOM 有界、截图）；
  回归 03/04/07/08 冒烟全过；全量 JS 1205 + Python 3159 通过。

**Status:** resolved

## 实现要点

- 输入路径（`syncEditorAfterInput` 等）改为窗口重绘：input 事件后只重算窗口并更新窗口行；输入导致行数/滚动高度变化时同步 spacer。
- 高亮阈值：对窗口内行分片高亮或按文件大小放宽回退（以实测为准），保持高亮准确性（至少窗口行高亮正确）。
- 5000 行合成 .c 文件：连续输入（含回车/缩进）与滚动流畅。
