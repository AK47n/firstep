# spec — 代码页 VSCode 化优化（视觉细节 / 底部面板 tab 化 / 面包屑 / 编辑体验 / 大文件性能）

## 问题陈述

代码「查看/编辑」页已经具备多标签、折叠、括号配对、选中词高亮、文件内查找替换、
快捷键帮助、状态栏等能力，视觉也已接近 VSCode（Dark+ 语法配色、当前行高亮、深浅双主题）。
但对照用户提供的 VSCode 截图，仍有三类差距：

1. **视觉细节**：代码区字体/行高/括号匹配样式/缩进引导线等细节与 VSCode 仍有差距；
2. **布局结构**：底部是「编译 / 磁盘变更 / AI 对话 / 修复 / 烧录」五个独立堆叠面板，
   而 VSCode 是一个底部面板容器 + 页签；标签条下方也没有文件路径面包屑；
3. **编辑体验与性能**：缺 VSCode 式行操作快捷键与注释切换；程序化编辑（Tab/Enter/
   括号/替换）会打断浏览器原生撤销栈；每次击键全量重绘高亮层，大文件输入与滚动卡顿。

## 方案

对代码页做一轮「VSCode 化」优化，分四块：

- **A1 代码区视觉细节打磨**（不动布局）：字体栈 / 字号 / 行高微调；缩进引导线
  （indent guides，VSCode 式竖线，双主题自动适配）；括号配对高亮从下划线升级为
  VSCode 式描边框；当前行 / 选区 / 滚动条观感微调。
- **A2 底部面板 tab 化**：五个独立面板合并为**一个**底部面板容器 + 页签条
  （编译 / 变更 / AI 对话 / 修复 / 烧录），同一时刻只显示一个面板；各面板的
  「新消息到达自动切到对应页签、可折叠、每面板独立收起态」语义保留；无消息的
  页签可隐藏（如从未编译过就不显示「编译」页签）。
- **A3 面包屑**：标签条下方显示当前文件相对工程根的路径分段（目录段可点击），
  点击目录段 → 文件树展开到该目录并高亮；空态 / 未打开文件不占位。
- **B 编辑体验**：Shift+Tab 反缩进；行操作快捷键（删除行 / 移动行 / 复制行 /
  选整行）；Ctrl+/ 注释切换（C 行注释 / 块注释、XML 注释）；查找替换增强
  （Ctrl+H 聚焦替换、替换单个命中、替换并跳下一处）；程序化编辑不打断原生撤销栈
  （Ctrl+Z / Ctrl+Y 覆盖所有编辑路径）。
- **C 大文件性能**：编辑器渲染改为**可视区窗口化**（只渲染可视行 + 上下 overscan，
  上下用 spacer 保持滚动高度），滚动与输入都只重绘窗口；在此基础上调整超大文件
  高亮回退阈值（现状超过 128KB 直接纯文本，窗口化后不再需要如此保守）。

对齐目标：VSCode **深浅两套主题都要**（现有双主题变量体系）。

## 用户故事

1. 作为用户，我希望代码区字体、行高、缩进引导线、括号匹配、滚动条都更像 VSCode，
   以便长时间写代码时观感舒适。
2. 作为用户，我希望底部面板是一个带页签的容器（编译 / 变更 / AI / 修复 / 烧录可切换），
   以便屏幕空间不被五个堆叠面板占满、我需要哪个看哪个。
3. 作为用户，我希望新消息到达时（编译完成 / 磁盘变更 / AI 回复 / 修复轮次 / 烧录完成）
   底部面板自动切到对应页签，以便我不错过状态变化。
4. 作为用户，我希望标签条下方有文件路径面包屑，点击目录段能在文件树中定位，
   以便快速知道当前文件在哪、并跳转到相邻文件。
5. 作为用户，我希望 Shift+Tab 能反缩进多行选区，与 Tab 缩进对称，以便调整缩进层级。
6. 作为用户，我希望用 VSCode 行操作快捷键删除 / 移动 / 复制行、选整行，以便不改用
   鼠标就能快速整理代码。
7. 作为用户，我希望 Ctrl+/ 能切换行注释（.c/.h、XML），选中含块注释时切换块注释，
   以便快速注释一段代码。
8. 作为用户，我希望 Ctrl+H 聚焦替换输入，并能「替换单个命中 / 替换并跳下一处 /
   全部替换」，以便逐步审查后替换，而不是一步全替。
9. 作为用户，我希望 Tab / Enter / 括号自动闭合 / 行操作 / 替换等程序化编辑之后
   Ctrl+Z 仍能撤销、Ctrl+Y 能重做，以便编辑历史连续。
10. 作为用户，我希望打开大文件（上千行）后滚动和输入不卡顿，以便工程规模较大时
    仍能顺畅编辑。
11. 作为用户，我希望以上优化在深色与浅色主题下观感一致、不破坏既有功能（折叠 /
    查找 / 选中词 / 括号 / .md 预览 / 保存 / 冲突 / 编译 / AI）。

## 实现决策

- **延续既有架构**：纯逻辑进 `fx/*.js`（node 单测可测），DOM 胶水留在 `ui/*.js`；
  不引入第三方编辑器内核（textarea 三明治 + 高亮层是既有架构，多光标等内核级功能
  明确不做）。
- **A1 用 CSS 变量 + 既有 token**：字号/行高调整走 `--code-font-size` 链（Ctrl+滚轮
  缩放继续联动）；缩进引导线挂在标记层同族的纯背景层，按行内前导空白逐行绘制
  （不覆盖文字，仅绘制在空白区）；括号配对样式改为描边框（保留现有「括号下划线」
  作为降级或直接替换，以双主题截图验收）。
- **A2 单一容器 + 页签**：五个面板 DOM 移入一个底部容器，页签条常驻（仅有内容的
  页签显示），页签点击切换；各模块的「完成事件」统一接到容器模块的
  `showPanel(id)`；每面板独立 `.collapsed` 语义保留（收起只收内容，页签与头部
  状态行常驻）。既有各面板的 head 状态行、按钮、事件 id 全部保留（少动业务 JS）。
- **A3 面包屑**：纯件负责把相对路径切成 `[{name, path}]` 分段并渲染（转义、长度
  截断）；目录段点击 → 文件树 `revealTreePath(dirPath)`：按段逐级设置目录
  `<details>.open` 并滚动到对应节点高亮（树渲染加 `data-dir-path` 供定位）。
- **B 编辑操作**：新 fx 模块（无 DOM 依赖、可单测）：
  `shiftTab`（反缩进，选区对称于 Tab）、`deleteLine` / `moveLine` / `copyLine`、
  `lineRangeOf`（选整行，含行尾处理）、`toggleLineComment` / `toggleBlockComment`
  （.c/.h：`//` 逐行 + 选中含 `/* */` 时切块；xml：`<!-- -->` 逐行）、
  `replaceOneAt`（替换当前命中并返回下一命中位置）。快捷键在现有 keydown 管线
  注册（与 Tab/Enter/括号同一分支风格）。
- **B 撤销栈**：程序化编辑尽量经 `execCommand("insertText")`/`` `insertLineBreak` ``
  等浏览器保留原生撤销栈的路径落地（失败降级为直赋值，现状行为）；
  find/replace 与行操作后焦点归还编辑器。若浏览器路径不可用，降级方案为
  快照式自定义撤销栈（仅覆盖程序化编辑段，与原生栈拼接），实现时以浏览器实测为准。
- **C 窗口化渲染**：新增 fx 纯件计算可视窗口
  （`[startLine, endLine]` + 上下 spacer 高度，含 overscan 与折叠视图行的映射），
  ui 层滚动 / 输入共用：`.code-hl` / `.code-gutter` / 标记层只画窗口行，上下各一个
  spacer 撑起总滚动高度；textarea 仍保持全量内容（透明覆盖层，编辑语义不变）。
  窗口化后调整高亮回退阈值（>128KB 纯文本回退可以放宽或按窗口行数分片，验收时
  以「打开 5000+ 行 .c 文件滚动/输入流畅」为准）。
- **性能验收基准**：以仓库既有样例工程 + 一个 5000 行左右的合成 .c 文件测滚动帧率
  与输入延迟（肉眼判定 + 控制台 Performance 面板粗测），不引入自动化帧率断言
  （避免脆测）。
- **交互细节**：所有新快捷键进既有快捷键帮助弹窗（数据单源）；面包屑/页签/按钮
  全部带 `aria-label` / `title`；focus-visible 沿用既有统一规则。

## 测试决策

- **最高既有缝 = `node --test tests/js/` 的 fx 纯件单测**（新 fx 模块全部按
  `tests/js/*.test.mjs` 先例补测）；DOM 胶水不做单测（无既有 jsdom 设施），以
  CDP 冒烟脚本（`.scratch/*/smoke*.mjs` 先例）在真实浏览器验证关键交互，
  **只对既有回归面做冒烟**：打开文件 / 编辑 / 折叠 / 查找 / 替换 / 保存 / 面板切换。
- 既有测试不得回归：`codeeditor.test.mjs` / `code-marks.test.mjs` /
  `code-fold.test.mjs` / `code-shortcuts.test.mjs` / `code-highlight.test.mjs` 等下
  游测试全绿；语言规范（中文提交 / 工单）照旧。
- **验收以双主题截图 + 用户亲测为准**：每张工单完成时用 CDP 截深色图，浅色至少
  检查视觉不回退（A1 相关工单双主题各截一张）。

## 范围外

- 多光标 / 智能补全 / lint 诊断 / 代码大纲符号美化（内核级，需换编辑器内核）。
- 小地图 minimap（未选）。
- 状态栏错误/警告计数徽标（未选，A5）。
- 活动栏（最左 icon rail）与顶栏菜单化改造（未选，布局级大改）。
- 编辑器主题切换 UI（跟随全局深浅主题，不加独立编辑器配色设置）。
- 第三方编辑器内核（Monaco / CodeMirror）替换。

## 补充说明

- 用户对照图为 VSCode 深色截图；明确要求深、浅两套主题都达标。
- 本次范围是用户从候选清单中勾选的：A1 + A2 + A3 + B 档全做 + C 档全做。
- 底部面板 tab 化与既有「面板自动出现」逻辑（编译完成显示编译面板等）冲突时，
  以「自动切页签 + 页签出现」为准，不静默弹面板。
- 面包屑目录点击的树定位为新增能力（树渲染无现成 reveal API），需给目录节点补
  定位属性，改树渲染纯件时保持既有测试全绿。
