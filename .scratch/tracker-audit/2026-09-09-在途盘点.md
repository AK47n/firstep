### ② 顺带查清：`cdp-harness` 的自动应答原本是**静默失效**的（已修）

按「harness 有 20s 守卫 + 自动应答」的字面预期切完之后，一边反证「如果没有自动应答会怎样」，
一边发现**共用件的真缺口**：`Page.javascriptDialogOpening` 是 **Page 域事件**，
`connect()` 从不 `Page.enable` ⇒ 框照弹、事件收不到、应答不发出、渲染进程停在等应答态，
**下一次 `Runtime.evaluate` 直接撞 20s 超时**（实测形态：前一步还好好的，某一步「脏页 → 导航」
之后整片命令超时）。域状态是**连接级**的，同一浏览器上别的连接 enable 过就会「看起来能收框」，
让这个缺口显得时灵时不灵 —— 这也是第八轮把它判成「挂死不是随机的」的干扰项之一。

**修法**：`connect()` 里无条件 `Page.enable` + `Runtime.enable`（带 3s 超时的 send，受限 target
上失败也不让 `connect` 抛）；`Runtime.enable` 顺带让 `Runtime.exceptionThrown` 诊断事件稳定上报。

**顺带定性的一条坑（本轮实测推翻了我自己先写的注释）**：`Page.reload` 在**脏页上同样会弹**
`beforeunload` 框，但被应答（accept）时 **导航被取消**：`Page.reload` 7ms 返回、`frameNavigated`
0 次、`window` 标记不变、标签仍是脏的（`.scratch/code-editor-refine/tmp-reload-dialog-probe.mjs` 取证，
跑完即删）。
⇒ **「用 `Page.reload` 把一个脏页复位」这条路不成立**，正确手段是 `rebuildTab()` 换标签页
（harness / 批跑器本来就是这么做的，所以一直没暴露）；「页面内发起的导航」`location.reload()`
才会真的走完（本单反证用例用它造框，导航 220ms 完成）。

### 本轮定位过程（四条「看着像偶发、其实是机制缺口」，均已修）

1. **旁听连接恒 0 事件（真因一）**：脚本自己 `rebuildTab()` 会**关掉**监听所在的那个标签页，事件全跑到
   新 target 上 ⇒ 旁听什么都收不到。修法：`connect()` 新增 `watchTargets`（跟随标签页，300ms 轮询改挂）
   与 `targetId`（确定性挂载；显式给了就不再静默兜底换页）。
2. **跟随挑错页（真因二）**：跟随换页时按「URL 对得上的任意页面」挑，会挑到现场残留的**孤儿标签页**
   （诊断脚本留下的旧页），监听挂在一个与脚本无关的页上 —— 整批恒 0 事件。修法：优先挑「上次清点时
   还不存在的**新**页面」。
3. **`spawnSync` 阻塞主线程（真因三）**：批跑器同步等子进程期间，WebSocket 的 message 回调跑不了，
   事件只排在 socket 缓冲里，随后 `drainEvents()` 又把它们清掉 ⇒ 事件「到过但没人解析」。
   修法：`settleEvents()` 在 spawn 返回后给 1.2s 解析窗口。
4. **批跑器进程崩过一次（exit `0xC0000409`）**：库 UI 批某轮在 `module-library-ui` 那支**整体崩掉**
   （该支单跑与随后 4 轮复跑均正常，属偶发；此前从未记录过批跑器自身崩溃）。监听是**旁路**，不该
   拖垮整批 ⇒ 重挂加 try/catch、连续失败 3 次即放弃跟随、`close()` 后不再改挂。

**配套约定（给后续写冒烟脚本的人）**：脚本可读批跑器给的 `CDP_BATCH_TARGET` 环境变量复用该标签页，
就**不必自己 `rebuildTab()`** —— 脚本与旁听落在同一 target 上，事件一条不漏；不支持该约定的脚本行为不变，
批跑器在没收到任何事件时改用**支次后追挂 + 反射现场**兜底（落盘文件里注明「反射非实录」）。
