# 体验优化第二轮（ux-polish-02）

> 本轮基于走查结论（子代理代码走查 + CDP 视觉走查合并），范围已经用户确认：
> 主流程顺畅度、配置与设置、生成后任务推进、库浏览与素材管理四项共 7 个改进包。
> 改动以**前端为主，少量后端配合**（仅 mtime 字段）；全程不调用真实 LLM。

## 问题陈述

上一轮（ux-polish-01）已落地首屏聚焦、Ctrl+Enter 预读、修复中心隐藏空输出、key 密码态显隐。
本轮走查发现剩余痛点集中在四类：

1. **向导信任受损**：AI 推荐返回空结果仍把步骤 5 标成「已完成」；按默认布线生成工程后步骤 7 显示「✓ 已就绪」，用户误以为引脚已配置。
2. **首屏过长**：12 张步骤卡默认全部展开，打开生成页信息密度过高；折叠状态不记忆，每次刷新复位。
3. **主路径绕路**：生成完成后点「去任务推进」只切页签不加载上下文，落入「请先在修订页签加载」空态；设置页未配置横幅在「应用设置」卡内，指向下方另有卡保存的 key 输入框，横幅与入口断链。
4. **任务推进防呆不足**：编译失败的卡仍可「确认通过」被误标已验证；「跳过」无确认且连锁影响不明；分钟级执行中卡片无过程进度（进度只在面板顶部单行）；全部完成无「去交付」引导；任务卡重渲染会复位卡上清单的折叠态。
5. **库浏览可发现性**：模块/参考/赛题三库排序无「最近更新」；PDF 库无刷新入口（新文件要重进页签）；母版库空表无空态；四库统计条的可点击筛选只有 title 悬停提示。

## 方案

按 7 个改进包交付（用户已确认范围）：

1. **步骤完成态修复**——推荐空结果不标步骤 5 完成；按默认布线生成后步骤 7 显示「默认布线」中性标记（区别于手动配置的绿「已就绪」），完成计数不变。
2. **生成页卡片折叠优化**——默认只展开当前步与未完成步，已完成步自动折叠；用户手动折叠/展开状态本地记忆；与「收起已完成」按钮语义一致。
3. **设置页未配置横幅定位**——「去设置」「去填写」统一走同一条路径：展开 AI API 卡 + 聚焦 key 输入框；横幅文案与按钮直指目标。
4. **去任务推进自动加载上下文**——步骤 9/12 的「去任务推进」切页签后自动加载当前输出目录的生成上下文（与「从当前会话加载」同一加载器），无上下文或目录变化时才加载，已加载则跳过。
5. **失败卡防误标与跳过确认**——failed 状态不再提供「确认通过」（改为重跑/重做）；「跳过」加确认弹窗并提示连锁影响；跳过/恢复/重做按钮文案与悬停说明统一。
6. **任务进度与完成引导**——执行中任务卡内显示 spinner + 当前阶段文案（面板顶部状态行保留为汇总）；全部任务进入终态后展示「全部完成」+「去交付」入口（切到交付页签）；任务卡重渲染保留卡上 details 的展开态。
7. **库页体验包**——模块/参考/赛题三库排序新增「最近更新」（后端为条目补 mtime 字段）；PDF 库工具栏加「刷新」按钮；母版库空表渲染空态引导；四库统计条可点击提示可见化（「点击可筛选」文案 + 激活态样式）。

## 用户故事

1. 作为用户，AI 推荐返回空结果时，我看到步骤 5 保持未完成并提示「去模块库添加模块」，而不是被标成已完成。
2. 作为用户，我按默认布线生成工程后，步骤 7 显示「默认布线」而非「已就绪」，知道引脚尚未手动配置；进度计数仍如实反映生成已走通。
3. 作为用户，我打开生成页时已完成的步骤默认折叠、当前步与未完成步展开，首屏更清爽；我手动调整过的折叠状态刷新后仍在。
4. 作为用户，我在生成页点「去设置」或在设置页点横幅按钮，AI API 卡自动展开、key 输入框获得焦点，不用自己找。
5. 作为用户，我在步骤 9/12 点「去任务推进」后直接看到本会话的任务清单，不再被要求先去「修订」页加载。
6. 作为用户，编译失败的卡上没有「确认通过」按钮，我只能重跑或回滚，避免把红卡误标成已验证。
7. 作为用户，我点「跳过」时会看到确认弹窗，明确知道后续依赖该步的卡可能受影响，且可随时恢复。
8. 作为用户，任务执行中我能在该卡上看到 spinner 与当前阶段（实现/编译/修复/总结），不必盯着面板顶部的状态行。
9. 作为用户，所有任务完成后我能看到「全部完成」提示并可一键去「交付」页签，而不是停在「继续下一卡」。
10. 作为用户，我展开过的任务卡详情（自检清单/更多菜单/本轮变化）在重渲染后保持展开，不用反复重新点开。
11. 作为用户，我能在模块库/参考库/赛题库按「最近更新」排序，刚录入的条目一眼可见。
12. 作为用户，我把 PDF 放进素材库目录后点「刷新」即可看到新文件，不必重进页签。
13. 作为用户，母版库为空时我看到的不是空白表头，而是「如何开始」的空态引导。
14. 作为用户，我看到四库统计条上的问题计数带有「点击可筛选」提示，知道它们可以点击过滤。

## 实现决策

- **步骤 5 完成判定**：仅在推荐结果存在可用命中（模块 / 需求建议 / 互斥组卡任一非空）时标记完成；空结果分支在标记前早退。用户后续手动加模块走步骤 6 标记，不反向补标步骤 5。
- **步骤 7 双态**：新增纯函数从「生成成功 + 有角色但未显式绑定 + 实例未配引脚」判定 `default`（默认布线）态，与 `configured`（显式绑定/实例配脚/无需配置）态区分；`default` 态在步骤卡与总览 chip 上显示中性「默认布线」标记，事件链与既有 markStepDone(7) 正交（完成计数不变）。
- **卡片折叠**：折叠状态本地记忆（新 localStorage 键，按步骤号记录）；初始值 = 记忆优先，无记忆时「已完成且非当前步」折叠；当前步判定复用既有 step-nav 的 current 标记；非步骤卡（多实例配置卡）不参与自动折叠与记忆。纯函数下沉 fx 层供 node:test，胶水层与「收起已完成」按钮共用同一存储写入。
- **设置页定位**：新增共享跳转助手（欢迎卡/生成页横幅/设置页横幅三处共用）：先展开 AI API 卡（复用既有设置折叠展开原语），再切页签并聚焦 key 输入框；设置页横幅改为带「去填写」按钮。
- **去任务推进自动加载**：生成上下文加载器导出复用；「去任务推进」在「当前无已加载上下文」或「已加载目录 ≠ 当前输出目录」时自动触发加载，加载完成事件自然激活「任务推进」页签（既有行为）；加载失败沿用既有错误展示，不阻塞页签切换。
- **失败卡动作**：failed 状态动作集去掉 mark；「跳过」弹确认框（文案点名依赖连锁与恢复入口）；跳过/恢复/重做按钮统一措辞并补 title 说明（恢复此步 = 回到待做；重做 = 回待做重跑；重做此步 = 重置并清除建议标记）。
- **执行进度**：任务卡在 doing 态渲染 spinner + 阶段文案槽（阶段事件更新该槽，与面板顶部状态行并存）；顶部状态行在任务执行期间保留汇总语义。
- **完成引导**：进度总览在无 pending/failed/doing/unverified 时输出「全部完成」+「去交付」按钮，点击切到交付页签（交付面板已有摘要）；纯函数与胶水分层。
- **details 折叠态保留**：渲染任务网格前快照各卡 details 的 open 状态，重建后按任务 id 恢复；仅恢复用户可交互的 details（更多菜单/自检清单/本轮变化）。
- **mtime 排序（少量后端配合）**：模块/参考/赛题条目在服务端序列化时补 `mtime`（条目目录元数据文件 mtime，整数 epoch 秒）；**不写回 manifest 文件**（保持既有写盘逐字节兼容）；前端三库排序选项加「最近更新」，pdf 库已有 mtime 排序不动。
- **PDF 刷新**：工具栏加刷新按钮，复用既有列表重拉函数；空态文案同步提示可点刷新。
- **母版空态**：空库时渲染既有 empty-state 组件样式（提示从「母版提炼」开始），不复用空白表头。
- **统计条提示**：四库统计条的每条可点击计数后追加可见的「点击筛选」弱化文案（保留 title 详细说明）；激活态沿用既有 `.on` 样式，微调为含选中说明。

## 测试决策

- 沿用 `tests/js/*.test.mjs`（node:test + node:assert）抽取纯函数：步骤 5 结果判定、步骤 7 双态判定、卡片初始折叠判定、任务卡动作集（failed 无 mark）、完成态总览输出、详情折叠快照/恢复辅助、三库 mtime 排序键；新增用例挂入既有测试文件或新建对应 `*.test.mjs`。
- 后端：为模块/参考/赛题列表补 mtime 的单元断言（沿用各库既有测试文件里列表形状断言处），并确认 manifest 写回形状不变（既有逐字节断言继续绿）。
- 行为级（CDP 走查脚本复用 .scratch/ux-polish-01/probe.mjs 模式）：验证空推荐不标完成、折叠初始态与记忆、横幅聚焦、去任务推进自动加载、failed 卡无「确认通过」、进行中卡出现阶段槽、库刷新按钮与空态渲染。全程不调用真实 LLM（走查不发推荐/执行请求）。
- 全量 `node --test "tests/js/*.test.mjs"` 与 pytest 保持全绿；`tests/test_repo_language.py` 兜底中文工单/spec。
