# Spec：UI 视觉打磨 + 生成页步骤导航（ui-polish）

> 状态：已完成（工单 01/02/03 全部 resolved，2026-08-21）。

## 问题陈述

电赛工程生成器（单文件 index.html）已有一套完整的深色科技风主题（GitHub 深底 + 青色强调 + JetBrains Mono），但整体「能用但平」：

- 生成页 12 步卡片全纵向堆叠，长页面滚动量大，回看/跳转靠手动滚轮；
- 所有交互零动效：按钮 hover 瞬间变色，无 transition，卡片无悬停反馈；
- 步骤徽章为实心青色方块，扁平无层次；
- header 与 nav 分两行，占垂直空间；
- 库页面为空时无引导提示（空状态）。

## 方案

两档叠加（用户已确认 A + B 档）：

**A 档 · 视觉打磨（纯 CSS 为主）**
- 全局交互过渡：按钮 / 卡片 / 输入框 hover 加 0.15s 左右 transition；
- 主按钮青色渐变 + hover 微光；卡片 hover 边框提亮 + 轻微上浮；
- 步骤徽章改渐变圆角 + 发光；顶栏品牌字呼吸光晕；
- 空状态统一样式（「暂无数据」+ 说明 + 引导按钮）并在库页面空列表处生效；
- 卡片间距、标题层级微调，更透气。

**B 档 · 生成页布局升级**
- 生成页左侧 sticky 步骤导航：12 步圆点 + 编号竖向排列，跟随滚动，点击平滑滚动到对应卡片；已完成步骤变绿打 ✓；当前步骤高亮；
- 步骤完成时徽章自动变绿（沿用现有步骤完成信号，不改后端契约）；
- header + nav 合并为一条顶栏。

## 用户故事

1. 作为用户，我希望按钮和卡片有平滑的悬停反馈，以便界面感觉精致、不僵硬。
2. 作为用户，我希望主操作按钮有渐变与微光，以便一眼看到最重要的操作。
3. 作为用户，我希望步骤徽章有层次感（渐变 + 发光），以便页面更「科技感」。
4. 作为用户，我希望库页面为空时有友好提示和引导，以便知道下一步该做什么。
5. 作为用户，我希望生成页左侧有固定的步骤导航，以便点击任意步骤直接跳转、随时看到整体进度。
6. 作为用户，我希望已完成的步骤显示绿色 ✓，以便知道做到哪一步了。
7. 作为用户，我希望顶栏更紧凑（header + nav 合并），以便减少垂直空间占用。

## 实现决策

- 只改 `src/contest_generator/static/index.html` 一个文件（样式在 `<style>`、交互在现有 `<script>`）；后端零改动、API 契约零改动。
- 设计令牌沿用现有 `:root` 变量（--bg/--panel/--accent 等），不新增色系。
- 步骤导航用「生成页左侧 sticky 容器 + 现有卡片 `h2` 的 `.step-no` 编号」对齐；通过每个卡片外框（id 或 data-step 属性）定位滚动目标；无新元素 id 冲突。
- 步骤完成信号：复用现有 JS 中已存在的「步骤成功」调用点（如简介生成成功、平台选定、模块添加、生成完成等），在对应处追加「标记 done」函数调用；不重构现有流程函数。
- 顶栏合并：header 流程链文案压缩为可省略（窄屏隐藏），nav 上提同一行。
- 测试缝：`tests/js/*.mjs` 正则抽取纯函数（不得改名/删除被抽取函数）、`tests/test_generate_check_contract.py` 结构钉（`const FIX_MAX_ROUNDS`、`id=btn-fix-continue` 等不得删除）；视觉回归用无头 Edge 截图人工比对。

## 测试决策

- 好测试 = 外部行为：现有 js 抽取测试与结构钉测试全绿 = 没破坏既有契约；
- 新增 JS（步骤导航）尽量写成可被现有 `tests/js/*.mjs` 模式抽取的纯函数（如「当前步骤计算」），并补一个 js 单测；
- 运行：`node tests/js/*.test.mjs` + `pytest tests/test_generate_check_contract.py` + 全量 pytest 一次；
- 视觉：无头 Edge 截图（1440 宽）前后对比。

## 范围外

- 不改后端、不改 API、不改生成逻辑、不重构现有流程函数体。
- 不做响应式重排（保持 max-width 980px 单列）。
- 不引入框架 / 构建工具 / 外部字体或 CDN（保持零网络请求）。
- C 档重构不做。
