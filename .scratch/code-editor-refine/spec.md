# spec — 代码编辑器优化第二轮（数据安全 / 快捷键 / 错误可视 / AI 衔接 / 性能）

## 问题陈述

「代码」tab 的 IDE 式编辑器已完成多标签、保存冲突、查找替换、折叠、括号配对、行操作、
状态栏、底部面板 tab 化、AI 对话 + diff 应用、编译错误跳行、烧录等能力，上一轮
VSCode 化（code-page-vscode-overhaul/01-09）刚收尾。但对照完整编辑器体验仍有四类差距：

1. **数据安全**：切换目录时 `setCodeDir` 直接清空标签页，未保存编辑静默丢失；页面
   刷新/关闭无 beforeunload 提醒（审计确认，grep 无监听）。
2. **编辑体验**：缺 VSCode 高频快捷键（关标签 / 侧栏开合 / 符号定位）；括号只有单对
   描边、无嵌套深度彩虹色；没有快速打开（Ctrl+P）；大纲只有列表、无过滤定位。
3. **工作流**：编译错误只在底部面板，编辑器内无行内标记；文件树行没有右键菜单
   （复制路径 / 重命名 / 删除需悬浮按钮）；保存后需手动点编译。
4. **AI 衔接与性能**：AI diff 应用成功后不定位到改动处、无法「插入到光标/选区」；
   大文件（5000 行 .c）每击键仍全量重算折叠（窗口化只覆盖高亮/标记/行号三层）。

## 方案

一轮 10 项，按轴分组：

- **A 数据安全**：切换目录前如有脏标签 → 确认模态（保存全部 / 放弃修改 / 取消）；存在
  脏标签时页面刷新/关闭 → 浏览器原生 beforeunload 提醒。
- **B 快捷键**：Ctrl+W 关标签（复用脏确认）、Ctrl+B 侧栏开合、Ctrl+Shift+O 唤起大纲
  符号过滤并跳转；全部进快捷键帮助数据单源。真机验证浏览器保留键，若被吞则换键并同步。
- **C 大纲符号定位**：大纲面板顶部加过滤框（函数 / 宏 / include 匹配），输入过滤列表、
  Enter/点击跳至该行；Ctrl+Shift+O 展开侧栏并聚焦过滤框。
- **D 括号彩虹色**：标记层按嵌套深度着色（色环变量，双主题）。
- **E 编译错误行内标记**：最近一次编译的解析错误（path + line + message）存内存态，
  打开对应文件时标记层画行号侧色点 + 行内下划线；点击跳转；重编/成功清除。
- **F 文件树右键菜单**：树行 contextmenu → 菜单（打开 / 复制相对路径 / 重命名 / 删除），
  Esc 或点击别处关闭；复制优先 navigator.clipboard（localhost 安全上下文），保底
  execCommand 复制。
- **G 选中代码快捷动作**：浮动按钮扩展为动作菜单（解释 / 加中文注释 / 重构）——模板
  prompt + 选中上下文经既有对话端点发送，回复含 `<DIFF>` 走既有预览应用闭环。
- **H AI 应用定位 + 插入**：应用 AI diff 成功后自动跳转到首处改动行；新增「插入到
  光标/选区」——前端拼接新内容进编辑缓冲（脏），用户 Ctrl+S 落盘（复用保存冲突 /
  写盘守卫），零后端改动。
- **I Ctrl+P 快速打开**：overlay 复用树清单做索引，basename 子串优先 + 路径子串 +
  模糊匹配，Enter 打开 / Esc 关闭；复用 tab 上限 / 只读 / md 两态语义。
- **J 保存自动编译开关**：设置页新开关（默认关）；保存成功且开关开 → 触发既有编译
  入口（其内部已自动保存全部 + 防重入）。
- **K 性能热点治理**：先探针（CDP + Performance 采样）定位逐键残余热点（审计初步
  指向折叠全文档重算），按实测做增量/缓存，不以预判为据。

## 用户故事

1. 作为用户，我希望切到另一个工程目录时，未保存的修改不会静默丢失，以便放心打开多个工程。
2. 作为用户，我希望忘记保存就刷新/关页面时能收到提醒，以便避免丢失半天的工作。
3. 作为用户，我希望 Ctrl+W 关闭当前标签、Ctrl+B 收起/展开侧栏，以便键盘操作更顺手。
4. 作为用户，我希望 Ctrl+Shift+O 能弹出符号过滤并快速跳到函数/宏，以便大文件里快速定位。
5. 作为用户，我希望括号按嵌套深度显示不同颜色，以便一眼看清嵌套层级。
6. 作为用户，我希望编译错误直接显示在编辑器对应行上（色点 + 下划线 + 悬停信息），
   以便不改看底部面板就能发现错误位置。
7. 作为用户，我希望在文件树里右键就能复制路径 / 重命名 / 删除，以便少用悬浮按钮。
8. 作为用户，我希望选中代码后能一键「解释 / 加中文注释 / 重构」，以便加速电赛代码修改。
9. 作为用户，我希望 AI 建议应用后自动跳转到改动处，以便立即查看效果。
10. 作为用户，我希望 AI 给出的代码能「插入到光标 / 替换选区」，而不是只能整文件替换。
11. 作为用户，我希望 Ctrl+P 输入文件名快速打开文件，以便不翻树。
12. 作为用户，我希望开启「保存自动编译」后保存即编译，以便减少一次点击（默认关，不惊扰）。
13. 作为用户，我希望 5000 行 .c 连续输入不卡顿，以便大工程里编辑流畅。
14. 作为用户，我希望以上优化在深浅双主题下观感一致、既有功能（折叠/查找/保存/冲突/
    AI/编译/烧录）不回归。

## 实现决策

- **延续既有架构**：纯逻辑进 `fx/*.js`（node 单测可测），DOM 胶水留 `ui/*.js`；
  不引入第三方编辑器内核（多光标 / Monaco 等明确不做）。
- **快捷键**：在既有 keydown 管线注册（与 Tab/Enter/括号/行操作同分支风格）；帮助
  数据单源（fx/code-shortcuts.js）同步新增条目；真机 CDP 验证 Chrome 可拦截，保留
  退路（换键组合并同步帮助数据）。
- **错误行内标记**：编译 done 载荷的 `parsed_errors` 由编译模块持有
  （`getCompileErrors()` 访问器），编辑器标记层新增 `kind: "error"`（现有
  标记优先级体系扩展）；行内下划线用标记层背景/边框，gutter 色点走行号层；
  成功编译或重新编译后清空。
- **右键菜单**：contextmenu 委托在树容器（与悬浮按钮同族）；菜单为共享浮层组件
  样式（复用 confirmModal / 浮层既有样式 token）；「打开」= openEditorFile、
  重命名/删除复用既有 tree-ops 动作与脏保护。
- **快捷动作**：浮动按钮从「问 AI」升级为「问 AI ▾」动作菜单；三种动作 = 固定
  prompt 模板（解释 / 加中文注释 / 重构）+ `selectionContextText` 拼接，经既有
  `/api/tasks/idea/chat/send` 发送（零后端新增）；assistant `<DIFF>` 走既有
  预览/应用闭环。
- **插入到光标**：纯前端——取活动标签内容，按光标/选区计算新内容（插入或替换），
  写入编辑缓冲（脏 + 撤销语义尊重既有 execCommand 路径判定）；落盘走用户 Ctrl+S
  （保存冲突 / 409 / 写盘守卫全复用）；后端零改动。
- **Ctrl+P**：overlay 数据 = 已有树清单（/api/code/open 返回的扁平清单，前端缓存
  于 loadCodeDir）；匹配 = basename 子串（大小写不敏感）优先，其次路径子串，
  再退模糊（字符序）；Enter 打开 / Esc / 点击空白关闭；无结果空态。
- **保存自动编译**：开关存 localStorage（与既有 UI 偏好持久化同族）；保存成功后
  若开关开且非编译中 → `runCodeCompile`（已含自动保存+防重入）；开关 UI 放设置页
  「编辑」组（若设置页无合适分组则放代码栏状态栏「自动编译」toggle，实现时择一处，
  spec 以「一处、默认关」为准）。
- **性能**：工单先行诊断（探针脚本不进 tests，放 `.scratch`，如既有 probe-*.mjs
  先例），据实测热点做增量——候选：折叠区域增量更新（只重算受影响区间 / 缓存
  doc 级括号配对）、标记层选中词全文 map 增量、查找框输入防抖；以「5000 行 .c
  连续输入无卡顿」为验收（肉眼 + 采样粗测，不引入帧率断言）。
- **括号彩虹色**：配对扫描已有（括号配对高亮），补「深度」计算；色环 6-8 色、
  深浅两套 CSS 变量；仅 c/xml/md 编辑态（与既有门控一致）。

## 测试决策

- **最高既有缝 = `node --test tests/js/` fx 纯件单测**：新增纯件全部按既有
  `*.test.mjs` 先例补测——快速打开匹配 / 错误标记映射 / 括号深度 / 动作模板 /
  插入拼接 / 折叠增量（若实现）等。
- **交互行为 = CDP 冒烟**（`.scratch/code-editor-refine/smoke*.mjs` 先例，真实
  Chrome）：覆盖切目录确认、脏刷新提示（beforeunload 难自动化则以手动+探针记录）、
  Ctrl+W / Ctrl+B / Ctrl+Shift+O、右键菜单各动作、错误行内标记出现与点击、动作
  菜单→AI 回复、插入到光标、Ctrl+P 打开、保存自动编译触发。
- **后端零改动**（不新增端点），pytest 全量回归跑一次确认无回退；视觉相关工单
  （括号彩虹、错误标记）深浅两主题各截一张图。
- 语言规范：spec / 工单 / 提交信息 / CHANGELOG 一律中文，照旧。

## 范围外

- 多光标 / Ctrl+D 选中下一个 / 列选择 / Monaco / CodeMirror 内核替换 / 小地图 /
  状态栏错误计数徽章 / 活动栏与顶栏菜单化（沿用上轮 spec 范围外）。
- 「在资源管理器中显示」（需后端端点）——本轮以右键「复制相对路径」代替。
- 跳转到定义（C 交叉引用，L，下轮候选）。
- 词 / 内容补全（下轮候选；本轮不做）。
- AI 对话自动注入当前文件全文（token 膨胀风险；保持选区级上下文）。
- 多 workspace 同时打开（本轮只做切换时的未保存保护）。

## 补充说明

- 可选包取舍（用户授权「自己想想」）：纳入 **Ctrl+P 快速打开** 与 **保存自动编译
  开关**；**词补全** 与 **AI 注入当前文件** 排下轮。
- 性能轴以「诊断先行」为准：审计指出折叠每键全文档重算是最大嫌疑，但具体改造以
  探针实测为准，避免为假设做无谓重构。
