# 代码 IDE 与生成流程的流畅结合（AI 写盘感知 + 变更面板 + 一键修复直达）

> 会话/系列 slug：code-ide-flow。立项：2026-09（用户拍板：方案 A + B低配）。
> 背景：生成页 12 步向导（修复中心 / 任务推进 / 修订与深化）与「代码」tab IDE
> 已经通过写盘守卫、编译横幅单源、main.c 双向桥等初步衔接，但仍有三处割裂待补。

## 问题陈述

用户完成生成后，AI 侧的写盘动作（修复中心应用修复、任务推进执行、修订与深化写盘、
参数改值）与代码栏 IDE 互不知情：

1. **AI 写盘后 IDE 不感知**——已打开的标签停留在旧内容（甚至旧编码状态），文件树
   缺新出现的文件；用户要切走再切回、或撞上保存冲突才被动发现。
2. **AI 改了什么不可见**——修复结果列表在生成页、任务变化 diff 在任务卡、
   深化 diff 在修订卡，IDE 内没有任何一处汇总"本轮磁盘被改动了哪些文件/哪些行"。
3. **AI 修复多一步跳转**——IDE 编译失败后按钮只跳去生成页，用户还要再点一次
   「一键编译修复」才开始。

## 方案

以**磁盘基线对比**为统一事实源（不依赖前端事件流转，覆盖一切写盘来源——
AI 修复/任务/深化/参数改值/外部编辑器）：

### 1. AI 写盘感知（基线对比 + 联动刷新）

- IDE 打开目录时记录基线：目录 → 每文件 `{path → mtime_ns, size}` 清单，
  持久化到 localStorage（键含目录路径）。
- 每次树刷新与切回「代码」tab 时重扫磁盘对比基线，得出三类变更：
  新增文件 / 修改文件（mtime 不同）/ 消失文件。
- 联动规则：
  - **干净标签**（无未保存编辑）→ 自动重载磁盘版，toast 提示
    「N 个文件已被外部更新，已自动重载」；
  - **脏标签**（有未保存编辑）→ **绝不静默重载**：标签栏加「磁盘已变更」徽章，
    用户点击徽章/该标签时弹既有保存冲突模态（覆盖我的修改 / 加载磁盘版 / 取消）——
    复用现有三选模态，不新建；
  - **文件树** → 同步刷新；新增条目带「新」徽章、修改条目带「变」徽章，
    消失条目从树移除（面板中仍可见）。
- main.c 若被 AI 改写，继续走既有 `refreshMainCDiskState()`（步骤 8 状态行联动），
  不另开路径。

### 2. 「磁盘变更」面板（IDE 底部，与编译面板并列、可折叠）

- 内容 = 基线 vs 磁盘对比结果，文件级条目：状态（新增/修改/消失）+ 相对路径 +
  修改时间/大小；行级尽力而为——main.c 显示确定性 diff hunk（复用既有
  main_diff 渲染，默认折叠）。
- 点击条目 → 跳转打开对应文件（新增/修改条目）；消失条目置灰不可点。
- 面板打开期间对比实时生效（配合 1 的感知刷新）；「清空并确认已看」按钮 →
  基线更新为当前磁盘快照，条目清空。
- 切换目录/工程 → 基线自动切换（localStorage 按目录隔离），不串台。

### 3. 一键修复直达（B 低配）

- IDE 编译失败时的「去生成页一键编译修复」按钮：跳转生成页后**自动开始**修复
  循环（不再要求用户二次点击），仍先走写盘守卫（若有未保存编辑先确认保存全部）。

## 用户故事

1. 作为用户，AI 修复/任务/深化写盘后切回代码栏，我希望打开的标签自动反映
   最新磁盘内容（我未保存的编辑不受损），以便在最新代码上继续干活。
2. 作为用户，我希望在代码栏一眼看到本轮磁盘被改动了哪些文件（含新增/消失），
   点击直达文件/行，以便快速审视 AI 改动。
3. 作为用户，IDE 编译失败时我希望一键直达 AI 修复（自动开始），以便更快闭环。
4. 作为用户，我用外部编辑器（CCS/Keil）改过文件后切回代码栏，希望同样被感知
   （与 AI 写盘统一机制、同样只读保护）。
5. 作为用户，我不希望自己的编辑被悄悄覆盖——脏标签永不静默重载，要么徽章提示
   要么显式三选。
6. 作为用户，切换工程/目录后旧工程的变更记录自动隔离，不相互污染。

## 实现决策

- **数据源 = 磁盘对比**：新增 fx 纯件（基线快照与对比：`baseline{dir → {relPath → {mtime_ns, size}}}`，
  localStorage 持久化 + 目录隔离 + 过期清理），不消费 fix/task/deepen 的 done 载荷
  （那些只有 main.c diff 或单事件清单，覆盖不全且刷新即丢）。
- **零后端改动**：/api/code/open、/api/code/file、/api/code/save 既有载荷已含
  mtime_ns，对比所需信息齐备；不新增端点。
- **冲突三选复用**：现有保存冲突模态（覆盖/重载/取消）与 saveAllDirtyTabs 编排
  直接复用，不新建模态；「磁盘已变更」徽章是新增的进入入口。
- **模块分工沿用仓库惯例**：fx 纯件无副作用（localStorage 不进 fx——键读写放
  ui 胶水层，同 codeTreeWidth 先例）；ui 胶水负责对比触发、徽章、面板、toast。
- **交互默认值**（可评审调整）：底部面板与编译面板并排；自动重载仅限干净标签；
  「清空并确认已看」为显式按钮；基线更新点 = 打开目录 / 点清空按钮。
- **main.c 行级 diff 复用**：main_diff 渲染已有（fx/diff.js）；非 main.c 文件
  第一版不做行级 diff（范围外）。

## 测试决策

- **纯件单测（主 seam = node 测试，tests/js 先例）**：基线对比判定（新增/修改/
  消失/无变化/空目录）、目录隔离与过期清理、徽章判定（脏/干净）、面板条目 HTML
  （含 main.c diff 区）。
- **CDP 冒烟（smoke 系列先例）**：①AI 写盘（真实任务/修复难——用桩或既有
  smoke 基建）→ 切回代码 tab → 干净标签自动重载 + 树徽章；②脏标签不被静默
  重载且点击弹三选；③面板条目点击跳转；④一键修复直达自动开始。
- 后端无改动 → 不新增 pytest；现有全量回归保持绿。

## 补充说明

- 感知联动与「写盘守卫」互补不冲突：守卫管"生成侧写盘前未保存编辑"，
  本特性管"写盘后 IDE 侧感知"，两者共用 mtime 事实源。
- 「磁盘变更」面板命名强调"磁盘"而非"AI"：外部编辑器改动同样可见，语义诚实。
