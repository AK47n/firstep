# 硬件检测加固（真机上板之前能修的那七件）——功能规格

> 2026-09-26 立项。起因 = `docs/improvement-review-hwcheck.md`（同日评审）的 P0 + P1 七项。
> 用户当天拍板四件事：**范围 = P0+P1 七项**（上板不在本轮）；**OLED 走"先如实降级 + 缩短横幅，
> 分页另开单"**；**链接器告警只修解析器 + 如实记账，不动 `ml_mpu6050` 驱动**；
> **每单一次中文提交**。本 spec 只收这四条口径下的落地，不重开已 resolved 的五块
> （`module-hwcheck` / `hwcheck-acceptance` / `hwcheck-specialize` / `hwcheck-unknown-device` /
> `hwcheck-pin-conflict-exit`）。

## 问题陈述

「硬件检测」已经能把检测工程生成出来、能编译、能如实标注"未专精"，但评审量到七处
**会让学生得出错误结论、或让页面的承诺不成立**的地方——它们都不需要真板子就能修：

- **配方里还留着一句过期的行动指令**（`key × mspm0`）：教学生"上板前把 main.c 里那行的注释去掉"，
  而那一行从 `hwcheck-acceptance/01` 起已经是活代码。学生照做会找不到那一行，且与页面清单自相矛盾。
  守卫只覆盖清单文本，**不吃配方文件**，所以这句残留在两轮修复里都漏了过去。
- **"未上板"只说到了一半**：57 格配方里 41 格在平台说明里如实写了"未上板"，缺的 16 格恰好是
  v1 pilot 那批（`led / oled / debug_uart / key / beep / sr04 / jy61p / adc / ml_mpu6050` 两平台），
  其中旗舰件 `ml_mpu6050` 的说明还写着"板上判 FAIL 就是通信真的没通"这种从未在真板上验证过的断言。
  页面上也没有一处"整块能力尚未上板"的总口径。
- **OLED 通道的承诺不成立**：页面上写着"结果分屏显示，不接串口也能看"，而框架把每一行都写到第 0 行、
  屏上只留最后一行；165 条读数里 53% 光"表达式 = "就超过 16 列，**数值根本进不了屏**。
  只用 OLED 的学生（没有 USB-TTL 线是最常见的情况）看到的是"一行行闪过去，最后什么都不剩"。
- **5 条读数行超过板上 128 字节行缓冲**（全在 pilot 格：`debug_uart × stm32` 239B、`adc × mspm0` 152B、
  `beep × stm32` 146B、`adc × stm32` 139B、`adc × mspm0` 139B），超出的部分**静默截断**，
  中文一字 3 字节 ⇒ 截在字中间就是半个乱码。既有守卫刻意只守扩张格，这 5 条无人看管。
- **复测字符池：勾满必 400，而报错把池子说大了**。池里 31 个字符，但**只有 25 个**被任何配方声明过
  （`4 5 6 7 8 9` 无人用）；报错文案却印"可用字符一共 31 个"，把人往"还能再勾"引，
  而真正撞车时（stm32 第 23 件 / mspm0 第 26 件）页面上**没有任何事前提示**。
- **"0 error / 0 warning"这条验收线在链接器诊断上是漏的**：解析器只认带 `文件(行)` 引用的行，
  链接器形态（`warning #10210-D:` 这类没有文件引用的）**两条路都看不见** ⇒ 编译面板对它报"0 warning"。
  实测已经有一格踩在这上面（`ml_mpu6050 × mspm0` 的 `.sysmem` 告警，矩阵判 FAIL 而面板说 0 warning）。
- **预览失败被说成"接线表取不到"，并且留着上一次的 main.c**：预览请求失败写进的是"接线"专用的
  错误位，专用文案没有消费者；失败分支还刻意不清 main.c，理由是"检测程序只依赖平台与通道"——
  这个前提不成立（主程序是按所选器件渲染的）。学生看到的是**上一组器件的程序**配一句指错方向的错误。

## 方案

七条互不重叠的切片，每条都能单独验、单独提交：

1. **配方文案与守卫**：改掉那句过期指令，并把「不许再教学生改生成代码」的守卫从清单文本**扩到整个配方文件**，
   带一次反证（把句子塞回去，用例必须红）。
2. **未上板披露补全**：把 41 格已经在用的那句如实自述补到缺的 16 格；页面加一句总口径
   （库内所有配方与探测小节都还没在真板上跑过），README 同步一句。
3. **OLED 如实降级**：页面与清单文案改成"OLED 只显示最近一行、长行会被截断，要看完整结果请勾调试串口"；
   读数行的表达式横幅收窄；spec 里"分屏显示"的旧口径一并更正；分页/逐件汇总**另开一单**（要真板子）。
4. **读数行不超行缓冲**：把那 5 条超限行的长说明挪进平台说明（页面文本，不进板上缓冲），
   行上只留短单位；把行宽守卫的射程从扩张格扩到**全量配方**。
5. **字符池容量与预警**：给声明了控制台字符的配方补上没人用过的池位（纯追加，顺序不动），
   让"把专精件全勾上"不再必然 400；报错文案改成如实表述（池子多大、谁排不上号、出路是什么）；
   页面在勾到接近上限时**事前**提示。
6. **链接器形态诊断**：解析器认得没有文件引用的 `#NNNN-D:` 形态（warning / error），
   汇总与面板随之如实计数；那一格不再"红着不算红"。
7. **预览失败**：前端改用专用的"检测程序预览失败"文案，失败时**清掉上一次的 main.c**（或明确标为过期），
   并把注释里那个不成立的前提删掉；补一条真浏览器用例。

## 用户故事

1. 作为学生，我想要配方里**不再出现任何"去改生成代码"的指令**，以便我不会照着一句过期的话去 main.c 里找一个不存在的注释。
2. 作为学生，我想要**每一格配方都如实告诉我它有没有上过板**，以便我不会把"配方没验过"读成"我线接错了"。
3. 作为学生，我想要页面上有一句**总口径**说明这批检测还没在真板上跑过，以便我对"检测结果"的分量心里有数。
4. 作为学生，当我只用 OLED 屏时，我想要页面**明说它只能显示最近一行**，以便我不会以为是自己板子坏了。
5. 作为学生，我想要 OLED 上至少能看清**短行**（判定与短读数），以便不接串口也能看到一部分结果。
6. 作为维护者，我想要"读数行不许超板上行缓冲"这条守卫**管全量配方**，以便 pilot 格不会继续烂在盲区里。
7. 作为学生，我想要**把库里的专精件全勾上也能生成**（不再撞字符上限），以便我一次验完整套硬件。
8. 作为学生，当我确实勾太多、字符排不下时，我想要**在生成之前**就被提醒，而不是生成时才吃一个 400。
9. 作为学生，当报错说"字符不够"时，我想要它报的是**真实的可用数**（不是比实际大 6 个的池子大小），以便我知道还能不能加件。
10. 作为学生，当编译带链接器告警时，我想要面板**如实显示这条告警**，而不是报"0 warning"。
11. 作为维护者，我想要"0 error / 0 warning"这条验收线**对链接器诊断也成立**，以便判据与读数不再脱钩。
12. 作为学生，当预览失败时，我想要一句**说得对的错误**（"检测程序预览失败"），而不是被引去查接线。
13. 作为学生，我想要预览失败时**看不到上一次的旧程序**，以便我不会把上一组器件的 main.c 当成这一次的。
14. 作为维护者，我想要每一条新守卫都配一次**反证**（撤掉修复 → 用例必须红），以便守卫不是摆设。
15. 作为维护者，我想要这七单**都不动板上运行时的行为**（没有真板子时改它 = 改了也没法验），以便"能编译"与"真能跑"不再次脱钩。

## 实现决策

**硬边界（本 spec 的第一条纪律）**

- **不动板上运行时行为**：不新增/修改检测程序在板上执行的语句序列、时序与通道分派逻辑。
  没有真板子时改这一层，等于把"未验证"的面积再扩大一块——这正是评审点名的教训。
  第 3 条里的"横幅收窄"属于**渲染出的文本内容**（字符串长度），不属于运行时行为。
- 已 resolved 的五块**只允许被动适配**（配方补一句、守卫加一条），不借本批重构它们的机制。
- 不修库内驱动（`ml_mpu6050` 的 `log_i/log_e` 与 `.sysmem` 告警只记账，不碰源码）。

**① 配方文案与守卫（生产数据 + 测试）**

- 口径照 `xunji × mspm0` / `adc × mspm0` 两处已经改好的写法：「…检测程序开头已经调了它
  （那一行是活代码，不需要你改 main.c）」。同一条说明里"这一行不生效 = KEY 的输入配置根本没配上，
  读数不可信"这半句是**有效信息，保留**。
- 守卫落点是**配方数据文件本身**（读真库那一份，不是样例），判据 = 全文不出现
  `取消注释` / `注释去掉` 这类"教学生改生成代码"的措辞。既有那条清单级断言**不动**（它管的是清单）。
- 反证：把句子写回去 → 新用例必须红（跑完复原，逐字节相同）。

**② 未上板披露补全（生产数据 + 页面 + README）**

- 16 格各补一条 note，措辞与扩张批**逐字同源**（先用扩张批已有的那句，不再造第二种说法）。
  这条自述会原样印到检测页的平台说明里——学生看得到。
- 页面总口径：一句，**单一出处**（域层产出、前端只渲染，沿用既有"文案单源"约定），
  说的是"本栏目的配方与探测小节尚未在真板上验证过；编译绿不等于板上成立"。
- README 同步一句（同一句措辞，别再写第二种）。
- 判据：数据层面 57/57 格命中；页面渲染出那一句；README 命中。

**③ OLED 如实降级（生产文案 + 渲染文本 + spec 口径）**

- 三处文案一致改口径：输出通道说明（只有 OLED / 串口 + OLED 两种形态）、上板清单里 OLED 那条、
  以及 spec 的用户故事 6/11（旧句"分段打出来 / 分屏显示"在 OLED 上不成立）。
- 横幅收窄：读数行的表达式前缀上限从 60 收到一个**能明显改善串口可读性**的值（超长以 `…` 结尾）；
  这一改**同时**让第 4 条的超限清单变化 ⇒ 第 4 条被第 3 条阻塞。
- **不承诺 OLED 能看到数值**：如实说的是"只显示最近一行、长行会被截断"。
  分页/逐件汇总另开一单（`08`），阻塞条件是**真板子**，不是代码。

**④ 读数行不超行缓冲（生产数据 + 测试）**

- 五条超限行的长单位说明挪进该格的平台说明（note 是页面文本，不进板上缓冲），行上留短单位。
- 守卫射程扩到全量配方：既有那条扩张格守卫**保留**（不缩小），新增一条吃全量（含 pilot）。
- 判据 = 按"算式 + 单位 + 数值位数"估算的最坏行宽 ≤ 板上缓冲；反证 = 把长单位塞回一行 → 必须红。

**⑤ 字符池容量与预警（生产数据 + 文案 + 前端）**

- 数据侧：给声明了控制台字符的配方补**纯追加**的候选池位（只用"既不是保留字、也不是任何一件首选"
  的字符），顺序不动、已有候选一个不删——沿用 `hwcheck-specialize` 批次 E/F 的共享后备池先例。
- 判据（这条是本单的核心验收）：**把库里该平台的专精件全勾上，命令表建得出来**（两平台各一次）；
  且小规模组合（`|S| ≤ 4` 全子集 + 固定种子抽样）仍零撞车。
- 报错文案如实：池子多大、这一趟谁排不上号、出路是什么（去掉几件），数字与实际分配能力一致。
- 页面**事前**提示：勾到接近上限时给一句（域层给数、前端只渲染），不再只能等到 400。

**⑥ 链接器形态诊断（解析域 + 展示域）**

- 解析器新增一类"**没有文件引用的工具链诊断**"（`#NNNN-D:` 形态，warning 与 error 都收），
  归到伪路径（照既有 SysConfig 冲突伪路径的先例），**行号 0 = 不可跳转**（沿用既有"不可跳转行"的渲染）。
- 汇总随之如实：面板的 `errors / warnings` 不再漏它。
- 判据：把那条真日志原文喂进解析器 → 出 1 条 warning；喂进汇总 → `warnings = 1`；
  真机日志形态不变（既有 UV4 / CCS / gmake 三类用例全绿）。
- 记账口径：`ml_mpu6050 × mspm0` 那格的 `.sysmem` 告警**如实写进账本**（属既有工具链行为，不修驱动）。

**⑦ 预览失败（前端 + 浏览器用例）**

- 前端改用专用的预览失败文案（今天那个函数**产品侧零消费者**，本单让它有）；
  失败时清掉上一次的 main.c，并删掉注释里"main.c 只依赖平台与通道"这个不成立的前提。
- 判据（真浏览器）：拦截预览请求返回 400 → 页面出现"检测程序预览失败"**且不显示上一次的 main.c**；
  恢复后能正常渲染。

**工单顺序**

七单里只有 ④ 被 ③ 真阻塞（宽度改了，超限清单要重量）。其余各单之间没有真依赖；
配方数据文件的编辑按 ①②③④ 顺序落地（避免同文件并发改），这不是阻塞边、是执行纪律。

## 测试决策

- **最高既有缝 = 域层纯函数**（字符串进 / 字符串出、内存直测、零 LLM）：文案类（②③⑤）、
  渲染类（③④）、命令表与分配（⑤）都在这一层测，沿用 `tests/test_hwcheck*.py` 的先例。
- **解析域**：`tests/test_fix_errors.py`（真机日志原文进 / 结构化条目出），⑥ 沿用它的 fixture 风格。
- **数据守卫**：读**真库那一份**配方文件（既有先例已有），不做样例替身——① 与 ④ 的守卫都必须是
  "真数据变了就红"。
- **命令表容量**：`tests/test_hwcheck_console.py` 既有全子集穷举用例扩一档（全勾满必须建得出表）。
- **前端**：`tests/js/hwcheck.test.mjs` 纯函数直测（⑤ 的预警文案、③ 的清单文案）。
- **真浏览器**：`tests/browser/hwcheck.spec.mjs` 补一条（⑦ 的预览失败）。
- **反证要求**（本仓库既有纪律）：①④⑤ 各配一次"撤掉修复 → 用例必须红"的实测；读数落本目录。

## 范围外

- **真机上板**（`hwcheck-acceptance/05` 仍是它的家，要板子与人在场）。
- **OLED 分页 / 逐件汇总**（本 spec 开出 `08`，阻塞于真板子）。
- P2 那七项（焦点与 aria、记录写加锁、拆 `fx`/`ui` 大文件、`tests/js` 的 DOM 桩、多实例、
  `export-surface-guard` 消费者集合、账本收口）——另立。
- 修库内驱动缺陷（含 `ml_mpu6050` 的 `log_i/log_e`）、配方 schema 变更（加实例维度 / 加结构化地址）。
- 未专精面的继续扩张（下一个 20 件）。
