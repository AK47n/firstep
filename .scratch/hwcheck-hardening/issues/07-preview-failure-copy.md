# 07 — 预览失败说真话，并且不留上一次的旧程序

**要做什么：** 预览失败时学生读到的是**说得对的错误**（"检测程序预览失败"），
而且**看不到上一次的 main.c**——不会把上一组器件的程序当成这一次的。

**被谁阻塞：** 无——可立即开始。

**状态：** ready-for-agent

- [ ] 前端改用**专用的预览失败文案**（那个函数今天产品侧零消费者，本单让它有消费者）；
      不再借用"接线表与冲突暂时取不到"。
- [ ] 失败时**清掉上一次的 main.c**（或明确标为过期并禁用复制/编译入口——二选一，取改动小的那条）；
      并删掉那段注释里"检测程序只依赖平台与通道"这个**不成立的前提**
      （主程序是按所选器件渲染的：`render_main_c(config, sections, generic, custom)`）。
- [ ] 真浏览器用例（`tests/browser/hwcheck.spec.mjs`）：拦截预览请求返回 400 →
      页面出现「检测程序预览失败」**且不显示上一次的 main.c**；解除拦截后能正常渲染。
- [ ] 前端用例：专用文案的那个函数有直测（防它再次变成死导出）。
- [ ] 相关面全绿：`node --test "tests/js/*.test.mjs"` + `node --test --test-concurrency=1 "tests/browser/hwcheck.spec.mjs"`。
