# 07 — 预览失败说真话，并且不留上一次的旧程序

**要做什么：** 预览失败时学生读到的是**说得对的错误**（"检测程序预览失败"），
而且**看不到上一次的 main.c**——不会把上一组器件的程序当成这一次的。

**被谁阻塞：** 无——可立即开始。

**状态：** resolved

- [x] 前端改用**专用的预览失败文案**（`hwcheckErrorHTML` 此前产品侧零消费者，本单让它有），
      落在产物区；不再借用"接线表与冲突暂时取不到"。
- [x] 失败时**清掉上一次的 main.c**（`hwcheckUI.preview = ""` + `outputHint = ""`），
      并删掉注释里"检测程序只依赖平台与通道"这个**不成立的前提**——改成"主程序是按所选器件渲染的"。
- [x] **顺手把那条老路整条删了**（实施时的发现，记录在案）：`wiringError` 状态槽与
      `hwcheckWiringErrorHTML`（"接线表与冲突暂时取不到"）**唯一**的写入点就是这次预览失败——
      所谓"接线表单独取不到"根本不存在（接线表与主程序是**同一次请求**回来的）。
      于是：ui 的 `wiringError` 全部引用、fx 的 `hwcheckWiringErrorHTML` 函数与导出、它的前端用例
      一并删除；接线区/冲突区/顺序区改成"预览失败时留空（错误已在产物区说清）、否则按 wiring 有没有值渲染"。
      —— 那条守卫用例（"ui 的接线表失败不连坐预览（main.c 只依赖平台与通道）"）也随前提更正为
      「三处清预览：换平台 / 换通道 / **预览失败**」。
- [x] 真浏览器用例（`tests/browser/hwcheck.spec.mjs` 新增一条）：先正常预览出一份 main.c →
      拦截 `/api/hwcheck/preview` 返回 400 中文理由 → 断言出现「检测程序预览失败」、理由原样带出、
      **旧 main.c 已不在**；解除拦截后能渲染回来。
- [x] 受影响的既有浏览器用例同步落点：`装不下时的出路…` 原来在**接线区**读 400 文案，
      现在改到**产物区**读（同一条 400 原文，标题从"接线表取不到"变成"检测程序预览失败"——
      断言本身一个字没放松）。
- [x] 前端用例：fx 文案函数有直测；结构钉改成"三处清预览 + 失败走专用文案 + 老路已删"。
- [x] **反证**：`probe-07-red.py` → 撤掉失败分支那一行清预览 → 前端用例 exit=1（红，
      `actual 2 !== expected 3`）；复原后 sha256 逐字节相同、再跑 exit=0。读数 `probe-07-red.txt`。
