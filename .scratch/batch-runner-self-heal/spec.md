# spec — 批跑器自助复判（红即单支复跑 + 自动落盘事件序列）

## 问题陈述

CDP 冒烟批跑器 `.scratch/cdp-smoke-run.mjs` 跑完一批后，「这一支红是**真缺陷**还是
**偶发/现场劣化**」目前**只能靠人看**：记录里只有 `exit / timedOut / hung / tail / forensics`，
没有复跑，也没有事件序列。第十一轮就挂账过两处批内偶发（`polish/smoke-03`、
`module-library-ui` 长连跑 `exit=1` 却**没有 FAIL 行**），第十二轮没复现、定性不了；
第十二轮把共用传输层 `cdp-harness.connect()` 补齐了（命令级 20s 超时 +
`Page.enable`/`Runtime.enable` 后稳定上报 `Runtime.exceptionThrown`、
`Page.javascriptDialogOpening` 与导航事件），**材料已经齐了，只差批跑器一段代码**。
没有自助复判，盘点每轮都要重新手判一次「偶发还是真红」，且判定口径随人而变。

## 方案

批跑器在每一支脚本跑完后，若结果**非绿**（`exit != 0`、超时挂死、退出码异常），
**自动把这一支单独再跑一次**（复跑前**重建标签页**，与批跑器既有「每支前重建」约定一致），
并给出终局判定：

- 首跑红 + 复跑绿 → **偶发（flake）**，记录两次结果留痕，**不算批失败**（不进失败计数、
  不影响退出码），但在汇总里单独列出「哪几支、第几轮偶发」；
- 两次都红 → **真红**，按真缺陷计入失败；
- 复跑绿 → 真绿。

同时，批跑器自己维持一条**常驻 CDP 连接**（复用 `cdp-harness.connect()` 的事件缓冲），
把 `Runtime.exceptionThrown` / `Page.javascriptDialogOpening` / 导航类事件按「每支次」切片，
**仅在非绿时落盘**成可读事件序列文件——红单从此自带现场，不用再人手去连 CDP 取证。

## 用户故事

1. 作为跑批的人，我想要红的支**自动复跑一次**，以便不必手工重跑就能知道它是真缺陷还是偶发。
2. 作为跑批的人，我想要汇总里**单独点出偶发支**（名字 + 轮次 + 两次退出码），
   以便区分「这批不干净」与「这批失败了」。
3. 作为跑批的人，我想要非绿支**自动落盘事件序列**（异常 / 对话框 / 导航，带时刻与折叠计数），
   以便打开文件就能看见现场，不必手工连 CDP。
4. 作为跑批的人，我想要**关掉复跑**（`--retry=0`）与**关掉监听**（`--no-diag`）的口子，
   以便对照复现、或在不关心取证时省开销。
5. 作为维护者，我想要判定逻辑是**纯函数**（输入一次支次记录，输出判定与是否需要复跑），
   以便用 `node --test` 直接单测，不必起 Chrome。
6. 作为维护者，我想要落盘文件名可 locate（含脚本名与轮次），以便在事件序列与运行记录之间来回对照。

## 实现决策

- **判定纯函数落在共用传输层** `.scratch/cdp-harness.mjs`（而不是批跑器自己）：
  批跑器与脚本共用同一份「什么算绿」的口径，避免第二处定义。
  - `runVerdict(rec)` → `pass` / `flake` / `fail`（含 `reasons`：退出码、超时、挂死信号等）
  - `retryDecision(rec, { retry })` → 是否需要复跑（`retry=0` 时永不复跑）
  - `digestEvents(events)` → 事件序列归拢：保留异常 / 对话框 / 导航类关键事件（带相对时刻），
    噪声事件（如 `Runtime.executionContextCreated`）折叠为计数，便于人读
  - `diagFileName(script, round)` → 落盘文件名（含脚本短名 + 轮次）
- **批跑器**（`.scratch/cdp-smoke-run.mjs`）：
  - 新参数 `--retry=<N>`（默认 1；0 = 关闭）与 `--no-diag`；
  - 复跑走**同一套**「重建标签页 → spawn」路径，从而与批跑一致（复跑前重建标签页）；
  - 常驻监听用 `connect({ ..., onEvent })`（或读 `cdp.events`）采集事件，**每支次前清空缓冲**，
    非绿时把该支次切片交给 `digestEvents()` 并落盘到 `.scratch/cdp-smoke-runs/`；
  - 记录 schema 扩展：`attempts[]`（每次尝试的 exit/timedOut/hung/pass）、`flake`、
    `verdict`、`retry` 段（复跑结果）、`diagFile`；**顶层的 `exit`/`pass`/`tail` 语义保持**
    （= 最后一次尝试的结果），既有读 `run-*.json` 的习惯不被打断；
  - 汇总新增偶发计数与偶发支清单；退出码：有真红 → 1，只有偶发 → 0（既有语义不变）。
- **测试缝隙**（既有最高缝隙，不新开）：`tests/js/*.test.mjs`（`node --test`）测纯函数；
  端到端用真实 Chrome（`http://127.0.0.1:9251`）+ webapp（`http://127.0.0.1:8000/`）
  跑批跑器取证（不新增 e2e 测试守卫，避免把需要活浏览器的用例塞进单测）。

## 测试决策

- **好测试**：只测外部行为——给定支次结果（退出码 / 超时 / 挂死信号）判定出偶发还是真红；
  给一串 CDP 事件，得到可读序列与折叠计数。不测实现细节（不测内部变量、不测私有函数）。
- **测哪些模块**：`cdp-harness.mjs` 新增的 4 个纯函数（`tests/js/cdp-harness-verdict.test.mjs`）。
- **既有先例**：`tests/js/write-guard.test.mjs`（纯函数直 import + 子串断言，防脆）。
- **端到端取证**（一次性、留档在 `.scratch/batch-runner-self-heal/`）：用计数器探针脚本
  造「首跑红复跑绿」的确定性偶发；用真实 CDP 脚本造「真红 + 事件序列落盘」。

## 范围外

- 不改各支冒烟脚本的断言与场景（本单只动批跑器与共用判定件）。
- 不复现/定性第十一轮那两处偶发本身（有了自助复判才有稳定判定口径，定性留给下一轮）。
- 不给 `pytest`/`tests/js` 增加需要活浏览器的守卫用例。
- 真机工具链 / 真实额度 / 干净机器 / 人工取源类验收不动（见 `real-acceptance` 单）。

## 补充说明

- 复跑判定「两次都红 = 真红、一次红一次绿 = 偶发」是**保守**口径：不追求统计意义上的
  flake 率，只回答「这一支现在能不能过」这一个问题；要更强定性需多轮 `--rounds`。
- 事件序列落盘**只落非绿支次**，避免每跑一批就产出几十个文件。
