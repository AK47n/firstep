# 08 — 词表「方案名不入合法 name」口径缺口：模型照抄提示词里的方案名 → 被闸拒收

**要做什么：** 让「模型给出的库外建议名恰好是词表里已登记的选购方案名（或其去括号裸名）」
这件事不再触发拒收——做法是**把这类方案名的裸名登记进同类别行的 `models`**（B1：
数据口径对齐），让「提示词里给模型看过的名字」与「闸认的合法 name」不再错位。
`SelectionError` 的语义边界**零改动**，不改 `_solution_group` 判据、不加代码分支。

**被谁阻塞：** 无（决策已拍，见下「决策记录」）。前置事实来自 `real-acceptance/03`
的评估节（那份评估只读取证，未改任何行为）。

**状态：** ready-for-agent

## 决策记录（2026-09-17，用户拍板）

**`wordlist.json` 的 `solutions` 语义边界 = 界面导览文本（含买件指引），
`models` 是唯一合法 name 域。**

理由（写下来免得下次再审）：

1. `models` 的既有定义就是「这个类别里有哪些可买的件」，且**已经在混装品类词**
   （`红外传感器` / `超声波传感器` / `指纹模块` / `4×4 矩阵键盘` / `步进电机` / `磁力计`）——
   把方案名的裸名登记进同一行是**同一类词继续往里放**，不是新增语义层；
2. `solutions` 保持「导览 / 买件指引」语义不变：价格、接线、适用场景是给人看的，
   原工单 B2（把方案名纳入合法 name）会让判据变两套（name 域 + solutions 域），
   并产生「chip 名 = 一整句话」与面板同一句话显示两遍的问题——**不采用**；
3. 候选方案 `B2`、`B3`（保持拒收）的取舍见 `real-acceptance/03` 实施记录 ③。

## 根因（一句话）

`format_wordlist_prompt` 把**方案名**列进「选购方案：…」段摆在模型眼前，
而闸的合法 name 域 = `类别名 ∪ models`（`selection._solution_group` 单源）——
**提示词给什么看，闸就不认什么**，于是模型照抄即被拒（第十七轮 2026H 现场抓到的
「串口摄像头（JPEG 输出 UART 转接）」逐字来自提示词方案段，把因果关系钉死了）。

## 实测数据（2026-09-17 全库现算）

| 量 | 值 |
|---|---|
| 词表行 / 选购方案总数 | 11 行 / **87 条方案** |
| 方案名**不在**合法 name 域（类别 ∪ models）的 | **85 / 87** |
| 其中「去括号裸名 ≠ 全名」的（模型可能照抄前半句） | **61 条** |
| B1 全量补裸名（74 条去重）后词表提示词体积 | 5134 → **7076 字节（+1942）** |
| 参照：整包推荐请求实测 / 上限 | 122161 / 131072 字节（余量 6.8%） |

**红证（实施前，逐条现算 `build_module_selection`，与工单 03 评估同源）：**

```
'红外对管循迹数组'                → 拒收  库外建议的硬件名不在硬件词表中：红外对管循迹数组
'红外测距传感器'                 → 拒收  库外建议的硬件名不在硬件词表中：红外测距传感器
'直流减速电机 + TB6612 双路驱动板'    → 拒收  库外建议的硬件名不在硬件词表中：直流减速电机 + TB6612 双路驱动板
'串口摄像头（JPEG 输出 UART 转接）'   → 拒收  库外建议的硬件名不在硬件词表中：串口摄像头（JPEG 输出 UART 转接）
```

四条各自逐字命中某行的 `solutions[].name` 或其去括号裸名 → **B1 可达**。
现场另外两条：`称重传感器`（词表只有方案「HX711 称重传感器（压阻半桥）」，**需裁定**）、
`TI MSPM0 主控板`（平台本身、无对应类别行 → **拒收正确，不治**）。

## 修复方向（实施会话照此做）

1. **补数据（主改动，`src/contest_generator/wordlist.json`）**：把六条现场被拒名中
   可达的四条对应的**裸名**补进同类别行的 `models`（去重保序）：
   - `感知传感器` ← `红外对管循迹数组`、`红外测距传感器`（同时可按需补
     `串口超声波` / `红外避障探头` 等同族裸名——判据见下）；
   - `执行机构` ← `直流减速电机 + TB6612 双路驱动板`（**逐字方案名**，本身长但有信息量）；
   - `视觉模块` ← `串口摄像头`（全名带括号长句不入 models，裸名入）。
2. **裁定规则（机械可判，实施时逐条过一遍再落盘）**：对 24 条「裸名未入 models」的方案，
   **入 models** = 该裸名是**电赛真会买的硬件**（能写进采购单的名词短语）；
   **不入** = ① 平台/主控本身（`TI MSPM0 主控板`）；② 上位概念（`称重传感器` 归
   `HX711 称重传感器（压阻半桥）` 那条方案，裸名要不要入需明确写理由）；
   ③ 形态是句子 / 组合描述（`车模自带驱动板（整车/轮组+驱动成品）`、`LED + 蜂鸣器 声光组合套件`）；
   ④ 与既有 models 条目重复（`EC11 旋转编码器（带按键旋钮）` → models 已有 `EC11 旋转编码器`）。
   **规则细节与逐条清单在实施会话写进本节下方（不要另开文档）**。
3. **旧契约用例改红为绿**：`tests/test_selection.py::test_build_selection_solution_name_is_not_a_legal_suggestion_name`
   钉的是「方案名不合法」的**旧现状**——本轮落地后该断言必须红着被改（改成
   「方案名裸名入 models 后合法」或补一条新用例），工单 03 已把它登记为回归锚。
4. **结构守卫（防空转）**：`tests/test_wordlist.py` 补一条——**现场被拒名不得再被拒**
   （用 `DEFAULT_WORDLIST` + `build_module_selection` 直测四条，断言不再抛
   `SelectionError`；同时留一条「`TI MSPM0 主控板` 仍拒收」的对照断言，防把闸放宽成万金油）。
5. **不改的东西（硬边界）**：`selection._solution_group` 判据、`OutOfLibrarySuggestion`
   字段与 `degraded` 语义、`fx/recommend.js` 的降级文案、`format_wordlist_prompt`
   的渲染形态——一个字都不动（B1 的卖点就是零代码）。

## 不做什么（明确范围外）

- **不治 `instances` 幻觉**（`模块 k230/xunji/ntb_time/adc/oled/huidu 不支持多实例`）：
  那是另一类失败（模型给非多实例模块加了 `instances`），已由 `real-acceptance/03`
  的带理由重试接住一部分；本轮按现场归类是 **4 条词表口径 + 5 条 instances 幻觉**，
  别把两笔混算成「词表闸 9 条」。
- **不做模糊匹配 / 跨类别猜测**：降级只允许确定性反查（与既有「词表外型号 + 模型
  给出词表内 category 才降级」同一条保守线）。
- **不动 `solutions` 的字段语义**（价格 / 接线 / 适用 / `recommended` / `lib_modules`
  解析与展示全部照旧）。
