# 08 — 词表「方案名不入合法 name」口径缺口：模型照抄提示词里的方案名 → 被闸拒收

**要做什么：** 让「模型给出的库外建议名恰好是词表里已登记的选购方案名（或其去括号裸名）」
这件事不再触发拒收——做法是**把这类方案名的裸名登记进同类别行的 `models`**（B1：
数据口径对齐），让「提示词里给模型看过的名字」与「闸认的合法 name」不再错位。
`SelectionError` 的语义边界**零改动**，不改 `_solution_group` 判据、不加代码分支。

**被谁阻塞：** 无（决策已拍，见下「决策记录」）。前置事实来自 `real-acceptance/03`
的评估节（那份评估只读取证，未改任何行为）。

**状态：** resolved（2026-09-17 落地：B1 补数据 + 预算配套；两处未了见文末「实施记录」）

## 决策记录（2026-09-17，用户拍板）

**`wordlist.json` 的 `solutions` 语义边界 = 界面导览文本（含买件指引），
`models` 是唯一合法 name 域。**

理由（写下来免得下次再审）：

1. `models` 的既有定义就是「这个类别里有哪些可买的件」，且**已经在混装品类词**
   （`红外传感器` / `超声波传感器` / `指纹模块` / `4×4 矩阵键盘` / `步进电机` / `磁力计`）——
   把方案名的裸名登记进同一行是**同一类词继续往里放**，不是新增语义层；
2. `solutions` 保持「导览 / 买件指引」语义不变：价格、接线、适用场景是给人看的，
   原工单 B2（把方案名纳入合法 name）会让判据变两套（name 域 + solutions 域），
   并产生「chip 名 = 一整句话」与面板同一句话显示两遍的问题——**不采用**；
3. 候选方案 `B2`、`B3`（保持拒收）的取舍见 `real-acceptance/03` 实施记录 ③。

## 根因（一句话）

`format_wordlist_prompt` 把**方案名**列进「选购方案：…」段摆在模型眼前，
而闸的合法 name 域 = `类别名 ∪ models`（`selection._solution_group` 单源）——
**提示词给什么看，闸就不认什么**，于是模型照抄即被拒（第十七轮 2026H 现场抓到的
「串口摄像头（JPEG 输出 UART 转接）」逐字来自提示词方案段，把因果关系钉死了）。

   - `感知传感器` ← `红外对管循迹数组`、`红外测距传感器`（同时可按需补

2. **裁定规则（机械可判，实施时逐条过一遍再落盘）**：对 24 条「裸名未入 models」的方案，

### 裁定结果（实施会话，2026-09-17）

**先更正两条量：**

1. 原文「24 条」是估值——**逐条现算去重后是 60 条**（`adjudicate-18-bare-names.py`，
   按行去重 + 全库唯一，两口径同数 60）。逐条清单见
   `.scratch/recommend-domain-reject/adjudicate-18-bare-names.txt`。
2. 这 60 条里，基线（补数据前）**已有 25 条**因裸名与其他方案重合而本来就在 models
   （所以 `measure-18` 报的「补裸名 74 条」是**未去重**口径，虚高）。真正要处理的
   是剩下 35 条，而**只有 15 条落得下**：`入 15 条 / 口径不入 9 条 / 其余 11 条未入选`。
   硬约束是**请求预算**（不是 2500B 那条软上限）：词表段必须**全量送达**（截断 =
   模型看不到合法名 = 退化成本工单要治的病，且
   `test_wordlist_segment_covers_default_wordlist_and_budget` 契约钉死），而真实库
   最坏形态（`test_recommend_real_library_budget`）在**基线**上距自设 2KB 边界只剩
   **97B**（HEAD 实测 mspm0 128927B）——即**任何有意义的补数据都必然越界**，
   这是本工单落地时最反直觉的一条。

**入选顺序按「真机可达性」而非成本排**：第一版按段成本从便宜收到贵（收 21 条），
真机复跑（2026H / mspm0）当场打到顺延里的 `脉冲式步进电机 + 驱动板`——**证明
「方案名 = 型号 + 品类长句」是真实可达面，不是理论风险**（模型就是照抄方案名），
于是改为「现场四条 → 工单点名的同族 → 已达可达性证明的长句名 → 高价值品类名」，
成本便宜但长句风险低的名字（`AT24C02 EEPROM` / `OpenMV Cam H7` / `GPS/北斗` 等）
让位。**这条教训值得记：词表补数据的排序依据是可达性，不是字节成本。**

**两条传导路径（只量词表段会低估数倍）**：`preselect_module_summaries` 吃词表做
词表挂接加分 → 词表变也可能改变摘要段排序/截断边界。实测本批摘要段 +0B、词表段
+773B；但**记账口径必须按「词表段实发增量」**（models 条目与 `format_wordlist_prompt`
的「选购方案」段重复，按 JSON/wire_size 估会偏），工具
`measure-18-wordlist-budget.py` + `size-18-candidates.py`（逐条试加现算）。
