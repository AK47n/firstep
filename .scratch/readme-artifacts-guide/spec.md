# Spec：README 生成物清单与「生成后怎么继续」指引

## 问题陈述

课程历次迭代后，生成器新加了很多生成步骤与产物，但随工程生成的三份 .md（README / 演示脚本 / 报告草稿）没有跟上：README「目录结构」章仍只列母版固有文件（main.c / pin_config.h / syscfg 等），而生成时新增的东西——README 自身、演示脚本、设计报告草稿（可选）、K230 副产物 main.py（可选）、.contest_context.json、.contest_wiring.json、mspm0 的 Debug/makefile 集——在目录表里完全看不到；README 也没有说明「工程生成后去哪继续」（修复中心 / 任务推进 / 参数速调 / 交付 / 交接），学生打开工程文件夹不知道每个文件是什么、哪些该自己编辑、哪些是工具自维护的、接下来的主路径是什么。

## 方案

随工程生成的 README 保持纯确定性渲染不变，内容补齐两处：

1. **目录结构章补「生成时新增」行**：清单 = 生成器写盘产物（README 自身、演示脚本、设计报告草稿（可选）、K230 副产物 main.py（可选，仅选了带副产物声明的模块）、.contest_context.json（工具上下文清单）、.contest_wiring.json（接线快照，板数据缺失时也不写）、mspm0 的 Debug/ 下 makefile 集（CCS 工具链未探测时跳过））。按平台声明行集合，非每次都有产物在行注中标「（可选）」；stm32 与 mspm0 的产物差异（mspm0 有 makefile 集）分别列出。

2. **新增「生成后怎么继续」章**（放在验证顺序清单之后）：说明生成完回工具继续——第 10 步修复中心（编译报错处理）、第 11 步修订与深化（任务推进 = 主路径：任务卡逐段实现 + 每步编译验证 + 上板反馈；修订；参数速调；交付打包；新想法 / 全局商量）、第 12 步交接提示词（复制给外部 AI，可选）；并说明 .contest_* 开头的文件是工具内部状态（任务清单 / 想法草稿 / 上下文清单 / 接线快照 / 参数识别），随生成与执行自动更新，不要手动改，打包交付时自动排除。

## 用户故事

1. 作为学生，我想在 README 目录结构表里看到生成时新增的全部文件（演示脚本 / 报告草稿 / 上下文清单 / 接线快照 / K230 main.py 等），以便知道工程文件夹里每个文件是干嘛的、哪些可以编辑。
2. 作为学生，我想看到「可选」标注（报告草稿 / K230 main.py 不是每次生成都有），以便文件缺失时不困惑。
3. 作为学生，我想 README 告诉我生成后去哪继续（第 10 / 11 / 12 步的用途与主路径），以便不回工具页面也能知道下一步干什么。
4. 作为学生，我想知道 .contest_* 文件是工具自维护、不要手动改，以便不误改内部状态。
5. 作为开发者，README 渲染保持纯确定性与平台静态话术（不依赖工具链探测结果），以便逐字节可测、跨运行稳定。
6. 作为开发者，目录结构表与母版的同步守卫继续有效：新增「生成时创建」行有明确的按平台豁免清单，母版目录 / 关键文件的全覆盖守卫不丢，以防结构性漂移被掩盖。

## 实现决策

- 渲染层新增**生成物行白名单常量**（按平台：`dict[平台, tuple[路径, ...]]`，单源），目录结构章渲染 = 母版行（现 DIRECTORY_STRUCTURE）∪ 生成物行；生成物行与母版行同表渲染（同列格式），可选性标注写进行注。**评审整改（双轴评审记录）**：mspm0 的 Debug/ 下 makefile 集不单列生成物行——Debug/ 母版行行注已承载该信息（并顺手修正原行注「makefile 点击构建后自动生成」的过时表述 =「makefile 由生成器写入，*.out 点击构建后生成」），再列一行与 Debug/ 行重复；两平台生成物行差异由该行注体现，白名单本身两平台共用同一生成物元组。
- 白名单与生产文件名常量的同步由测试钉住（生成物行文本必须包含实际文件名常量，防只改常量不改表）。
- 新增**「生成后怎么继续」章**：章节标题固定；正文 = 平台无关的静态话术 + .contest_* 状态文件说明段；位置在验证顺序清单章之后、文档尾部。
- 母版同步守卫（三方向）调整：方向一（列出项必须真实存在于母版）对生成物行白名单豁免——白名单路径不再要求母版存在；新增方向四：白名单每项必须出现在该平台目录结构表中（防漏列）；方向二 / 三（母版目录与关键文件全覆盖）不动。
- 演示脚本 / 报告草稿：校核交叉引用（README 章节名「快速上手：编译 + 烧录」「引脚接线表」「验证顺序清单」保持不变，引用不漂移）；报告草稿「测试记录模板」引导语与 README「验证顺序清单」同源不变。
- 渲染签名不变（不新增入参）：新内容全部是渲染器内部静态文本——zero 接口变更、zero 写侧变化（只改 README 文本内容）。

## 测试决策

- 主 seam = test_readme 渲染器纯函数直测：断言新章节标题、生成物行（含可选标注）、新章节关键话术（第 10/11/12 步、.contest_* 说明）出现在两平台渲染输出。
- 流程级 seam = test_generator / test_readme 既有「生成到 tmp 断言 README」用例扩展：生成后 README 含「生成后怎么继续」标题与 .contest_context.json 行。
- 同步守卫测试更新：白名单豁免 + 方向四（白名单必列）；既有方向二 / 三断言保持。
- 演示脚本 / 报告草稿既有测试不动（交叉引用核对 = 人工校对 + 现有断言回归）；若校对发现文案需微调，相关测试随工单同步。

## 范围外

- 不改 12 步向导编号 / 标题 / 现有页签结构（README 引用与向导现状一致）。
- 不改教程（guide.js）内容。
- 不改验证顺序清单语义 / bring-up 排序。
- 不改演示脚本与报告草稿的章节结构（仅校对交叉引用；若无需改动则零差异）。
- 不做 README 模板用户自定义、不做语言切换。

## 补充说明

- 起点：用户发现「生成的 .md 可能逻辑过时，因为后面又新增加了生成步骤」——指 README 目录结构章漏列新产物、无生成后流程指引；经确认范围 = 目录结构章补齐生成物清单 + 后段流程指引（推荐），另两 .md 交叉引用同步校对。
- 写盘产物事实（供文案准确性）：README 与演示脚本总是写；设计报告草稿仅 LLM 文本可用时写；.contest_context.json 总是写；.contest_wiring.json 仅板数据存在时写；K230 main.py 仅选中带副产物声明的模块时写；mspm0 Debug/makefile 集仅工具链探测到 ccs_tools 时写（未探测 = 跳过）。
