# 08 — 浏览器门禁在 CI 上没有 Keil / gmake：真编译用例必红，并把两条无关用例一起拖红

**要做什么：** 让浏览器门禁在「这台机器没有编译工具链」这个前提下的行为是**显式**的：
无工具链时"真 UV4 编译"那条**如实 skip 并写明原因**（不是 30 秒超时红，也不是静默绿）；
同时**一条真红不许滚成三条**——`hwcheck.spec.mjs` 文件头早就记着这个坑，这次在 CI 上又中了。
并且要让本机**能造出 CI 的那个前提**，否则这道门以后还会重演同样的"本机全绿、CI 三条红"。

**被谁阻塞：** 无——可立即开始。

**状态：** ready-for-agent

- [ ] 先建**本机可跑的反馈回路**（这是本单的地基）：夹具要能把"没有工具链"这个条件**造出来**，
      回路 = 一条命令，能在本机复现 CI 的 3 条红。做法照本仓既有单源：工具的探测**本来就有配置
      覆盖口**（`config.json` 的 `uv4_path` / `gmake_path`，`compile_runner.find_uv4` 明写
      "非空但指向不存在的文件按未找到处理"）——夹具把这两个键指到不存在的路径即可，不新造概念。
- [ ] 复现：贴出本机在两态下的读数（有工具链 → 现状全绿；按上面的姿势造出无工具链 → 复现 CI 的
      3 条红）。**复现不出来就别改**——形态对不上说明根因判断错了。
- [ ] 定性级联：`:818`「自建件的串口复测」与 `:914`「装不下时的出路…真能生成」是**独立根因**
      还是被 `:398` 那条拖下水的（文件头 `clearDevices()` 那段写着"一条真红滚成两条"的旧账）。
      按定性结果决定改哪一层——**不许用"把超时调大"糊过去**。
- [ ] 无工具链时 `:398` 改成显式 skip（原因里点名缺的是哪件工具链、以及本机怎么补），
      **判据不许静默变绿**：skip 必须在摘要里看得见。
- [ ] 产品侧核实过了：预览 / 生成**本来就不依赖**编译工具链（`fx/hwcheck.js` 的
      `hwcheckCanPreview` 只看平台；`/api/hwcheck/generate` 的 docstring 明写"mspm0 无 CCS
      工具链时只出 build_hint 提示，不阻断"）。若复核时发现别处真有把工具链当生成闸门的写法，
      一并收窄到"只挡编译按钮"这一处。
- [ ] 有工具链的本机读数：`hwcheck.spec.mjs` 仍全绿（`08` 不许把本机那几条真编译用例弄丢）。

**已定性的一条**：`:398` 的直接根因是**没有工具链**——`ui/hwcheck.js` 的 `compileReady()`

⇒ `false` ⇒ 编译按钮置灰（`fx/hwcheck.js:327-329` 的 `ready` 门）。这条用例自己的名字
（"工具链缺失时本用例如实红"）就是**本机口径**：本机开发机装着 Keil，所以它一直绿，
而 CI runner 不该、也不能装 Keil。

**待定性的部分（本单第三、四条验收标准要回答）**：`:818` / `:914` 两条在**本机**
（有工具链）全绿、在 CI 上红。可能是独立根因，也可能是 `:398` 那条红之后的**级联**——
文件头 `clearDevices()` 那段记着同形的旧账（"一条真红滚成两条，读的人会以为坏了两个地方"）。
不许凭形态猜，要用上面那条本机回路把它问清楚。
