# spec：界面「呼吸感」改造（样板 = 硬件检测页）

> 状态：待用户确认（clarify 已完成：范围 = 先做检测页样板；力度 = 允许拆框套框 + 调排版；
> 靶子 = 字太小 / 框套框 / 间距单档 / 重点不突出）
> 立项日期：2026-09-27

## 问题陈述

用户看硬件检测页时的原话：「好挤啊，感觉一点也不够明朗，给我一种小家子气的感觉」。

盘上量出来的硬指标（改前读数，2026-09-27 实测）：

- **字号没有台阶**：全站 13 种字号里 `12px × 168 处`、`11px × 60`、`12.5px × 62`、`13px × 74`
  ——**364 处 ≤13px**，而 `15px` 只出现 3 次。等于**不存在"正文"这一级**：卡片标题 16px 与正文
  只差 3px，说明文字与正文同为 `--muted`，扫一眼分不出主次。
- **间距只有一个档**：`--space-2`（8px）用 168 次，`--space-4`（16px）23 次，`--space-6`（24px）
  **一次没用**。区块之间与区块内部一样紧 ⇒「挤」。
- **框套框**：检测页一屏内可达四层描边（页面卡 → 蓝色左条大框 → 器件行分隔线 →
  表单框 `--border-strong` → 字段），圆角还全是同一个 `--radius-md` ⇒ 边界很吵、层级很平 ⇒
  「小家子气」。
- **步骤标题被做成了灰字**：主卡里的「1. 目标平台 / 2. 输出通道 / 3. 要测的器件 / 4. 保存位置」
  是 `13px + --muted`，比正文标签还弱 ⇒「重点不突出」。
- **同形卡片堆叠**：检测页从上到下 10 张形状完全一样的卡（配置 1 张 + 结果 7 张 + 上板 2 张），
  没有分组，且未生成时多数是空态 ⇒ 首屏看不清"我现在该干什么、下一步看哪里"。

## 方案

给界面补上**缺失的三件东西**，先在硬件检测页落地、看效果：

1. **一条字台阶梯**（三级 + 标签级）：区块标题明显大于小节标题、小节标题明显大于正文，
   正文明显大于「说明」，且改变靠**字号 + 字重 + 颜色**三者共同承担，不再只靠 `--muted`。
2. **一条间距阶梯**：区块之间用大间距（24px 档）、小节之间用中间距（16px 档）、
   行内用 8–10px。同一页内不再只有一个 8px 档。原则：**能用留白分组的，不描边**。
3. **描边只留一层 + 重点会跳**：一屏内只有最外层容器有完整边框；内层改留白 / 一条分隔线 /
   浅底；当前选中、危险操作（删除）、主操作（生成）各自有明确的视觉重量。

## 用户故事

1. 作为第一次打开检测页的学生，我想要一眼看出"这一页分几段、我现在该点哪里"，
   以便不用读完整段说明就开始用。
2. 作为老师傅用户，我想要正文能舒舒服服读完（而不是满屏 12px 灰字），
   以便长时间对着这一页勾引脚、对读数不费眼。
3. 作为用户，我想要"步骤标题"看起来就是标题，以便在长页面里滚动时能靠标题定位段落。
4. 作为用户，我想要当前选中的器件 / 正在编辑的那一件在视觉上"跳出来"，
   以便确认我改的是哪一件（而不是靠逐字读名称）。
5. 作为用户，我想要"删除"这类不可逆动作与普通动作明显不同，以便不会误点。
6. 作为用户，我想要没生成之前的那几张空卡片不那么吵（弱化或说清"生成后这里会出现什么"），
   以便首屏不被空盒子占满。
7. 作为用户，我想要深色与浅色主题下都是同一套层级（不是只有暗色好看），
   以便按环境切换主题。
8. 作为维护者，我想要这次改造不改变任何 **id、DOM 顺序与既有类名语义**，
   以便 96.6 KB 的真浏览器用例与结构钉继续有效（视觉改、契约不变）。
9. 作为维护者，我想要一套**能防回退的守卫**（字号 / 间距取值不许再碎片化），
   以便下一个人加样式时不会又把 12px 铺满全页。
10. 作为维护者，我想要 before/after 的真浏览器截图落盘，以便"改好了"这件事有人眼可查的证据，
    而不是只靠"门禁全绿"。

## 实现决策

- **改造面**：样式层（`index.html` 的内联样式块）为主 + **只新增类名**的极小标记改动。
    明确不动：任何 `id`、任何 DOM 顺序、既有类名的语义（`hwcheck-section` / `hwcheck-generic` /
    `hwcheck-my-device` / `hwcheck-custom-plan` 等被守卫与用例点名的类）。
    理由：`tests/js/hwcheck.test.mjs` 按源码文本钉 id 与顺序、`tests/browser/hwcheck.spec.mjs`
    有 361 处选择器引用——"视觉大改、契约不变"能把回归面压到最小。
- **"拆框套框"用 CSS 完成**：边框是 `border` 声明，内层容器去掉描边、改留白与分隔线即可，
    不需要动 DOM。只有"给卡片分组"这一类需要**新增**分组标记（加类名，不搬 DOM）。
- **字号与间距落地为令牌**：新增/收敛成一条有限的取值集合（正文 / 次要 / 小节标题 / 区块标题 /
    标签），后续全站推的时候直接复用同一套令牌，不再各页各写。
- **两套主题同步**：改的是令牌与结构层级，不是散落的硬编码色值；浅色主题（`data-theme="light"`）
    必须同轮验证。
- **检测页内部的信息取舍**（不删事实，只调呈现）：主卡现在塞了 4 件事（选器件 / 我的器件 /
    搜索与器件网格 / 保存位置与动作）；空态卡片弱化；长说明段不删，但降为"说明"级（可折叠留着）。
- **不做**：不改宽屏 `max-width`（用户明确未选这条）；不改任何文案事实与判据；不做交互行为变更
    （除纯呈现的折叠开关外，不加新功能）。

## 测试决策

- **最高既有缝照旧吃住**（不新造缝）：
    ① 前端门禁 `node --test "tests/js/*.test.mjs"`——含 DOM 契约（页面声明的 id ↔ ui 引用）、
      import 使用面、结构钉（`tests/js/hwcheck.test.mjs` 的 id 与顺序断言）；
    ② 浏览器门禁 `node --test --test-concurrency=1 "tests/browser/*.spec.mjs"`——真页面 + 真后端，
      其中 `hwcheck.spec.mjs` 是检测页行为契约的主证据；`ui-contract.spec.mjs` 覆盖向导与折叠态。
- **新增一条静态守卫**（本 spec 唯一的"新缝"）：字号 / 间距取值必须落在允许集合内
    （防再次碎片化）。形态照既有先例：判据纯函数 + 守卫用例 + 合成红证（往页面里塞一个越界字号 ⇒ 红）。
- **人眼验收**：真浏览器 before/after 截图（暗 / 亮两主题 × 检测页整页），落盘为证据；
    用户在样板页上拍板"是不是这个方向"，再谈全站。
- **红证先行**：先把"现在的碎片化"钉成红（越界字号 / 间距档）→ 改完转绿；守卫自身要能被
    合成注入判红（判据强度自检，照 `tests/js/` 既有先例）。

## 范围外

- **全站其他 8 个页面**：本轮只做检测页样板；用户看过样板、认可方向后另立一轮
  （届时复用的正是本轮定下的令牌与层级规则）。
- **宽屏铺太满（`main` 的 `max-width` 与两侧留白）**：用户在靶子里明确没选这条，本轮不动。
- **文案事实与判据**：不改任何"说什么"（如「未上板」「专精 / 通用降级」的措辞与判据），
  只改"怎么说、放在哪一级"。
- **交互行为变更**：不新增功能；折叠态这类纯呈现开关若引入，必须有既有用例覆盖的等价行为。
- **图标体系 / 字体更换 / 动效**：不引入外部资源与动画体系（本地应用、离线可用是硬约束）。

## 补充说明

- 用户的靶子（四条）：字太小（正文与说明同级）、框套框太多、间距单档、重点不突出。
  其中"宽屏铺太满"**未选**——记在范围外，避免下一轮当成漏做。
- 本 spec 的改前读数是可复跑的（字号 / 间距分布可由静态文本统计得出），
  工单里要把"复跑方式"写下来，供下一轮全站推的时候再量一次。
- 视觉改造的验收天然带主观成分：**用户看样板拍板**是最终判据，门禁只保证"没改坏"。
