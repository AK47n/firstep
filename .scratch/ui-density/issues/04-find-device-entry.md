# 04 — 检测页：挑器件 / 登记「我的器件」的入口藏在下面（决策单）

**要做什么：** 用户想「代入模块」和「引入自己创建的模块」，**在页面上找不到入口**，
往下翻了半天才发现（原话：「ui 提示不够到位……找了才发现原来在下面才是」）。
本单先拍板走哪条修法，再实施。

**被谁阻塞：** 无——可立即开始（但要先拍板：这是决策单）。

**状态：** resolved（2026-09-27；用户选 b，同日落地，零 JS）

## 现场（用户原话 + 页面实况）

用户报的是「很多输入框都无法点击输入」，排查后**不是点击被挡**——是**入口不在视野里**：
他要找的是"把器件带过去"和"登记自己的件"，两块都在**首屏之下**。

判据（`.scratch/ui-density/probe-04-input-clickable.mjs`，真浏览器 + 真后端，12 个页签滚到底、
每个控件取中心/左 1/4/右 1/4 三个点看"最上层元素是不是它自己"，再真点进去打字）：

```
去重控件 50 个 / 被盖住 1 个（单独挖开时不复现，见 probe-05）/ 打字失败 0 个
```

⇒ **点击面没坏**。坏的是**信息架构**。检测页主卡里「3. 要测的器件」这一段现在的顺序是：

1. 已选 chips（选了什么）
2. 撞脚 / 缺失 / 互斥组提示
3. **带入生成页**（把选中的带过去）
4. **我的器件**（库外件登记：名称 / 总线 / 地址 / 身份寄存器 / 备注）
5. **器件搜索 + 器件网格**（从库里挑）← **挑器件的地方在最下面**
6. 「4. 保存位置」+ 预览 / 生成

也就是说：**"挑"在"带过去"的下面**，而"我的器件"夹在中间；三块的标题都只有一行小字，
不像入口。用户顺着读下来，读到"带过去"时手上还没东西可选，自然就卡住了。

## 三条修法（拍板选一）

| 选项 | 做什么 | 代价 / 风险 |
|---|---|---|
| **a. 只补文案** | 在「3. 要测的器件」标题旁 + chips 空态里各加一句指向：「从下面『器件搜索』挑（在『我的器件』下方）」/「没有的件点『+ 我的器件』登记」 | 最小：改 `fx/*.js` 两处文案 + 断言；**不动 DOM、不加交互** |
| **b. 加两个跳转锚** | 步骤 3 顶部加「↓ 挑库内器件」「↓ 登记我的器件」两个小链接，点了滚到对应块 | 中：新增元素 + 滚动逻辑（新交互要进浏览器用例）；不重排 DOM |
| **c. 真的调顺序** | 把「器件搜索 + 网格」提到「带入生成页」之前，并把「我的器件」收成一行入口 | 最大：**动 DOM 顺序** → `tests/js/hwcheck.test.mjs` 的 indexOf 顺序断言、`probe-03-contract.py` 的对账口径、浏览器用例都要跟着改，重跑三套门禁 |

**推荐 b**（可发现性问题的正解是"看得见的入口"，而不是再写一句话让人往下找；代价可控）。
若只想止血，选 a；c 留到真有第二个人被绊到时再做。

## 实施（2026-09-27，同日落地）

样式与标记各一处，**零 JS**：

- **标记**（`index.html` 检测页）：`<h3>3. 要测的器件</h3>` 之下新增一行两个原生锚
  ——`<a class="hwcheck-jump" href="#hwcheck-device-search">↓ 挑库内器件</a>` 与
  `href="#my-devices"` 那条。原生 `<a href="#id">` 打底：**无 JS / 键盘 / 读屏都能跳**。
- **样式**：两个胶囊（`--radius-full` + `--fs-note` + accent 字色），
  目标三件（`#hwcheck-device-search` / `#my-devices` / `#hwcheck-device-grid`）加
  `scroll-margin-top: calc(var(--header-h) + 16px)`——**不然跳过去正好被黏顶栏压住**；
  高亮走 **CSS `:target`** 动画（1.6s 一圈 accent 光晕），不写一行 JS。

**为什么最后是零 JS（一次真实的返工，值得记）：** 第一版我按"平滑滚动 + 高亮 class"写了
一个 `handleJumpAnchor` 挂在 `ui/hwcheck.js` 的入口接线里，**被既有结构钉当场判红**——
`tests/js/hwcheck-split-integrity.test.mjs` 钉着"入口只有接线 + 两个导出"，而且它按
**行多重集**与搬迁前快照对账（那份台账是 `hwcheck-hygiene/11` 的验收物）。它的判词是对的：
这是**纯呈现**的东西，原生锚点 + `:target` 就能给，不该往那份台账里加一页。
**结论：能不给 ui 四件加分支就不加**；真要加，得先改那份台账的算法（不是改它的名单）。

## 备注

- **顺带修掉一条真红（值得记）：** 新用例第一版开头调了本文件通用的 `openTab()`（整页 `goto`）
  ——那会**打断上一条用例里尚未结算的路由桩**（那条用例给 `**/api/hwcheck/preview` 装了个
  1.5s 延时的 `route.continue()`）。后果是 Playwright 在本文件收尾时抛
  `route.continue: Route is already handled!`，走 `unhandledRejection` → **文件级判红**，
  而 38 条用例**每一条自己都是绿的**（跑单文件也绿，只有放进整套才红）——最容易被读成"随机红"。
  修法：这条用例只切页签 + 回顶部，不重开页面（本文件共用一张 page）。
  **教训**：一个 spec 文件里混用"整页 goto"与"路由桩"时，goto 会把前一条的桩打断。
- **同源教训（写在这里免得下轮重走）**：用户报「点不动」时，先分清三种病——
  ① 真被盖住（`elementFromPoint` 判据，本单的 probe-04 就是这把尺，**实测 49/50 正常**）；
  ② 控件状态如此（`readonly` / `disabled`，用户看到的现象一样）；
  ③ **入口不在视野里**（本单中的就是这条）。前两种能机器判，第三种只能靠"用户找不到哪儿"这句话本身。
- 与 `ui-density/02` 的关系：02 已经把"10 张同形卡片"分成三段，但**卡内**的段落顺序没动
  （那是 DOM 顺序）。本单选 b，仍然没动顺序；**c 留到真有第二个人被绊到时再做**。
- 用户的第二个困惑（"怎么带入模块"）如果指的是**生成页**那一侧的模块清单，
  那是另一个页面的入口问题——不在本单射程，遇到再单开。
