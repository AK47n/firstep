# 03 — 防回退守卫 + 前后对照证据

**要做什么：** 把「界面又开始碎片化」这件事变成**机器能判红**的：字号与间距的取值必须落在
允许集合内（检测页必须落在新台阶上），越界即红；并把「改好了」落成人眼可查的证据——
真浏览器 before/after 截图（暗/亮 × 整页）与可复跑的读数脚本。

**被谁阻塞：** 02（对照图的"after"要等拆框与重点都落定；守卫的允许集合也要等 01/02 的取值定下来）。

**状态：** ready-for-agent

## 为什么要有这单

本轮改造的价值一半在"改对"，另一半在"**不被下一个人改回去**"。仓库既有先例都是这个形状：
`tests/js/ui-dom-contract.mjs`（id 契约）、`tests/js/import-usage.mjs`（未使用导入）、
`tests/js/boot-contract.mjs`（装载契约）——判据纯函数 + 守卫用例 + 合成红证。
本单照这个形状补一条**排版契约**。

## 验收标准

- [ ] **判据纯函数**（`tests/js/` 下新增，形状照 `ui-dom-contract.mjs`）：输入 = 页面源码文本，
      输出 = 违规清单。判据至少两条腿：
      ① **检测页样式段**里出现的字号 / 间距值必须落在 01 定下的集合内；
      ② **全站**取值集合不许**新增**越界值（现状 13 种字号以**冻结清单**登记在案，
      只许减不许增——照 `IDENTITY_BACKLOG` / `LATER_EDITS` 的既有手法，全站推广时逐条摘）。
- [ ] **守卫用例进前端门禁**（`node --test "tests/js/*.test.mjs"` 自动吃住，无需改闸门配置）。
- [ ] **合成红证**：往页面里注入一个越界字号 → 红；注入一个越界间距 → 红；复原后转绿。
      读数落盘，并附**判据强度自检**（每条腿都被 stub 验证过会红——防止"永远绿"的守卫）。
- [ ] **改前读数可复跑**：字号 / 间距分布统计脚本落 `.scratch/ui-density/`，
      一条命令跑出本 spec 里那张表（全站推广时直接再跑一次对比）。
- [ ] **before/after 截图**：真浏览器 + 真后端，检测页**整页**截图（暗 / 亮两套），
      改前（`git stash` 或对照固定版本）与改后逐对落盘；文件命名与本目录 README 索引写清
      "哪张是哪一版"。
- [ ] **口径说明**：截图脚本与守卫各自的**边界**写清楚（截的是哪一屏、什么视口宽度、
      哪些状态是造出来的数据），别让下一个人以为"整站都判过了"（`hwcheck-hygiene/12` 的教训：
      判据面收窄必须留话）。
- [ ] **门禁读数**：前端门禁 + 浏览器门禁 + 全量 pytest 改后读数落盘。

## 备注

- 守卫**不判"好不好看"**（那是人眼验收），只判"取值有没有越界"——这条边界要写在守卫文件头，
  免得后人以为它能替代审美判断。
- 冻结清单不是"免死金牌"：全站推广完成后，清单应收敛到新集合、条目数写进读数
  （体量本身就是"改造推进到哪了"的尺子）。
