# 01 — 排版地基：字台阶梯 + 间距阶梯（检测页落地）

**要做什么：** 硬件检测页上，「区块标题 > 小节标题 > 正文 > 说明」四级**肉眼可辨**；
区块之间用大间距、小节之间用中间距、行内用紧间距（不再只有一个 8px 档）；
深色与浅色两套主题同一套层级。**不删任何文案、不动任何 id 与 DOM 顺序、不改既有类名语义**
（只新增类名与令牌）。

**被谁阻塞：** 无——可立即开始。

**状态：** resolved（2026-09-27；读数、契约对账与账见文末「结论」）

## 验收标准

- [x] **令牌化**：新增一条有限的字号集合与一条间距集合（命名令牌，深浅主题共用）；
      检测页样式段里不再出现一次性字号（`12.5px` / `11.5px` 这类"就地为某一句写一个值"）。
- [x] **四级可辨**：给出改后每级的（字号 / 字重 / 颜色）三元组，且相邻两级至少在两个维度上不同
      ——不能再出现"只差 3px"或"只差颜色"的层级。
      **口径如实修正**：`h2`(20/650/正文色) ↔ `h3`(16/650/正文色) 之间**只有字号一条可用维度**
      —— 本机中文字体（Microsoft YaHei）只有 Regular / Bold 两档，600 与 700 渲染相同，
      **字重轴在 CJK 上不可用**。故这一对靠"字号 1.25× + 位置（卡片标题顶在卡片内边距上，
      小节标题在正文流里带上间距）"区分；其余相邻两级都是两条维度（h3↔正文：字号 + 字重；
      正文↔说明：字号 + 颜色）。若用户仍觉得 h2/h3 难分，02 可再引入一个维度（如步骤编号徽章）。
- [x] **步骤标题升格**：主卡里「1. 目标平台 / 2. 输出通道 / 3. 要测的器件 / 4. 保存位置」
      明显强于正文（改前是 13px + 灰，留档对比）。
- [x] **间距阶梯**：区块之间 / 小节之间 / 行内三档，取值分别落在三条不同令牌上；
      检测页里同一档不再同时承担"区块之间"与"行内"两种语义。
- [x] **两套主题**：深色与浅色各出一份整页截图，层级关系一致（不是只有好看的那一套）。
- [x] **契约机械对账**（红证式）：改前 vs 改后逐项比对 —— ① `index.html` 的 **id 集合完全相同**；
      ② 检测页段落的 **DOM 元素顺序完全相同**；③ 被守卫点名的类名（`hwcheck-section` /
      `hwcheck-generic` / `hwcheck-my-device` / `hwcheck-custom-plan` / `hwcheck-handoff` …）
      的**出现次数与语义不变**。对账脚本与读数落盘。
- [x] **门禁读数**：前端门禁（`node --test "tests/js/*.test.mjs"`）+ 浏览器门禁
      （`node --test --test-concurrency=1 "tests/browser/*.spec.mjs"`）+ 全量
      `python -m pytest -n auto -q`——改前基线 / 改后读数并列落盘，零回归。
- [x] **不改清单核对**：文案逐字未删（`git diff` 里删除行只允许是样式与新增类名，
      不允许出现中文文案行的删除）。

## 结论（形状、读数、账）

**形状。** 两处：① `:root` 新增五个字号令牌 `--fs-page/--fs-block/--fs-body/--fs-note/--fs-tag`
（20/16/14/13/12px，`--fs-body` 与全站 `body` 的 14px 同值，意思是"别再往下压"）；
② 检测页自己的那批规则（`hwcheck-*` / `my-device-*`）**就地**把裸 px 字号与 4/8px 间距换成令牌，
外加一段 `#tab-hwcheck` 作用域的**共用基类**覆盖（`card` / `h2` / `h3` / `.muted` / `label` /
`.card-details` / `.badge`）——共用基类必须带作用域，否则一改就是全站（本单只做样板）。

**为什么不叠一层覆盖。** 第一版写的是"新增一段覆盖层"，读数当场打脸：老的裸 px 声明还在文件里，
碎片化读数一点没降，同一条规则变成两处说它多大（双源）。改成就地替换后，
检测页段的裸 px 字号读数从 **30 条 → 0 条**。

**契约对账（`probe-03-contract.py` → `probe-03-contract.txt`，全部通过）：** id 集合

那些类名天然不变）。截图见 `shots/`（暗/亮 × 空态/选了器件 × 首屏/整页）。

**账（留给后面的人）：**

1. **改了 2 处内联 `style=` 的数值**：预览/生成那一行的 `margin-top` 12→16px、排障按钮行 8→12px。
   这是**属性**改动（不动 id / 顺序 / 类名），为的是让"小节之间 16px"在按钮行上也成立——
   否则只能用 `!important` 去压内联式，那是更坏的做法。
2. **器件网格用的是共享组件**（`.module-card` 一族，与「模块库」页同一份 `fx/module.js`）：
   它里面还有 11/12/13px 的字号，本单**故意不动**——在本页单独改它会让同一个组件在
   两页长得不一样，那是全站轮的事。读数探针也因此**不含 `module-card`**。
3. **h2↔h3 的"第二个维度"没有**（见上面验收第 2 条的口径修正）：不是没做，是这台机器上
   **没有这个轴**（CJK 字重只有 Regular / Bold）。下一步若要更分明，应换轴（编号徽章 / 左侧色条），
   而不是继续调 `font-weight`。
4. **人眼验收还没做**：本单只做到"门禁没改坏 + 读数达标 + 对照图落盘"。**"这样好看吗"要用户拍板**；
   若方向被否，`--fs-*` 令牌与就地替换的形状仍可保留（改的只是取值，不是结构）。
5. **【2026-09-28 补记·本单的读数曾被下一单打破】** 02 在 `#tab-hwcheck` 里写了
   `font-size: 22px`（空态图标）—— **本单"裸 px 字号 = 0"这条验收当场被打假**，而当时
   没有守卫看着这一类（本该由 03 看着，03 被跳过了一轮）。05 复查时抓到：把 22px 收成
   `--fs-icon` 令牌、重跑两把尺子的读数（现 387 处 / 13 种 / 检测页段裸 px = **0**），
   并把守卫补上（03）。**教训**：一单宣布的读数**每轮改动后都要重跑**，否则它只是那一刻的照片。
