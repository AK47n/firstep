# 02 — 拆「框套框」+ 让重点会跳

**要做什么：** 硬件检测页**一屏内只剩一层完整描边**——内层容器改成留白 / 单条分隔线 / 浅底
（同类信息靠"挨得近"分组，不靠画框）；当前选中与正在编辑的那一件**一眼看得出是哪件**；
「删除」与「生成」两个动作视觉重量分明；未生成时那几张空卡片**安静下来**，并让整页读起来分成
「配置 / 结果 / 上板」三段（用分组标题 + 大间距表达，**不搬 DOM**）。

**被谁阻塞：** 01（地基不在，重点就没法"跳"——层级是靠对比出来的）。

**状态：** ready-for-agent

## 现状（截图与代码实读）

用户原话：「好挤啊……小家子气」。一屏内可达**四层描边**：

1. 页面卡 `.card`（1px `--border`）
2. 「我的器件」外壳 `.hwcheck-my-devices`（1px `--border` + 左 3px `--accent`）
3. 每件一行 `.hwcheck-my-device`（`border-bottom` 分隔）
4. 表单 `.hwcheck-my-device-form`（1px `--border-strong`）+ 字段行
   圆角还全是同一个 `--radius-md`（76 处在用）⇒ 边界很吵、层级很平。

另外两条：

- **选中态太弱**：`.hwcheck-my-device.picked` 只加一道 3px 绿左条；候选器件 chip 的选中态与之
  不是同一种"重量"，用户得逐字读名字才知道改的是哪一件。
- **空态占满首屏**：接线表 / 冲突 / 顺序 / 检测计划 / 命令台 / 检测工程 / 清单 / 最近检测
  在未生成时都是"一张空卡 + 一句空态文案"，与有内容时同样重。

## 验收标准

- [ ] **一层描边**：检测页任一屏内，完整矩形描边**只有一层**；内层改用留白、单条分隔线或浅底。
      给出"改前四层 / 改后一层"的逐层清单（哪一层被什么替代）。
- [ ] **同形之物同形**：「我的器件」/ 自建件计划 / 带入生成页三块原本共用外壳形状，
      拆框后仍必须**看起来是一类东西**（形状单源不破）。
- [ ] **重点会跳**：当前选中 / 正在编辑的那一件，与"未选中"的差别**不依赖读文字**即可分辨
      （尺寸、底色、左条、边框至少两项同时变化）；页面里"选中态"只有一种表达，不与其它状态混淆。
- [ ] **动作重量**：「生成检测工程」（主）/「删除」（不可逆）/ 其余（次要）三级分明，
      且删除在任何情况下都不会与主操作混淆。
- [ ] **空态安静**：未生成时那几张卡明显弱于有内容时；每张空态仍说清"生成后这里会出现什么"
      （**不删文案**，只降一级呈现）。
- [ ] **三段可读**：整页能读出「配置 → 结果 → 上板」三段（分组标题 + 间距），
      且 **DOM 顺序与 id 集合零变化**（分组只靠新增类名与标题表达）。
- [ ] **契约机械对账**：同 01 的三项对账（id 集合 / DOM 顺序 / 既有类名出现次数）+ 文案零删除。
- [ ] **门禁读数**：前端门禁 + 浏览器门禁（`hwcheck.spec.mjs` 361 处选择器引用是本单的主要风险面）
      + 全量 pytest，零回归，读数落盘。
- [ ] **人眼验收**：整页截图（暗/亮）落盘，用户在这版样板上拍板方向。

## 备注

- **不许动的东西**：id、DOM 顺序、既有类名语义——`tests/js/hwcheck.test.mjs` 按源码文本钉 id 与顺序，
  `tests/browser/hwcheck.spec.mjs`（96.6 KB）按选择器驱动真页面。要"视觉大改、契约不变"。
- 若某条"重点会跳"必须改标记才能达到，**停下来记账**（写清哪一条、为什么、代价），
  不要顺手改结构——那会让本单的回归面从"样式"扩到"行为"。
