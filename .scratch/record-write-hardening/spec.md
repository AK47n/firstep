# spec — 记录写加固：固定临时名 + 无锁 → 唯一临时名 + 按路径短临界区

**立项依据**：`.scratch/backlog.md` §24 记账的「另三处同构的『固定临时名 + 无锁记录写』仍未修」，
外加 `hwcheck-hygiene/03` 双轴评审时实测补出的第四处（`master_store._write_meta`）。
样板与判据先例 = 同一次评审做掉的 `hwcheck-hygiene/03`（`hwcheck_triage.py` 的
`write_hwcheck_record` / `_record_lock` / `update_hwcheck_record`）。

## 问题陈述

学生在同一个检测工程上会同时开两处入口（两个标签页、或一个页面点着而另一个页面在商量）。
今天这些 JSON 记录都是「读整份 → 改 → 写整份」，而写实现用的是**固定临时名 + 无锁**，于是有两种疼法：

1. **丢更新**：两笔改动各自读了一份旧快照，后落盘的那份把先落盘的那笔整份盖掉。
   最疼的一条横跨模型调用——想法的全局商量一轮要**秒级**，这期间学生若在另一处采纳结论，
   商量结束时的整份写回会把他刚采纳的结论抹掉，而他看到的是"采纳成功了"。
2. **坏写留残渣 + 互抢临时文件**：写实现没有 `finally` 清残渣，
   失败（磁盘满、被杀毒锁住、进程被中断）会在工程根留下 `.tmp`；
   两个写者并发时抢**同一个**固定临时名，一个刚写完另一个把同一文件截断，
   `replace` 落盘的可能是半成品，或者后一个 `replace` 直接失败——而"原子写"这句承诺正是为了防这个才写的。

## 方案

把这一族的写实现收成一套：**唯一临时名 → 原子替换 → `finally` 清残渣**，
再给"先读后写"的路径套一把**按记录路径的进程内锁**，读-改-写整段在锁里（毫秒级），
跨模型调用的窗口把调用留在锁外、合并动作只碰自己那几个字段。

用户侧可见的变化只有一句话：**两个地方同时动同一份记录，两笔都在；写坏了不留垃圾文件。**

## 用户故事

1. 作为学生，我在一个标签页加想法草稿、在另一个标签页删草稿，两笔改动都要留住（不许后一笔吃掉前一笔）。
2. 作为学生，我发起一轮"全局商量"（要等几秒），期间在另一处采纳一条全局结论；
   商量结束后，**我采纳的结论与这轮对话都要在**，不许被写回覆盖。
3. 作为学生，参数商量（另一份历史，独立文件）与全局商量互不干扰——两份记录各自的写不许共锁、不许互抢临时名。
4. 作为学生，我应用一次参数值后表被刷新，同时参数扫描刚写进一张新表——不许把新表盖回旧快照。
5. 作为学生/维护者，母版导入（同一平台连点两次、或一个导入一个删除）不许互抢临时文件，
   也不许在库目录留下 `.{platform}.json.tmp` 这种看不见的垃圾（`list_masters` 会跳过点开头的条目，残渣没人发现）。
6. 作为学生，写盘失败（磁盘满 / 文件被占用）时我看到的是原来的中文报错，**不是**被清理动作掩盖掉的另一个异常。
7. 作为维护者，我要一条结构守卫盯住"全仓只有一个原子写实现"，新写的记录文件不会又手搓一个固定临时名。
8. 作为维护者，我要每条改动都有反证读数：把修撤掉，对应用例必须红——证明判据真的钉住了这一条。

## 实现决策

### 共享原语（新模块，唯一新增的机器）

- `atomic_write_text(path, text, encoding="utf-8") -> None`：唯一临时名
  `f"{path.name}.tmp-{os.getpid()}-{next(_TMP_COUNTER)}"` → `os.replace` → `finally` 清残渣
  （清理失败不掩盖原异常）。**逐条对照** `hwcheck_triage.py:896-919` 的既有实现搬，不重新发明。
- `path_lock(path) -> threading.Lock`：键 = `os.path.normcase(os.path.abspath(path))`，
  表只增不减（照 `hwcheck_triage.py:387-406` 与其记账注释）。**按完整路径（含文件名）区分**——
  两份记录（全局商量 / 参数商量）天然各拿一把锁。
- **不提供通用 `update_json`**：四个域的读侧错误语义不同（各自抛带文件名的中文 `TaskError`），
  共享的只有「锁 + 原子写」两个缝；域级 `update_*` 各写六行。
- **字节格式归调用方**：原语只写字符串。实测（收口时逐字节核过）**没有**尾换行的是
  `master_store._write_meta` 的 `{platform}.json` 与两份聊天记录（`.contest_idea_chat.json` /
  `.contest_params_chat.json`）；**有**尾换行的是 `.contest_ideas.json`、`.contest_params.json`
  与 `.hwcheck_record.json`。原文这句「三个记录文件有尾换行」把聊天记录算错了，按实际字节为准。

### 域级改动（四处）

| 域 | 新增 | 调用位改法 | 说明 |
|---|---|---|---|
| 想法草稿 | `update_drafts(output_dir, merge)` | 增 / 删两个端点改走它（merge = 既有纯函数 `add_draft` / `delete_draft`） | 窗口本来只有微秒级，锁是防交错 + 换唯一临时名 |
| 想法商量 | `update_idea_chat(output_dir, merge, filename=…)` | 两个 send：**模型调用留在锁外**；临界区里在**新读到的记录上追加**本轮两条；adopt 改走它 | 合并语义定案：**追加而非"base 变了就不写"**——聊天是追加型日志，追加重放能同时保住两笔（与 `hwcheck-hygiene/03` 的 `record_with_triage` 口径不同，理由写进工单 03） |
| 参数表 | `update_params(output_dir, merge)` | `params.py` 的「应用后刷新」改走它（在最新盘上重放单参数刷新）；LLM 扫描那条**整份盲写**只换写实现**＋取同一把锁**（06 收口时加的：它不读旧表，加锁只让它多等临界区那几微秒，却关掉了"刚落盘的新表被刷新的旧快照盖掉"那条缝） | 扫描不读旧表，本身无合并可言；但它的落盘与刷新必须在同一把锁里排队 |
| 母版元数据 | 无（整份重写） | `_write_meta` 换原语 + `finally` + 按路径锁；`delete_master` 的 meta 删除也归同一把锁 | 实测确认是**整份重写**（调用方现场造 meta，不读旧文件），故不上"读-改-写" |

### 不变量（不许变的东西）

- 各域读侧的中文错误文案（含文件名）逐字不动。
- 四个文件的 JSON 字节格式不动（缩进 / `ensure_ascii` / 尾换行）。
- `_persist_applied_param` 的「写盘失败不阻断主流程」（吞 `OSError`）语义保留。

## 测试决策

- **好测试 = 只测外部行为**：判据取**最终落盘内容**与**目录里有没有多余文件**，
  **例外一条**：`path_lock` 的**同一性契约**要断言（工单 01 明写"同一路径同一把锁 /
  同目录不同文件名不同锁"）——那是调用方依赖的契约本身，不是实现细节。
  除它之外不断言锁对象、临时名形状、内部调用次数。
- **域层**（每个域一组，形状照 `tests/test_hwcheck_triage.py:554-685` 五条先例）：
  ① 原子写不留 `.tmp`；② 写失败（注入抛错）不留残渣；③ 并发写不互抢、不报错、不留残渣
  （把本模块看到的 `os` 换成只暴露 `path`/`getpid`/`replace` 的 `SimpleNamespace`，在 `replace` 上卡一个 `Event`）；
  ④ 读-改-写不丢另一路字段（A 卡在自己的合并里，B 写另一路 → 两笔都在）；
  ⑤ 跨慢窗口的合并（商量那轮：模型调用期间别人采纳 → 两笔都在）。
- **端点级**（每个端点族一条，家 = 既有端点测试文件）：判据取最终落盘（不取响应体），
  并在「撤锁」注入下实测**变红**——`hwcheck-hygiene/03` 被双轴评审抓过"端点用例撤锁照样绿 = 测不出锁"。
- **既有测试先例**：并发用 `threading.Thread` + `Event`（`tests/test_full_task.py:279/1022`、
  `tests/test_hwcheck_triage.py:633`）；端点级并发用 `tests/test_hwcheck.py:3319/3393-3397` 的形状。
- **反证**：每单一条探针脚本，**逐条声明**哪些用例必须红并把实得 `FAILED` 集合与声明对账
  （多出来的红如实打印、不据此判 PASS——照 `probe-03-red.py` 整改后的形状）。
- **闸门**：只跑后端（`python -m pytest -n auto -q` + `tools/prepush.py --changed <文件>` 选的关联子集）；
  落点不在 `static/` 或 `tests/js/`，故不跑前端与浏览器门禁。

## 范围外

- `materials_apply._extract_zip`（`:103` 固定 `.update-tmp`）——解包被更新任务锁串行化，风险低一档。
- `recent_jobs`（已用 `tempfile.mkstemp` 唯一名）、`codeview`（pid 后缀）、
  `hwcheck_triage`（本次原语的来源，已是正确实现）——**不动**。
- `entry_store.write_json` 的裸 `write_text`——它靠目录级事务兜底，不是本次这一族。
- **跨进程并发**：本应用是单进程（`uvicorn.run(app, …)`），锁是进程内的；
  多开两个应用实例同时写同一工程不在射程，也不假装安全。
- **强杀残留清扫**：只清本进程本次写失败留下的临时文件；进程被强杀留下的不扫。
- 把 `hwcheck_triage` 的私有副本（`_record_lock` / `write_hwcheck_record`）迁到共享原语：
  属纯重构，**另开单 = 工单 07**（否则两份锁表 + 两份原子写长期并存——双轴评审 2026-09-27 点名的重复）。
- **母版"目录换入 × 删 meta"的窄缝**（工单 05 的账，收口时**明确承认为已接受的残留**）：
  `import_master` 的目录换入在 `path_lock({platform}.json)` 之外，与 `delete_master` 的
  `delete_entry` 之间还留着一条缝——按"导入钉在目录换入之后、删除先跑完"的时序能造出
  "有 meta、没目录"的悬空状态（`list_masters` 看不见它）。要闭得把锁提到目录换入之前、
  并把 `delete_entry` 也包进来（还要权衡 `rmtree(backup_dir)` 期间持锁的代价）；
  当前判断是**收益不抵风险**（窗口毫秒级、后果只是库目录里一份没人读的 json），故不改、只记账；
  真要改就另开单。
