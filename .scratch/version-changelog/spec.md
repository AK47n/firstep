# spec：版本更新记录（把「提交流水账」改成「用户视角的版本要点」）

## 问题陈述

「更新记录」栏目现在是 git 提交流水账：post-commit 钩子把每条提交主题自动补录进
CHANGELOG.md，前端按天全量平铺。后果：825 行 / 157KB 的条目，工单编号、内部重构、
性能黑话满天飞（如「feat：滚动 rAF 节流 + 折叠与窗口三层组合（工单 editor-…/04）」），
对做题的用户又臭又长、没有意义；栏目挂在「资料管理」组里，名实不符。

## 方案

引入「版本」概念，把栏目从「开发者变更日志」改成「用户视角的版本更新记录」：

1. **数据双分工**：`CHANGELOG.md` 原样保留为自动草稿区（post-commit 钩子与
   changelog.py 一行不改）；新建 `VERSIONS.md` 为定稿区——只有这里的内容进前台。
2. **发版仪式**：每次发布新版本时，把草稿归纳成 3~6 条「用户听得懂」的要点，
   写进 `VERSIONS.md` 顶部（以后由我按用户一句话代劳草拟）。
3. **前端**：tab 改名「版本更新记录」并从「资料管理」组挪到「指南」组；版本卡片
   展示（版本徽章 + 日期 + 一句话主题 + 带「新增/改进/修复/性能」标签的要点列表），
   默认只展开最新版本，其余折叠。
4. **本次不发版**：首版内容（v1.1.0 要点）等用户说「发布」时再写；当前前端
   呈现「还没有正式版本」空态。

## 用户故事

1. 作为做题的学生，我想要打开一次「版本更新记录」就 30 秒读完最近版本改了什么，
   以便知道工具新能干什么、修了什么。
2. 作为做题的学生，我想要不看到工单编号 / 内部重构 / 性能黑话，以便不被噪音淹没。
3. 作为做题的学生，我想要旧版本默认折叠、点标题才展开，以便页面不拉长成流水账。
4. 作为工具维护者，我想要 post-commit 自动补录继续工作，以便草稿不丢、机制零改动。
5. 作为工具维护者，我想要发版时有一个明确的定稿文件与格式约定，以便归纳有处可去。
6. 作为工具维护者，我想要「版本更新记录」的条目同样受仓库中文门禁保护，以便
   用户可见内容不出现英文条目。

## 实现决策

- **VERSIONS.md 格式契约**（repo 根，Keep a Changelog 风格子集）：
  - `# 版本更新记录` 大标题 + 说明段（发版流程与格式约定，写给维护者）。
  - `## v<主>.<次>.<补丁> (<YYYY-MM-DD>)` 开新版本区块（ASCII 括号、严格日期）；
    新版本永远在最前。
  - 组内条目 `- <标签>：<一句话>`，标签 ∈ 新增 / 改进 / 修复 / 性能（还有可选
    `- 主题：<一句话概括本期>`，归入 summary 不占条目）；`- <无标签文本>` 归
    「其他」且整行保留（不静默丢内容）。
  - HTML 注释可用作格式示例（解析器跳过）。
- **解析器**：`changelog.py` 增 `parse_versions(text) -> list[dict]` 与
  `load_versions(path) -> list[dict]`（缺失 / 读取 / 解析异常 → []，纯展示数据
  不抛，与 load_changelog 同风格）；返回
  `[{version, date, summary, items: [{kind, text}]}]` 按文件顺序。
- **API**：`GET /api/changelog` 改读 `VERSIONS.md`，返回
  `{"releases": [...]}`（对象包裹便于将来扩展；内部契约破坏可接受——前端是唯一
  调用方）。自动草稿不进 API。
- **前端**（ui/master.js `loadChangelog` 重写 + index.html 内联样式）：
  - tab：`更新记录` → `版本更新记录`，挪入「指南」组（与「新手指引」并列）；
    title 改写为面向用户的说明。
  - 页头 h2 与说明同步；卡片折叠交互（`aria-expanded` + chevron 旋转 + 默认
    最新展开）；空态「还没有正式版本——发布新版本时会在这里归纳对用户重要的要点」。
  - 样式复用既有 token（`--accent` / `--radius-md` / `--space-*` / `--mono` /
    `--muted`），标签色按语义取既有色板。
- **版本号**：本次不 bump `__version__` / pyproject（未发布 v1.1.0，不预提版本）。

## 测试决策

- 最高复用既有 seam：changelog.py 纯函数（test_changelog.py 增 parse_versions /
  load_versions 的契约单测：正常样例、主题行、无标签行归其他、缺文件 → []、
  损坏 → []、非版本 `##` 小节不进组）。
- webapp 路由测试（tests/test_webapp.py 更新记录测试）改为断言 `{releases: [...]}`
  形状与 VERSIONS.md 实况。
- 中文守门（tests/test_repo_language.py）扩展：VERSIONS.md 每条 `- ` 条目
  ≥4 个中文字符（与 CHANGELOG 同一规则），文件缺失即红。
- 前端无 DOM 测试骨架（tests/js 仅静态守卫），卡片渲染与折叠交互以手动验证
  （本地起 app 打开栏目）为准；ui-cycle 静态守卫不涉及（无新增 ui 模块）。

## 范围外

- 本次不发布任何版本、不写 v1.1.0 要点（等用户指示）。
- 不改 post-commit 钩子 / changelog.py 自动补录逻辑、不别名 CHANGELOG.md。
- 不做 GitHub Release / tag / 版本号 bump 流程（发版时另议）。
- 草稿（CHANGELOG.md）不进前端 UI；维护者自行查看或让发版时归纳。
- 不改「新手指引」的页面结构，只同步其导航介绍文案。
