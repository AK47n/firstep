# PDF 资料库页 UI 提升（信息查看 + 即时检索 + 数据健康 + 美感）

> 会话/系列 slug：pdf-library-ui。本 spec 描述「第四个栏目 = PDF 资料库
> （tab-pdf）」整轮提升的共同方向；实施按竖切工单逐张落地（见 issues/）。
> 与第三轮「参考文件库」（reference-library-ui，已完成 5 张工单）对偶。

## 问题陈述

「PDF 资料库」栏目是全站管理第三原始的面板：浏览靠 1 个服务端关键字输入框
（文件名 / 批次 / 路径子串）+ 搜索按钮，表格只有 4 列（文件名 / 批次 / 大小 /
操作），无排序、无统计、无批次分组视角；文件元数据（完整路径、修改时间、页数）
一律看不到——「给人看的资料库」却不好找、不好比、不好确认新旧；素材库里
**真实存在数据健康问题**（实扫 66 份 / 10 批）：3 份 **0 字节损坏 PDF**
（`大矩形(视觉识别训练样本).pdf`、`简单图形的识别.pdf`、`DL-43P尺寸图.pdf`，
点击预览直接失败），4 组 **同名同大小疑似重复**（`000_2017-2025_真题汇总.pdf`
在 2026_04 与 2026_07 两批各一份 33.4MB；`TB6612FNG电机驱动芯片数据手册.pdf`、
`RT8289GSP电源芯片数据手册.pdf`、`RT9013-33GB稳压芯片数据手册.pdf` 在塔克R3批
的 6/7 子目录各一份）——没有警示，用户不知道哪些文件打不开、哪些白占了约 100MB。
视觉上落后于生成页与管理页（无令牌化表头 / 行 hover / 徽章 / 空态）。

## 方案

把「PDF 资料库」页提升为信息完整、可即时检索、数据健康可见的管理面板，四主轴：

1. **信息与查看**：表格精修（文件名截断 + 完整路径 tooltip、批次 chip、目录列、
   大小、修改时间）+ 全新「详情」弹窗（完整路径 / 批次 / 目录 / 大小 / 修改时间 /
   页数按需读取 + 打开 / 复制相对路径）+ 客户端即时过滤（关键字防抖 + 批次
   chips）/ 排序 / 统计条，替换现有服务端搜索框。
2. **数据健康**：0 字节损坏 PDF 警示 + 同名同大小疑似重复警示——行内 ⚠ 标注 +
   统计条红色计数段（点击 = 只显示该类，再点取消）；**提示语义，不拦截浏览、
   不提供删除动作**（素材根是 git 版本化的原始素材区，清理由人在文件系统确认后
   进行，警示的作用是曝光）。
3. **美感**：复用既有 `.lib-table / .lib-toolbar / .lib-chip / .lib-stats`
   令牌与空态 / 加载 / 错误态文案，与生成页、模块库页、参考文件库页观感一致。
4. 主体形态维持**表格**（管理场景信息密度优先），不做卡片网格、不做双视图。

## 用户故事

1. 作为资料库使用者，我想要在表格上方输入关键字即可即时过滤行（匹配文件名 /
   批次 / 目录 / 完整路径，大小写不敏感），以便库大了以后快速定位 PDF。
2. 作为资料库使用者，我想要按批次（素材根下第一级目录）用 chips 过滤，以便
   按「某套件配套资料」这个自然分组浏览。
3. 作为资料库使用者，我想要按文件名 / 批次 / 目录 / 大小 / 修改时间排序，以便
   按我关心的维度浏览（如「最近更新的资料」「最大的文件」）。
4. 作为资料库使用者，我想要一个统计条（总份数 / 总体积 / 批次数 / 疑似重复组数 /
   损坏份数），以便对素材库的规模与健康度一目了然。
5. 作为资料库使用者，我想要每行有「详情」入口，以便一键查看完整路径、批次、
   目录、大小、修改时间与页数（页数按需读取），不再需要猜文件来历。
6. 作为资料库使用者，我想要在详情里「打开」PDF 并「复制相对路径」，以便预览
   与搬运（把路径粘到对话/文档里引用素材）。
7. 作为资料库使用者，我想要 0 字节 PDF 被显式标注（「损坏」），以便知道哪些
   文件打不开、需要重新导出或删除。
8. 作为资料库使用者，我想要同名同大小的 PDF 被显式标注（「疑似重复」），以便
   发现跨批次 / 跨子目录的重复文件（白占空间与产生「两份哪个新」的困惑）。
9. 作为资料库使用者，我想要点击统计条的重复 / 损坏红段只看那一类，再点取消，
   以便快速核对数据质量问题清单。
10. 作为参考文件库管理者，我想要列表数据与详情没有两套口径（详情 = 列表同源
    + 按需补充的页数），以便零维护成本。
11. 作为资料库使用者，我想要表格 / 徽章 / 按钮 / 空态 / 加载态 / 错误态的视觉
    与生成页、模块库页、参考文件库页一致，以便整个工具观感统一。

## 实现决策

### API 契约（后端小改：列表加 mtime + 新增 1 个端点）

- `list_pdfs` 每条目新增 `mtime`（UNIX epoch 秒，int）——`path.stat().st_mtime`
  取整；排序键按已有 (batch, rel_path) 不变（排序维度在客户端做）。
- 新增 `GET /api/pdfs/{rel_path:path}/pages` → `{"pages": N}`：PyMuPDF
  （`fitz.open`）按需读取单文件页数，**不做全量预扫**（66 份含超大 PDF，列表
  响应必须保持快）；路径安全复用 `resolve_pdf`（非法路径 / 不存在 / 非 PDF →
  ReferenceError → 400）；**0 字节或损坏 PDF = 页数读取失败 → 400 中文报错**
  （与 resolve_pdf 同通道），前端详情弹窗对该字段显示「无法读取」。
  fitz 软导入为防御性写法（extraction.py 先例），但 **ImportError 语义与
  extraction 区分**（评审定稿）：页数端点无处可降，PyMuPDF 又是声明依赖
  （pyproject `pymupdf>=1.24`），缺库 = 服务器环境缺陷 → RuntimeError（未登记
  → 500 大声失败），不伪装成 400「文件损坏」。
- 路由注册顺序：`/api/pdfs/{rel_path:path}/pages` 必须注册在
  `/api/pdfs/{rel_path:path}`（文件预览路由）**之前**——后者是 path 贪婪匹配，
  不先注册页数路由会被它一并吞掉；补一条注册顺序的回归测试（页数路由 + 文件
  路由各自返回正确语义）。
- 既有端点零改动：`GET /api/pdfs`（无参全量 + `name` 子串参数保留——
  topic tab 的真题汇总链接仍用 `?name=`，不破坏）、`GET /api/pdfs/{rel_path:path}`
  （预览）不动。
- 页数不写入列表（每个文件索引都要 parse 会拖慢列表）；详情弹窗打开时按
  rel_path 懒取一次并 memo（内存 Map），同一文件重复打开零重复请求。

### 前端（交互逻辑继续下沉纯函数，DOM 层只转发）

- 纯函数组（与 reference-library-ui 的 ref 系列同范式，直接 function 声明 +
  tests/js 括号配平抽取）：`pdfFilterEntries`（关键字 × 批次 × 健康状态过滤，
  正交组合）、`pdfSortEntries`（文件名 / 批次 / 目录 / 大小 / 修改时间，
  稳定排序，同键保序）、`pdfStats`（总份数 / 总体积 / 批次数 / 重复组数 /
  损坏份数）、`pdfStatsText`（统计条文案，formatSize 注入）、`pdfDupGroups`
  （同名同大小分组，size>0 才判可疑——0 字节归损坏类不重复参与）、
  `pdfBroken`（size_bytes === 0）、`pdfSubdir`（批次内子目录：rel_path 去掉
  批次段与文件名，空 = 在批次根）、`pdfRowHTML`（行渲染：文件名截断 +
  完整路径 tooltip、批次 chip、目录列、大小、修改时间、损坏 / 重复 ⚠ 徽章、
  打开 / 详情按钮）、`pdfDetailHTML`（详情弹窗渲染）、`formatMtime`
  （epoch 秒 → `YYYY-MM-DD HH:mm` 本地时间）、`pdfFilterContext`（组装过滤
  上下文 + 去重，对偶 refFilterContext）。
- 数据源：`GET /api/pdfs`（无参，全量在手）→ 客户端即时过滤排序统计；打开
  详情时按需 `GET /api/pdfs/{rel_path}/pages`。
- **重复 / 损坏判据（纯客户端，零后端）**：损坏 = `size_bytes === 0`；疑似重复
  = 同名（大小写不敏感）且同大小且大小 > 0 的组内成员（组数 ≥ 2）。同名不同
  大小 = 不同版本，不算重复。备注：同名同大小不读内容 hash——提示语义已够，
  列表端点不做全量读盘（会拖慢 6GB 素材根的响应）；冒烟对真实数据断言
  「4 组重复 / 3 份损坏」锁定判据与素材库现状一致。
- **id 唯一性防线（对偶 reference 轮评审 C1）**：新元素 id 前缀 `pdf-` 命名空间
  （pdf-filter / pdf-sort / pdf-sort-dir / pdf-batch-chips / pdf-stats /
  pdf-rows / pdf-detail-*），冒烟检查页面内 id 唯一。
- 详情弹窗：复用 `.ref-files-overlay` / `.ref-files-close` 遮罩与关闭模式
  （先例：module-info-dialog / reference detail dialog）；内容两段——元数据段
  （文件名 / 完整路径 / 批次 chip / 目录 / 大小 / 修改时间 / 页数（懒取，加载
  中 / 成功 / 「无法读取」三态）+ 损坏 / 重复 ⚠ 标注）+ 操作段（打开复制路径）。
  「复制相对路径」用 `navigator.clipboard.writeText`，失败降级显示「复制失败，
  请手动复制」（127.0.0.1 为 secure context，正常可用）。
- 统计条：`共 N 份 · 总体积 X · M 个批次` + 疑似重复红段（N 组，点击只看重复，
  再点取消）+ 损坏红段（N 份，同理）；红段与关键字、批次 chips 正交组合过滤。
- 旧筛选区替换：1 个服务端输入框 + 搜索 / 清空按钮移除；换关键字即时输入
  （防抖）+ 批次 chips（全部 / 各批次，带份数）+ 排序下拉 + 方向切换。
- 既有「打开」行为保留：`window.open` 浏览器原生预览（`pdfFileUrl` 逐段编码）；
  不引入站内 iframe 预览——浏览器原生 PDF viewer 已胜任，本轮不改预览形态。
- 表格列：文件名（链接 = 打开，截断 + 全文 tooltip）/ 批次（chip）/ 目录 /
  大小 / 修改时间 / 操作（打开 · 详情）；`#tab-pdf table` 的 fixed 布局改走
  `.lib-table` 令牌（表头底纹 / 行 hover / 斑马纹）。

### 模式变更 / 架构决策

- 不引入新依赖（PyMuPDF 已是既有硬依赖，extraction.py 软导入模式沿用）。
- 后端新增仅 `pdf_page_count`（pdf_library.py）+ 1 条路由（webapp.py）；错误
  类型复用 ReferenceError（已在 error_to_http 表登记），零新错误类。
- 交互逻辑继续下沉纯函数（先例：ref 系列 / lib 系列），DOM 事件层只做转发，
  保持 tests/js node:test 可测。
- CONTEXT.md 词表补一行：「PDF 资料库（给人看的资料库）——素材根
  sources/materials 全量 PDF 的直通入口（批次 = 素材根下第一级目录，批次内子
  目录 = 二级目录）；列表字段 rel_path/name/batch/size_bytes/mtime；页数按需
  读取（PyMuPDF，单文件）；数据健康判据：0 字节 = 损坏、同名同大小（>0）=
  疑似重复（提示语义）」。清单 / 预览端点 = pdf_library.list_pdfs / resolve_pdf；
  页数 = pdf_page_count。

## 测试决策

- 前端主 seam = `tests/js` 的 node:test 纯函数单测（extract 范式：
  reference-library.test.mjs / module-library.test.mjs 同款）。覆盖：过滤规则
  （关键字四合一、批次、健康状态正交）、排序稳定性（五维）、统计汇总、重复 /
  损坏判定（含 0 字节不参与重复、同名不同大小不判重复、大小写不敏感）、
  formatMtime、子目录推导、行渲染子串断言（⚠ 徽章 / 批次 chip / tooltip）。
- 后端：`test_pdf_library.py` 增 mtime 字段断言 + `pdf_page_count` 用例（合法
  多页 PDF = topic_pdf_fakes.make_multi_page_pdf 构造 → 页数正确；0 字节 / 损坏
  / 不存在 → ReferenceError 400）；`test_webapp.py` 增 `/api/pdfs` 带 mtime
  断言 + `/api/pdfs/{path}/pages` 路由（成功 / 非法路径 / 损坏 / 存在性）+ **路由
  注册顺序回归**（页数路由先于文件路由，文件预览不被吞）。
- 交互层（弹窗开合、懒取页数三态、红段过滤、复制路径）延续浏览器级验证先例
  （.scratch/pdf-library-ui/smoke.mjs + 截图，对偶 reference-library-ui/smoke.mjs
  范式：CDP 9251 连接、check 计数、真实素材库数据断言）。
- 全量回归：pytest 全量（现状 2393 绿）+ tests/js 全量（现状 336 绿）+
  冒烟清单（对偶 48 项）保持全绿。

## 范围外

- 删除 / 重命名 / 移动素材文件（素材根是 git 版本化的原始素材区，警示只曝光
  不代劳；清理由人在文件系统确认后做）。
- 同名不同大小的版本对比（只判「疑似重复」提示，不做内容 hash / 差异对比）。
- 重复文件的自动合并 / 去重迁移动作。
- 站内 PDF 预览形态改造（浏览器原生预览维持；页图渲染 / 翻页器不属本轮——
  tab-topic 取题面页图已有独立轮次）。
- 服务端搜索过滤参数改造（/api/pdfs?name= 保持现状，客户端过滤已够用）。
- 卡片网格视图 / 表格-卡片双视图切换。
- 移动端 / 窄屏专项适配（表格维持水平滚动）。
- 深色主题。
- PDF 的页数全量预扫 / 缓存落盘。
