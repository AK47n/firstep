# 批次 11 C 类核对报告（servo/motor/ml_mpu6050/0-96-iic）

- 核对口径：页面（sources/materials/lckfb-地阔星移植手册/）↔ 库内 stm32 条目逐页对照；只读核对，不改仓库（本报告除外）。
- 页面均为 UTF-8 读取；库内 .c/.h 个别 GBK（ml_pwm/ml_i2c 母版）按 GBK 读。

## 1. servo（control--16-ch-servo-drive-module.md）

- 页面事实：芯片 = **PCA9685 16 路舵机驱动板**，I2C（软 I2C 位操作：GPIOA，SDA=PA5/SCL=PA6，Out_OD+IPU，5us 半周期）；从地址 0x40（写 0x80/读 0x81，A5..A0 可扩 62 板）；芯片内部 25MHz 振荡器生成 16 路 12bit PWM（主控只写寄存器）；LEDn 寄存器基址 0x06+4n、ON/OFF 12bit，代码把 ON 置 0、OFF 即脉宽；prescale = round(25e6/4096/freq)-1，舵机时基 50Hz；页面两套角度映射并存（setAngle `off=158+angle*2.2`、Init `off=145+angle*2.4`），main 演示 60Hz。
- 库内实现（servo，stm32）：**单路舵机 TIM 硬件 PWM**（母版 ml_pwm 封装），非 PCA9685。API = `servo_init(servo_id, channel)` / `servo_set_angle(servo_id, angle)`；50Hz/20ms 周期，0.5-2.5ms 脉宽映射 0-180°（MAX_DUTY=50000 → 1250/6250，角度线性插值，越界钳位）；默认脚实测 pin_config.h L29-30：`SERVO_PWM_TIM = TIM_4`、`SERVO_PWM_CH = TIM4_CH1 /* PB6 */`（与 manifest 一致）；初始化直接 `pwm_init`（其内部调 pwm_pin_init，无遗漏）；manifest notes 无页面来源引用。
- 对照事实：**页面与 servo 模块不是同一实现**。页面（PCA9685 I2C 16 路）在库内的真实对应模块是 **pca9685**（library/modules/pca9685/：pca9685_stm32.c/.h 首行就引用本页 URL，默认 SCL=PA6/SDA=PA7 软 I2C + 25MHz/4096/12bit/0x40 全部对应），其 stm32 notes 已完整记录本页 7 条缺陷（①两套角度映射不一致→统一 0.5-2.5ms 口径；②main 60Hz vs 正文 50Hz→50Hz；③delay_1ms→delay_ms；④NACK 全丢→超时发停止；⑤正文频率公式 `(50+1)` 错误（正确 = 代码 `25e6/4096/freq-1`，页面正文 119.68/120 与正确值 121 不符）；⑥Excel FLOOR 注释污染；⑦直接控角度→set_pwm+set_angle 两级）。servo 模块语义同源页面是 **control--sg90-steering-engine.md**（50Hz/20ms、0.5-2.5ms、0-180° 线性——与其映射逐项吻合，但默认脚 TIM3_CH1/PA6 未照抄，库用 TIM4_CH1/PB6，宏化可绑）。
- 结论：**差异（对照错位，非实现缺陷）**。servo 模块与页面无任何事实矛盾，无需改动其代码/引脚；库内已正确实现页面（pca9685 模块）并记录全部页面缺陷。建议（可选、记录性）：`library/modules/servo/manifest.json` stm32.notes 补一行「本件 = 单路 TIM PWM（对应页面 control--sg90-steering-engine.md）；16 路 I2C 扩展见 pca9685 模块」——与 pca9685 notes 已有的「与 servo 模块区分」段互相闭环，防后来者按「16 路舵机」页误选 servo。

## 2. motor（control--tb6612-motor-drive-module.md）

- 页面事实：TB6612FNG 双路电机驱动，PWM 控制（VM<12V、VCC 2.7-5.5V、1A）；STBY 接 3.3V 固定（不占 IO）；**代码只实现 A 路**：PWMA=PA6（TIM3_CH1）、AIN1=PA1、AIN2=PA2；`TB6612_Init(72,1000)` → PWM ≈1kHz（72MHz/(72×1001)）；`AO_Control(dir, speed)`：dir=1 → AIN1=0/AIN2=1，dir=0 → AIN1=1/AIN2=0，speed 0~per-1 无钳位；页面另有两处下品：AIN_GPIO_INIT 用 PORT_AIN2 初始化（=PORT_AIN1 同 GPIOA，巧合无害）、注释「Channel2」实为 OC1。
- 库内实现（motor_stm32，2021F 提取）：双路 + 编码器超集。PWM = TIM2_CH1/CH2 = PA0/PA1，`MOTOR_PWM_FREQ=1000`（与页面 1kHz 同频）；方向 A=PA6/PA7、B=PB0/PB1；编码器 A=PB5（EXTI 线 5）+ 方向 PB4、B=PA4（EXTI 线 4）+ 方向 PA5（pin_config.h L41 注「A 编码器已离 PA2/PA3 让位 DEBUG_UART」）；API = motor_init/encoder_init + 统一 motor_set_duty/set_direction/motor_encoder_read（旧 API 保留，注释注明）；方向极性核对一致：统一「1=正转」→ 旧 dir=0 → AIN1=0/AIN2=1，与页面 dir==1 完全相同；速度经 pwm_update 内建 duty≥MAX_DUTY 钳位（页面无钳位，库已补）。
- 结论：**差异（功能扩展 + 默认脚体系不同，无事实矛盾）**。库是页面功能的超集（补 B 路、编码器、方向语义归一），页面「双路名实不符」（正文说 B 路、代码无 B 路）由库补齐；页面默认脚（PWMA=PA6/AIN1=PA1/AIN2=PA2）与库默认（PWM PA0/PA1、方向 PA6/PA7/PB0/PB1）不同——PA6 语义甚至相反（页面 PWM vs 库方向），但整条默认脚体系在 pin_config.h 有出处注释（21F 原值/让位理由）且全部宏化可绑，属结构性设计差异。**实质差异 1 条（notes 名实不符，建议修改）**：`library/modules/motor/manifest.json` stm32.notes 写「21F 原值：…编码器 PA2/PA4 + 方向 PA3/PA5」，易读成「当前默认 = 21F 原值」，而当前实际默认编码器 A 已为 PB5（EXTI 线 5）/PB4（方向），B 为 PA4/PA5——建议改为「21F 原值 PWM TIM2 CH1/CH2（PA0/PA1）、方向 PA6/PA7/PB0/PB1、编码器 A=PA2+PA3、B=PA4+PA5；现默认 A 已离 PA2/PA3 让位 DEBUG_UART TX → PB5/PB4（见母版 pin_config.h）」；manifest pins 段（PB5/PB4/PA4/PA5）本身与 pin_config.h 一致，不用动。
- 另记录（非本件问题）：双平台统一 API 的 duty 量纲不同（stm32 0~50000 母版 ml_pwm 口径 vs mspm0 0~1300 limit_duty）——stm32 头注释已写明，属平台物理差异，非页面对照项。

## 3. ml_mpu6050（sensor--mpu6050-six-axis-sensor.md）

- 页面事实：MPU6050 六轴，IIC；AD0 接地 → 从地址 0x68（写 0xD0），0x75 返 0x68；默认脚 **SDA=PB8/SCL=PB9**（GPIOB，Out_OD+IPU，5us 半周期）；初始化：复位 0x6B←0x80 → 100ms → 唤醒 0x6B←0x00 → 陀螺 ±2000dps（0x1B←fsr<<3=0x18）→ 加速度 ±2g（0x1C←0）→ 50Hz（0x19←19）→ 正文 LPF 0x03(42Hz) / 代码 MPU_Set_Rate(50) 自动取 0x04(20Hz)（正文代码矛盾）→ INT_ENABLE←0x00、USER_CTRL←0、FIFO_EN←0、INTBP_CFG(0x37)←0x80 → ID 校验 → 0x6B←0x01（PLL X）、0x6C←0；温度 = 36.53 + reg/340；陀螺/加速度大端 6 字节；**核心产出 = 官方 DMP 库（inv_mpu 等 6 文件）mpu_dmp_init/mpu_dmp_get_data 出 pitch/roll/yaw**，20ms 节拍。
- 库内实现（stm32，21F ml_mpu6050.c/.h）：走**母版 ml_i2c 共享总线**（I2C_GPIO=GPIO_A、SCL=PA11/SDA=PA12，pin_config.h L722-729：已离 PB10/11 让位 Zigbee、PA11/12 为 USB 共用脚、用 USB 勿占）；API = MPU6050_Write/Read/Init/GetData（4 个），地址 0xD0、寄存器宏（0x19/0x1A/0x1B/0x1C/0x3B-0x48/0x6B/0x6C/0x38/0x75）与页面一致；初始化序列：复位 0x80→100ms→唤醒 0x00→50ms→SMPLRT 0x27（**200Hz，CONFIG=0x00 DLPF 关**，与页面 50Hz/DLPF 开不同档但合法）→GYRO 0x18（±2000dps 同页面）→ACCEL 0x00（±2g 同页面）→INT_ENABLE 0x01（页面关中断；本件开了 data-ready 但无 EXTI 接线，空配）；数据 = 单字节读 H/L 后 `L|H<<8` 拼装（大端正确）；**无温度读取、无 DMP/欧拉角**（原型 roll/pitch/yaw_*、Kalman 全局在 .c 定义但无任何计算——名实不符的死全局）；**MPU6050_Init 不初始化 I2C 引脚/总线**（须先调母版 I2C_Init()，两处均无记录）。
- 结论：**差异（多项实质差异）**：
  1. **错误常量（建议修改）**：`library/modules/ml_mpu6050/ml_libs/ml_mpu6050.h` `TEMP_OUT_H 0x65` —— MPU6050 温度高字节是 **0x41**（0x65 非法；TEMP_OUT_L 0x42 对）。宏当前未被使用，属休眠错误；建议改为 0x41（或直接删除未用温度宏）。
  2. **前置条件漏记（建议修改）**：ml_mpu6050 依赖母版 ml_i2c 原语但 Init 不调 I2C_Init，须调用方先 `I2C_Init()`（默认 PA11/PA12）——.h 头注释与 manifest stm32.notes 均未记录。建议在 `ml_mpu6050.h` 加一行「使用前先调 I2C_Init()（母版 ml_i2c，默认 PA11/PA12）」并在 manifest notes 同步。
  3. **页面缺陷未记录（建议补充）**：模块 notes 仅「文件来自 21F 且真机编译过」，未记录页面缺陷（对照 sht20/pca9685 先例的 notes 清单风格）——页面 `(uint8_t*)(fsr<<3)` 整形转指针当数据地址（GPR 配置会从地址 0x18 读垃圾，模块已直接写 0x18 正确）；页面 MPU6050_Init 返回值注释（0成功/1失败）与代码（成功 return 1）相反；页面正文 LPF 42Hz vs 代码 20Hz。建议在 manifest stm32.notes 补「页面缺陷清单：fsr 指针转换→直写 0x18 修正；Init 返回值注释相反；正文/代码 LPF 不一致；温度与 DMP 未提炼——范围说明」。
  4. **差异未记录（建议补充）**：页面默认脚 SDA=PB8/SCL=PB9（=母版 OLED 段）未照抄，库走母版 ml_i2c PA11/PA12（pin_config.h 有总体注释，模块 notes 无）；页面 50Hz/DLPF 开 vs 库 200Hz/DLPF 关；页面 DMP 欧拉角在 stm32 侧无对应（inv_mpu 系列仅在 mspm0 条目）——建议 stm32 notes 说明「姿态解算需按 mspm0 侧 mpu_port 先例移植或改用 jy61p/imu_uart 串口姿态模块；本件只出原始数据」。此条为记录性建议，不强制补码（DMP stm32 端口属范围外工单）。

## 4. 0-96-iic（oled I2C，screen--0-96-iic-single-screen.md）

- 页面事实：SSD1306 128×64，IIC，3.3V/9mA，4 Pin；软 I2C 默认脚 **SCL=PB10/SDA=PB11**（GPIOB，**推挽 PP**，IIC_delay=delay_us(10)）；地址 0x78（写）；初始化序列：0xAE→0x00/0x10（列地址）→0x40→0x81/0xCF→0xA1→0xC8→0xA6→0xA8/0x3F→0xD3/0x00→0xD5/0x80→0xD9/0xF1→0xDA/0x12→0xDB/0x40→0x20/0x02（页寻址）→0x8D/0x14→0xA4→0xA6→Clear→0xAF；上电延时 200ms；API = OLED_Init/OLED_Clear/OLED_WR_Byte(命令 0x00/数据 0x40)/OLED_ShowString(x,y,str,**size=8/12/16/24**,mode)/OLED_Refresh（厂家 LCD 文件夹，页面只给移植片段：sys.h→stm32f10x.h、delay.h→board.h、u8/u16/u32）。
- 库内实现（stm32 I2C 路径 = 母版 ml_libs/ml_oled.c/.h + ml_oled_font.h，江协科技参考）：软 I2C 两脚 **OUT_OD + 置高**（页面为 PP；OD 需外上拉，SSD1306 模块自带）；地址 0x78 + 0x00/0x40 同页面；初始化序列 0xAE→0xD5/0x80→0xA8/0x3F→0xD3/0x00→0x40→0xA1→0xC8→0xDA/0x12→0x81/0xCF→0xD9/0xF1→0xDB/**0x30**→0xA4→0xA6→0x8D/0x14→0xAF→Clear（与页面等价：未写 0x20 页寻址（SSD1306 复位默认即页寻址，且逐字符 SetCursor 显式定点）；0xDB 0x30 vs 页面 0x40 均合法档；页面 0x00/0x10/0xA6 重复为冗余）；默认脚 **OLED_SCL=PB8/OLED_SDA=PB9**（pin_config.h L730-732，OLED_GPIO 宏可绑；母版 PB10/11 已归 Zigbee UART_3 段）；API = OLED_ShowChar/ShowString(Line,Column,Str)/ShowNum/ShowSignedNum/ShowHexNum/ShowBinNum/ShowFloat/DrawBMP/ShowCharBig(16×32)/ShowStringBig + 公共层 oled_show_text/oled_show_number/oled_refresh；**8×16 单一字体（+16×32）**，逐字符直写无显存抽象（无 OLED_GRAM/OLED_Refresh）。
- 结论：**一致（事实层）+ 2 项记录性建议**。芯片/分辨率/地址/命令语义/软 I2C/128×64 序列全部对应，无事实矛盾；页面初始化与库序列逐项等价（差异项均属合法实现变体）。记录性差异：
  1. **默认脚**：页面 SCL=PB10/SDA=PB11 未照抄，库用母版 OLED 段 PB8/PB9（可绑）——`library/modules/oled/manifest.json` stm32.notes 未记录该「页面默认不照抄」说明（pin_config.h L722-729 注的是 ml_i2c 离 PB10/11 让位 Zigbee，未点名 OLED 与 0-96-iic 页的关系）。建议 notes 补一行。
  2. **API 形制**：页面四档字号（6×8/6×12/8×16/12×24）+ OLED_Refresh 全帧；库 stm32 只有 8×16（+16×32 大字）、无 GRAM/Refresh——batch10 笔记已记「stm32 母版字库口径 8×16 唯一套、6×12 mspm0 有而 stm32 无」，建议补全「6×8/12×24 与 OLED_Refresh 同缺；如需多字号/全帧刷新参考 mspm0 侧 oled.c（中景园同族 API）」。不改码（母版 ml_oled 既有、不可改名/重定义，batch10 已声明）。
- 页面缺陷（对照库实现）：注释「0x8D-0x14 // set(0x10) disable」注释与值不符（0x14 = 充电泵使能，库同 0x14 正确）；0xA6 重复、页面无 ACK 检查（库同样无，江协式）——均已在库侧以正确形式实现，无需改动。
