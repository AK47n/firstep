## 3. 本轮撞出来的真问题：候选池太浅（已修一半）

`|S| <= 6`（学生真会用的规模）**全子集穷举**在批次 E 落地后出现 **3 组真撞车**，全部不是
本批四件的首选被抢，而是**旧件的候选被本批挤干**。最典型的一组：

```
ads1115 + at24c02 + bmp180 + pca9685 + sgp30 + sht30
  → sht30 声明 e（首选，被 at24c02 拿走）、n（被 pca9685 拿走）、z（被 sgp30 拿走）
  → 分不出字符，构建期 400
```

根因与批次 D 那次同类（`at24c02` 候选 `e` 撞 `sht30` 首选）：**候选池整体太浅**，
新件一多，"候选全是别人的首选"必然发生。修法 = 给每条已声明 `console` 的配方补一个
**共享后备池**：

```
n z i 0 1 2 3
```

* **纯追加**：已有候选一个不删、顺序不动 ⇒ 老配方的让位顺序逐字不变；
* 顺序理由：`n`/`z` 是所有件都在用的公共后备，放最前；`i` 是批次 F 的 `joystick` 首选，
  放它后面；数字尾巴是最后兜底（`at24c02` / `sgp30` / `mlx90614` 已在用这套写法）。
  三种顺序都用「本批 + 合成批次 F」两套目录实测过（全部 `|S| <= 6` 零撞车），
  取最保守的这一个。
* 落盘脚本 = `_topup_console_pool.py`（带上面的理由注释）；
* **新守卫** = `tests/test_hwcheck_console.py::
  test_any_small_selection_of_real_recipes_builds_one_console_table`
  （真库任意 `|S| <= 3` 全子集 + 固定种子抽样到 8 件：必须建得出表、字符互不相同、
  每件拿到的字符在**它自己声明的**面内、页面载荷与板上 `case` 同字符）。

**仍未修的容量天花板**：把库里专精件**全勾上**（26 件 > 25 个可用字符）必然撞死，
本批前就是这样（当时点名 `tcs34725`）。记账进 `.scratch/backlog.md` §22。

## 4. 本批八格的形状（逐格）

| 格 | include | init / init_expect | probe | read | console |
|---|---|---|---|---|---|
| ads1115 × stm32 | `ads1115_stm32.h` `pin_config.h` | `ads1115_init()` / — | `ads1115_write_config(ADS1115_DEFAULT_CONFIG)` = 0 | 原始值 + 电压两行（locals `float v = 0`） | `v` |
| ads1115 × mspm0 | `ads1115.h` | 同 | 同 | 同 | `v` |
| pca9685 × stm32 | `pca9685_stm32.h` `pin_config.h` | `pca9685_init(PCA9685_DEFAULT_FREQ_HZ)` / — | **无**（如实写「没有读取型探头」） | 能力回显 1 行 | `c` |
| pca9685 × mspm0 | `pca9685.h` | 同 | 同 | 同 | `c` |
| dht11 × stm32 | `dht11_stm32.h` `pin_config.h` | `dht11_init()` / — | `dht11_read(&temp, &humi)` = 0 | 温度 / 湿度各两行 | `h` |
| dht11 × mspm0 | `dht11.h` | 同 | 同 | 同 | `h` |
| ds18b20 × stm32 | `ds18b20_stm32.h` `pin_config.h` | `ds18b20_init()` / `"0"` | `ds18b20_init()` = 0 | `(t = read_temp(), (int)t)` + 小数位 | `t` |
| ds18b20 × mspm0 | `ds18b20.h` | 同 | 同 | 同 | `t` |

`ds18b20` 那两格的 `init_expect` 与 `probe` 是**同一次物理检查**（同一条 0xCC 家族的自证），
会记**两笔判定**——这是工单要求的形状，note 第 2 条已把这一点写给学生的原话：
"这不是「两级自证」，是同一件事报了两遍"。
