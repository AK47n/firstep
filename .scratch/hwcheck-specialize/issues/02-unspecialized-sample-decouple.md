# 02 — 未专精样本夹具解耦：别再让"某件一定没配方"绑死用例

**要做什么：** 把用例里"拿某一两件当未专精样本"的写法改成**从真实库里现挑一个当趟真的没有配方的件**
（或登记一组明确留作样本的件）。做完之后，**后续每一批专精化都不需要改任何一条既有用例**——
本批专精化 `sht20`（批次 03）不再把 `test_hwcheck.py` 里那两处断言变成假红。

**被谁阻塞：** 无——可立即开始（建议与 01 同批做掉，内容批次都等它俩）。

**状态：** ready-for-agent

- [ ] 未专精样本的判据**单源**：一处 helper（挑件规则）或一处登记清单，用例不再各写各的 slug
- [ ] 走真实配方路径的两处断言改用新来源：`test_hwcheck.py` 的
      「preview 报未专精」与「生成后回读工程报未专精」——两处都要求样本件**当趟真的没有配方**
- [ ] 挑出来的样本件必须**带总线扫描那种**（既有断言要吃 `hwcheck_generic_<slug>` 与扫描行），
      所以挑件规则要能表达"我要一个 I2C 类、且没有配方的件"
- [ ] 基线数（`test_hwcheck_generic.py` 的"未专精格 ≥ 157 / 能拿初始化 ≥ 132"）
      随批次下调时**如实改数并写原因**（该用例注释本来就要求这么做）——本轮只提供"改哪里"的说明，
      实际下调发生在各内容批次里
- [ ] **反证**：把样本件之一写进配方（模拟专精化）→ 用例自动挑到别的件、仍然绿；
      若把可用样本**全**专精化 → helper 必须**大声失败**并说明"没有样本件了，请留一件"
- [ ] 不改任何断言的语义（只换样本来源），前端 / 产物侧零改动

## Comments

### 2026-09-25 立项依据（实测，不是推测）

**会真红的耦合点**（走真实配方路径、断言"这一件没有配方"）：

| 位置 | 断言 | 本批哪一颗工单会把它变红 |
|---|---|---|
| `tests/test_hwcheck.py:2166` | `unspecialized == ["sht20"]`（`/api/hwcheck/preview`） | 批次 03（sht20） |
| `tests/test_hwcheck.py:2245` | `unspecialized == ["sht20"]` + `hwcheck_generic_sht20 in main_c`（`/api/hwcheck/project` 回读） | 批次 03 |

**不会红的**（已核实，别顺手改）：`tests/test_hwcheck.py` 的 `_generic_stm32(slug="sht20")` 系列
与 `tests/test_hwcheck_generic.py` 的 `_real("sht20"|"pca9685"|"servo", …)` —— 它们直接调
`plan_generic_section(...)` **合成**一个通用小节，绕开配方文件，所以那件有没有配方都无所谓。

**基线数**（会随批次下降，属预期）：`tests/test_hwcheck_generic.py:423`
`assert planned >= 157`（与上面的 `with_init >= 132`）。

### 为什么值得单独一张单（这一课已经付过两次学费）

`tests/test_hwcheck.py:2144` 那条用例的 docstring 自己记着账：
> 工单 05 起 `ml_mpu6050` 已经专精了…工单 09 又把 v1 清单补到 17 格（`beep` 也专精了）
> ——**拿专精件当"未专精"的样本会变成一条假红**。

也就是说这套夹具已经因为"专精面推进"被改过两次。本 spec 还要再推 20 件（后续可能更多批），
不先解耦就是把同一笔学费交第三、第四次。

### 挑件规则的建议（工单内定，两个方向都行）

- **动态挑**（推荐）：`{slug × platform}` 里筛出"没有配方 且 有该平台条目"的，再按需要挑一个
  I2C 类的（能出总线扫描行）；挑件结果在用例里可见，失败时点名"这一趟挑到的是谁"。
- **登记样本件**：在测试里显式登记 2~3 件"本批不专精"的件（如 `ws2812` + 一件 I2C 类），
  并在本 spec 的批次工单里写明"这几件不许被专精化"。

两条都行，选面窄、可读的那条；判据是同一条：**后续批次专精化任意件，既有用例不用改**。
