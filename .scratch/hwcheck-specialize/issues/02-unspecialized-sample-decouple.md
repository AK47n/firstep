# 02 — 未专精样本夹具解耦：别再让"某件一定没配方"绑死用例

**要做什么：** 把用例里"拿某一两件当未专精样本"的写法改成**从真实库里现挑一个当趟真的没有配方的件**
（或登记一组明确留作样本的件）。做完之后，**后续每一批专精化都不需要改任何一条既有用例**——
本批专精化 `sht20`（批次 03）不再把 `test_hwcheck.py` 里那两处断言变成假红。

**被谁阻塞：** 无——可立即开始（建议与 01 同批做掉，内容批次都等它俩）。

**状态：** resolved

- [x] 未专精样本的判据**单源**：一处 helper（挑件规则）或一处登记清单，用例不再各写各的 slug
- [x] 走真实配方路径的两处断言改用新来源：`test_hwcheck.py` 的
      「preview 报未专精」与「生成后回读工程报未专精」——两处都要求样本件**当趟真的没有配方**
      （落地时发现另有**两处也必须改**，见 Comments：i2c 总线扫描那条与 generate 落盘那条）
- [x] 挑出来的样本件必须**带总线扫描那种**（既有断言要吃 `hwcheck_generic_<slug>` 与扫描行），
      所以挑件规则要能表达"我要一个 I2C 类、且没有配方的件"
- [x] 基线数（`test_hwcheck_generic.py` 的"未专精格 ≥ 157 / 能拿初始化 ≥ 132"）
      随批次下调时**如实改数并写原因**（该用例注释本来就要求这么做）——本轮只提供"改哪里"的说明，
      实际下调发生在各内容批次里（批次 03 已照办：157/132 → 153/128）
- [x] **反证**：把样本件之一写进配方（模拟专精化）→ 用例自动挑到别的件、仍然绿；
      若把可用样本**全**专精化 → helper 必须**大声失败**并说明"没有样本件了，请留一件"
- [x] 不改任何断言的语义（只换样本来源），前端 / 产物侧零改动

## Comments

### 2026-09-25 立项依据（实测，不是推测）

**会真红的耦合点**（走真实配方路径、断言"这一件没有配方"）：

| 位置 | 断言 | 本批哪一颗工单会把它变红 |
|---|---|---|
| `tests/test_hwcheck.py:2166` | `unspecialized == ["sht20"]`（`/api/hwcheck/preview`） | 批次 03（sht20） |
| `tests/test_hwcheck.py:2245` | `unspecialized == ["sht20"]` + `hwcheck_generic_sht20 in main_c`（`/api/hwcheck/project` 回读） | 批次 03 |

**不会红的**（已核实，别顺手改）：`tests/test_hwcheck.py` 的 `_generic_stm32(slug="sht20")` 系列
与 `tests/test_hwcheck_generic.py` 的 `_real("sht20"|"pca9685"|"servo", …)` —— 它们直接调
`plan_generic_section(...)` **合成**一个通用小节，绕开配方文件，所以那件有没有配方都无所谓。

**基线数**（会随批次下降，属预期）：`tests/test_hwcheck_generic.py:423`
`assert planned >= 157`（与上面的 `with_init >= 132`）。

### 为什么值得单独一张单（这一课已经付过两次学费）

`tests/test_hwcheck.py:2144` 那条用例的 docstring 自己记着账：
> 工单 05 起 `ml_mpu6050` 已经专精了…工单 09 又把 v1 清单补到 17 格（`beep` 也专精了）
> ——**拿专精件当"未专精"的样本会变成一条假红**。

也就是说这套夹具已经因为"专精面推进"被改过两次。本 spec 还要再推 20 件（后续可能更多批），
不先解耦就是把同一笔学费交第三、第四次。

### 挑件规则的建议（工单内定，两个方向都行）

- **动态挑**（推荐）：`{slug × platform}` 里筛出"没有配方 且 有该平台条目"的，再按需要挑一个
  I2C 类的（能出总线扫描行）；挑件结果在用例里可见，失败时点名"这一趟挑到的是谁"。
- **登记样本件**：在测试里显式登记 2~3 件"本批不专精"的件（如 `ws2812` + 一件 I2C 类），
  并在本 spec 的批次工单里写明"这几件不许被专精化"。

两条都行，选面窄、可读的那条；判据是同一条：**后续批次专精化任意件，既有用例不用改**。

### 2026-09-25 落地记录（实现 + 反证读数 + 双轴评审整改）

**做法 = 动态挑**（登记清单那条没选：登记就意味着"这几件不许专精化"，把扩张的射程又绑了一次）。
落点全在 `tests/test_hwcheck.py` 一个区段：

- `_unspecialized_candidates(platform, *, extra_specialized)`：三条判据（有该平台条目 / 该格没有配方
  / 是 I2C 类且有可调用的无参初始化），按 slug 排序返回 `GenericSection` 列表；"没有配方"的判据
  直接用生产侧同一个 `catalog.for_platform(...)`（不另写一套）；
- `_unspecialized_sample()`：取第一个，**挑不到 = 大声失败**（"请留一件别专精它"）；
- `_module_headers` 改为直接调生产侧的 `read_module_headers`（读盘口径同一份）；
- `extra_specialized` 是**测试专用钩子**（与真实配方集合**取并集**，不写盘），里面有库内不存在的
  slug 会当场红——静默无效会让反证给出假的"没有样本件了"。

**实际改了 4 处用例**（工单表里只点名了 2 处，落地时实测另两处也必红）：

| 位置 | 为什么必须改 |
|---|---|
| `preview 报未专精` | 断言的 `unspecialized == ["sht20"]` 直接失效 |
| `project 回读` | 同上 |
| **`preview 的 i2c 总线扫描`**（表里没点名） | `body["unspecialized"][0]` 会 IndexError |
| **`generate 落盘`**（表里没点名） | `count("hwcheck_generic_sht20();") == 1` 会变 0 |

❌ **不改的**（工单已核实，别顺手改）：`_generic_stm32(...)` 系列与
`tests/test_hwcheck_generic.py` 的 `_real(...)` —— 它们合成通用小节、绕开配方文件。

**反证读数**（`.scratch/hwcheck-specialize/probe-sample-decouple.txt`，真读真写 + 逐字节回滚）：

| 形态 | 读数 |
|---|---|
| 前置 | 配方文件 sha256 `00a22893…`；候选样本 13 件，挑到 `ads1115` |
| 把 `ads1115` 临时写进配方（真头名 + 一个当时没被占用的命令字符） | 候选 12 件，挑到 **`ags10`**（✓ 换人）；相关 10 条用例 **10 passed** |

同一判据另有**常驻用例** `test_unspecialized_picker_survives_losing_its_current_sample`：
① 把当前样本标成已专精 → 首挑必须换人；② 候选全标成已专精 → 挑件为空且大声失败。

**双轴评审整改**（固定点 `71c4941c`）：

- Spec 轴：反证用例原来只验了"全专精光 → 失败"，**没有断言'换人'**（docstring 承诺过头）
  → 补上第 ① 条断言；探针的伪配方原来写死 `command: "9"`（日后被真配方占了会误导）
  → 改成从 `COMMAND_POOL` 里现挑一个没被占用的；docstring 里"本文件顶部那段注释"改成实际位置。
- Standards 轴：`_module_headers` 与生产 `read_module_headers` 分叉 → 改为直接复用；
  `extra_specialized` 不校验（写错平台静默无效）→ 改成 slug 集合 + 库内存在性断言；
  探针的 `PATCH_SLUG` 写死 + "换人了吗 ✗"不进退出码 → 改成用当趟挑到的样本、三条判据
  一起进退出码；回滚改为"只在文件仍等于我们写进去的那份时才写回"（不覆盖并发改动）；
  返回值 `(slug, section)` 里 slug 冗余 → 直接返回 `GenericSection`；
  端点那条用例补一个**不取自被测调用**的字面量判据（`_SCL_GPIO` 命名约定的正则）。
