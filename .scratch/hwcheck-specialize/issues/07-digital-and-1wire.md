# 07 — 专精化批次 E：数字外设与单总线四件（ads1115 / pca9685 / dht11 / ds18b20）

**要做什么：** 学生勾这四件中的任何一件（各两平台、共八格）时，检测页给它一个 `[专精]` 小节：
能判的判（`ads1115` = 写配置事务的 ACK 返回码、`dht11` = 应答 + 40bit 校验和、
`ds18b20` = 复位应答脉冲），判不了的**如实说没有探头**（`pca9685` 全 void API、板上不可自证），
四件都给读数（电压 / 能力回显 / 温湿度 / 温度）与一个复测字符。此前它们只有"未专精：只验总线和初始化"。

**被谁阻塞：** 01（命令字符让位——四件都要声明字符，不留位机制就等着撞车）、
02（未专精样本夹具解耦——本批不是靠它才不会红，而是**有了它才不必再改任何一条既有用例**：
`pca9685` 现在被若干用例当"未专精样本"用，但那些用例直接调 `plan_generic_section(...)`
**合成**一个通用小节、绕开配方文件（见工单 02 的核查表），所以它们本来就不会红——
02 做掉之后，"专精化任意件都不动既有用例"这条对后续每一批都成立）。

## Comments

### 2026-09-25 立项依据与关键事实

- 这 8 格现在全部是"未专精"（`library/hwcheck_recipes.json` 顶层只有 10 件 / 17 格专精），
  学生看不到任何判定与读数；四件 manifest 的实测结论都是 **未上板**（recon-02 §5-11）。
- **本批是"探头强度"最好的展示面**，四件的探头强弱一眼可见，正好对应 spec 第 5 条用户故事：
  `dht11`（应答 + 40bit 校验和，`dht11.c` 的 `dht11_read`）>
  `ds18b20`（复位应答脉冲，`ds18b20.h:56`）>
  `ads1115`（一条写事务的 ACK，`ads1115.c:161-178`）>
  `pca9685`（**无**——`pca9685.h:39-55` 全是 void，`read_reg` 与寄存器宏只在 .c）。
- 三件 `read` 都有"能自证在动"的抓手，note 里要用上：`ads1115` AIN0 接 GND ≈ 0、
  接 3V3 ≈ 26400（±4.096V 档 1 LSB = 0.125mV）；`dht11` 哈一口气湿度就动（分辨率 1%RH，
  **小数位恒 0 是正常的**）；`ds18b20` 手指捏住传感器温度就爬（0.0625℃/LSB）。
- `ds18b20` 的失败签名特别具体，note 必须写：stm32 侧悬空 → 寄存器 0xFFFF → 读回 **-0.0625℃**；
  恒 **85.0℃** = 上电默认未转换；恒 0.0℃ = 读位全 0（recon-02 §2 `ds18b20` 小节）。
- `pca9685` 照 `xunji` 先例**检测程序不该主动驱动执行机构** → 这一节不放任何
  `set_angle` / `set_pwm`，只调 `pca9685_init(PCA9685_DEFAULT_FREQ_HZ)`；
  代价是这块板"什么都没发生"，note 要如实说清楚（recon-02 §2 `pca9685` 小节）。
- 字面上最省事的一格是 `ds18b20`（init 与 probe 同句），但它是**两笔判定**——spec 硬约束⑥
  要求这种"知情选择"写进 note，别让学生把"同一件事报了两遍"读成"两级自证"。
