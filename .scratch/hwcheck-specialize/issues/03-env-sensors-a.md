# 03 — 专精化批次 A：三件温湿度（aht10 / sht20 / sht30）

**要做什么：** 学生勾这三件中的任何一件（含两平台）时，检测页给它一个 `[专精]` 小节：
板上打**通信 OK / FAIL**（探头 = 整条读事务的返回码），回显温度与湿度（整数 + 小数第一位两行），
并给一个复测字符。此前它们只有"未专精：只验总线和初始化"。

**被谁阻塞：** 01（命令字符让位——三件都要声明字符，不留让位机制就等着撞车）、
02（未专精样本夹具解耦——本批会把 `sht20` 专精化，那一处断言必须先去耦）。

**状态：** resolved

- [x] `include` 用**该平台真头名**（`aht10.h` vs `aht10_stm32.h` 等，六格全不同——写错构建期红）

## Comments

### 2026-09-25 立项依据与关键事实

- 这 6 格现在全部是"未专精"，学生看不到任何判定与读数（`recon-01-env-sensors.md` 实测：12 格
  `verified: true` 编译绿、全部**未上板**）。
- **六格函数名两平台完全同名**，只有 include 头名不同（`aht10.h` / `aht10_stm32.h` …）——配方两侧
  几乎对称，是这批里最省事的切片，适合当第一个内容批次（拿它把配方写法与量具跑顺）。
- **三件都做不出"身份探头"**（AHT10/SHT20/SHT30 都没有 ID 寄存器读法）：探头只能是返回码比对
  `== 0`。这是如实的"通信通"判据，不是身份校验——**note 里必须把这句话写给学生看**，
  别让学生以为"OK = 器件是正品/数据准"。
- `sht20` 的 mspm0 `init` 是**空函数**（引脚由 `SYSCFG_DL_init()` 配），stm32 `init` 只配脚不做通信
  → 两平台都不写 `init_expect`。
- 已知驱动缺陷（**本单不修**，只在 note 里如实提示）：`sht30_init()` 吞掉 `write_mode` 返回值
  （sht30.c:189）；AHT10 测量窗口 ~25ms ≪ 手册 ≥80ms（aht10.c:184-186 自记）——后者是 probe
  判 FAIL 的第一嫌疑，note 要给"先加大读前延时再复测"的出路。

### 2026-09-25 落地记录（实现 + 读数）

**配方**：6 格写进 `library/hwcheck_recipes.json`（`aht10` / `sht20` / `sht30` × 两平台），
事实底稿 = `recon-01-env-sensors.md` §1–§3：

- `include` 用该平台真头名（`aht10.h` vs `aht10_stm32.h`，六格全不同）；
- `locals` = `float t = 0` / `float h = 0`；`init` 三件全 **void** → **不写 `init_expect`**；
- `probe` = `xxx_read(&t, &h)` == `0`；`read` = 温度 / 湿度各拆「整数 + 小数第一位」两行；
- `console`：`aht10` 首选 `h`（候选 `i`/`n`）、`sht20` 首选 `t`（候选 `w`/`z`）、
  `sht30` 首选 `e`（候选 `f`/`c`）——工单 01 的让位机制就位后，同组首选撞车不再等于 400；
- `note` 逐格覆盖：探头证明了什么（**证通信 ≠ 证型号 ≠ 证数据准**）、失败模式与返回码分段、
  正常范围（室温 20~30℃ / 30~70%RH）、接线与地址坑（`sht20` 与 `pca9685` 同址 0x40、
  `sht30` 的 ADDR 必须接地 + stm32 侧推挽 SDA 依赖模块自带上拉、`sht30` × mspm0 与 `ms5611` 同脚）、
  平台差异、以及**未上板**这句实话。

**扩张地板**：`tests/test_hwcheck_recipe.py` 新增 `EXPANSION` + `EXPANSION_CELL_COUNT`（**只装扩张格**，
现在 6；`len(PILOT) + len(EXPANSION)` = 配方文件应有的总覆盖 23）+ 三条用例（逐格 / 精确条数 /
与 `PILOT` 不重叠）。`PILOT` 一个字没动。工单 05/06 里"地板条数"的写法同批对齐到这个常量语义
（它们原来写的是"总数"口径）。

**未专精基线**：`tests/test_hwcheck_generic.py` 如实下调 **157/132 → 153/128**，并写明"本批 6 格
每格都能拿到无参初始化，所以两个数各降 6"（实测读数与算式 = `probe-batch-cells.txt`）。

**真编译矩阵**（`probe-compile-matrix.py --slugs aht10,sht20,sht30` → `probe-compile-matrix.txt`）：

**反证**（`probe-expansion-floor.py` → `probe-expansion-floor.txt`）：把 `sht30` 两格临时从配方文件

sha256 与前置一致（`00a22893…`）。"撤掉必红、拿回来必绿"两条读数都在。

**行缓冲余量**（`hwcheck_line[128]`，`hwcheck_report` 是**逐段攒行**、按整行算）：本批最长的一行
= **112 字节**（温度小数位那行，含「与上一行拼起来读：25 与 3 → 25.3℃」这个例子），余 16 字节；
console 那行 94 字节。既有的 `test_every_reported_line_fits_the_line_buffer` 只吃手搓小节 + 通用件
（**不读真配方**），所以这一条是本批自查的读数，如实记在这里。

**结论**：完成（本批是三批里最省事的一批，也把后续批次的写法与量具跑顺了）。
⚠ 残留的洞（照 spec 的设计取舍，不在本单修）：`EXPANSION` 的「逐格 + 精确条数」两条一起挡的是
"删一格"；若有人把 `EXPANSION_CELL_COUNT` 一起改小，两条都会绿——这一层与 `PILOT` 同款，
spec 明确说既有的**文件级**下限断言（`>= 17 格 / >= 10 件`）不改（它管的是 v1 那 17 格）。
这条洞已写进 `EXPANSION_CELL_COUNT` 上方的注释（不靠措辞掩盖）。

### 2026-09-25 双轴评审整改（固定点 `8481894f`）

**Spec / Standards 两轴一致点名的硬错（已改）**：

1. **aht10 × mspm0 的 note 事实写错**：原写"本平台 `aht10_init()` 是空实现"——实际
   `aht10.c:149-163` 做的是软复位 + 校准使能、内含两次 `delay_ms(50)`（"空实现"是 **sht20**
   的特征，被套用了）。已改成实话，并补上"上电这一遍停约 100ms，属正常"（stm32 格本来就有）。
2. **两处 stm32 格引了对侧平台的行号**：`sht20` × stm32 的窗口出处改为 `sht20_stm32.h:49-51`
   （原引 mspm0 头 `sht20.h:37-39`）；`sht30` × stm32 的 CRC 出处改为 `sht30_stm32.c:227`
   （原引 mspm0 文件 `sht30.c:243`）。
3. **note 缺"读数 0 / 恒定"这条失败模式**（spec 口径要求"读数恒 0 / 恒定值 / 超时各意味着什么"）
   → 六格各补一句：探头已判 OK 却读数恒 0 或长时间不动，先敲复测、再查器件是否真在测量 /
   线长 / 上拉（`sht20` 那格另注明"本件判据最弱、没有 CRC 兜底"）。
4. **`read` 单位缺正常范围参考**（spec：单位里带量纲与正常范围）→ 温度 / 湿度的整数行改成
   「温度 ℃（整数部分；室温 20~30℃ 属正常，手捏着会升）」这类写法（小数行保持"与上一行拼起来读"）。

   三处同动仍会全绿）→ 改成如实说明 + 把残留的洞写进注释（见上）。
