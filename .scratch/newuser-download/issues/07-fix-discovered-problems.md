**要做什么：** 把前几张工单真机演练时**顺带发现、但当时只登记未修**的问题收掉：

② 没装 / 版本太低时只给下载页，用户装完 Python 后没有顺畅的"回到这里继续"路径；
③ 本机全局 site-packages 里同一份包有两个版本元数据并存（pip 会犯迷糊）。

## 验收记录（2026-09-13）

**修好了什么**（`git diff install.bat`：+61/-6 行，全是文案与一个端口变量块）：

| 问题 | 修前 | 修后 |
|---|---|---|
| K6 端口写死 | 完成提示恒为 `http://127.0.0.1:8000` | `http://127.0.0.1:%PORT%`，随环境变量走 |
| 失败分支没出路 | 「装完重新运行本脚本即可」 | 「按一次回车，本脚本会重新检查并接着装」+「之后也可以再双击一次」 |
| 重复元数据 | `0.1.0` 与 `1.1.1` 两份 dist-info 并存 | 只剩 `1.1.1`；`local-environment.md` 记明"别再跑全局 `pip install -e .`" |

**诚实说明两处验证的强度差别**：

- **端口动态**：真机跑通（三档位 + 端到端），强度高。
- **续跑路径**：本机造不出「没有 Python」的环境，所以走的是**结构守卫**——
  断言脚本里真的有 `call :recheck_python` → 真的重查版本 → 真的 `goto :step_python_ok`。
  这能保证"路径存在且接线正确"，但**没有**在一次真实的"用户装完 Python 按回车"里跑过。

**这次排查最该记住的两件事**（已写进 `local-environment.md` 2.5b）：

1. **我给验证脚本算错了仓库根层数**，于是它每跑一次就把「测试版 `install.bat`」覆盖到**真身文件**上一次。
   后果是"真身 `install.bat` 跑到 Python 检查就静默退出"，看起来完全像产品缺陷，实际是测试写坏的。
   现在所有这类脚本都只改 `%TEMP%` 下的副本，并**先断言真身文件字节未变**。
2. **模拟外部命令别用 `.cmd/.bat` 垫片**：批处理里调用 `.cmd` 缺 `call` 会**转移控制权**，
   父脚本直接终止——同样伪装成"脚本提前退出"。要模拟版本不符，只改脚本里那一行判断。
   另外：本会话一度把 `PATH`/`USERPROFILE` 改坏（折叠成只剩 System32），
   后续每次调用都受影响，直到从注册表重建才恢复——**改环境变量要逐项增删，别整段替换**。
