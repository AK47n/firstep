# spec — 不可选形态统一为灰底灰字（feature-slug：`disabled-forms`）

> 上游：`backlog.md` §31 / §32 的「仍开着的①」；`code-contrast/03` 收尾时量出、按票面判据够不着的
> 那两处"别的类名"，外加同类第三处 `.param-stale`。
> 本轮**不发版**（发布节奏另开一轮）。

## 问题陈述

界面里有三处"这个组合不成立"的形态，用整块 `opacity` 变淡来表达"不可用"：

| 形态 | 它是什么 | 现值 |
|---|---|---|
| `.module-card.off` | 模块卡：当前选的平台没有这个模块的条目（点它会弹「请先切换目标平台」） | `opacity: .55` |
| `.pin-menu-list li.cant` | 引脚菜单里"这根脚接不了这个角色"的行（整行不可点，带「不兼容：…」原因） | `opacity: .5` |
| `.param-stale` | 参数卡：main.c 改过、锚可能失效，输入与应用已禁用，带「位置已变」徽章 | `opacity: .65` |

`opacity` 把**整块**（文字 + 底 + 彩色徽章）一起往容器底上拉，于是：

1. **该读的字被洗淡**——而这三处最该读清的恰恰是"为什么不能用"（「需切换平台」/「不兼容：…」/「位置已变」）。
   现算（`probe-00-inventory.py` §2，浅色主题）：`.module-card.off` 说明字 **2.24**、slug **3.40**；
   `li.cant` 原因行 **2.23**、角色名 **3.16**；`.param-stale` 提示 **2.65**——**全部低于 AA 4.5**。
2. **比值算不出来**：`opacity` 是合成运算，静态面（腿⑧的"同规则 color × background"）看不见它，
   全站扫描面又会被祖先渐变滤掉（`code-contrast/03` 实测：禁用桶曾经整批为空）——两头都看不见。
3. **没有闸门**：判据⑥（禁用态不许用 `opacity`）按**类名**认人（`:disabled` / `.disabled`），
   这三处是"别的类名"，判据注释里明写了够不着。于是一边低于 AA、一边没人管。

## 方案

三处改用与**按钮禁用态同一口径**的形态：**灰底 + 灰字 + 描边**。

- 底 `--panel-2`（`.module-card.off` 用 `--panel`，见下）、字 `--muted`、描边 `--border`；
  比值与按钮共用族面**同一格**（`--muted` × 禁用态底：浅 **5.25** / 暗 **5.67**）。
- **彩色徽章保留原色**（平台状态、角色类型、「必接」、「需切换平台」、「位置已变」）——
  它们回答"这是什么"，是事实，不是"不可用"的一部分。
- "不可选"的辨识改由**形状**承担：虚线描边 / `cursor: not-allowed` / 无 hover 反馈 /
  已有的警示标签。不再由"把字洗淡"承担。
- 判据⑥的认人面从"写死两个类名"扩成**一份登记表 + 一条反向嫌疑面**：
  盘上凡"用 `opacity` 弱化、且命中嫌疑信号（同规则 `cursor: not-allowed`，或类名词法命中
  不可选词表）"的规则，必须在认人面里登记（登记为"禁用形态"= 不许 `opacity`，或登记为
  "合法弱化"= 给出理由）。**这一类从此兜住**，不再靠人眼复核兜底。

## 用户故事

1. 作为浅色主题下的用户，我想读清「需切换平台」的模块卡上的说明字，以便知道这个模块是干什么的、
   该换到哪个平台去用它。
2. 作为在引脚菜单里挑脚的用户，我想读清「不兼容：…」那一句，以便知道这根脚为什么接不了这个角色、
   该换哪根脚。
3. 作为参数表的用户，我想读清「位置已变」那张卡的提示行，以便知道要去重新识别参数。
4. 作为维护者，我想让"不可选形态"只有一种被认可的写法，以便新增形态时不必重新发明口径。
5. 作为维护者，我想让"盘上又用 `opacity` 表达不可选"在门禁里**当场变红**，以便这条线不靠人眼。
6. 作为读屏用户，我想在不可用的模块卡上听到它是"不可用"，以便不必先点一次、再听那句 toast。
7. 作为后续接手的人，我想从登记表一眼看出"哪些选择器算不可选形态、哪些是登记在案的合法弱化"，
   以便判断新形态该登记到哪一类。

## 实现决策

### 1. 三处落值（产品面）

| 形态 | 改动 | 改后比值（浅 / 暗） |
|---|---|---|
| `.module-card.off` | 去 `opacity`；卡面底 `--panel-2` → **`--panel`**（与所在容器同底 = "退到背景里"）+ **虚线描边**（形状信号）；卡内文字走 `--muted` | 说明 `--muted` on `--panel` **6.59 / 6.06**；slug `--text` **15.80 / 14.64** |
| `.pin-menu-list li.cant` | 去 `opacity`；行底 `--panel-2`（可绑行是 `--panel`）+ 文字 `--muted` + `cursor: not-allowed` | 角色名 / 原因行 **5.25 / 5.67**（与按钮同一格） |
| `.param-stale` | 去 `opacity`（卡面本来就是 `--panel-2`）；卡内文字走 `--muted`；徽章保留 | 提示 **5.25 / 5.67**；参数名 **12.59 / 13.70** |

三处**都不新增族面格**：用到的两对（`--muted` × `--panel`、`--muted` × `--panel-2`）已在
`code-contrast/03` 建的"禁用态底"族格里。

**连带的两个小调整**（都是为"底撞色"服务的，写清楚免得被当越界）：

- `.pin-menu-list li.can:hover` 的底要让开：可绑行 hover 现在也是 `--panel-2`，与不可选行的**静底同色**
  ⇒ 悬停时读起来像"这行也不能点"。候选改 `--accent-dim`（仓里既有的 hover 语汇，`.mc-info:hover` /
  `button.ghost:hover` 都在用）。
- `.module-card.off` 的底改成 `--panel` 后，卡内「详情」按钮（`.mc-info`，底也是 `--panel`）会与卡面糊成
  一片 ⇒ 该按钮在 off 卡上改用 `--panel-2` 底（它仍是**可用**的：看模块说明与"能不能用"无关）。

**a11y**：`.module-card.off` 仍可聚焦、仍可点（点了弹 toast 解释为什么不行）⇒ 加 **`aria-disabled="true"`**
（读屏念"不可用"，但不夺焦点、不改键盘路径）。这正是**不改名**的配套：语义由 aria 承担，
类名继续表示"这个组合不成立"。`.module-card` 由 `fx/module.js` 的 `moduleGridHTML` 一处渲染
（生成页与检测页器件网格共用），改一处即两页生效。

### 2. 判据扩面（`tests/js/css-tokens.test.mjs` 腿⑧）

- **认人面**：原 `:disabled` / `.disabled`（剥 `:not(…)` 后判定，语义不变）
  **+ 新登记表** `CONTRAST_DISABLED_FORMS`：`[作用域, 剥注释的选择器, 类别, 理由]`；
  类别两档（照 `CONTRAST_KINDS` 的既有写法）：
  - `disabled` = 不可选形态 ⇒ **不许**出现 `opacity`；
  - `dim` = 合法弱化 ⇒ 允许 `opacity`，但理由必须写清（非文字装饰 / 仍可点的状态）。
- **正向判据**（⑥的延伸）：认人面命中的规则里出现 `opacity: <1` ⇒ 红（文案点名选择器）。
- **反向判据**（新）：**活规则**（排除 `@keyframes` 帧）里出现 `opacity: <1`，且命中任一嫌疑信号
  ——① 同规则有 `cursor: not-allowed`；② 选择器里的类名逐字命中 `CONTRAST_DISABLED_HINTS`
  （`disabled|off|cant|stale|inactive|unavailable|locked|dim|ro|na`）——**必须**落在认人面里，否则红。
- **双向对账**：登记表每条必须在盘上认到人（选择器真的存在），否则红——防死条。
- **镜像**：`CONTRAST_DISABLED_FORMS` / `_HINTS` 若被 Python 侧（`probe_lib.py`）复用于生成器或探针，
  照既有惯例在 `tests/test_contrast_mirror.py` 加一组同源断言（**先看需不需要**：只有两侧都用到才加，
  别造一份没人读的镜像）。

**recon 基线（`probe-00-inventory.py` §1，须随工单复跑复核）**：样式块里 `opacity < 1` 共 **26** 条
（动画帧内 5 条，判据排除；活规则 **21** 条），命中嫌疑信号的 **7** 条 —— 3 条将来登记为 `disabled`
（本轮三处目标），4 条登记为 `dim`（`.pin-dim` SVG 引脚圆点 / `.wiring-dot-dim`、`.wiring-line.wiring-dim`
接线图装饰 / `.code-tab.ro .code-tab-name` 只读页签名——仍可点）。剩下 **14** 条不命中信号，不在射程（见范围外）。

### 3. 量具与证据

- **真像素**：`.scratch/code-contrast/probe-08-disabled-state.mjs`（真元素截图 + 读像素）扩一格口径
  ——把"哪些元素算不可选形态"从"`el.disabled === true` 或 `classList.contains('disabled')`"扩成
  **认人面同源的选择器清单**（照本轮登记表取值），并给三处目标加 `--tag before/after` 对照。
- **人眼**：两主题 × 三处形态的截图（改前 / 改后）。
- **红证**：把 `opacity` 放回任一处形态、以及注入一条新的 `.x.off { opacity: .4 }` ⇒ 前端门禁必须红且
  文案点名；复原后 sha256 一致。

### 4. 读数口径（免得上一条账目对不上）

票面记的 `浅 3.40 / 2.24` 这个口径 = **字往元素自己声明的底上按 opacity 拉平、底不动**（`probe-00-inventory.py`
§2 的"模型 B"逐格复现到 0.01）。另一种模型（整块连底一起压到祖先底上 = probe-08 的几何）给 3.22 / 2.16。
两份都要在读数里写明是哪个模型；**最终判据以 probe-08 的真像素为准**。

  经前端门禁 `node --test "tests/js/*.test.mjs"` 跑。**不新造缝**。
- 前端渲染层那一条（`aria-disabled` + 类名）落在 `tests/js/module-grid.test.mjs` / `tests/js/hwcheck.test.mjs`
  既有的字符串断言旁（它们已经在断言 `class="module-card off"`）。
- 真浏览器用例（`tests/browser/*.spec.mjs`）**不新增**：三处形态是纯样式与属性，初始态可达性差
  （`.pin-menu-list li.cant` 要选模块 + 开菜单；`.param-stale` 要有生成过的工程）——真浏览器这一层
  沿既有用例跑回归即可，证据由 probe-08 真像素承担（`code-contrast/03` 同款处置）。
- 既有先例：`code-contrast/03`（判据⑥⑦ + 红证 n1–n6 + probe-08）；`border-guard`（登记表 + 双向对账）。

## 范围外

- **改名 `.disabled`**：用户拍板不改——这三处语义是"这个组合不成立"（不适用 / 不兼容），不是控件禁用；
  且 `.module-card.off` 仍可点（弹解释），叫 `.disabled` 会让人误判"能不能点"。语义由 `aria-disabled` 承担。
- **全站 `opacity` 全量登记（腿⑩）**：剩下 14 条不命中嫌疑信号的 `opacity`（装饰图标 / 折叠箭头 /
  瞬态动画 / 轻微弱化的次要字如 `.welcome-sub` `.92`、`.sugg-count` `.85`）**不做**。词法 + 光标是**代理信号**，
  够不着"用别的名字、又不用 not-allowed"的新形态——真正的闭合是全量登记，留 backlog 明写。
- **JS 内联 `opacity`**：`app.js` 一处（代码页隐藏输入层）与 SVG 属性（`fill-opacity` / `stroke-opacity`）
  不在样式块口径里，不在本轮射程。
- `backlog` §31/§32 的其余尾巴：叠加态定价、`--accent` 控件描边非文字 3:1、`.pin-subtitle` 的
  `var(--fg)` 笔误、两个图例色点的令牌归属。
- AI 相关路径（骨架 / 深化 / 推荐）零改动；后端零改动。
