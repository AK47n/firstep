# 工单：generate-conflict-guard（桌面同名工程冲突防护）

## 背景

多标签页 / 连点「生成」时，桌面模式 `unique_desktop_topic_dir` 会静默改名
（`Auto_Car` → `Auto_Car_20260825-000224`），一次点击攒出五六个半成品目录
（无 .out、无 modules，仅 6 个开局文件）；生成中途失败留残渣（非空目录
`OutputDirNotEmptyError` 拒绝覆盖，失败路径不清目录）。用户已确认方案。

## 决策

1. **不静默换名**：同名完整工程已存在 → 400 中文「请先删除或换题名」。
2. **同键互斥**：同名生成进行中 → 409 中文「正在生成中」（AppContext 共享
   注册表 + threading.Lock，跨标签页 / 并发请求生效）。
3. **残渣自愈**：目录存在但既无 `.contest_context.json` 也无 `main.c`
   （空 / 半成品）→ 清理后生成。
4. **失败清理**：桌面模式生成失败 → 删除本次目录，不留半成品（手动模式
   不清理——目录是用户显式指定的）。
5. **成功即聚焦**：生成成功后自动 `explorer.exe` 打开工程目录。

## 验收

- 已存在完整同名工程 → 400，目录内容原样未动。
- 生成中同名二次请求 → 409（不浪费第二次生成）。
- 半成品目录 → 清理重建，产出完整工程。
- 生成失败 → 桌面不留目录。
- 成功 → explorer 打开（可 mock）。
- 全量 pytest 绿；errors.py 登记新异常（结构测试兜底）。
