# 顶部导航 tab 分组与悬停说明（Y2）

> 来源：`docs/improvement-review-newcomer-onboarding.md`（2026-08-29）第二梯队 Y2「tab 分组」。
> 立项前已与用户确认 3 个设计走向（见「实现决策」）：两段分组标签形态 / 静态标记 + 文档守卫 / 8 个 tab 全部加 title。
> 与 `.scratch/newcomer-onboarding/`（第一梯队 R1/R2/R3）相互独立，互不依赖。

## 问题陈述

顶部 8 个功能 tab 平铺无主次：**生成 / 模块库 / 参考文件库 / PDF 资料库 / 赛题库 / 母版 / 更新记录 / 设置**。其中 5 个（模块库、参考文件库、PDF 资料库、母版、更新记录）是内容管理/维护页，纯新人做题全程用不到，还可能误入误操作；评审原文：8 个 tab 平铺无主次，「其中 5 个是库管理页，新手完全用不到」，是评审结论点名的核心缺陷之一。新人第一眼看不出「哪些 tab 是给我做题用的、哪些先别碰」。

## 方案

把顶部导航分成两段（组标签为非交互的弱化小字，组内按钮平铺、行为完全不变）：

- **做题**组：生成 / 赛题库 / 设置 —— 新手主路径（选赛题 → 生成 → 配置）。
- **资料管理**组：模块库 / 参考文件库 / PDF 资料库 / 母版 / 更新记录 —— 内容管理/维护页。
- 8 个按钮全部加 `title` 悬停说明（一句面向新人的话：这个页面是干什么的、什么时候用）。

## 用户故事

1. 作为纯新人，我想要导航按「做题 / 资料管理」分组，以便一眼看出哪些 tab 是我做题要用的、哪些先别碰。
2. 作为纯新人，我想要悬停任意 tab 有一句中文说明，以便不必点进去也能知道每页是干什么的、什么时候用。
3. 作为做题学生，我想要「生成 / 赛题库 / 设置」集中在同一组，以便主流程入口在导航左半区一眼可见。
4. 作为资料维护者或进阶用户，我想要模块库等 5 个管理页收纳进「资料管理」组，以便不干扰做题主流程，且仍可一键到达。
5. 作为二次使用者，我想要分组不改变原有 tab 行为（点击切换、激活态、分发加载、标签会话记忆），以便零回归。
6. 作为开发者，我想要文档守卫测试锁定分组与文案，以便日后有人误删/改动分组或 title 时 CI 能拦住。

## 实现决策

### 已确认的设计走向（用户选择）

- 分组形态：**两段分组标签**（非折叠/非下拉）。「做题」= 生成 / 赛题库 / 设置；「资料管理」= 模块库 / 参考文件库 / PDF 资料库 / 母版 / 更新记录。
- 实现与测试：**静态标记 + 文档守卫**。分组 = `index.html` 纯标记 + CSS + `title` 属性，零新增运行 JS；守卫测试读 `index.html` 锁定结构（照 `tests/js/tab-nav-guard.test.mjs` 先例）。
- title 覆盖：**8 个 tab 全部加**（不只资料管理 5 个）。

### 标记 / 样式

- 每组 = `<div class="tab-group" role="group" aria-label="做题|资料管理">`，内含组标签 `<span class="tab-group-label" aria-hidden="true">做题</span>` + 组内按钮（现有 `<button data-tab>` 原样保留）。
- 组标签**不可点击**（无 `data-tab`）——`nav button[data-tab]` 选择器绑定不受影响（`tab-nav-guard.test.mjs` 守卫的选择器字符串不动）。
- 组间视觉分隔：第二个组左侧细分隔线（`--border` 令牌，`::before` 或边框实现），组内按钮间距沿用现状。
- 组标签样式：`muted` 小字（复用 `--muted` 令牌），不做按钮外观（无背景/无 hover 高亮）。
- 激活态 / hover / focus-visible / 会话记忆（`TAB_ID_KEY`，app.js）全部不动。

### title 文案（中文，面向新人，每句一句话）

- 生成：主流程：粘贴赛题 → AI 推荐 → 引脚配置 → 生成工程 → 编译修复。
- 赛题库：历年真题（题面 + 附带程序），点「取题面」可一键填入生成页。
- 设置：配置 AI API key、环境体检、工具链路径与库设置——第一次使用先来这里。
- 模块库：管理可复用模块（查看 / 补录 / 编辑 / 删除）；做题时 AI 推荐自动匹配，一般不用手动操作。
- 参考文件库：套件例程 / 说明书等配套资料，生成时作学习素材；管理入口，做题用不到。
- PDF 资料库：素材根目录全部 PDF 的浏览与整理（含疑似重复清理）；管理入口，做题用不到。
- 母版：stm32 / mspm0 两平台基础工程浏览与体检；管理入口，做题用不到。
- 更新记录：本工具的更新日志（CHANGELOG）。

### 边界

- 只做分组与文案，不改 8 个 tab 的任何既有行为（顺序、激活、分发加载、会话记忆、进度条显隐）。
- 不做默认折叠 / 下拉收纳（用户选定两段平铺形态）；不做移动端抽屉导航。

## 测试决策

- **新增 `tests/js/nav-tabs-guard.test.mjs`**（node:test，`readFileSync` 读 `index.html`，仿 `tab-nav-guard.test.mjs` 先例）：
  1. 组标签：`「做题」`/`「资料管理」` 各恰好一个（按 `.tab-group-label` 锚定），组容器 `role="group"` + `aria-label` 正确。
  2. 键完整性：`nav button[data-tab]` 恰好 8 个，key 集合 = {generate, library, reference, pdf, topic, master, changelog, settings}，无多余/缺失；组归属正确（做题组 3 个、资料管理组 5 个，按 `.tab-group` 容器锚定）。
  3. 组标签不可点击：`.tab-group-label` 不含 `data-tab`（防回退成按钮）。
  4. title 覆盖：8 个按钮均有非空 `title` 且长度 ≥ 8（防「占位半句话」）。
- **既有 `tests/js/tab-nav-guard.test.mjs` 必须继续绿**（选择器字符串未变）。
- 其余前端 node:test 全套回归；本特性零后端改动，pytest 跑一次确认无意外。
- 人工验收：8 tab 切换正常、组标签点击无反应、悬停 title 显示、窄屏不破、启动器模式标签会话记忆不回归（切 tab 后刷新恢复原 tab）。

## 范围外

- Y3 迷你词表（术语解释）、Y4 交接提示词「无需外部 AI」说明——另立项。
- 默认折叠 / 下拉收纳 / 抽屉导航——已明确不做（用户选定两段平铺）。
- 不改 8 个 tab 的既有行为；不改 `TAB_ID_KEY` 会话机制。
- 不做导航排序调整（组内顺序 = 现状顺序）。
