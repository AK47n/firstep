# 02 — MQ 系九件的词表说明口径统一（映射方向 + 预热时长）

**要做什么：** 学生在选购方案里读到 MQ 系九件（mq2 / mq3 / mq4 / mq5 / mq6 / mq7 / mq8 / mq9 /
mq135）的气体传感器说明时，**同一件事的说法一致**——不因为选了哪一件而读到不同口径。

**被谁阻塞：** 无——可立即开始。

**状态：** ready-for-agent

## 现状（实测）

`src/contest_generator/wordlist.json` 感知传感器组的九条 `solutions[].note`：

| 件 | 「正向映射」 | MEM0 共读限制 | 预热写法 |
|---|---|---|---|
| mq3 / mq4 / mq6 / mq7 / mq8 / mq9 | ✅ 有 | ✅ 有 | 「预热 **3-5 分钟**」 |
| mq2 | ❌ 缺 | ❌ 缺（它正是共享 MEM0 的那一件） | 「预热（**几分钟级**）」 |
| mq135 / mq5 | ❌ 缺（不共享 MEM0，独立 MEM4/MEM5——这条缺得有理由） | ❌（同上，有理由） | 「预热（**几分钟级**）」 |

**同一份证据支持九件同口径**（各件手册/页面原文，`library/references/气体传感器器件手册合集-气体/mq-*.md`）：
「…传感器的电导率随空气中<气体>浓度的增加而增大」→ 分压输出随浓度升高 → ADC 值越大 →
`percent = value/4095×100` 越大 = **正向映射**（九件代码同一式子，见各件 `code/*.c`）。

## 验收标准

- [ ] mq2 / mq135 / mq5 三条 note **补上「正向映射」**（依据写进本票；纯补齐，不删既有信息）。
- [ ] mq2 那条补上「**多路气体同选共读 MEM0 物理通道限制**：每路只能接一个器件到 PA24」
      （它确实与 adc/us016 共读 MEM0——缺的是这一句）；mq135 / mq5 是独立 MEM 通道，
      **不补**这一句（它们已有"与 mq2 的 MEM0 薄封装不同"的对照说明）。
- [ ] 预热写法统一成同一句（九件一致）。
- [ ] 库数据守卫：`python -m pytest tests/test_wordlist.py tests/test_manifest.py -q` 全绿；
      **预算守卫必须仍绿**（词表进推荐提示词：`WORDLIST_PROMPT_BYTES` 余量、瘦身行预算那两条），
      改完把余量数字记进票尾。
- [ ] 一条不变量判据（新用例，形状照 `tests/test_hwcheck_console.py` 那族）：
      **声明了 `read_percent` 类换算的 MQ 系方案，note 里必须写明映射方向**——
      新加一件 MQ 系器件忘了写 → 红。（判据面只到 MQ 系，别扩成全库。）
- [ ] 反证探针：把三条里的一条改回"无方向" → 新判据红；逐条声明 + 对账 + 复原 sha256 逐字节。
- [ ] 读数落盘：定向 + 全量 `python -m pytest -n auto -q`。

## 备注

- 词表是**库数据**（`src/contest_generator/wordlist.json`）：改它要跑预算守卫，且**不许让
  `WORDLIST_PROMPT_BYTES` 余量见底**（§5.3 记过 mspm0 最坏形态余量曾只剩 378 B）。
- 本单**不动**任何模块代码（`library/modules/mq*/**` 只读不改）——措辞问题只在词表这一层。
