# spec — backlog 收尾：界面体量声明说实话 + MQ 词表口径统一 + 解包走共享原语

**立项依据**：`.scratch/backlog.md` 全盘复核后**真还开着的三条**（用户指令：把剩下的做了）。
其余条目要么已 resolved、要么是人为阻塞（真机项 / 人工取源）、要么是 spec 里明确划走的边界——
逐条在「范围外」记账，不再当待办。

## 问题陈述

三件事各自都小，但都有人被咬：

1. **更新面板上的体量是已下线渠道的数字**：产品界面写「不用重下 **6.2 GB** 完整包」——
   那个 6.2 GB 是**已下线的 7z 分卷形态**（v1.0.0 的事），现在的完整包是 **792 MB**、
   轻量更新包 **302 MB**。学生据此判断"要不要更新"时读到的是十倍的量级。
   同一面板还有第二处不实：资料库写「**5 GB+**、几 GB 级更新」——实测装完的资料库
   **≈0.67 GiB**（5066–5088 文件）；"5 GB 以上"那句在 README 里指的是**故意不进包的
   第三方安装件**（CCS 安装包 / K230 资料 / VSCode），被混成了资料库的体量。
   根因不是写错一次，而是**守卫扫不到产品界面**：`tools/check-download-docs.py`（发版前自检）
   与 `tests/test_onboarding_docs.py`（测试期门禁）都只扫 README 与 Release 说明。
   顺带实测到守卫自身一个**假阴性**：否定式回看跨了分句（`…不用手动下分卷、需要装 7-Zip`
   里的「不用」正好落在窗口内，把真推荐当成提醒放过去了）。
2. **MQ 系九件的气体传感器说明口径不齐**：同一族（同一换算公式、同一页面证据）的九条词表
   说明里，只有六条写了「**正向映射**（浓度越高 ADC 值越高）」，mq2 / mq135 / mq5 没写；
   预热时长的写法也在「预热（几分钟级）」与「预热 3-5 分钟」之间摇摆。学生选到哪一件，
   读到的口径就不一样。
3. **解包那只固定临时名还留着**：`materials_apply._extract_zip` 逐条目先写
   `<目标名>.update-tmp` 再 `os.replace`——**固定名 + 无 `finally`**：两个写者（或一次中断）
   会互抢同一个临时名、失败还会在资料库里留下 `.update-tmp` 残渣。它是 `record-write-hardening`
   批明确"没修"的站点之一（当时理由是"解包被更新任务锁串行化、风险低一档"）。

## 方案

1. **界面文案按实测数字写**（完整包 ≈ 792 MB / 更新包 ≈ 302 MB），并把「已下线渠道 / 体量离谱」
   这条判据从 README 扩到**产品界面文本**（`static/index.html`），测试期就能红，不必等发版自检。
2. **MQ 系九条词表说明补齐口径**：三条缺「正向映射」的补上（依据 = 同一份页面/手册证据：
   "电导率随浓度增加而增大" → AO 电压随浓度升高 → ADC 越大百分比越高）；预热口径统一成
   **手册支持的措辞**（手册只说「使用之前必须加热一段时间」，**没有时长**——初稿写成
   「3-5 分钟」被评审抓到是 `ms1100.md` 的数字串台，已退回）。
   **词表方案 note 不进提示词段**（`format_wordlist_prompt` 只发类别/型号/方案名），
   所以补字对段级预算零影响（实测词表段 10994 B / 预算 12150 B）。
3. **给共享原语加"写字节 / 流式写"入口**（`atomic_write_bytes` / 内部 `_atomic_replace` 收口），
   `materials_apply._extract_zip` 改走它（唯一临时名 + `finally` 清残渣）；结构守卫的例外清单里
   那条按棘轮删掉。
4. **`entry_store.write_json` 只核实、不改**：它是条目目录内的裸写，靠目录级事务兜底——
   本次把"为什么不动"写成可核对的账（读 `entry_transaction` 的实现作证），不新增机器。

## 用户故事

1. 作为学生，我在更新面板里看到的完整包体量是**真的**（几百 MB 级），不是已下线渠道的 6.2 GB。
2. 作为维护者，产品界面里的下载体量声明**有机器盯着**——再写回已下线渠道的写法，测试期就红。
3. 作为学生，MQ 系九件气体传感器说明口径一致（映射方向、预热时长都写同一套），
   选哪一件读到的说法都一样。
4. 作为维护者，资料库解包失败**不留 `.update-tmp`**，两个写者也不互抢同一个临时名。
5. 作为维护者，`entry_store` 的裸写"为什么可以不动"有据可查（不是我忘了）。

## 实现决策

- **文案**（`static/index.html` 更新面板三行，实测真值）：
  - 「不用重下 6.2 GB 完整包」→「不用重下完整包（约 800 MB）」；
  - 资料库那行的「5 GB+」+「几 GB 级更新」→「约 0.7 GB / 5000+ 个文件」+ 去掉"几 GB 级"；
  - 完整包下载那行的「约 1 GB」→「约 800 MB」（实测 792 MB）。
  - 判据：界面里与「完整包 / 资料库」同行的 GB 数字 **≥ 2** 即红（真值都 < 1 GB；
    2 GB 是"混进了别的量"的粗线——6.2 GB 与 5 GB+ 两处都会被它抓到）。
- **守卫面**：`tests/test_onboarding_docs.py` 已有 `dead_channel_hits`（否定式回看那套）。
  本次把它**同一份判据**用到产品界面文本上，并新增一条体量判据：
  界面里凡出现「完整包」的那一行，若同行的 GB 数字 ≥ 2 → 红（真值 < 1 GB；十倍级错法一次抓住）。
  README 侧判据不动（`tools/check-download-docs.py` 是它的发版前孪生，两处口径照旧保持一致）。
- **词表**（`src/contest_generator/wordlist.json`）：只动 mq2 / mq135 / mq5 三条的 `note`
  与预热写法，**纯补齐**（不删既有信息、不新增方案、不动 `lib_modules`）；
  依据写进票里（页面/手册原文），改完必跑词表与预算守卫。
- **原语**（`src/contest_generator/atomic_io.py`）：把"临时名 + 换入 + 清残渣"抽成一个内部
  `_atomic_replace(path, write: Callable[[Path], None])`；`atomic_write_text` 与新增的
  `atomic_write_bytes` 都走它。`materials_apply._extract_zip` 用流式入口（`shutil.copyfileobj`
  不能改成"先读进内存"——资料库里有大文件）。
- **不动**：`recent_jobs` / `codeview`（各自已是正确实现，白名单在案）。

## 测试决策

- **好测试 = 只测外部行为**：文案判据取**界面文本里那句话**（不是"某文件被改过"）；
  词表判据取**九条 note 同时成立的那条不变量**（不是逐字快照）；解包判据取
  **最终盘上有没有残渣 / 内容对不对**（不是临时名形状）。
- **先例**：`tests/test_onboarding_docs.py`（README 下载渠道门禁，本批把同一判据扩到界面）、
  `tests/test_hwcheck_console.py`（库数据一致性守卫的形状）、`tests/test_atomic_io.py`
  （原语的原子性/残渣判据）、`tests/test_materials_update*.py`（解包既有行为）。
- **反证**：文案与词表两条各一条探针（把修撤掉 → 对应判据红，逐条声明 + 对账）；
  解包那条按 `record-write-hardening` 的口径做（撤唯一临时名 / 撤清残渣 → 红）。
- **闸门**：文案那条动 `static/` → **必须**跑前端门禁与浏览器门禁（`index.html` 在浏览器门禁落点里）；
  其余两条只跑后端。

## 范围外

- **真机上板类**（`hwcheck-acceptance/05`、`hwcheck-hardening/08`、§5.5 的「77 条目未上板验证」）：
  本机没有板子，机器代不了。**不属于本批**。
- **硬件身份字段 6 slug / 11 条**（`identity-fields/06`）：要用户给"实际买过那件实物"的链接，
  三轮实测取不到可核实出处。**不属于本批**。
- **跨进程并发**（本应用单进程）、**强杀残留清扫**、**母版"目录换入 × 删 meta"窄缝**：
  `record-write-hardening` spec 已明确划走/已承认为残留，本批不翻案。
- **C7「73 个私有符号公开化」**：它是量"测试还翻不翻墙"的**尺子**，不是功能（backlog §15 已拍板）。
- `entry_store.write_json` 的**改**：本次只核实与记账（见实现决策第 4 条）。

## 补充说明

- 本批不动用户可见的**功能**行为，只动：界面上一句话的数字、库内三条说明、解包那只临时名。
- CHANGELOG 预期：「更新面板体量声明改说实话」这一条是**用户可见**的（发布说明该点名）；
  另两条是内部加固/库内容，可不单列。
- 记账纪律：做不动的三类（真机 / 人工取源 / 明确划走的边界）要在 `backlog.md` 里
  **写清"为什么不是待办"**，免得下一轮又当新发现重开。
