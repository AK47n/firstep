# spec — 沙箱真机演练：v1.1.1 → v1.2.1 升级 + 断网极端场景 + 完整包换装

## 问题陈述

三件"只差真机"的事挂在这台机器上：

1. **沙箱「模拟用户机」还停在 v1.1.1**（`local-environment.md` 第 1 节自记），而线上已经是 v1.2.1——**没有一台机器真的从旧版升上来过**。今天的 v1.2.1 是照流程发出去的，升级链路本身没走过。
2. **G1 后三步（极端场景）一直没做**：弱网中途取消 / 断网重试 / 故意改坏一个卷制造校验失败——`.scratch/real-acceptance/issues/01` 里勾选状态是空的，理由写着"代码侧已由自动化覆盖"。代码侧覆盖不等于真机覆盖：半成品文件留没留、边车写没写、中文报错对不对、旧版本还能不能用，这些只有真跑才看得见。
3. **编码钉「真解决了乱码」目前只是推断**。今天发 v1.2.1 时我只能证明"两个文件在包里"——**CCS 读不读它、乱码问题是否真的消失，没有任何实测**。生成工程里那两个文件的落点是生成器行为，可以直接验。

另外，完整包换装（档③）此前用 `verify-07-tier3-e2e.py` 验过 v1.1.1，但那是**复用本机已下过的 zip**（脚本里明写"未重新下载"）。真实用户第一次装是**从线上真下 802 MB**，这一格没有在 v1.2.1 上重验过。

## 方案

在沙箱与一次性工具根上跑一轮**真机演练**，判据全部落在真实产物上（真线上包、真字节数、真 sha256、真端口、真进程），并把可复跑的脚本与原始证据留在 `.scratch/`：

- **升级**：沙箱 `Desktop\firstep-sim`（v1.1.1）走产品自己的小发版更新（305 MB，线上真实 Release）→ 替换 → 重启 → 判据 = **跑起来的服务 `GET /api/health`.version == 1.2.1**（不只看盘上文件）。
- **极端场景**：三个场景各有"产品行为"判据，全部在真实下载任务上跑（真实字节流，弱网/断线由本地可控服务器制造）：
  - **中途取消**：半成品与 `.partial.json` 边车留在 `updates/`（不是被删）、任务状态 `cancelled`、工具仍可用；**再点重试从已下字节接着下**。
  - **断网重试**：连接被切断 → 自动重试（`retry_count` 增长、话术说明"正在自动重试"）→ 网络恢复后**续传完成**，终态字节数与 sha256 都对。
  - **校验失败**：改坏一个卷 → 报**中文**错误且指明校验失败、半成品被清、**旧版本仍可用**（服务还能起来、版本还是旧的）、备份目录在、`updating.lock` 已释放。
- **完整包换装**：一次性工具根（`USERPROFILE` 重定向隔离）上**从线上真下 802 MB** → 校验 → 替换 → 重启 → 判据 = 服务版本 1.2.1 + 资料库基线写回 + 第三方安装包未被动过 + 真身零触碰。
- **编码钉落点**：在沙箱生成一个 mspm0 工程（真调生成链路），断言产物里有编码钉文件与内容——**把"修复有效"从包内文件存在升级到生成产物存在**。

## 用户故事

1. 作为已装 v1.1.1 的用户，我希望点「检查更新 → 一键更新」就能到 v1.2.1，以便不必重下 802 MB 完整包。
2. 作为升级中的用户，我希望工具停服、备份、替换、重启全程不需要我操作，且我的 key / 任务 / 资料库原样保留，以便升级不丢数据。
3. 作为网络不稳的用户，我希望中途取消后已下的部分还在，重试时**从断点接着下**而不是从 0 重来，以便不白烧流量。
4. 作为网络不稳的用户，我希望断线时工具自己重试（有明确话术），恢复后能续传完成，以便不必盯着进度。
5. 作为遇到校验失败的用户，我希望看到**中文**说明「这个包坏了、重下也不会有变化」并知道旧版本还能用、备份在哪，以便不被吓到也能自救。
6. 作为第一次安装的用户，我希望从线上下的完整包能一次装好、资料库基线一并写回、以后只收增量，以便不必再摸完整包。
7. 作为生成 CCS 工程的用户，我希望产出的工程带着 UTF-8 编码钉，以便中文注释在 CCS 里不乱码。
8. 作为维护者，我希望这一轮演练**可复跑**（脚本 + 原始输出留档），以便下次发版照跑而不是重新摸索。

## 实现决策

- **脚本落点** `.scratch/verify-gate-drills/`（本特性工单区，与既有 `.scratch/full-download/`、`.scratch/resumable-download/` 同族，不进发布包）：
  - `drill-01-upgrade.py`：沙箱小发版升级（线上真实 Release → 8020 → 版本判据）。
  - `drill-02-degraded.py`：三极端场景（本地可控服务器造弱网/断线；真实字节；产品下载任务与端点）。
  - `drill-03-full-pack.py`：一次性根真下 802 MB 完整包 + 换装 + 隔离校验（骨架照 `verify-07-tier3-e2e.py`）。
  - `drill-04-encoding-pin.py`：沙箱生成 mspm0 工程 → 断言编码钉在产物里。
- **复用而非重写**：隔离手法（`USERPROFILE` 重定向 + 一次性工具根 + `tree_stamp` 真身未变判据 + 收尾收端口）照 `verify-07-tier3-e2e.py`；本地可控服务器照 `.scratch/resumable-download/sim-server.py`（六种行为、`--port 0` 内核分配）；沙箱重建照 `.scratch/full-download/make_sim_sandbox.py`。
- **端口纪律**：沙箱 8020；真身 8000 **只读**（今天探测它没在跑，演练不得把它拉起来当靶子）。收尾查 8000/8020 监听 + 残留 python 进程 + 真身数据目录 mtime。
- **不做假**：不使用 `--reuse-package` 之类捷径冒充"真下载"——完整包那一格必须真下载；小发版那一格也真下载。缓存只允许用于"同一份字节的 sha256 复核"，且要在证据里明写。
- **失败照记**：任何一格不成立 → 原始输出照贴 + 如实记账（不许写成"基本通过"）；发现的产品缺陷按 `docs/agents/issue-tracker.md` 开工单，不在演练脚本里就地改产品。

## 测试决策

- 演练脚本自身**不进 pytest**（要真网络、真端口、几分钟级），与既有的"真机验收脚本"同口径：**证据 = 原始 stdout**，收尾写 `verify-*.txt` / `.json`。
- 每个场景的判据必须是**产品可观察量**：`/api/update/*/status` 的字段与状态、`updates/` 下的文件与边车、`/api/health` 的版本、更新器日志行、备份目录内容——**不读内部变量、不 import 私有函数**。
- 每格配超时并把"卡住"与"红"分开记（沿用 `run-11-suite.py` 的口径）。
- 编码钉那一格的判据 = 生成产物里的文件存在 + 内容含 `encoding/<project>=UTF-8`（`test_master_template_config.py` 同判据），**并且**说明"这证明的是落点，不是 CCS 实际读取行为"——不在证据里外推。

## 范围外

- **不在真机验 CCS 打开工程后注释是否真的不乱码**（这台机器没有可交互的 CCS 工作区实测条件；结论只到"编码钉随生成工程落盘"）。
- 不重跑模块推荐 / 骨架生成的 LLM 链路（烧额度，与本特性无关）。
- 不修演练中发现的产品缺陷（另开工单）；不重打 v1.2.1 的任何包（已发布）。
- 不动沙箱的既有"故意不真实"两处（`__init__.py` 起版号、无 `.venv`）——它们是下次还能重演升级的前提。

## 补充说明

- 这一轮做完，`local-environment.md` 的第 1 节（沙箱状态）、第 0/3 节（落差）与 `.scratch/real-acceptance/issues/01` 的 G1 勾选要**当场更新**（纪律见该文件开头）。
- 若三极端场景暴露产品问题，它们比这一轮演练本身更有价值——那才是"真机演练"的目的；届时按缺陷开工单并**在本轮如实记账**。
