# Spec — 引脚自动配置（pin-auto-assign）

## 问题陈述

生成第 7 步引脚配置：用户手动点选引脚，冲突（定时器实例、EXTI 同线、UART 实例、共享宏值不同等）要到生成前才 400，用户得自己排查挪线。需求：一键"自动配置"——算法把**真冲突**的角色重新分配到不冲突的引脚，**合法共享保留**（I2C 总线多设备同挂等，电气上必须共用），结果回填板图可再手动调。

## 方案

第 7 步加「自动配置」按钮 → 后端确定性求解 → 返回新绑定 + 冲突说明 + 共享标注 → 前端应用并重绘。

**冲突定义（只解这些）**：复用 `resolve_bindings` 的校验面（与 /api/bindings/validate 同源）——能力不匹配 / UART TX-RX 成对约束 / mspm0 槽位互斥 / 类型级实例约束。**合法共享（保留 + 标注）**：同引脚多角色共享（ADR 0010 允许，如 I2C SCL/SDA 总线多设备、巡线传感器共读、UART TX/RX 同实例）——拆了反而编译不过/功能坏。TIM/EXTI/UART 实例级冲突属生成门禁（需 main_c 上下文，第 7 步判不了），不在本功能范围（自动配置后仍有生成期门禁兜底）。

## 用户故事

1. 作为用户，我在第 7 步点「自动配置」，冲突角色被自动挪到不冲突的引脚，板图/角色列表更新，可继续手动微调。
2. 作为用户，合法共享（I2C 总线、传感器共读）不被拆开，界面上有"共享"标注说明原因（如"I2C 总线：MPU6050/HMC5883L 同挂 SCL/SDA，协议允许"）。
3. 作为用户，我手动绑过的合法绑定和未冲突的默认脚保持不变（只动冲突的）。
4. 作为用户，无冲突时点自动配置 = 原样返回（说明"当前无冲突"）。
5. 作为用户，引脚不够/无解时收到明确中文说明（缺什么能力/引脚耗尽），不强求成功。

## 实现决策

- 求解器 `auto_assign_bindings`（pin_bindings.py，resolve_bindings 同文件共享能力判定/校验）：
  - 输入：{platform, slugs, bindings（用户当前绑定）}；输出：{bindings 增量（只含改动）、fixed 说明、shared 标注、error?}
  - 流程：resolve_selection + board_for_platform（与 validate/generate 同源）→ 收集全部角色（含默认脚）→ 锁定合法绑定（用户绑定 + 默认脚，逐个验证）→ 冲突角色进入候选池 → 贪心分配（能力匹配 + 未占用 + 整体 resolve_bindings 验证通过）→ 无解报中文说明
  - 共享标注：同引脚多角色共享的合法组（I2C 总线 / 同脚多角色）→ 输出 shared 列表（引脚 → 角色组 + 说明词）
- 端点 `/api/bindings/auto`（webapp，照 bindings_validate 先例）：{platform, slugs, bindings} → {bindings?, fixed?, shared?, ok:true} 或 {ok:false, error}
- 前端：第 7 步加「自动配置」按钮（pin-auto 区，与"全部还原默认"并列）→ apiPost → 应用新绑定（pinBindings 合并/替换）→ 重绘板图 + 显示结果说明条（"已自动调整 N 处冲突：… / 保留共享：…"）
- 幂等/安全：自动配置不落盘、不持久化（随请求走，与现有绑定同生命周期）；不改变 resolve_bindings / 门禁语义

## 测试决策

- 求解器单测（test_pin_bindings）：I2C 共享保留 / TIM 冲突重分 / EXTI 同线重分 / 用户合法绑定不动 / 无冲突原样 / 无解报错
- 路由集成（test_webapp）：/api/bindings/auto 契约 + 与 validate 同源
- 结构钉：前端按钮 + 调用点存在（tests/js）

## 范围外

- 不引入 AI（确定性算法，用户已确认）。
- 不做"全部重排"（保留原则已定：只动冲突）。
- 不改共享合法语义（ADR 0010 不动）。
- mspm0 跨族迁移等高级场景：算法只做"换引脚 + 实例一致"，不做族迁移渲染（pin_family.h 现有机制不变）。
