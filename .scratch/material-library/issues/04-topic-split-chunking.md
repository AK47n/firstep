# 04 — 拆条分块：长 PDF 分批拆（治 flash 模型静默漏题）

**What to build:** `/api/topics/split` 对多年真题长 PDF（如 2017-2025 汇总，163K 字符 ≈ 8 万+ tokens）不可用——flash 模型输出预算小（实测加 `max_tokens=8192` 仍截断），一年 8 题只回 2-3 题且输出仍是合法 JSON，解析器放行 → **静默漏题无感知**。把已验证的确定性切分方案产品化：上传 PDF → 按年份章节切块 + 按标题标记（"（X 题）" / 行首 "X 题："）切到单题 → 分批调 LLM 拆条（或纯确定性切分）→ 合并草稿。拆条 UI（工单 05）依赖本工单。

**已验证的方案**（2026-08-08 真机，`.scratch/real-run/topic_split_by_year.py`，69/69 全对）：
- 年份章节边界：`20(1[7-9]|2[0-5])[ ]*年` 标记，同一年变体（"2017年"/"2017 年"）按数字归组，取"到下一年距离最大"的出现为章节起点（封面/页眉只有几百字符，章节跨度天然最大）；
- 题目标记：`[（(]\s*([A-H])\s*题\s*[)）]|^([A-H])\s*题[：:]`（MULTILINE）——只认括号式/行首式，正文里的"停止条件"类误匹配全排除；同字母去重取首次；
- 题面 = 标题行起点到下一题标题行的**原文段落**（零 LLM 改写，比 AI 抽取更忠实，含评分标准表）；每年最后一题含该年尾部杂项（评分汇总/页脚），需在校对阶段可修剪；
- 2017 缺 D/G、2020 缺 H——PDF 本身没有，不是切分错误（每年 6-8 题）。

**要求：**
- 分块逻辑进 `topic_library.py`（`split_topics_document` 之类，输入全文 → 输出分块草稿），webapp `/api/topics/split` 改走新流程（或保留单次路径、超长自动分块——实现取舍自定，写明理由）；
- 分批调 LLM 时：每批 ≤ 一年（或一题），失败批单独报错不拖垮全量（参考 413 预算政策的分批风格）；
- 超长判定阈值：参考实测 163K 全量必截断，单块 ≤ 20K 字符左右安全；
- 测试：假文本 fixture 覆盖（多年变体年份标记、括号式/行首式/正文误匹配、同字母去重、缺题年份、最后一题含尾部杂项）；真机验证用现有真题 PDF 重跑拆条对比 69 条；
- 不得改变 `confirm_topics` 契约（草稿形态不变：year/number/problem_text）。

**Blocked by:** 01 — 赛题库录入（确认/解析流程复用）

- **取舍（工单允许"分批调 LLM（或纯确定性切分）"，选纯确定性）**：`/api/topics/split` 按全文长度分流——≤ `TOPIC_SPLIT_LLM_CHAR_CAP`（20K 字符）单次调 LLM 拆条（既有路径，任意格式，单题短 PDF）；超长走确定性分块。不选"分批调 LLM"的理由：flash 输出预算截断是根因（实测 max_tokens=8192 仍断），大年份 8 题 ≈ 20K 字符输出仍超预算——块变小只是缩小不消除漏题；确定性切分无输出预算问题，且 2026-08-08 真机已验证 69/69 全对（`.scratch/real-run/topic_split_by_year.py`），题面 = 原文段落零 AI 改写正是工单要求的形态。代价：非标准格式长 PDF 无法自动拆 → 大声失败给可操作提示（宁可不拆，不静默漏题）。
