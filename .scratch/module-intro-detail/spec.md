# spec — 推荐区模块「详细说明」（module-intro-detail）

## 问题陈述

AI 推荐结果里，每个命中模块只显示 slug 加一句推荐理由，而推荐理由是**对照题面**写的
（如 ir_beam 的「可选点/起始做辅助」）。不懂这个模块的学生看到 slug + 短线代号，
不知道它**到底是个什么东西**：是传感器还是驱动？量什么？怎么接？只能到模块库页
翻，而模块库卡片上的简介又被截断到 26 字（`.mc-desc`），点开详情也仍然只有一句
给 AI 看的简介（「ir_beam_init / ir_beam_read 按光束遮挡返回 0/1」——一上来就是
函数名）。

也就是说：**「它是什么」这一层事实，在用户第一次遇到这个模块名的地方（推荐区）
不存在；唯一存在的长文入口在模块库页，且内容对新手不友好。**

## 方案

两条腿，缺一不可：

1. **推荐区每个模块名旁边都有「这是什么」入口**：推荐 chip、功能组选择卡成员行、
   已选模块行三处都能点开模块详情弹窗，弹窗里先回答「这是什么 / 怎么接 / 怎么用 /
   什么时候用」四问，再回答「为什么推荐它」（把推荐理由带进弹窗，chip 上的短线
   代号在弹窗里有上下文）。
2. **简介本身改写成能看懂的口语顺序**：`manifest.description` 保持单源（不新增
   字段，零漂移），但按固定四拍书写——① 这是什么东西、量什么／② 怎么接线（线制、
   占几个脚、脚在哪）／③ 怎么用（init/read 函数、返回什么、默认极性）／④ 什么时候
   用（适用赛题功能）。前端按标点与词法把这段简介**拆段**渲染成四个小标题，用户
   不用读一坨字。

## 用户故事

1. 作为不懂 ir_beam 是什么的学生，我想要在推荐结果里就地看到「红外对射传感器：一对
   红外发射管和接收管相对安装……」这样的说明，以便不用去猜 slug 的含义。
2. 作为要买件／接线的人，我想要说明里直接写清「三线制 VCC/GND/OUT，只占 1 个 GPIO，
   默认 PA8」，以便照着接。
3. 作为要写代码的人，我想要说明里写清接口（`ir_beam_init` / `ir_beam_read`，1=遮挡、
   0=无遮挡），以便不用翻源码就敢调用。
4. 作为已经看过 chip 上推荐理由的人，我想要弹窗里同时保留那句理由，以便知道 AI 是
   按题面哪一点挑的它。
5. 作为用户，我想要在功能组选择卡、已选模块清单里也能点开同一份说明，以便在换选／
   复核清单时不用回推荐区找。
6. 作为用户，我想要弹窗里还能看到默认引脚表、源码文件与购买链接，以便接线与采购
   一次看全。
7. 作为维护者，我想要简介仍然只有一处（manifest.description），以便模块库页、AI
   摘要行、推荐区说明不会各说一套。
8. 作为维护者，我想要新写法有测试守卫，以便后续补录的模块不会退回「函数名开头」。

## 实现决策

- **不改 manifest 模型**：不新增 `intro` 之类的字段。理由 = 简介判据已有四要素
  （与代码一致 / 硬件身份 / 能力方向 / 无题绑定），且摘要行（喂 AI）、缓存指纹、
  结构守卫、参考关联全部以 `description` 为单源；新增同义字段 = 两处会漂移。
- **新增后端域模块**：描述 → 分段讲解的机械拆段（标点切句 + 词法分类），输出
  `[{label, text}]`。`GET /api/modules` 每条投影 `intro` 键（与 `kind` /
  `requires_identity` 同款投影风格：判据在后端，前端只渲染）。
- **前端只渲染不知道规则**：`moduleInfoHTML` 在简介之后渲染分段块；分段缺失（旧
  载荷无 `intro`、或简介为空）时回落为原样一句简介——旧载荷零变化。
- **入口复用**：不新造弹窗。三处入口统一走 `openModuleInfo(slug, platform, reason)`；
  推荐区/组卡/已选行的按钮用事件委托（`data-mod-info`），渲染函数保持在 fx 层。
- **chip 交互不变**：点 chip 本体仍是「从工程里移除这个模块」；说明按钮是 chip 上的
  独立小按钮（`?`），点它不走移除。
- **不推荐理由不失真**：弹窗里的「为什么推荐」只在调用方确实有推荐理由时渲染
  （模块库页打开时没有理由，不渲染该段，也不编造）。

## 测试决策

- 最高既有接缝：`tests/`（pytest）与 `tests/js/`（node:test）**两层纯函数单测**，
  都不碰 DOM / 网络——先例：`tests/js/module-info-dialog.test.mjs`、
  `tests/test_library_invariants.py`。
- 后端测：拆段纯函数的分类与顺序（四拍各自归位、空/单句/无标点容错）、
  `/api/modules` 投影带 `intro`。
- 前端测：`moduleInfoHTML` 渲染分段标题与全文、无 `intro` 时回落、`data-mod-info`
  按钮出现在 chip/组卡/已选行（字符串断言）、`generate-recommend.js` 委托接线断言。
- 库测：pilot 模块简介满足四拍顺序守卫（防止回退）；不新增全库强制（存量简介
  分批重写，见「范围外」）。

## 范围外

- **全库 60+ 简介一次性重写**：本单只精写推荐链路高频／易误解的一批（含 ir_beam），
  其余模块沿用现有简介——它们同样能点开说明（拿到全文 + 接口 + 引脚），只是暂无
  四拍分段标题。后续按批次补写。
- **AI 生成按题面定制的说明**：不做。说明必须是库内事实，AI 生成会引入幻觉且每次
  推荐都要多花额度。
- **模块库页卡片截断长度调整**：`.mc-desc` 的 26 字截断不在本单（详情弹窗已经是
  全文入口）。

## 补充说明

- 分段标题固定四问，顺序固定：`这是干什么的` / `怎么接线` / `怎么用（接口）` /
  `什么时候用`；落不进四类的句子归入末段 `其它说明`（不丢信息）。
- 四拍书写规范写进 `CONTEXT.md` 的「简介」行（判据⑤），并在结构测试里对 pilot
  模块钉住。
