feat(模块说明): 推荐区模块名旁「说明」入口 + 简介四拍改写（工单 module-intro-detail/01-04）

痛点：推荐结果里每个命中模块只显示 slug + 一句对照题面的推荐理由（如 ir_beam 的
「可选点/起始做辅助」），不懂这个模块的学生不知道它到底是个什么东西；唯一的长文
入口在模块库页，且简介首句就是函数名（ir_beam_init / ir_beam_read 按光束遮挡返回
0/1），对新手仍然不友好。

做两件事，都不新增文案字段（简介仍是 manifest.description 单源）：
1) 后端按四问机械拆段：新增 module_intro.intro_sections（标点切句 + 词法分类 →
   这是干什么的 / 怎么接线 / 怎么用（接口） / 什么时候用 / 其它说明兜底），
   GET /api/modules 每条投影 intro；零丢信息不变量 = 原简介句子多重集 = 各段句子
   多重集（段间按四问固定顺序重排，故不是拼接逐字相等）。
2) 前端三处入口点开说明弹窗：推荐 chip、功能组选择卡成员行、已选模块清单行——
   分段讲解 + 「为什么推荐它」（chip 上那句短线代号在弹窗里有上下文）+ 既有引脚表 /
   源码文件 / 购买链接。入口统一 data-mod-info + 容器级事件委托（重绘后仍有效），
   说明按钮在 chip 内必须 stopPropagation（否则点说明会顺手把模块移除）。
   pilot 批次 9 个模块（ir_beam / sr04 / servo / step_motor / led / beep / pid /
   xunji / ws2812）简介按四拍口语顺序重写，接口名逐个对源码核过。

实测修正：首句若让词法覆盖，93 个模块里 57 个的首段标题会变成「怎么用」（存量简介
把定义与接口压在一句）；「检测/识别/显示」这类弱词当场景判据会让 80/93 个模块都带
「什么时候用」段——两处都已改口径并写进代码注释与工单记录。

测试：pytest 4161 passed（新增 tests/test_module_intro.py 125 条：分类 / 顺序 / 容错 /
全库零丢句 / API 投影 / pilot 四拍守卫）；node --test 1481 passed（新增
tests/js/module-intro-detail.test.mjs 11 条：分段渲染 / 回落 / 转义 / 三处入口接线）。
未做真浏览器点击（仓库无 playwright），运行时行为由静态接线断言 + 审读覆盖。
