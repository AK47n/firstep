# 01 — 简介拆段：后端出「四问」分段，/api/modules 投影 intro

**要做什么：** 前端拿到任一模块（`GET /api/modules` 一条）就能渲染四段讲解
（这是干什么的 / 怎么接线 / 怎么用（接口） / 什么时候用）——分段由后端从
`manifest.description` 机械拆出，前端不做规则判断。

**被谁阻塞：** 无——可立即开始。

**状态：** resolved

- [x] 新增后端域模块（简介 → 分段讲解）：标点切句（`。`/`；`/换行/`!`/`?`，英文
      句点仅在后随空白时切断，避免切坏 `HX711_GAP_VALUE` 之类标识符），按词法分类
      到四类，输出有序 `[{label, text}]`。
- [x] 分类判据可测：接线类（线制/VCC/GND/接/引脚/占用/供电）、接口类（函数调用形态、
      返回/电平/极性/初始化）、场景类（适用/用于/用来/场景/检测/识别）、其余归
      「这是干什么的」；落不进任何一类（且非首句）的进末段「其它说明」——不丢信息。
- [x] 容错：空简介 → `[]`；单句无标点 → 只有一段；一句话同时命中多类 → 只进最优先
      的一类（顺序：首句恒「这是干什么的」> 接口 > 接线 > 场景）。
- [x] `GET /api/modules` 每条投影 `intro` 键（与 `kind` / `requires_identity` 同款
      投影风格，判据在后端）。
- [x] pytest：拆段纯函数分类/顺序/容错；端点载荷带 `intro` 且零丢句（句子多重集相等）。

**实现记录（reviewer 视角的三处偏差，均已按实测改口径并写进代码注释）：**

1. **零丢信息不变量改口径**：初版实现把切句标点**丢掉**了（`"。".join` 拼回时补），
   实测 93/93 真实模块都做不到「拼接 = 原文」；且段间按四问重排后，原本不相邻的两句
   会相邻（`…滑动平均场景` + `纯逻辑模块…`），拼接逐字相等**在设计上就不成立**。
   定稿 = 句子多重集相等（不丢句、不重复、不造内容）+ 段内用句号连接（展示可读）。
2. **首句强判「这是干什么的」**：词法优先级若覆盖首句，93 个模块里 57 个的首段标题会
   变成「怎么用（接口）」（存量简介把定义与接口压在一句，如 relay 含 `relay_set(`）
   ——用户最想看的「这是什么」被埋掉。
3. **场景段只用强标记**：初版把「检测/识别/显示/测量」当场景判据，实测 93 个模块里
   80 个都带「什么时候用」段（分段等于没分）——这些词是「怎么干活」（软 I2C 位操作
   读取），不是适用场景。改强标记（适用于/可用于/用来/常见于）后分布正常。
