# 07 — 收干净：`/api/selection/expand` 与前端选择集的并发竞态

**要做什么：** 展开比点击慢时（真实网络/慢机器上必现），选择集与展开结果必须收敛到
**最新选择**，且**过期响应绝不写进状态**——用户不会看到已选清单中途塌陷成旧集合。

**被谁阻塞：** 06（该竞态是修 chip 开关时用探针挖出来的）。

**状态：** resolved

- [x] **令牌**：每次请求带自增 `expandSeq`，落地前判 `token > expandApplied`——旧响应作废。
- [x] **请求体快照**：落地前比对 `[platform, selectedSlugs]` 与发起时是否一致——拦住
      「选择集在等待期间变了、但还没有新请求发出」的窗口（令牌单靠不够）。
- [x] **排队不丢弃**：`if (expandBusy) { expandPending = true; return; }`，收尾时若
      有 pending 或本次未落地 → 用**当前**选择集再跑一次（原实现是静默 `return`：
      那次预期的展开永远不发生，已选清单停在「未展开依赖」）。
- [x] **选择集变化后重跑展开**：`reRenderAfterSelectionChange` 清掉 `expanded` 之后
      必须跟一次 `runExpand()`（否则界面停在「已选（未展开依赖）」）——在途时它只是
      记一笔排队，不会重复打请求。
- [x] 按钮文案还原改成「首次进入时存一次、收尾统一还原」：重跑不再把 spinner 文案
      当成原始文案存下来（否则按钮永远停在「展开检查中…」）。
- [x] 真机用例：给 expand 响应注入 500ms 延迟 + **MutationObserver 盯中间帧**——
      连点过程中已选清单任何一帧都不得丢掉当前已选模块。
- [x] **反向验证**（这条是关键）：临时把令牌+快照、排队+重跑两处分别停用，
      用例**必须变红**；实测停用令牌+快照后当场红（报「过期 expand 响应把已选清单
      写成了旧集合」），确认过的回退痕迹已全部清除。

**为什么终态断言不够**：收口后的重跑总会把**终态**修对，所以「最终选择集对不对」
这种断言在有竞态的代码上照样绿——必须盯**中间帧**才抓得住「过期响应被写进状态」。
这是本单最值钱的一条方法记录。

**没做（如实记录）**：`/api/selection/expand` 服务端侧未改（竞态纯在前端状态机：
请求与响应的配对、落地时机）。服务端每次 expand 都是按请求体里的 slugs 现算的纯函数，
没有跨请求共享状态，故无需服务端令牌。
