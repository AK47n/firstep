# 03 — 详情弹窗讲人话 + 推荐区/组卡/已选清单三处入口

**要做什么：** 用户在推荐结果里看到不懂的模块名（ir_beam、huidu、xunji…），点模块名
旁边的说明按钮就能就地弹出一份讲人话的说明：四问分段（复用 01 的 `intro`）+「为什么
推荐它」（把 chip 上那句短线推荐理由带进弹窗）+ 默认引脚表 / 源码文件 / 购买链接。
三处入口都能点：推荐 chip、功能组选择卡成员行、已选模块清单行。

**被谁阻塞：** 01（`intro` 载荷）。

**实现记录：**

1. **推荐 chip 渲染上收 `fx/module.js`**：原 `recommendChip` 是 `ui/generate-recommend.js`
   里的局部函数，而需求清单灰注（`groupRequirementNote`，在 fx 层）也要同一个入口——
   两处各写一份 chip 结构必然漂移，故上收为 `recommendChipHTML`。
2. **入口用容器级事件委托**：三处容器都是 `innerHTML` 全量重绘，逐按钮绑监听重绘即失效。
   `bindModuleInfoEntry` 挂在容器上（`dataset` 标记幂等），点 `[data-mod-info]` 即开弹窗。
   **必须 `stopPropagation`**：说明按钮嵌在 `.chip.rec`（`data-remove`）里，不拦住冒泡
   就会「点说明顺手把模块从工程移除」——这是本单最容易埋的坑，测试里单独钉了一条。
3. **不重复印整段简介**：分段本来就是同一份简介拆出来的，弹窗里再印一遍就是同一段话
   连读两遍（实测预览时发现）→ 有分段时标题下不再输出整段 `description`，无分段时
   才用它兜底。
