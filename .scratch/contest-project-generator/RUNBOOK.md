# 执行 Runbook — 电赛工程生成器

## 基本纪律

- **每张工单 = 一个全新会话**，上下文清空，从工单文件出发
- **只做 frontier 上的工单**（所有阻塞都已完成的）
- 工单完成后：`/implement` 内部会收尾（tdd 红绿 → code review → 提交）；完成后开新会话做下一张

## 开工命令

在新会话里输入：

```
/implement .scratch/contest-project-generator/issues/01-generator-core.md
```

把工单编号换成当前要做的即可（工单文件里已写好"被阻塞于"）。

## 工单顺序（frontier）

| 批次 | 工单 | 被阻塞于 | 说明 |
|------|------|---------|------|
| 第 1 批 | **01** 生成器核心骨架 + fixture 基座 | 无 | 必须最先做，一切的地基 |
| 第 2 批 | **02** Keil 修改器 / **03** CCS 修改器 / **04** LLM 选择 / **05** main.c 骨架 / **06** 文本抽取 | 01（06 无） | 五张互不依赖，任选顺序 |
| 第 3 批 | **07** 模块库管理 / **08** 母版提炼 | 01, 04 | 两张互不依赖 |
| 第 4 批 | **09** 生成流程页 + 端到端装配 | 02, 04, 05, 06 | 最后收尾 |

## 工单收尾约定

1. `/implement` 内部自动执行：`/tdd` 红绿循环 → `/code-review`（标准 + 规格两轴）→ 提交
2. 提交前确认工单里所有验收项勾完；勾不完的如实说明，不要假装完成
3. 每个工单提交后，工单文件状态保持 `ready-for-agent` 之外的完成标记（按 implement 约定）

## 你的手工验证点（AI 替不了）
