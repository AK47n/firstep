# 电赛工程生成器 — 规格

## Problem Statement

我参加电子设计竞赛（电赛）。每个赛题会决定用哪块开发板：地猛星开发板（MSPM0G3507，CCS 烧录）或 STM32F103C8T6 最小系统板（Keil5 烧录）。每次拿到新赛题，我都要从零搭工程：复制旧工程文件夹、挑出能复用的 `.c/.h`、微改代码、配 include path——这套手工流程重复、易错，且每个旧工程都带着上一场比赛的残留。我手里积累的模块代码（传感器、显示、通信……）没有系统化：散落在各个旧工程里，想不起来有哪些、在哪、能不能直接用在当前平台上。

## Solution

一个本地运行的网页工具。我把赛题原文贴给它（或传 PDF/Word），选好目标平台，它基于我持续维护的模块库（每模块带 AI 校验过的说明），帮我生成一个"打开就能编译、直接开写"的完整工程文件夹：需要的 `.c/.h` 已就位、工程结构搭建好、include path 填好、main.c 已排好各模块的初始化序列。模块库由 AI 辅助录入与校验——我随时往里加模块，库越用越准。工程母版由多个旧工程提炼而成，每个平台一个。素材另有独立两库：赛题库（历年真题拆条，"几几年几题"编号解析为题面、可作生成入口）与参考文件库（套件配套资料 / 提炼残渣，生成时 AI 按需读取学习）。

## User Stories

1. As an 电赛参赛者, I want to 把赛题文本直接粘贴进工具, so that 不用手工整理题目
2. As an 电赛参赛者, I want to 上传 PDF 格式的赛题文件, so that 工具自动抽取题目文字
3. As an 电赛参赛者, I want to 上传 Word（.docx）格式的赛题文件, so that 工具自动抽取题目文字
4. As an 电赛参赛者, I want to 在生成前选择目标平台（地猛星 MSPM0 / STM32 最小系统板）, so that 生成的工程是针对我实际要用的开发板
5. As an 电赛参赛者, I want to AI 以题面为依据分析这题需要的功能并推荐模块（库内命中可勾选 + 库外建议附常识替代举例）, so that 我不必自己回忆筛选模块、库里没有的也有推荐方向
6. As an 电赛参赛者, I want to 在生成前增删 AI 推荐的模块, so that 最终工程符合我的实际方案
7. As an 电赛参赛者, I want to 看到每个模块在哪些平台验证过, so that 我判断它能否直接用
8. As an 电赛参赛者, I want to 选中的模块缺少目标平台版本时收到明确警告, so that 我不会拿到一份没法编译的工程还不知情
9. As an 电赛参赛者, I want to 把硬件绑定的模块用于另一平台时收到明确警告, so that 我意识到代码需要移植
10. As an 电赛参赛者, I want to 生成时自动带上所选模块的依赖模块, so that 不会出现"缺了底层驱动"的半成品工程
11. As an 电赛参赛者, I want to 拿到一个打开 IDE 就能编译的完整工程文件夹, so that 我不用再手工搭工程
12. As an 电赛参赛者, I want to 生成的 main.c 已排好各模块的初始化调用序列并带注释与预留编写区, so that 我直接往骨架里填业务逻辑
13. As an 电赛参赛者, I want to 生成后工具自检（main.c 引用的函数确实存在于模块库）, so that 减少拿到手才发现编译错误的概率
14. As an 电赛参赛者, I want to 把新模块的 `.c/.h` 拖进工具, so that AI 自动通读代码生成模块简介
15. As an 电赛参赛者, I want to AI 校验我填写的模块描述与实际代码一致并在不一致时提示纠正, so that 模块库的说明保持可信
16. As an 电赛参赛者, I want to 一个模块同时维护多个平台的代码版本, so that 双平台模块一次入库、按平台取用
17. As an 电赛参赛者, I want to 浏览、编辑、删除模块库中的模块, so that 库可以持续整理
18. As an 电赛参赛者, I want to 导入多个旧工程让 AI 提炼出综合母版并审查报告（保留/合并/剔除）, so that 母版不带历史残留
19. As an 电赛参赛者, I want to 为每个平台配置独立的母版, so that 两边生成都开箱即用
20. As an 电赛参赛者, I want to 在设置里配置 AI API（默认 DeepSeek，可更换）, so that 我可以选择自己有的 API
21. As an 电赛参赛者, I want to 生成时选择输出目录, so that 工程落在我想放的地方
22. As an 电赛参赛者, I want to 导入历年真题长 PDF，AI 拆成赛题条目（年份 + 编号 + 题面），我校对确认后入库, so that 我以后说"2026C"就能拿到题面
23. As an 电赛参赛者, I want to 把套件配套资料（例程 + 说明书）存为参考文件并锚定赛题或套件, so that 生成时 AI 能读取它们学习真实例程
24. As an 电赛参赛者, I want to 提炼时被剔除的业务代码一键归档为该题参考文件, so that 素材不丢、以后还能当学习资料
25. As an 电赛参赛者, I want to 生成时选择历史赛题编号或直接粘贴题面, so that 不用每次都整理题目文字

## Implementation Decisions

- **技术栈**：Python 3.14 + FastAPI 后端；前端为单页 HTML/JS（无构建链）；本地 localhost 服务，不部署。
- **架构**：薄壳（Web 路由 / LLM 网络调用 / 文本抽取）包裹一个纯逻辑核心——工程生成器核心。
- **测试接缝**：工程生成器核心，输入 `(目标平台, 已选模块的 manifest 集, 母版工程路径, main.c 骨架内容)`，输出一个完整工程目录。全功能只通过这一个接缝测试。
- **LLM 接口**：抽象为协议；生产实现调用 DeepSeek（base_url / key / 模型可配置）；测试注入固定返回的假实现。LLM 承担三个职责：赛题→模块推荐（输入赛题 + 模块库 manifest 摘要 + 硬件词表，输出功能需求层 + 库内命中 + 库外建议）；main.c 骨架生成（只调用模块库中真实存在的函数，不确定的写成注释占位，保证可编译）；模块简介生成与描述一致性校验。
- **模块推荐**：题面证据驱动——题面逐句编号对照产出功能需求层（能力/外设级，防脑补）；逐条实现覆盖检查（库内命中可勾选进工程；无命中 → 库外建议：类别名 + 常识举例，仅展示不进工程）；AI 以题面为裁判自检收敛（连续两轮一致即停，上限 4 轮，拿不准向用户补问）；库外建议 name 必须命中硬件词表（型号/类别），词表外降级或拒收，examples 自由；收敛解可缓存进赛题条目（v2，库内命中每次现算）。
- **模块库**：磁盘目录即数据库。每个模块一个目录：机器可读 manifest（JSON）+ 各平台版本文件。manifest 字段：功能简介、依赖列表、平台条目（每平台的文件列表、验证状态、硬件绑定标记、备注）。
- **依赖解析**：生成时按 manifest 递归带入依赖模块。
- **平台工程修改器**：统一接口的两个插件——Keil（修改 `.uvprojx`：注册文件 + include path）与 CCS（修改 `.cproject`：include path）。文件复制、目录组装等核心逻辑两平台共享；Keil 插件先做扎实。
- **母版提炼**：导入多个同平台工程 → 结构对比 + XML 配置对比 → LLM 判定公共骨架与项目残留 → 输出提炼报告（保留 / 合并 / 剔除清单）→ 用户确认 → 母版入库。入库前一律做结构分析。
- **文本抽取**：PDF 与 Word 在本地解析为纯文本后再交给 LLM；纯文本直接读取。
- **配置**：AI API key 等存本机配置文件，不入版本库。
- **自检**：生成后静态校验——main.c 引用的函数名在所选模块的头文件中存在；所选模块文件齐全。

## Testing Decisions

- **原则**：只测外部行为（输入→输出），不测实现细节。
- **主测试对象**：工程生成器核心。用 fixture 假母版（最小化的 Keil/CCS 工程）、假模块库（带 manifest 的 `.c/.h`）、假 LLM（返回固定模块选择与骨架）驱动；断言输出目录的结构、文件内容、include path 与 main.c 骨架。
- **次要测试对象**：文本抽取适配器（PDF/Word 样例文件）、manifest 校验逻辑（缺失字段、平台条目冲突）。
- **框架**：pytest。全新项目无既有测试先例，以生成器核心的 fixture 测试为首个模板。

## Out of Scope

- 历史记录与生成回放
- 模块示例用法代码生成
- 图片（拍照 / 截图）赛题输入
- 自动调用 IDE 编译验证（由用户在 IDE 中验证）
- 多用户、账号、远程部署
- 桌面应用打包（Electron/Tauri）
- 未验证平台模块的自动移植（只提示，不自动改）
- 移动端适配

## Further Notes

- 首次使用流程：设置里配置 AI API → 导入旧工程提炼两个母版 → 开始生成。
- 平台选择：用户拍板，AI 可按赛题内容给出建议。
- 提炼出的母版首次使用后，用户需在 IDE 编译验证一次（flash 配置、烧录算法等细节）。
- 生成器不保证编译：最终以 IDE 编译结果为准。
- 模块库目录、母版目录的物理位置在实现时定为用户可配置，默认放在工具工作目录下。
