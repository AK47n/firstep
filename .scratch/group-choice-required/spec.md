# spec — 功能组卡改为「用户显式选择」（不再默认选中 AI 推荐件）

**状态：** 已拍板（2026-09-12 会话：用户选「必须先选才能生成（卡住 + 提示）」+「加『请选择』提示」）。

## 问题陈述

AI 推荐出卡时，同一个功能的几个互斥件（`imu_uart` / `jy61p` / `ml_mpu6050` 这类）会渲染成一张
「功能组选择」卡。现状是**卡里已经替用户勾好了 AI 推荐的那一个**（radio 选中 + 「AI 推荐」徽标），
用户不点也能直接生成——于是：

- 用户以为自己没做选择，其实工程里已经进了一个件（默认值隐身）；
- 一旦 AI 的推荐顺序与用户预期不同（例如「句子 12 先提到 jy61p」，卡里就默认勾了 jy61p，
  而用户心里想的是 imu_uart），用户会先看到「怎么选的是它」的困惑，再手动去改；
- 更糟的是**用户根本没注意到这张卡**时，生成会静默带着一个他没看过的选择走到底。

用户要的是：**这一组必须由我来点**——卡上不给默认选中，给出「请选择」提示，没选就不许生成。

## 方案

1. 功能组卡**不再预先勾选**任何成员：`renderGroupCards` 只在「用户点过这一组」时才画选中态；
   未被点过的卡显示为**未选**，标题旁挂一枚「请选择」提示。
2. 需求清单里的灰注同步说话：那一组还没选时，灰注写「（请选择）」，而不是复述 AI 的理由。
3. **未选就拦住生成**：点「生成」/「生成骨架」时，只要还有未选的功能组 → 就地报
   「功能组『<组名>』还需要你选择一项」并不发请求。
4. **服务端同源守门**：`/api/generate` / `/api/skeleton` 也校验（载荷带 `group_choices`），
   缺选即 400 中文——前端拦不住的路（CLI、脚本、旧页面）也不会把「没选过的默认」当用户选择。
5. 用户点一下即选定：写入 `group_choices`，并让**选中的那个成员顶替**原来在集合里的同组件
   （幂等：重复点同一个是 no-op；换选就是换掉）。

## 用户故事

1. 作为**参赛选手**，我想要功能组卡一开始不替我勾选，以便我清楚「这个选择是我做的」。
2. 作为**参赛选手**，我想要没选时卡上有「请选择」提示，以便我知道还有一件事要我做。
3. 作为**参赛选手**，我想要没选就点生成时被明确拦住（而不是悄悄用默认值），以便我不会把
   一个自己没确认过的硬件带进工程。
4. 作为**参赛选手**，我想要点一下成员就完成选择、并自动替换掉同组的另一个件，以便不用手工删。
5. 作为**维护者**，我想要服务端也校验同一件事，以便 CLI / 脚本 / 旧页面走同一条规矩。
6. 作为**做真机验收的 agent**，我想要这条规矩的判据是纯函数 + 端点契约，以便机器可判、可回归。

## 实现决策

- **载荷契约（`exclusive_groups[]` 新增 `choice_required`）**：命中卡（组内已有推荐成员）为
  `true`，hint 卡（AI 未推荐、题面疑似需要）为 `false`——hint 卡本来就是「你看着办」的软提示，
  没有默认值可替，不纳入硬拦。旧载荷无该键 → **前端**一律按 `false`（不做前端硬拦，避免历史缓存
  在页面上把用户卡死）。**如实记**：服务端的判据看的是**库内组定义**（不依赖前端载荷字段），
  所以「页面上是改版前的旧推荐载荷、用户直接点生成」时服务端仍会 400——这是有意的（服务端不能
  依赖一个可能被伪造/过期的字段），并在文案里给出了出路：「若推荐卡上现在没法点选，请重新跑一次
  『让 AI 推荐』拿到新版结果」。
- **跨语言镜像（评审整改）**：同一条判据有两份实现（后端 `missing_group_choices` 守端点，前端
  `pendingGroupChoices` 守即时反馈）。仓库先例不允许「各写一份、谁也不管谁」
  （`tests/test_library_invariants.py:619` 的跨语言常量镜像 + 守卫），故：
  场景表单一出处 = `tests/test_group_choice_mirror.py::cases()`，期望值由 Python 判据现算并导出
  `tests/js/group-choice-mirror.fixture.json`，JS 侧 `tests/js/group-choice-mirror.test.mjs` 逐场景
  比对前端判据 → **改一侧忘了另一侧就红**。文案同样单源：前端拦截文案只在 `fx/module.js`
  的 `groupChoiceGapText` 里写一份（`ui/generate-core.js` 与就绪检查单都读它）。
- **用户选择的存在哪里**：前端新增 `groupChoices = {组 id: slug}`（草稿持久化，随现有草稿机制
  落盘/恢复）；后端请求新增可选字段 `group_choices`（同形状字符串映射）。
- **选中态的唯一判据 = `groupChoices`**：`renderGroupCards` 不再从 `selectedSlugs` 反推选中，
  只有 `groupChoices[id]` 命中的成员才是 checked。这样「没点过」与「点过」在渲染层就是两回事，
  不需要前端另存一份「用户是否点过」的旁证状态。
- **集合的推导仍然单源**：`applyGroupChoices(selectedSlugs, groups, choices)` 纯函数——
  先移除这些组的所有成员，再按 `choices` 加回；`groupChoices` 变化时重算，幂等、可复算。
  `selectedSlugs` 依旧带着 AI 推荐的那一个（服务端生成集合不因「未点选」而缺件），
  但**用户看不到它被勾选**，且未选时不许生成。
- **卡住生成的判据**：`pendingGroupChoices(groups, choices)` 返回未选组清单；非空即拦。
  前端在两处生成入口（`generateMain` 骨架/自检、`generate()` 主生成）各拦一次，文案带上组名。
- **服务端门禁**：新增纯函数 `missing_group_choices(group_defs, platform, group_choices, slugs)`
  （域层，判据单源），两个端点调用它 → 抛 `SelectionError` → 既有 `errors.py` 映射成 400 中文。
  校验点：① `choice_required` 的组分平台投影后 ≥2 成员；② 该组的 `group_choices[id]` 必须在
  **该组成员里**（越界/不认识的 slug 也算未选，不静默接受）；③ 缺省 `group_choices` 且存在
  待选组 → 400（宁严勿松）。
- **hint 卡不拦**（见上）；**无组载荷 / 旧载荷不拦**（`choice_required` 一律 false）。
- **不改**：`converge_exclusive_group_selection` 的「保模型清单首个」规则（它只决定
  `recommended` 是谁、以及哪一个是「未点选时服务端会用的那一件」），也不改生成侧
  `HARD_EXCLUSIVE_PAIRS` 兜底。

## 测试决策

- 纯函数层（前端，`tests/js/group-cards.test.mjs` 既有先例）：`renderGroupCards` 未选时不画 selected
  + 带「请选择」；`applyGroupChoices` 幂等 / 换选 / 非组模块不动；`pendingGroupChoices` 的判据
  （hint 卡不算、单成员组不算、旧载荷不算）。
- 域层（`tests/test_selection.py` 先例）：`missing_group_choices` 的正反例（缺选 / 越界 slug /
  hint 卡 / 旧载荷 / 平台投影后单成员）。
- 端点层（`tests/test_webapp.py` 先例）：`/api/generate` 与 `/api/skeleton` 缺选 400 且**不产生
  输出目录**；带齐 `group_choices` 200。
- 真机：一次真实推荐（2026H / mspm0 或用户当前题）→ 组卡不预选、点一下即选定、未选点生成被拦。

## 范围外

- **不**改 AI 提示词与收敛规则（谁被标为 `recommended` 照旧）。
- **不**动 CLI 的 `--drop/--add` 语义；CLI 走的是「选完之后」的集合，本单只加端点门禁
  （CLI 若要走同一条规矩需另立单）。
- **不**给非功能组的普通模块加任何「必须显式选择」的约束。
- **不**改功能组卡的视觉体系（沿用现有卡片样式，只加一枚提示与去掉默认勾选）。

## 补充说明

- 背景：用户报告「已经选了姿态传感器，需求句里又出现另一个姿态件」——那一半已由
  `attitude-group-jy61p/01`（jy61p 并入 `attitude-hold` 组）修掉；本单解决的是同一次对话里
  指出的另一半：**选择应该由用户做，而不是 AI 替他做**。
