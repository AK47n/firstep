# 赛题库页 UI 提升（信息查看 + 即时检索 + 编辑体验 + 数据健康 + 美感）

> 会话/系列 slug：topic-library-ui。本 spec 描述「第五个栏目 = 赛题库
> （tab-topic）」整轮提升的共同方向；实施按竖切工单逐张落地（见 issues/）。
> 与第四轮「PDF 资料库」（pdf-library-ui，已完成 6 张工单）对偶，交互语言
> 与令牌体系沿用前几轮（.lib-toolbar / .lib-chip / .lib-stats / modal 复用
> 模式，不新造令牌）。

## 问题陈述

「赛题库」栏目是五个栏目中唯一没有进过 UI 提升轮的面板：浏览靠 1 个搜索
按钮（输入年份 / 编号后点按钮才触发客户端过滤，无即时性）、无排序、无统计；
卡片上只有编号徽章 + 年份 chip + 80 字题面预览，想看全文只能点「用此题
生成」跳生成页；**条目元数据零入口**——附带程序清单（programs，如 2026C
→ `C:/Users/luoji/Desktop/2026C`）、功能组声明（hint_module_groups，2024H
= attitude-hold）入库后 UI 完全看不到，也无法修改（只能手改 manifest.json
或整条删除重录）；**数据健康不可见**——附带程序目录悬空（引用已删目录）、
原 PDF 缺失（页面图端点 400、AI 拆错核对原文的能力丢失）、功能组 id 不在
模块库组词表（推荐链路静默忽略）三种问题没有任何警示。实扫 15 条现状：
全部条目原 PDF 与附带程序目录均在、hint 组命中词表——健康机制缺失不构成
当前事故，但库会在使用中腐坏（用户删了源目录 / 手工改坏 manifest），没有
任何手段看见。

## 方案

把「赛题库」页提升为信息完整、可即时检索、可编辑、健康可见的管理面板，
四个主轴：

1. **信息与查看**：详情弹窗（元数据 + 题面全文 + 题面页图懒加载），替换
   「只能跳生成页看全文」；卡片精修（元数据小行 + 健康徽章 + 详情入口）。
2. **即时检索**：客户端关键字即时过滤（防抖）+ 年份 chips + 排序 + 统计条，
   替换「搜索按钮才触发」的服务端式交互。
3. **编辑体验**：「编辑」弹窗（题面全文 / 附带程序清单 / 功能组勾选），经
   新后端端点一次事务提交（对偶参考文件库轮的编辑弹窗 + PUT）。
4. **数据健康**：附带程序目录悬空 + 原 PDF 缺失 + 功能组 hint 悬空三类
   警示——行内 ⚠ + 统计条红段（点击只看问题条目，再点取消）；**提示语义，
   不拦截浏览**（编辑弹窗正是修正 hint 悬空的闭环动作）。

主体形态维持**卡片网格**（题库当前 15 条，信息密度足够；卡片网格是
ui-polish-9 轮刚落地的形态，本轮加强不推翻）。

## 实现决策

### 健康判据（三类，服务端实况 + 客户端词表）

- **附带程序目录悬空**：`programs` 中的绝对路径经 `Path(p).is_dir()` 判定，
  **服务端**计算（文件系统实况，前端无从判断）——悬空 = 清单条目标 ⚠。
- **原 PDF 缺失**：条目目录内 `original_pdf` 文件不存在，**服务端**计算；
  无原 PDF 字段（空串）不算缺失（没有就不查）。
- **功能组 hint 悬空（客户端）**：`hint_module_groups` 的组 id 不在模块库
  exclusive_group 词表（对所有模块的 `exclusive_group.id` 去重）→ 悬空。
  词表从 `/api/modules` 派生（对偶参考文件库轮 kitVocabulary 先例），
  **词表为空 = 跳过检查**（模块库未配置 / 接口失败，避免全库误报）。
- 判据均为提示语义：不拦截浏览、不阻止编辑保存；悬空程序目录可在编辑弹窗
  里移除（修正动作），原 PDF 缺失只能重导入或删除条目（提示）。

### API 契约（浏览列表补字段 + 新增 1 个端点）

- `GET /api/topics`（浏览列表，既有端点）：每条目 `to_dict()` 增补
  `health` 对象：`{original_pdf_missing: bool, programs_missing: [绝对路径...],
  original_pdf_size: int}` ——topic 域纯函数计算（对偶 PDF 轮 list_pdfs
  增补 mtime 先例，一次算好返回，前端不再按条回查）；`original_pdf_size`
  为原 PDF 字节数（缺失 = 0），详情弹窗体量展示需要（spec 审定：实现期
  补记，契约以本行为准）；单条 GET `/api/topics/{key}`（生成入口素材）
  **不带 health**（该端点是生成入口、字段保持现状）。
- 新增 `PUT /api/topics/{key}`，body：
  `{problem_text, programs, hint_module_groups}` ——三字段全量必填（表单
  总是提交完整值），其余键一概忽略（只读字段：year / number / original_pdf
  / problem_md 不可改——目录名与文件引用是身份）。成功返回编辑后
  `entry.to_dict()`。
- 校验（全部在首次落盘前，任何失败 TopicError → 400 中文，磁盘零变化）：
  - 编号格式非法 / 查无此条 → 明确报错（与编号解析同文案，不猜测编造）；
  - `problem_text` 非空（strip，与确认入库同标准）；
  - `programs`：非空字符串列表；每条非空且目录实际存在
    （`Path(p).is_dir()`，与确认入库同标准——悬空引用不允许编辑写入，
    要移除就在清单里删掉）；
  - `hint_module_groups`：非空字符串列表（与条目加载同判据）。
- 落盘顺序：先写题面文件（文件名取 `problem_md`，不变），再写 manifest
  （保留既有全部字段，仅替换 programs / hint_module_groups），成功一次
  自动 git 提交（`lib: update topic {key}`，沿用 autocommit 机制）——
  原子语义：写题面成功但 manifest 失败 = 文件已改，与既有 enrich 补图注
  的落盘粒度同级（先写内容后写元数据是仓库惯例，failure 面已够小）。
- 既有端点零改动：GET /api/topics / POST /api/topics/split / confirm /
  extract-number / GET /api/topics/{key} / GET /api/topics/{key}/pages /
  DELETE /api/topics/{key} 全部不动。
- 错误类型复用 TopicError（已在错误映射表登记，文案中文），零新错误类。

### 前端（交互逻辑继续下沉纯函数，DOM 层只转发）

- 纯函数组（挂 window，供冒烟直接调用；对偶 pdf 轮 pdf* / ref 轮 ref*
  系列）：`topicFilterEntries`（关键字 × 年份 × 健康状态过滤，正交组合）、
  `topicSortEntries`（编号 / 题面字数，稳定排序）、`topicStats`（总数 /
  含附带程序数 / 含图注数 / 题面合计字数 / 数据问题条目数）、
  `topicStatsText`（统计条文案）、`topicGroupVocabulary`（/api/modules →
  组 id→label 词表，对偶 kitVocabulary 派生）、`topicDanglingGroups`
  （hint 组悬空判定，词表空 = 空结果降级）、`topicHasNotes`（题面是否含
  图注段：子串「[示意图」/「[图N 标注」判定）、`topicHealthText`
  （health 对象 → 中文描述）、`topicCardHTML`（**改造既有卡片渲染**：
  保留编号徽章 / 年份 chip / 80 字预览 / 转义 / 「用此题生成」+「删除」，
  追加元数据小行（题面字数 / 程序 N 份 / 图注 ✓）+ 健康 ⚠ 徽章 + 「详情」
  按钮——既有 tests/js 的卡片断言语义保持兼容，追加不进旧断言范围）、
  `topicDetailHTML`（详情弹窗渲染：元数据段 + 题面全文段 + 页图容器 +
  操作按钮）、`topicEditHTML`（编辑表单渲染：题面 textarea + programs
  textarea 每行一个 + 功能组勾选（词表项 + 当前值悬空项兜底，标注悬空））
  、`topicFilterContext`（组装过滤上下文 + 去重，对偶 refFilterContext）。
- 数据源：`GET /api/topics`（全量 + health，在手即过滤排序统计）+ 详情页图
  懒取 `GET /api/topics/{key}/pages`（打开详情即请求一次并 memo——Map
  key→结果，重复打开零重复请求；三态：加载中 / 成功叠放 / 失败显示 400
  中文原因）+ `/api/modules`（tab 切换加载组词表，对偶 loadKitVocabulary）。
- 工具栏（替换既有年份 / 编号输入框 + 搜索按钮 + 清空按钮）：关键字即时
  输入（防抖，匹配编号 / 年份 / 题面全文 + 健康红段正交）+ 年份 chips（全部
  / 各年份，带条数）+ 排序下拉（编号默认 / 题面字数）+ 方向切换。
- 统计条：`共 N 题 · 含附带程序 X · 含图注 Y · 题面合计 ~Z 字` + ⚠ 数据
  问题红段（N 条任一健康缺项，点击只看问题条目，再点取消；红段与关键字 /
  年份 chips 正交组合过滤）。
- 详情弹窗：复用 `.ref-files-overlay` / `.ref-files-close` 遮罩与关闭模式
  （module-info-dialog 先例），内容两段——元数据段（编号 / 年份 / 题面
  字数 / 原 PDF（文件名 + 大小 + 缺失 ⚠）/ 附带程序清单（每条绝对路径 +
  悬空 ⚠）/ 功能组（组 label（词表外显示 id）+ 悬空 ⚠）/ 图注 ✓）/ 题面
  全文段（pre-wrap 纯文本 + 滚动——题面是 markdown 给 AI 的素材，本轮不
  做渲染，保留原文形态）+ 页图段（懒加载叠放）+ 操作段（用此题生成 / 编辑
  / 删除——删除沿用现有确认弹窗）。
- 编辑弹窗：全字段表单（题面多行 / 附带程序逐行 / 功能组勾选列表）+ 一次
  「保存」调 PUT；保存中 / 成功 / 失败三态；成功 = 刷新列表 + 关闭弹窗；
  年份 + 编号只读展示（身份不可改文案即说明）；编辑入口 = 详情弹窗按钮 +
  卡片操作（可选，放卡片会拥挤——**仅详情弹窗入口 + 详情内操作段**）。
- id 唯一性防线：新元素 id 前缀 `topic-` 命名空间（topic-filter /
  topic-sort / topic-sort-dir / topic-year-chips / topic-stats /
  topic-grid 沿用 / topic-detail-* / topic-edit-*），冒烟检查页面内 id 唯一。
- 拆条录入卡（上传 → 拆条 → 校对 → 确认入库）本轮**不动**。

### 模式变更 / 架构决策

- 不引入新依赖；后端新增仅 `topic_health` / `update_topic`（topic
  domain 层）+ 浏览列表拼 health + 1 条 PUT 路由（webapp 薄壳层）。
- 交互逻辑继续下沉纯函数（先例：pdf* / ref* 系列），DOM 事件层只做转发，
  保持 tests/js node:test 可测。
- 组词表客户端派生对偶 kitVocabulary 先例：不做新后端端点（/api/modules
  已带 exclusive_group 字段，避免第三个「库清单」端点）。
- CONTEXT.md 词表「赛题库」行补本轮语义：浏览列表 health 字段
  （original_pdf_missing / programs_missing，服务端实况判定）+ PUT 编辑
  端点（题面 / programs / hint_module_groups，编号身份不可改）+ 组词表
  客户端派生（exclusive_group.id 去重，hint 悬空判定）。

## 范围外

- 拆条录入卡（上传 / 拆条 / 校对 / 确认入库）的任何改动——本轮聚焦浏览区。
- 共享 PDF 副本（2018C–2024H 七条各一份 33.4MB 汇总 PDF，≈234MB）的
  去重 / 合并 / 警示——用户裁决未入选，属另行议题。
- original_pdf 的更换 / 改名 / 重新导入（编辑只读身份字段；PDF 缺失提示
  后自行文件操作或删除重录）。
- 题面 Markdown 渲染预览（题面是给 AI 的素材原文，纯文本展示更忠实）。
- 页图翻页器 / 缩放 / 单页下载等查看器增强（现有叠放展示不动）。
- 服务端搜索查询参数改造（/api/topics 查询参数保持现状，客户端过滤已够用）。
- 卡片网格视图 / 表格双视图切换、移动端 / 窄屏专项适配、深色主题。
- 批量编辑 / 批量删除 / 健康问题自动修复。
- hint 组词表的持久化新端点（用 /api/modules 派生，不新设端点）。

## 补充说明
