# 模块推荐候选预筛（预算账本补齐）

## 问题陈述

模块库持续入库（批次 9–13 密集，当前 mspm0 线 84 个模块）后，AI 推荐提示词的「模块库可用模块」摘要段（`ManifestSummary.to_line` 全量注入）从预算账本推导时的 **14 条 ≈ 7.6KB wire** 涨到真实 **84 条 ≈ 73.1KB wire**（stm32 线 24 条 ≈ 12.2KB，同样超出推导值）。该增长**从未进预算账本**（budget.py 全文段推导只记账了词表段的逐批增长）。

后果（实测，`.scratch/recommend-covered-check/measure_select_wire.py`）：
- mspm0 线最坏形态（满额参考全文 + 20 条长澄清历史 + 15 条相关候选）载荷 ≈ **195KB** > 网关 128KB 上限（`MAX_REQUEST_BYTES`，发送前预检即大声失败，且快重试同尺寸必败——budget.py 已记录同款教训）；
- mspm0 线现实形态（无全文无历史，只题面 + 摘要 + 词表 + 清单段）≈ **119KB**，余量仅 12KB——一旦带任意参考全文或澄清历史即超限；
- stm32 线最坏形态 ≈ **133.6KB**，同样超限 2.5KB；
- 结构测试 `test_selection_prompt_worst_case_fits_request_budget` **假绿**——它用固定 14 条假摘要样例（≈7.4KB），未反映真实库，测试绿掩盖了真实风险。

## 方案

推荐前对模块候选做**题面驱动的预筛**：按题面词激活「相关性词表」给每个模块打分，命中得分高的模块排在前；摘要段按新设 wire 预算截断（截断只发生在尾部 = 低分 / 未命中模块）；预筛后提示词明确标注「按题面初筛 N/M」，模型不会把子集误当全量。预算账本把摘要段纳入（新常量 `MODULE_SUMMARY_BYTES`，与全文段联动红证校准），并新增真实库驱动的预算回归测试——模块库每涨一点，测试立即红。

语义关键点：**预筛是「排序 + 预算截断」，不是过滤**——得分 0 的模块仍可能进入预算（题面没提但常见的模块不被抽象排除）；覆盖折损只发生在「命中集本身就超预算」或「题面零外设词命中」的极端场景，且有保底下限。

## 用户故事

1. 作为参赛学生，输入赛题后 AI 推荐在任何场景下都不再因请求体超限而失败（mspm0 / stm32 两线一致）。
2. 作为参赛学生，题面明确提到的功能模块在推荐清单中必然靠前、尽量完整送达（命中优先排序）。
3. 作为参赛学生，预筛发生后推荐提示词明说「按题面初筛 N/M 条」，我（和 AI）都知道这不是全量清单。
4. 作为模块库维护者，新模块入库后自动进入推荐可见面（摘要行自动生成机制不变，零手工登记）。
5. 作为模块库维护者，推荐缓存指纹与模型**实际看到的**摘要行一致（预筛后子集 hash），换题 / 换库自动失效的语义不变。
6. 作为模块库维护者，新模块入库若将破坏请求预算，真实库驱动的回归测试立即红（照词表段逐批红证校准流程）。
7. 作为模块库维护者，词表方案的 `lib_modules` 挂接参与预筛打分——题面说「气压」时 BMP180 / MS5611 直接被带出。
8. 作为用户，题面完全命中不了一个外设词时，排序规则零变化（slug 序）——预算内全量送达（stm32 线 24 条零变化）；预算装不下时照常按 slug 序截断 + 注记（物理约束：mspm0 全量 73KB 本就超预算，零命中不豁免），不引入任何新行为。
9. 作为用户，stm32 线（24 条 ≈ 12.2KB）在预算内全量送达，不截断、不打标、行为不变。
10. 作为用户，命中集本身超过预算的极端题（如大杂烩传感器题），截断标注明说，不静默丢模块。

## 实现决策

- **预筛纯函数**放 `selection.py`（模块推荐域，与 `related_references` 同层）：`preselect_module_summaries(summaries, topic_text, hardware_words, budget_bytes) -> PreselectResult`（结果对象，见下），输入全量摘要（已按平台过滤）、题面、词表、预算；输出预筛后子集（保序）。返回到 `PreselectResult(summaries, total, truncated)`——truncated/total 供调用方「按题面初筛 N/M」注记两态判定（工单 03；spec 原「返回 tuple」为推导初稿，注记契约要求结果对象，已记录在案）。
- **词源复用单点**：`PERIPHERAL_TERMS`（reference_library.py 单源——题面侧激活规则照 `related_references` 既有实现：英文词独立出现 / 中文子串 / 同义词组去重；selection 经同包私有互导复用 `_activated_terms` / `_text_has_term` / `_term_matches_token` / `_synonym_group` / `_is_ascii_term`，events._emit 先例，单源意图保留）。
- **模块侧匹配面** = 两层：slug 走 token 级规则（`_term_matches_token` 精确 / 前缀 + 纯数字尾巴（adc → adc12；描述文本边界规则覆盖不到数字尾巴形态））+ description + kits 拼接文本走连续文本规则（`_text_has_term` 英文词边界 / 中文子串）。零新词表——84 个模块全面覆盖靠描述的自然语言内容，批次 13 的 description 已写题面场景关键词（实测四件均含）。
- **词表 lib_modules 挂接**：题面词命中词表行的 category / models（或方案名——方案级精确优先、行级兜底：题面「继电器」→「1 路 5V 继电器模块」方案 → 仅 relay；题面只写型号且无方案名命中 → 该行全部方案的 lib_modules 并集；中文双向子串：题面「气压」命中方案名「MS5611 高精度气压计」，中文连续段 2-4 字滑窗，短侧 ≥ 2 字）→ 挂接 slug 计命中分（词表行与题面文本的子串判定，中文语义；这是入库流程 already 维护的数据，批次 13 已配套更新）。
- **打分**：命中词项数（去重后，同义词组计一次）；1 词 1 分，不做加权；得分相同则按 slug 字典序（确定性，与 `list_modules` 排序同构）。
- **截断与保底**：预筛后按「命中得分降序 → slug 序」排列，新 `_fit_summaries_by_wire` **行级** wire 预算截断（不劈半行——spec 原「`_fit_segment_wire` 字节前缀截断」会劈半行，实现取行边界变体，有益偏差）；「截了要明说」契约由调用方承担：`PreselectResult.truncated = True` 时调用方在提示词标题带注记（模型侧可见），截断器自身零文案（摘要行是结构化清单，行内插标注污染模型解析）；**保底下限 MIN_PRESELECT = 20 条**——截断后不足 20 条时扩到前 20 条（覆盖下界，防命中稀少时清单过短）。
- **预算常量**：`MODULE_SUMMARY_BYTES`（**定值 40000**，红证实测：mspm0 预筛 46/84 条、stm32 24 条全量）放 budget.py（摘要段入账本）；`REFERENCE_FULLTEXT_BYTES` **60100 → 27000**（红证实测校准：28000 时 mspm0 最坏 128605B 距 129024 边界仅 419B 过紧，取 27000 保 ~3KB 呼吸；单篇全文 ≈4500 中文字，两级注入契约下足够；照词表段逐批先例每涨必红证、保 2KB 边界余量）。固定项（题面 24KB + 历史 15KB + 词表 7.9KB + 清单 4.1KB + 系统提示 ~3.8KB + 壳/契约 ~1.7KB ≈ 56.5KB）；`MIN_PRESELECT` **定值 20**（保底下限，现实库 20 条 ≈17KB ≪ 预算）。
- **接入点**：webapp `/api/recommend` 路由，`_assemble_topic_context` 之后、`library_fingerprint` 之前：预筛结果**替换** `topic.manifest_summaries`（或经 `run_recommendation` 新可选参数透传，默认 topic 全量——二选一在工单 02 定，倾向 replace 后同对象，`_default_instances_for` 同源受益）。指纹 `library_fingerprint` 改用预筛后列表（模型实际所见；确定性函数保证同题面同指纹，缓存语义不变——同题面同预筛，换题面指纹自然变）。
- **提示词契约**：`_selection_user_prompt` 的「模块库可用模块：」标题携带预筛注记（如「（按题面初筛 46/84 条，仅展示前 40000 wire 字节）」）；**未预筛 / 全量未截断时标题逐字节不变**（向后兼容，stm32 线与既有测试零影响）。注记仅在中标段发生实际变化（截断 or 子集 < 全量）时输出。
- **只改推荐链路**：骨架 / 生成 / 影响分析 / 修订保持全量摘要注入（各自预算形态不同、未到最坏形态；后续若超另行建账——范围外）。
- **CLI 对偶**：验收脚本 `generate_check.py` 经 HTTP 调 `/api/recommend` 自带对偶，无需改动；其缓存元数据沿用（指纹口径变化意味着旧缓存失效走真实推荐——正确语义，非回归）。

## 测试决策

- **测试缝（推荐唯一新缝）**：`tests/test_selection.py` 纯函数级测试（预筛打分 / 排序 / 截断 / 保底 / 零命中零增量 / lib_modules 挂接 / 确定性），随工单 01 落地。
- **预算回归（真实库驱动）**：`tests/test_llm.py` 新增 `test_recommend_real_library_budget`——扫真实 `library/modules`，对 mspm0 / stm32 两平台构造最坏形态（满额全文 + 最长历史 + 15 相关候选 + 真实词表 + 预筛后摘要），断言 `json.dumps` 序列化 ≤ `MAX_REQUEST_BYTES` 且余量 ≥ 2KB。这是「入库即红」守卫：任何新模块入库若破坏预算，此测试先红（照词表段 test_wordlist_segment 契约红证先例）。现有固定 14 条样例测试**保留**（最小结构测试，不依赖真实库，防止样例与真实库同步漂移）——两测试并存，断言基线以真实库测试为准。
- **提示词标注测试**：预筛注记出现 / 不出现的两态（`test_llm.py`，照既有 prompt 契约测试）。
- **既有测试影响面**：webapp 集成测试（/api/recommend）在真实库下运行 —— 预筛后摘要注记变化可能影响「prompt 逐字」断言类测试，逐一核对，必要时按「注记仅在实际变化时输出」的契约修正。

## 范围外

- manifest 加 keywords 字段、摘要行压缩、两级注入（清单全量 → 点名回读详情）——均不动（本方案用排序 + 预算截断达成覆盖，不需新增数据形态）。
- 骨架 / 生成 / 影响分析 / 修订各段的预算改造。
- 推荐缓存格式 / 键 / 指纹算法的结构变更（只换指纹输入为预筛后子集）。
- stm32 侧新模块入库流程本身的变更。
- 词表本身增补（PERIPHERAL_TERMS 不加词——描述与 lib_modules 已够；若某模块描述用词完全不在词表层，属库数据质量问题另行处理）。

## 补充说明

- 本方案与「题面证据驱动」系统提示词哲学同源：题面没提的模块本来就不该被推荐，预筛只是让"不该被推荐的模块"让位给预算内的命中模块——覆盖逻辑零折损，且顺带缓解 84 条清单的模型注意力退化。
- 参数候选值（`MODULE_SUMMARY_BYTES=40000`、`MIN_PRESELECT=20`）为初稿，实现时以红证实测校准（照 budget.py 词表段先例，实测数值 + 余量断言一并更新注释）。
- 批次 13 四件（relay / as32 / bmp180 / ms5611）入库时已按流程配套更新词表段预算与 lib_modules 挂接——本方案落地后，它们即被预筛规则自然覆盖（「继电器」「LoRa」「气压」均在词表层 / 描述面）。
