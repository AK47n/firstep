# 新手向上手指引（R1+R2+R3）：README + 安装脚本 / 启动器中文反馈 / 首次欢迎卡

> 来源：`docs/improvement-review-newcomer-onboarding.md`（2026-08-29）第一梯队 R1 / R2 / R3。
> 立项前已与用户确认 4 个设计走向（见「实现决策」）。

## 问题陈述

一个纯新人（第一次参赛、第一次拿到本工具）目前无法独立走通"拿到手 → 打开 → 开始做第一题"：

1. 仓库没有面向人的 README，不知道这是什么、需要装什么（Python ≥3.13）、怎么装、要买什么；安装也没有脚本，全靠会的人手把手。
2. 双击启动器后，若 Python 缺失 / 版本低 / 依赖未装 / 端口被占，用户只看到"什么都没发生"——失败信息悄悄落进 `%USERPROFILE%\.contest_generator\webapp.log`（英文 traceback），没有任何中文反馈；端口 8000 被其他程序占用时还会误判"已在运行"并打开别的页面。
3. 首次打开后没有任何引导：不知道哪一步开始、哪些 tab 是给自己用的、两件必须做的事（配 API key、跑环境体检）藏在哪；无 key 提示只是一条没有按钮的静态横幅。

## 方案

给"纯新人"补上三段前置体验：

- **一段说明书 + 一个安装脚本**：根目录 `README.md`（面向人，非面向 agent：这是什么 / 30 秒读懂 / 需要什么 / 三步安装 / 启动 / 常见问题），`install.bat`（检测 Python ≥3.13 → 建 `.venv` → 装依赖 → 自检，全程中文提示）。
- **启动器全程中文反馈**：`start-app.bat` 重写为"探测优先"流程：优先用 `.venv` 的 Python；缺 Python / 版本低 / 依赖缺失 / 端口被占 / 启动超时，全部弹中文消息框并给出下一步（安装指引、下载链接、日志路径）。新增后端 `GET /api/health` 作为"是不是本应用"的探测端点，替代纯 netstat 误判。
- **首次欢迎卡 + 提示行动化**：生成页顶部欢迎卡（首次打开出现，一句话说明这套工具是什么 + 三步走 + 两件事先做：配 API key、环境体检，各带一键跳转按钮；可"不再显示"）。无 key 横幅升级为带「去设置」按钮的行动条。

## 用户故事

1. 作为纯新人，我想要读到一份"人话"README，以便知道这是什么、要先准备什么（Python/API key/板子/IDE），能独立装起来。
2. 作为纯新人，我想要一个安装脚本，以便双击就完成 Python 虚拟环境 + 依赖安装，出错时告诉我缺什么、怎么办。
3. 作为使用 Windows 的纯新人，我想在 Python 缺失/版本过低/依赖未装时看到中文弹窗提示（而不是双击没反应），以便知道我该去装什么、去哪下载。
4. 作为使用 Windows 的纯新人，我想在端口 8000 被其他程序占用时得到明确提示（而不是打开别人的网页），以便关掉占用程序后重试。
5. 作为使用 Windows 的纯新人，我想在启动服务超时后看到中文错误说明和日志位置，以便自己排查或把信息发给帮我的人。
6. 作为二次使用的人，我想要启动器优先使用 `.venv` 的 Python（若存在），以便环境隔离不污染全局、也与 README 安装路径一致。
7. 作为纯新人，我想要首次打开页面时看到一张欢迎卡，以便知道"我该从哪开始"，并一键跳转去配 API key / 跑环境体检。
8. 作为已配好 key、已做过题的人，我想要欢迎卡不再出现（或只在未配置 key 时出现），以便不被打扰。
9. 作为未配置 API key 的用户，我想要无 key 横幅有一个「去设置」按钮，以便不必自己找到设置页。
10. 作为开发者/排障者，我想要一个稳定的 `GET /api/health` 端点（JSON：应用标识 + 版本），以便启动器探测"是否本应用"、也便于人工诊断。

## 实现决策

### 已确认的设计走向（用户选择）

- Python 门槛：**保持 `requires-python = ">=3.13"` 不动**；install.bat / start-app.bat 只做检测 + 中文指引（含官网下载链接）。不追求放宽到 3.11/3.12。
- 安装脚本形态：**install.bat 建 `.venv` 虚拟环境**并安装依赖；`start-app.bat` 优先使用 `.venv\Scripts\python.exe`（不存在则回退系统 python）。
- 端口冲突处理：**只探测 + 中文提示**，不做自动换端口。探测方式 = HTTP 请求 `GET http://127.0.0.1:8000/api/health`。
- 欢迎卡形态：**生成页顶部卡片（非浮层）**；localStorage 标记首见；「不再显示」可关。

### 模块 / 接口

- `README.md`（仓库根，面向人）：定位一句话 → 3 秒看懂 → 需要什么（Windows 10/11、Python 3.13+ 下载链接、DeepSeek API key 获取说明、硬件与 IDE 一句话说明）→ 三步安装（install.bat / 启动 / 配 key + 环境体检）→ 常见问题（启动没反应、端口占用、编译工具链接口）。中文。
- `install.bat`（仓库根，GBK/ANSI 编码与现有 start-app.bat 一致）：检测 `python`（缺失 → 中文提示 + 下载链接）→ 版本 ≥3.13 校验 → 创建 `.venv` → 用 `.venv` 的 pip 安装本包（`pip install -e .`）→ 导入自检（fastapi/uvicorn/pypdf/PIL/fitz）→ 中文成功/失败提示。幂等（重复运行安全）。
- `start-app.bat` 重写：流程 = ① 选 Python（`.venv` 优先）→ ② 版本/依赖检查（缺→中文弹窗并提示先跑 install.bat）→ ③ 探测 8000：`/api/health` 是**本应用** → 直接开浏览器退出；是**其他程序** → 中文弹窗"端口被占"；**无服务** → 后台启动（日志仍落 `%USERPROFILE%\.contest_generator\webapp.log`）→ 轮询 `/api/health` 就绪（上限 20 秒）→ 开浏览器；超时 → 中文弹窗（常见原因 + 日志路径）。
- 中文弹窗实现：`mshta`（vbscript MsgBox）无黑窗口弹窗，文本含中文；参数里的中文按 cmd 的 GBK 编码处理（与 .bat 文件编码一致，注意事项见测试决策）。**（实施修正 2026-08-29：改用 powershell WScript.Shell.Popup——mshta vbscript:Execute 语义不可靠：cmd 对 GUI 程序不等待、URL 引号/时序无法验证弹窗停留；powershell 全路径调用于所有 Win10/11 可用，理由详见工单 02 实施记录）**
- 后端 `GET /api/health`：返回 `{"app": "contest-generator", "version": "<__version__>", "ok": true}`；不依赖配置（始终 200，即使未配 key）；接入 `create_app` 与既有路由注册区。
- `stop-firstep.bat`：保持现有机制（kill 8000 进程），可顺带把进程识别改为"仅杀本应用启动的"（与 /api/health 探测共享思路，非本次核心，不扩scope，保持现状即可）。
- 欢迎卡（`index.html` 生成页顶部 `gen-overview` 上方）+ 新前端模块（ui/fx 分层与现有约定一致）：内容 = ①一句话"这是什么" ②三步走（贴题→选平台→生成） ③两件事先做：「去配置 API key」（切到设置 tab 并聚焦 key 输入框）与「环境体检」（切到设置 tab 并触发一键体检）④「不再显示」。首见判定与显示条件做成 fx 纯函数（输入：是否已配置 key、是否有草稿、是否已选择不显示 → 输出：显示完整/精简/隐藏）；localStorage key 独立（如 `firstep.welcome-dismissed.v1`）。
- 无 key 横幅 `gen-banner`：追加「去设置」按钮（同欢迎卡的跳转逻辑，组件与行为复用，避免两套实现）。

### 边界

- install.bat 不覆盖"一键安装 Keil/CCS/烧录器驱动"（那些是第三方安装，README 给链接与一句话说明即可）。
- 不自动跑环境体检（环境体检含 LLM 真实调用，产生费用；欢迎卡只做"跳转 + 用户点击触发"）。
- 不自动换端口、不改 webapp 的端口约定（8000）。

## 测试决策

- **后端接缝（既有最高接缝）**：`tests/test_webapp.py`（FastAPI TestClient 先例充分）。新增 `GET /api/health` 用例：状态 200、`ok=true`、`app="contest-generator"`、`version` 非空；未配置 key 时同样 200。
- **bat 编排逻辑保持"薄"**：不做 Python 端单元测试（bat 无法进 pytest）；验收 = 人工按 4 种场景走查（无 Python / 版本低 / 未装依赖 / 端口占用）＋ 正常启动 1 次。测试决策中记录：任何需要判定的逻辑（如"探测响应是不是本应用"）都放后端可测端点，bat 只做编排与弹窗。
- **文档守护**：新增轻量测试（沿用 `tests/test_repo_language.py` 的思路，pytest）：`README.md` 存在、非空、含关键节（Python 版本 + API key + 板子/IDE 条目）与中文；`install.bat` 存在。避免我写的"人话说明书"在后续提交中被悄悄删掉/改没。
- **前端**：无 node 测试设施（static/js 无 test 脚本、无 *.test.js），欢迎卡/横幅按现有人工验收流程；判定逻辑集中到 fx 纯函数（便于未来接入测试）。

## 范围外

- Y1 前置速查卡（设置页硬件/软件/key 速查）与采购汇总——另立项（README 会先覆盖"需要什么"的信息层面，但设置页速查卡、模块采购汇总不在本 spec）。
- Y2 tab 分组、Y3 迷你词表、Y4 任务推进默认化/交接提示词入口说明——本次不做。
- C1 无 key 离线兜底、B2 题型决策骨架、真题入库（2023 等）——沿用前次评审遗留，不在本 spec。
- 自动换端口、端口可配置化——已明确不做。
- Keil/CCS 安装器与镜像——README 仅给指引与链接。

## 补充说明

- 语言规范：README / 弹窗文案 / spec / 工单 / 提交信息全部中文；`install.bat`、`start-app.bat` 用 GBK（ANSI）编码存储（与 cmd 默认代码页一致，现有 start-app.bat 即如此）；若新增 `.ps1` 必须 UTF-8 with BOM（硬性约定）。
- 弹窗在 `mshta` vbscript 里拼中文时注意：vbscript 字符串里的中文经 cmd 传递按 ANSI 处理，与 .bat 文件自身编码一致即可，测试时在中文 Windows 上走查一次。
- README 要写成"给第一次参赛的人"，不出现面向 agent 的术语（工单号/ADR/CONTEXT 等）。
