# 生成链路真机审计（换面：引脚 / 编译 / 生成 / 模块库 / 代码栏失败路径）

## 问题陈述

前一轮（`.scratch/module-intro-detail/`）已经把「模块说明 + 推荐区」这一面用真机
playwright 压过一遍（9 条验收 + 25 条审计断言全绿，工单 05–10 收口）。那一面之外，
**整条生成链路**此前只有两层覆盖：

- Python 侧：单元测试 + `TestClient`（接口契约与域逻辑很强）；
- JS 侧：`tests/js/*.test.mjs` 纯函数/静态接线断言（**跑在 node 里，没有浏览器**）。

两者都证明不了「真浏览器里点下去会怎样」——前一轮的工单 09（展开自激重试）与工单 10
（弹窗焦点）都是这么漏出去的。本单把生成链路按收益排序，逐面用真机 playwright 压一遍，
**先列「没被真机碰过的面」清单并排优先级，再动手**（不先找 bug，避免重复挖同一块）。

## 方案

新增真机审计脚本 `tests/browser/gen-chain-audit.mjs`（分节可单跑），按下列优先级逐面审计：

| 面 | 内容 | 修前状态 |
|----|------|----------|
| P | 引脚分配 / 冲突消解 / 多实例 | 只有 Python 域测试 + JS 纯件；**板图点选、菜单可绑判据、板图选脚链路从未被真机碰过** |
| R | 编译 → 错误跳行 → 修复轮 | `compile_runner` 有单测、`compile-error-jump` 只有纯件断言；**真 UV4 编译 + 点错误行跳行从未被真机碰过** |
| W | 生成 → 输出目录 → 覆盖确认 | `generation_output` / webapp 有单测；**覆盖确认弹窗从未端到端跑过**（原冒烟把 `apiPost` mock 掉了） |
| X | 模块库 CRUD | `library.py` 有强单测；**列表 / 改简介 / 删除弹窗从未被真机碰过** |
| Y | 代码编辑器 / AI 面板失败路径 | `codeeditor` 有大量纯件单测；**保存失败 / 编译失败 / 「点文件打开」从未被真机碰过** |

**零 LLM 额度**：只拦真会花钱的端点（`/api/recommend`、`/api/skeleton`、`/api/fix-errors`、
`/api/tasks/*` 等，注入 502 —— 顺带就是它们的失败路径判据）。`/api/generate` 在
**题面留空时零 LLM**（`report_draft` 短路，源码确认），所以「生成 → 输出目录 → 覆盖确认」
可以走真后端真落盘而不花一分额度。

## 用户故事

- 作为用户，我**在板图上配得出的绑定**，生成时必须能过——不能等到点「生成工程」才被告知 400。
- 作为用户，桌面已有同名工程时，我**必须看到一个覆盖确认弹窗**（并且知道旧工程会备份成 `.bak`），而不是一条死报错。
- 作为用户，我在代码栏**点文件名就该打开它**。
- 作为用户，编译失败了，我点错误行**应该跳到出错那一行**。

## 实现决策

1. **审计脚本与验收用例分离**（照 `deep-audit.mjs` / `module-intro.spec.mjs` 先例）：
   审计脚本是报告式（可以带红，红的地方就是待修问题），进仓库但不进默认
   `node --test "tests/js/*.test.mjs"`（要起服务 + 开浏览器）；
   查出真 bug 之后，**为每个 bug 建独立工单**（TDD 守卫 + 反向验证），bug 自己的
   验收用例进 `tests/browser/*.spec.mjs`。
2. **不改生产代码只为好看**：判据一律先「真机复现 + 读源码定根因」，再声明 bug——
   本轮审计脚本自己第一版就有两条 FAIL 是判据误报（见「如实记录」），已按
   `deep-audit.mjs` 文件头的三步自检改掉。
3. **零额度纪律**：需要 LLM 的端点由审计脚本 route 拦截；生成链路只用「题面留空 +
   手输目录 + 自带 main.c」这条零 LLM 路径。
4. **不污染用户桌面**：一律手输临时输出目录（`os.tmpdir()` 下），结束后清理；
   桌面模式的覆盖确认链路用**注入真冲突 400 文案**（与 `GenerationConflictError`
   模板逐字同形）+ 第二次请求放行到真后端来验，不往桌面写东西。

## 测试决策

- `tests/browser/gen-chain-audit.mjs`：报告式审计（P/R/W/X/Y 五节可单跑）。
- 每个真 bug 的守卫：
  - 纯函数 / 结构守卫 → `tests/js/*.test.mjs`（进默认 JS 回归）；
  - 端到端行为 → `tests/browser/*.spec.mjs`（真浏览器）；
  - **反向验证**：临时停用修复，用例必须当场变红。
- 归零回归：全量 pytest + `node --test "tests/js/*.test.mjs"` + 相关 browser spec。

## 范围外

- 推荐区 / 模块说明弹窗（上一轮已覆盖，本轮不碰）。
- 全仓遮罩 `role="dialog"` / `aria-modal`（上一轮已记为全仓欠账）。
- 需要真 LLM 的链路（推荐收敛、骨架生成、修复轮的真实修复效果）——本轮只验其**失败路径**。
