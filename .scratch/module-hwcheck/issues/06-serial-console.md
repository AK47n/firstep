# 06 — 交互式串口控制台（自动一遍 + 命令复测）

**要做什么：** 上电自动跑完一遍之后，程序进入串口命令交互：敲一个字符就能重测对应器件、看回显，**不用重烧**就能边动线边看现象。库内既有的点灯 / 蜂鸣命令语义保持不变，新命令由配方声明。

**被谁阻塞：** 05（配方与探头已就位）。

**状态：** resolved

- [x] 自动一遍照旧（逐件自报 + LED 心跳常驻）；之后进入命令循环
- [x] 命令表由配方生成（每件声明的命令字符 + 固定的帮助命令）；字符冲突在**构建期**报错（不是运行时静默覆盖）
- [x] 既有 `r` / `y` / `g` / `o` / `b<N>` 五条命令**语义一个字节不动**（已上过板的既有行为），新命令只追加
- [x] 回显格式固定（含"这是哪件、测的是什么、结论/数值"三段），并有单测锁定格式
- [x] 无 debug_uart 的构建：只跑自动那遍，检测页**明说**"没有串口 = 不能交互式复测"（不静默降级）
- [x] 命令解析是纯函数（字符串进 / 结果出），单测覆盖：合法命令 / 未知命令 / 多字符参数 / 空输入
- [x] 真机口径：至少一个平台编译绿；交互行为未上板则如实标注

## 边界与决策引用

- 不做串口实时波形、不做上位机（spec 范围外）。
- 控制台形态的既有先例是库内已有的接线检测台，本单是"把它扩成配方驱动"。

## Comments

### 一个必须先定的缝：生成的 main.c 拿不到"学生敲了什么"

库内 `debug_uart` 的接收缓冲是模块内的 `static char cmd_buf[8]`，`debug_cmd_poll()`
自己读它再清空——**生成的 main.c 一个字都看不到**。所以"命令表由配方生成、新命令
只追加"这件事绕不过一个库侧交接面。三种形态摆出来问过用户，**用户拍板 A**：

| 方案 | 取舍 |
|---|---|
| **A. 库侧加 `debug_cmd_peek()` / `debug_cmd_consume()`（选定）** | `debug_cmd_poll()` **一个字节不动**（那五条命令走的还是库内那份代码，两个平台各自的原样）；命令台只"看一眼"再决定认不认领，其余不消费、留给库内 poll。纯增量，对既有工程零行为变化 |
| B. 库侧加回调注册（`debug_cmd_set_handler`） | 主循环更简单，但要改 poll 的分支形状、帮助文案行为随注册变化 |
| C. 不动库、生成侧重写那五条命令 | 两平台既有语义不同（mspm0 只回显），重写就是副本，与 spec「平台差异住在配方数据里、不在渲染器分支里」冲突 |

于是"既有语义一个字节不动"不是一句承诺，而是**结构上不可能被改**：`hwcheck_console.py`
里没有任何一行重写那五条命令的代码（分派树里那一组 `case` 只有 `return;`），
`probe-06-console-behaviour.py` 把**真库源码**编进同一跑做行为证据。

### 三块判据落在哪里

| 判据 | 落点 | 为什么在这 |
|---|---|---|
| 命令表 + 冲突（保留字 / 重复 / 形状） | `hwcheck_console.build_console_table`（纯函数） | 冲突要在**构建期**红：渲染 main.c 与预览载荷都调它，两处都是 400 中文 |
| 一行输入 → 结果 | `hwcheck_console.parse_console_command`（纯函数） | spec 测试决策："域层纯函数（字符串进 / 结果出）"是最高既有缝 |
| C 侧分派 + 帮助 + 三段回显 | `hwcheck_console.render_console_runtime` | 渲染是确定性文本，可逐字断言；顺序（在小节之后）由 `hwcheck.render_main_c` 保证 |

保留字单源 = `LEGACY_COMMANDS`（镜像库内 `debug_cmd_poll` 的分派），有 **parity 守卫**
逐字符核对两个平台的库内源码（库加了第六条命令而这里没跟上 → 当场红）。

### 命令字符的取法（"首字符"口径）

与库内既有命令同一口径：`debug_cmd_poll()` 也只看 `cmd_buf[0]`（所以 `r50` 就是红灯、
`b50` 才把数字当参数）。配方命令是单字符、多打的尾巴忽略、大小写都认（照 `r`/`R`
先例）。"多字符参数"那一格由 `b50`（既有）与 `m12`（配方命令 + 尾巴）两条用例覆盖。

### 逐件命令（真库配方补的 `console` 段）

`led` → `l`、`oled` → `d`、`ml_mpu6050` → `m`（双平台同名），帮助命令固定 `?`
（库内既有提示语本来就是 `? r/g/y/o/b<N>`，沿用同一个字符，不另发明）。
两平台同名的理由：命令表的判据面是**本平台的小节**，同名不会撞（两件之间才查重）。

### 真机判例（本单新增的一条）

**命令台的顺序是功能前提，不是风格问题**：主循环里必须先 `hwcheck_console_poll()`
再 `debug_cmd_poll()`。反过来的话库内 poll 会先把缓冲清空，配方命令永远认不出来
——现象是"敲了没反应、既有命令照常"，且不会报任何错。
`probe-06-console-behaviour.py` 有这条的**真跑反证**（同一份命令台代码，只换顺序，
`l` 就落进库内那句 `? r/g/y/o/b<N>`）。

### 页面那一半

命令表进三个端点共用的 `board` 载荷（`console_payload`：能不能复测 + 那句提示 +
配方命令 + 既有命令 + 帮助字符），前端 `fx/hwcheck.js` 只渲染、不重推判据
（"哪个字符是谁的"只有一个来源）。**没有串口时不摆那张表**，只出那句
"不能交互式复测 + 勾上调试串口再生成"——摆一张这一趟敲不了的表，像"敲了就行"。

## 给后续工单的接口备忘

- **07（通用降级）**：命令表只认"有配方的小节"，通用降级的小节**不带 `console` 段
  = 不进表**（没有字符可敲）。若要给降级件挂复测命令，就在配方里补 `console`——
  `build_console_table` 是纯函数，多一件少一件都不用改它；冲突判据（保留字 / 重复）
  自动覆盖新来的那件。
- **09（pilot 补齐）**：新配方的 `console` 段照 `led` / `oled` / `ml_mpu6050` 的写法加。
  **字符要在整趟内唯一**（两件抢一个 = 预览就 400，不是上板才发现）；库内既有
  `r/y/g/o/b` 与帮助 `?` 是保留字，配方占用会当场红。覆盖率地板守卫若要一并钉命令
  字符，判据读 `build_console_table` 即可（那是唯一一处"谁用哪个字符"）。
- **任何以后改库内那五条命令的人**：`LEGACY_COMMANDS` 是镜像，
  `test_our_legacy_command_mirror_matches_the_library_dispatch` 会逐字符核对
  `debug_uart.c` / `debug_uart_mspm0.c`——**库改了这里就必须跟上**，否则配方可能
  抢走一条既有命令（学生敲 r 不再点灯）。
- **`debug_cmd_peek` / `debug_cmd_consume` 的契约**：peek **只读**（不碰缓冲）、
  consume 才清空。生成侧靠这个分工做"认领"。想让库侧顺手清空 = 既有命令全体
