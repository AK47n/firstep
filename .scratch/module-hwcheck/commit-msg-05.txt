工单 module-hwcheck/05：MPU6050 双平台专精 + 互斥单选交换

让"新到一块 MPU6050 通不通"真正闭环：板上自证判定（stm32 读 WHO_AM_I 比对
0x68；mspm0 官方 DMP 初始化返回 + 探头），mspm0 出三维角度（拆整数 / 小数两次
回显，本平台无浮点显示接口），stm32 出原始六轴并明写"本平台没有姿态解算"。
平台差异住在**配方数据**里，渲染器只剩平台垫片与固定 include 两张表。

库内配方（ml_mpu6050 × 两平台）+ 渲染机制 + 载荷 + 前端选择：

- 新增 `include` 段：器件模块的头（含跨模块前置头如 ml_i2c.h）由配方声明
- 新增 `locals` 段：小节级局部变量声明（探头要把角度搬进变量）+ extern 全局量
  （ax…gz）并入接口清单
- 互斥：载荷带按平台过滤的库级功能组（判据单源 = collect_exclusive_groups），
  检测页「单选交换 + 提示」（用户拍板）
- mspm0 补空 `SysTick_Handler`：DMP 端口自开 SysTick 中断，母版没有服务函数，
  缺它就掉进 TI 启动文件的 Default_Handler 死循环

顺带修掉四条上一单留下的真缺陷（都是不修就交不了差）：

1. 框架 include 不覆盖器件模块 → stm32 真机 7 error（隐式声明 + 标识符未定义）
2. `\xNN` 转义贪婪吃十六进制数字（"±2g" → `\xb12` 越界，ARMCC #27-D）→ 改三位
   八进制，字节不变
3. 配方校验拿当前平台的清单去查所有平台的段 → 平台不对称一出现就误报（mspm0
   预览 400 说 stm32 的 ax 找不到）
4. `_calls_in` 只认小写开头的标识符 → 官方库那些大写函数名（DMP_Init 等）压根
   没过判据，拼错一个字母也不会红

证据（.scratch/module-hwcheck/）：两平台编译矩阵 6/6 全绿（UV4 + gmake，
0 error / 0 warning）；**行为红证** 4/4——把渲染出的那一节用 gcc 真编真跑，
探头值 0x68 → OK + 六轴读数、0x69 → FAIL + 中文排查行且一行读数都没有；判据
强度探针 11/11 注入变红；pytest 4815 passed / 1 skipped；前端门禁 1645 passed；
真浏览器 9/9。**未上板**（本机没有模块与板子）——如实记账，不假装。
