    /* 平台说明：**这里判的是「通路通不通」，不是「传感器准不准」**：读数接近 4095 / 0 只说明引脚与 ADC 通道工作正常；传感器量得准不准要看它的输出范围、分压电路和标定（那是赛题功能层的事）。本检测程序**不做阈值判决**，只回显原始值 + 给正常范围参考。 */
    /* 平台说明：电压怎么算：12 位满量程 4095，Vref = 3V3，所以 电压 ≈ 读数 / 4095 × 3.3 V。**外接电压不要超过 3V3**（超了会打坏引脚）。想跟真值对一遍，拿万用表量同一个点比读数最直接。 */
    /* 平台说明：通道参数怎么给：签名是 `adc_get(ADCx_enum adc, ADCINx_enum adc_channel)`（ml_adc.h 第 33 行）。初始化写绑定宏 `ADC_0_CH` / `ADC_1_CH`（pin_config.h 第 19-20 行，值 = 通道枚举 ADC_Channel_0 / ADC_Channel_1，即 PA0 / PA1）——换引脚只改这两个宏。两路读数写成 `adc_get(adc_i, ch0)` / `adc_get(adc_i, ch1)`：`adc_i` = 用哪颗 ADC（= `ADC_1`），`ch0` / `ch1` = 通道号（= `ADC_Channel_0` / `ADC_Channel_1` = PA0 / PA1），三个变量由本节的 locals 声明、在探头段用强转赋值（`ch0 = (int)ADC_Channel_0` 这类）。**为什么绕这一下**：配方校验的 read 段只认 C 关键字 / 本节变量 / 接口清单里的名字，而枚举常量**不在清单里**（清单只收函数声明 / `#define` 名 / extern 全局量），直接写 `adc_get(ADC_1, ADC_Channel_0)` 会当场判红；变量形是唯一既过校验、又真编得过的写法。 */
