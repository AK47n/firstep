# spec — 代码编辑器 textarea 视口化（窗口文本三明治 + 三层偏移映射）

## 问题陈述

6000 行 .c 打开实测 ~253ms（fetch ~58ms + 渲染 ~195ms），逐键/滚动也已压到
架构上限。拆解表明渲染大头是**浏览器原生 textarea 全量全高**：textarea 装着
108KB 全文、盒子高 12.6 万 px（6000 行 × 行高），打开时浏览器要为这个巨型
原生控件做布局/绘制/命中测试；逐键时 textarea 的任何选区/滚动操作也都发生
在这个巨盒上。高亮层/标记层/行号层早已窗口化（只渲染视口 ~56 行，上下
spacer 撑虚拟高度），唯一没有窗口化的就是 textarea——「三明治」的最底层。

**视觉与交互不变**：用户看到的仍是全量内容可滚动的无限画布（滚动条 = 虚拟
高度 12.6 万 px），视口一次显示多少行由屏幕决定，与现在完全一致。视口化
只改「谁承载光标/输入」这一内部实现，不改「用户能看/能滚到什么」。

## 方案

把 textarea 从「全量全高」改为「**视口高 + 窗口文本**」：

- **盒子**：textarea 高度 = 视口高（滚动容器可视高度），不再 inset 铺满
  12.6 万 px。
- **内容**：textarea 只装当前窗口 [start, end)（视口 ± 上下 overscan）的那
  ~56 行文本（约 1.5KB）；滚动/输入/跳转时窗口切换 → 重装窗口文本。
- **偏移映射（三层）**：模型偏移 ↔ 视图偏移（折叠映射，**复用折叠态既有
  先例**——折叠时 textarea 本就装视图文本、偏移经映射工具换算）↔ 窗口偏移
  （窗口起点绝对偏移 + 行内偏移）。
- **输入回写**：textarea input 的窗口文本变更 → 变更段定位到窗口文本 → 绝对
  偏移 = 窗口起点 + 段偏移 → 折叠映射回模型 → 模型全文更新（同一
  editChangeSpan 判定口径：非结构编辑增量、结构编辑全量折叠重算）。
- **程序化编辑**：缩进/注释/行操作/查找替换/AI 插入等不再走 execCommand
  （其原生撤销栈只认 textarea 全量文本），统一改「模型级编辑 + 窗口重装 +
  快照栈撤销」——大文档（>200KB）直赋值 + 快照栈的既有路径全域化。
- **滚动同步**：scroll 事件 → rAF 节流 → 窗口切换（文本重装 + 光标窗口内
  定位）；textarea 自身禁止内部滚动（窗口文本高度 ≤ 视口，无内部滚动条）。
- **一致性校验与回退**：任何事件后若「textarea 窗口文本」与「由模型推导的
  预期窗口文本」不一致（粘贴/跨窗口/IME 等罕见路径）→ 以模型为准重建窗口
  文本（宁可重装，不可错位）。

## 用户故事

1. 作为用户，我希望打开 6000 行（乃至更大）工程文件秒开（≤80ms），以便
   频繁切换文件不等待。
2. 作为用户，我希望大文件滚动/输入/跳转与现在一样顺滑甚至更快，以便编辑
   体验不因文件变大而变差。
3. 作为用户，我希望视口化后看到的内容、滚动条、行号、当前行、查找跳转、
   折叠、AI 插入、保存与现在完全一致（视觉零回归），以便无感升级。
4. 作为用户，我希望深浅主题、缩放（100/150/200%）、折叠态组合仍三层对齐，
   以便视觉可信（对齐矩阵 12 格守卫不回退）。
5. 作为用户，我希望撤销/重做在窗口切换、折叠、程序化编辑后语义正确，以便
   不丢稿。

## 实现决策

- **模块划分照旧**：纯映射/拼接/校验逻辑进 fx 纯件（node 单测）；
  DOM 胶水（窗口同步、滚动节流、输入回写）留 ui。
- **建模为三层偏移**：窗口起点（全量文本绝对偏移数组 = 既有 lineStarts
  的窗口切片）、视图层（折叠映射既有工具）、模型层（tab.content）。新增
  纯件：窗口文本构建（模型/视图 → 窗口文本 + 偏移表）、窗口编辑映射
  （窗口文本变更 → 绝对变更段）、一致性校验（模型推导窗口文本 = 实际）。
- **折叠组合**：折叠态 = 视图文本 ≠ 模型文本；窗口文本在视图文本上切。
  映射链：模型 → 视图（折叠）→ 窗口（切片）；回写反向。占位行（折叠
  省略符）在窗口内时按既有折叠渲染语义处理（textarea 装占位文本，输入
  触碰占位 → 展开，既有语义保留）。
- **撤销**：程序化编辑与普通输入统一走模型级快照栈；不再依赖原生撤销栈
  （窗口文本的原生撤销只有局部意义，且跨窗口必错乱——明确放弃，快照栈
  全域接管；大文档直赋值 + 快照栈为既有先例，风险已知可控）。
- **输入法（IME）**：compositionstart/end 既有保护沿用；composing 期间
  禁止窗口切换/重装（避免组合中途内容被换）。
- **滚动**：窗口切换仅在「窗口行区间变化」时发生（不是每次 scroll 事件）；
  rAF 节流 + 行区间比较；快速滚动直接跳到目标窗口（不逐帧重装）。
- **性能验收**：打开 6000 行 ≤80ms（从 ~253ms）；逐键热路径 ≤25ms 不回退
  （当前 ~21-25ms）；滚动每事件 ≤10ms 不回退；内存下降（textarea 全文
  108KB → 窗口 1.5KB）。
- **不引入第三方内核**（Monaco/CodeMirror 依旧范围外）。

## 测试决策

- **最高既有缝 = node --test tests/js/** fx 纯件：窗口文本构建/偏移表往返
  一致、窗口编辑映射与「模型直接编辑」逐字节一致（插入/删除/跨窗口/折叠
  组合/占位行）、一致性校验（错位 → 可检出）、快照栈在窗口切换下的
  撤销/重做语义。
- **交互行为 = CDP 探针**（既有 probe/smoke 先例）：打开 ≤80ms 计时、
  逐键/滚动采样、上下界快速滚动、跳行（大纲/搜索/查找）、折叠开合、
  复制粘贴、IME（手动样例）、撤销/重做、保存；矩阵 = 缩放 100/150/200% ×
  折叠开/关 × 深浅主题（对齐守卫 12 格全绿）。
- **视觉回归**：双主题截图对比（打开首屏、滚动中部、折叠态）存档 `.scratch`。
- 后端零改动；pytest 全量跑一次。spec / 工单 / 提交信息中文照旧。

## 范围外

- 替换 textarea 为 contenteditable/canvas 自绘、Monaco/CodeMirror 内核、
  多光标、列选择、小地图（沿用既有范围外）。
- 打开延迟中 fetch ~58ms（后端文件读取 + outline 扫描）——零后端预算，
  本轮只优化前端渲染段；若需再压由后端另行立项。
- 不等高行（折行字体、CJK 全角宽度）的精细宽度模型——维持既有 mono
  等宽近似。
- 视觉/交互层任何改动（本 spec 明确「视觉零回归」）。

## 补充说明

- 风险等级：**架构级**（改三明治最底层 + 全部写路径）。对策：①纯逻辑
  全部 fx 化单测；②三层映射以「模型为唯一事实源」，textarea 只作输入/
  光标代理（可随时重建）；③一致性校验兜底；④CDP 矩阵回归；⑤分 5 个
  纵向切片（见工单），每个切片可独立验证、可回滚。
- 与既有折叠映射的关系：折叠态已经是「textarea ≠ 模型文本」的先例且线上
  稳定运行——视口化是同一思想再进一步（视图 → 窗口），两者组合时映射链
  变长，但每一环都是既有模式的复用。
