# 代码编辑器利用优化（生成页↔代码栏联动补齐 / 查找替换 / 烧录入口）

> 会话/系列 slug：code-editor-utilize。立项 2026-09-01（用户：「分析 firstep 中代码编辑器利用情况」→ 全选改进方向并授权「你自己决定，决定好了之后直接一条龙做完」）。

## 问题陈述

代码编辑器（「代码」tab）已深度利用（双向跳转桥 / 磁盘基线 / AI 对话与 diff 应用 / 编译与错误定位 / 树操作 / 写盘守卫 / 保存冲突），但仍有几处「就差一步」的断点：

1. 生成页结果区的自动附带产物（设计报告草稿.md / 演示脚本.md）chips 点击只复制路径——用户想直接看/改却要手动去资源管理器打开。
2. 步骤 8 工具栏唯一入口「查看工程」只打开整个目录（文件树），没有「直接打开 main.c 到编辑器」的精确入口；新手指南描述的「第 8 步『编辑源码』直接切到代码栏打开该 main.c」与实际行为（打开整个目录）不符。
3. 编辑器当前文件内查找（Ctrl+F）只能找不能替换，批量改名/改数值只能手动逐个改。
4. 代码栏没有烧录入口——「改代码 → 编译 → 烧录」闭环要在代码栏与生成页之间来回切。

## 方案

1. 结果区产物 chips 点击行为从「复制路径」改为「在代码栏打开该文件」（在代码 tab 打开目录并直接打开该产物文件；.md 默认预览态，可切编辑）。
2. 步骤 8 工具栏新增「编辑 main.c」精确入口（在代码 tab 打开 main.c 并聚焦编辑），保留「查看工程」；同步修正新手指南文案，使描述与实际实现一致。
3. 文件内查找补「全部替换」：查找行下增加替换输入与「全部替换」按钮，另配 Ctrl+H 快捷键唤起；替换按「模拟手输」路径落进编辑缓冲（脏点出现，需用户 Ctrl+S 保存），只读标签拒绝替换。
4. 代码栏状态栏新增「烧录到板子」按钮 + 底部「烧录」结果面板（复用编译面板观感）；烧录执行体直接复用现有共享烧录逻辑（探针名通用文案），烧录前自动保存全部脏标签（同编译语义）；编译通过后 toast 提示「可烧录」，衔接「改-编译-烧录」闭环。

## 用户故事

1. 作为生成页用户，我想要点击结果区产物 chips 直接跳「代码」栏打开该文件，以便生成完立刻查看/编辑设计报告草稿与演示脚本，而不是复制路径后手动找。
2. 作为生成页用户，我想要步骤 8 的「编辑 main.c」一键在「代码」栏打开 main.c，以便从骨架编辑无缝过渡到完整工程编辑。
3. 作为生成页用户，我想要「查看工程」与「编辑 main.c」两个入口并存且语义清楚，以便按意图选择（浏览整个工程 vs 直接改 main.c）。
4. 作为新用户，我想要指南描述与实际行为一致，以便不被误导。
5. 作为代码栏用户，我想要查找时一键「全部替换」当前文件匹配项，以便批量改引脚名/数值而不必逐个手动改（替换进编辑缓冲、可 Ctrl+S 落盘）。
6. 作为代码栏用户，我想要 Ctrl+H 直接唤起替换（如同 Ctrl+F 唤起查找），以便不离开键盘。
7. 作为代码栏用户，我想要状态栏「烧录到板子」按钮，以便改完/编译完不必切回生成页就能烧录。
8. 作为代码栏用户，我想要编译通过后收到「可烧录」提示，以便按「改-编译-烧录」顺序推进。
9. 作为代码栏用户，我想要烧录前自动保存全部未保存文件（与编译一致），以便烧录的内容就是当前编辑的内容。

## 实现决策

- **打开桥扩展**：`openCodeViewer(dir, filePath?)` —— filePath 非空时，目录加载完成后再打开该文件（复用现有打开/激活标签逻辑）。chips 与「编辑 main.c」按钮共用此桥，不新增目录加载路径。
- **产物 chips 行为变更**：点击 = 打开（不再复制路径）；chip 提示文案同步更新（「复制路径」注释与实现一并移除，理由：内置代码编辑器已取代「本地应用不引后端打开接口」的旧限制，打开即达，路径在编辑器内可见）。
- **替换纯件**：新增 `replaceAllText(src, needle, replacement) → {count, value}`（纯函数，放编辑器 fx 域）：空查找串 → count 0 且原样返回；无匹配 → count 0；有匹配 → 全部替换并返回次数。UI 层 `replaceAllInActiveFile(needle, replacement)`：只读标签 / 无活动标签 / 无匹配 → 0 且不改；有效时走既有「模拟输入」路径（改 textarea 值 + 同步高亮/行号/脏点/标签条），光标置于文件尾——与用户手输同语义，不自动写盘。
- **替换 UI**：查找行下方增加替换行（替换输入 + 「全部替换」按钮）；`Ctrl+H` 与 `Ctrl+F` 同口径（仅「代码」tab 内截获、.md 预览态先切源码、展开侧栏并聚焦替换输入）。
- **烧录入口**：状态栏新增「烧录到板子」按钮；底部新增烧录结果面板（头部「烧录」+ 状态位 + 收起按钮 + 结果容器，视觉复用编译面板样式）；执行体复用现有共享烧录逻辑（`flashRunShared`），平台参数传空 → 通用探针文案（烧录平台由后端从产物树反推，前端探针名仅展示用途）；烧录前自动保存全部脏标签（取消/冲突则中止，同编译）。
- **编译→烧录联动**：编译通过后 toast 提示「编译通过——可点状态栏『烧录』写入板子」。不做自动烧录、不做按钮禁用联动（用户可能跳过编译直接烧录——保留自由）。
- **guide 文案修正**：指南「与第 8 步联动」条目改写为与新入口一致（「编辑 main.c」直接打开 main.c；「查看工程」打开整个目录）。

## 测试决策

- **纯函数单测（node --test tests/js/ 既有先例）**：`replaceAllText` 在编辑器 fx 单测文件增测（空针/无匹配/单处/多处/替换含特殊字符/替换为空串）；新 fx 导出登记进 fx-guard 全域表。
- **交互冒烟（CDP，既有先例：.scratch/<slug>/smoke-*.mjs + headless Chrome）**：① 结果区 chips → 代码 tab 激活且产物文件标签打开；② 步骤 8「编辑 main.c」→ 代码 tab 激活、main.c 标签打开且为活动标签；③ 查找替换：打开文件 → 侧栏输入查找与替换 → 点「全部替换」→ textarea 值与活动标签内容断言 + 脏点出现（不保存，验证后关标签弃改）；④ 烧录：状态栏按钮点击 → 无产物/无工具 400 → 烧录面板打开且渲染指引卡（**绝不触发真实烧录**——样本目录无产物）。
- **回归**：完成后跑 `node --test tests/js/` 全量 + 既有 CDP 冒烟点（三栏布局/状态栏宽度）抽查，确保 565 窄视口状态栏新增按钮不回归竖排问题。

## 补充说明

- 本批 4 项均不改后端 API（桥/替换/烧录全部复用现有端点：/api/code/file、/api/code/tree、/api/flash 与既有保存链路）。
- 烧录冒烟以「无产物目录 → 400 指引卡」路径验证 UI 链路，真实烧录由用户在有板子环境验证（与 flash-deploy/02 冒烟同策略）。
