# 05 — 进度说人话：剩余时间人话化 + 弱网提示 + 重试可见 + 两种失败话术

**要做什么：** 让用户一眼分得清「**慢**」「**在重试**」「**真失败了**」——
现在这三种在界面上长得几乎一样（都是进度条不动 + 一行原始异常）。

**被谁阻塞：** 04（`retrying` / `retry_count` / `error_kind` 三个字段就位）。

**状态：** ready-for-agent

- [ ] `static/js/fx/core.js` 新增共享格式化 `fmtEta(sec)` →
      「约 12 分钟」/「约 1 小时 20 分」/「不到 1 分钟」（**复用既有 `fmtDuration` 的词形**，不另起一套）。
- [ ] `static/js/fx/full-update.js`：
      - 剩余时间由「剩余 N 秒」改 `fmtEta`；
      - 速度低于 50 KB/s 时补「**网络较慢**」（与「断了」区分开）；
      - `retrying` 为真时进度区明写「正在自动重试（第 N 次），从 X% 接着下」；
      - 完成行在有重试时补「（下载中自动重试 N 次）」——让「它自己扛过去了」这件事留下痕迹。
- [ ] `static/js/fx/materials-update.js` 同一套口径；顺带修掉它现在显示 `done / total 字节`
      的原始数字（与完整包用 `formatSize` 不一致）。
- [ ] **两种失败话术分开**：
      `error_kind == "verify"` → 校验失败 + 明确「重新下载也不会有变化」；
      其余（`network` / 空）→ 网络失败 + **已下载百分比** + 「点击重试会从这里接着下」。
- [ ] 纯件测试（`tests/js/`，沿用既有 `node --test` 形态）：
      `fmtEta` 边界（0 / 59 秒 / 60 秒 / 59 分 / 60 分 / 极大值）；
      进度 HTML 在「慢」「重试中」「verify 失败」「network 失败」四态下的关键文案在场与**互斥**
      （不许出现两种话术同时在场）。
- [ ] 真机目视：8020 沙箱里对**真实下载态**截一张进度区（含重试），
      证据落 `.scratch/resumable-download/verify-05-ui.txt`。

## 备注

- 前端**不许解析 `error` 文案**来分类（分类只认 `error_kind`）——这条写成断言。
- 「网络较慢」的阈值（50 KB/s）是**显示阈值**，不参与任何判定逻辑：慢不等于失败，重试与否只由是否真断决定。
