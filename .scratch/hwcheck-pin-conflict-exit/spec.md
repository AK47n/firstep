# spec — 检测页在 mspm0 默认双通道下不再必 400（工单 01）

## 问题陈述

学生打开「硬件检测」栏目、选 mspm0、什么都不改就点「生成检测工程」，得到的是
一句他没法执行的 400：

```
mspm0 引脚冲突：… · PA22：oled（…角色 oled.OLED_SPI_RES）× debug_uart（…角色 debug_uart.DEBUG_UART_RX）
出路：在引脚配置里改绑上述角色（或点「自动配置」一键解开）…
```

检测页**没有**引脚配置入口，「自动配置」按钮长在赛题页上。同一时刻页面上写的是
「生成时若报引脚冲突，请先只勾一个通道再生成」——即产品把母版默认布局的账
算到了学生头上。同一类病还有第二处：选 `adc`（以及 us016 / mq2 / flame /
ir_distance 等十几件共读 ADC12_0 的件）时，母版里属于**没选中的**模块的那几根
ADC 脚仍在落盘 syscfg 里占着，冲突求解器看不见它们（「角色未登记」），于是
`adc` / `xunji` 两格在矩阵里进不了板。

## 方案

两件事一起做，因为它们是同一个缝的两侧（**落盘 syscfg 的引脚判据**）：

1. **孤儿 ADC 槽位让位**：按选中集裁剪时，未被本趟任何模块声明的 ADC12_0 槽位，
   一旦它占的脚与**本趟已声明角色（含改绑后）**撞上，就把该槽位改成与已声明的
   槽位共读同一 ADC 通道，并撤掉它的 `adcPinN.$assign` 行——「薄封装共读同槽」
   的既有先例。没撞上的孤儿槽位保持原样（今天就是这样，且构造上再也不会挡住生成）。
2. **检测页自动解冲突**：检测页在预览与生成前跑一次与赛题页「自动配置」**同源**的
   求解器（`auto_assign_bindings(resolve_default_conflicts=True)`），把默认脚撞脚
   提前解开；动了哪几根线如实打在页面上，并随 `bindings` 进生成内核——
   接线表与工程 README 因此跟着变（学生照表接线）。仅 mspm0 自动搬
   （stm32 的默认重叠按 ADR 0010 是提示语义，不动，避免逐字节回归）。
   预览与生成吃**同一份判据**：装不下时两边都 400，且文案是检测页能执行的出路。

## 用户故事

1. 作为学生，我想在检测页选好平台与器件后直接点生成，不必先去赛题页改引脚，以便把注意力放在接线上。
2. 作为学生，我想在生成前就看到「这一趟动了哪几根线」，以便照着新脚接线而不是照原厂例程。
3. 作为学生，我想让页面上的接线表与工程 README 的接线表说同一组脚，以便两处对照不会打架。
4. 作为学生，我想在选了 adc / 超声 / 气体 / 火焰这类模拟件时也能生成，而不是被一句「角色未登记」挡住。
5. 作为学生，我想在组合真的装不下（9 件同堂）时看到「为什么装不下、该去掉哪几件」，而不是一句指向别的页面的出路。
6. 作为学生，我想在预览阶段就看出这组选择生成不出来，而不是预览通过、点生成才失败。
7. 作为维护者，我想让「同一根脚被两只实例抢」只有一个判据（落盘 syscfg），门禁、写侧与检测页共用它。
8. 作为维护者，我想让 `adc` 与 `us016` 这类「共读同槽」组合继续被当成合法共享，而不是被自动配置把模拟输入脚悄悄搬走。

## 实现决策

- **判据新增一处**：`mspm0.syscfg` 落盘文本的同脚冲突报告从 `generator._check_syscfg_pin_conflicts`
  抽成可复用函数（`syscfg_prune.syscfg_pin_conflict_report`），门禁（抛既有
  `SyscfgPinConflictError`，文案逐字节不变）与检测页（抛 `HwCheckError`，文案换成
  检测页出路）共用；引脚容量诊断（`pin_capacity`）留在其内。
- **裁剪新增一个入参**（`SyscfgModel.prune(..., adc_plan=AdcSlotPlan)`）：
  `claims` = 实例 → 本趟声明的 ADC MEM 槽位（role id 尾 `_CH<N>`，单源
  `syscfg_model.adc_mem_index`）；`occupied` = 本趟所有已声明角色的**生效脚**
  （默认 ∪ 绑定）。两处判据由 `syscfg_prune.adc_slot_plan()` 一处装配，
  门禁与写侧（`pinwriter.apply_pin_bindings`）传同一份。
- **让位机制**：孤儿槽位的 `adcMem<N>chansel` 改指已声明槽位的通道，`adcPin<C>.$assign`
  行撤掉——真机 SysConfig CLI 实证（`.scratch/hwcheck-pin-conflict-exit/recon-syscfg-lab.txt`）：
  **只删 `$assign` 行不够**（SysConfig 按 chansel 把脚认回来、照样 Resource conflict），
  必须连通道一起改成共读。被让位的槽位在模型里记成「跟随」已声明槽位，
  绑定时跟随改写（`SyscfgModel.adc_followers`）——否则已声明槽位改绑换通道后，
  被让位槽位会回到一个没有显式落点的通道、靠 SysConfig 隐式分配，门禁看不见。
- **共读同槽是合法共享**：`pin_bindings._role_resource_keys` 补 adc 分支
  （同 `INSTANCES_BY_SLUG` = 同一 ADC 实例 ⇒ 同一物理通道 ⇒ share）。
  不补这一支，`auto_assign_bindings` 会把共读同槽的件当成冲突搬开——
  实测 `us016.US016_OUT_CH0 → PB24`（等于悄悄换掉模拟输入脚），
  而十几件薄封装件（adc/us016/mq2/mq3…/ms1100）默认都在 PA24。
- **仅 mspm0**：`resolve_default_conflicts` 只对 mspm0 开；stm32 走原路径（零变化）。
- **检测页留出三档出路**（文案单源在 `hwcheck_board`）：① 少选一件（附引脚容量诊断的
  「至少要去掉 N 个模块」与冲突模块名）；② 只勾一个输出通道；③ 想去赛题页改绑也行，
  但作为第三条而不是唯一一条。
- 检测页的 `project`（回读）端点**不跑**可解性判据：它回放的是已经生成成功的那一次，
  没道理因为后来换了库就让人打不开；预览与生成两端判据同源。

## 测试决策

- 判据测试落在既有缝上，不新开：
  - `tests/test_syscfg_model.py`（若在）/ `tests/test_module_adc.py` 同族：孤儿槽位让位、
    没撞上则不动、被让位槽位跟随改绑、无 plan 时逐字节不变；
  - `tests/test_generator.py`：门禁文案逐字节不变 + 让位后真机组合不再报错；
  - `tests/test_pin_bindings.py`：共读同槽判 share 不判 conflict（反向验证：去掉
    adc 分支后 `us016` 会被搬走）；
  - `tests/test_hwcheck.py`：mspm0 默认双通道端点从 400 变 200、`pin_fixes` 如实、
    预览与生成判据一致（同一形态两边都 200 / 都 400）、装不下时文案含三档出路；
  - `tests/js/hwcheck.test.mjs`：引导文案不再教「只勾一个通道」而是「已自动移开 + 如实列出」。
- 真编译回归：`.scratch/module-hwcheck/probe-09-compile-matrix.py`
  （`mspm0 adc` 与 `mspm0 xunji` 从「生成前拦下」变「能生成 → 0 error / 0 warning」；
  「生成前拦下」一节只收**没有页面出路**的形态——`全选 9 件` 属物理不可实现，
  带页面出口，单列一节并附文案证据）。

## 范围外

- 检测页最小改绑入口（工单候选修法 2）——本单不做。
- `auto_assign_bindings` 换成完整分配求解（全选 9 件仍物理不可实现）。
- 给 `adc` 模块 mspm0 补声明 `ADC_CH1`（会让每份选 adc 的工程 README 多一行、
  并动全库引脚表）——本单不做，孤儿槽位只在撞脚时让位，配方第二路仍真读 PA26。
- 赛题页引脚配置 UI 的任何改动。
- **器件在本平台没有条目**时预览 200 / 生成 400 这处差异**有意保留**（评审提出
  的对齐项）：两边判的是同一件事（这一件在本平台测不了），预览必须留在 200——
  它还要把其余器件的接线表画出来，而 `wiring.missing` 点名本来就是 200 级载荷
  （工单 module-hwcheck/03「点名，不静默省略」）。判据一致性由用例
  `test_missing_platform_device_is_judged_by_both_endpoints` 钉住（两边点同一件、
  同一句理由），不是靠两边返同一个状态码。

## 补充说明

拍板记录（用户："你好好想想做决定"）：缺陷 A 取「自动解冲突」（不另做改绑入口、
不改默认只勾串口）；缺陷 B 取「孤儿槽位跟随选中集共读同槽」，且**只让位真撞上的
槽位**——一律让位会把 `adc` 配方第二路（MEM1 = PA26）改成共读 PA24，
检测程序就会打印「ADC_CH1（PA26…）」而实际读 PA24，正是本功能禁止的「假装测过」。
