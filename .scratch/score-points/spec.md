# 评分点验收清单

## 问题陈述

新赛题的评分标准通常已经包含在题面中，但当前推荐链路只提取功能需求与模块覆盖关系，不把评分点、分值和原文依据结构化展示。学生拿到生成工程后，需要重新翻阅题面确认基础分与发挥分，容易遗漏评分项；后续 AI 也无法直接获得一份与题面对应的验收清单。

## 方案

在现有 `select_modules` 推荐调用中并入可选的评分点输出。评分点与功能需求同读题面、同走现有收敛与重试机制，不新增独立 LLM 调用。解析结果作为推荐结果的一部分向后端、前端和生成产物传递。

首版评分点只表达题面事实，不承担功能设计或模块推荐：保留题面顺序、分区、描述、分值和原文句号引用。分值无法量化时保留评分点并使用 `null`；无法确定分区时使用 `unknown`；无法关联句子时使用空数组。题面没有评分表或解析失败时不阻断推荐和生成，评分清单缺省不展示。

## 用户故事

1. 作为参赛学生，我想在确认模块推荐时看到评分点清单，以便在生成工程前知道基础分与发挥分分别要求什么。
2. 作为参赛学生，我想看到每个评分点对应的题面句号，以便快速回查原文而不是相信模型自行概括。
3. 作为参赛学生，我想在生成后的 README 中继续看到评分点，以便拿到工程后按清单逐项验收。
4. 作为参赛学生，我想在交接提示词中带上评分点、分值、分区和句子引用，以便后续 AI 能围绕评分要求继续协助。
5. 作为使用旧推荐缓存的用户，我想在没有评分点字段时继续正常使用已有推荐结果，以便新增字段不破坏历史缓存。
6. 作为使用不含评分标准题面的用户，我想继续完成模块推荐和工程生成，以便评分点只是增强能力而不是主链硬门禁。
7. 作为维护者，我想让评分点解析与功能需求共用题面句子编号和收敛机制，以便避免多次读题造成内容漂移。

## 实现决策

- 评分点作为推荐结果的可选字段并入现有推荐链路，不新增独立 LLM 操作。
- 评分点字段形状固定为：
  - `id`：稳定的评分点序号或标识；
  - `part`：`basic`、`development` 或 `unknown`；
  - `description`：评分点描述；
  - `score`：整数或小数，无法量化时为 `null`；
  - `sentence_refs`：题面句号数组，无法关联时为空数组。
- 评分点按题面原文顺序保存和展示，不按分值重排。
- 评分点不要求与功能需求一一对应；功能需求继续使用现有逐句对照机制。
- 旧推荐缓存缺少评分点字段时按旧格式正常读取，前端、README 和交接提示词均不显示评分清单。
- 评分点解析异常、评分表缺失、字段为空或句子引用为空均不阻断推荐与生成；异常路径按现有可选增强信息的降级口径处理。
- 推荐结果区域与现有功能需求、模块推荐结果并列展示，首版只读，不增加主流程步骤，不允许前端编辑回写。
- README、生成结果摘要和交接提示词均使用同一份评分点结构化数据；没有评分点时保持既有输出不变。
- 交接提示词完整输出评分点描述、分值、分区和句号引用；没有引用时显示未关联原文。
- 不引入新的硬件角色、模块底座、离线模式、工程历史或独立评分清单文件。

## 测试决策

- 以推荐结果的外部行为为主：完整评分点被保留、字段规范化、题面顺序保持、缺失和异常可降级、旧缓存可读取。
- 以生成产物的外部行为为主：有评分点时 README 和交接提示词包含完整清单，无评分点时输出与旧行为一致。
- 以页面载荷和展示行为为主：推荐结果可看到只读评分点，旧载荷或空清单不显示异常面板。
- 复用现有推荐解析、收敛、缓存、README 渲染、交接提示词和前端推荐结果测试缝；仅在现有缝无法覆盖评分点结构时新增专项测试。
- 测试整数、小数、`null` 分值，三种 `part`，空引用，题面无评分表，模型输出缺字段，解析失败和旧缓存缺字段等边界。
- 不以 LLM 具体措辞作为稳定测试依据；模型响应使用固定 fake，断言解析后的结构与最终用户可见产物。

## 范围外

- 不新增独立评分点 LLM 调用。
- 不让评分点替代功能需求、模块推荐或逐句对照。
- 不强制评分点与模块、功能需求或代码函数绑定。
- 不实现评分点编辑、人工修正、持久化版本迁移或单独评分清单文件。
- 不根据评分点推断题面没有明确写出的分值、功能或模块。
- 不实现演示脚本；演示脚本可在评分点链路稳定后另行立项。
- 不处理工程历史、离线生成和工程问答。

## 补充说明

评分表确定性保留在赛题文本中，解析只消费题面，不修改题面原文。评分点是验收辅助信息，任何评分点层面的失败都必须让原有推荐和生成主链继续可用。
