# 母版提炼 v2 — 判定模型改造（ADR 0001 / 0002 实施）

## Scope

把母版提炼的判定从"出现范围分类"升级为"内容判据"，并落实"空的最小系统板工程"目标：

- 判定唯一判据：读文件内容后判断**是否通用、是否基础建设必需**，不看重复次数（ADR 0001）
- AI 判定两阶段：先逐文件读全文出摘要 → 再基于摘要判定
- 动作词表收敛：公共文件进判定（keep 默认倾向 / exclude）；冲突文件 merge / exclude；merge = 读多份 → 分析 → **整合出通用版本**（选一份是特例），产物全文 + 说明进报告
- 已知残留（构建产物 / 备份 / 临时文件）机器识别、确定性剔除，但进报告 exclude 清单 + 规则化原因
- 母版 = 空的最小系统板工程：基础设施文件齐全 + **确定性模板 main.c**（时钟初始化 + while(1) + TODO），能直接编译烧录（ADR 0002）
- 报告形态：判定清单（带原因）+ 整合产物（全文 + 说明）+ 残留清单 + 模板 main.c 预览 → 用户一次确认

## Out of Scope（后续拓展，本 spec 不实现）

- 驱动 .c/.h 文件的通用提炼与整合（业务代码现一律剔除）
- AI 基于保留头文件生成骨架 main.c（机制已有 skeleton.py，暂不用于母版）
- 上传题目 → AI 理解 → 模块库推荐 → 生成带模块代码的完整路线
- UI 层（沿用工单 08 约定：后端核心先行，端到端 UI 由生成流程工单统一装配）
