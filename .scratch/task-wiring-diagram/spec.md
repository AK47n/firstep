# 任务卡接线图（task-wiring-diagram）

> 状态：已与用户澄清（三个方向均确认推荐项）——2026-xx-xx

## 问题陈述

任务推进的每一步执行后，AI 在步骤报告里用一段中文文字告诉学生「接下来要做什么」（`user_action`，如「把 PA0 接到灰度模块的 DIO，注意极性；8 路按 HUIDU 宏序接……」）。这段文字往往一长串，接线信息藏在句子里，学生要逐句读、自己脑补「哪根线接哪」，容易看漏、接错。用户希望能用**图**来表达接线要求——图上一眼看到「板子哪个引脚、连到模块哪个端子」，比文字清楚得多。

## 方案

任务卡（与结果面板）上为每步报告新增一块**接线图**：「下一步要做」框内顶部放图，原文字保留在下方（图文并存）。

接线图 = **开发板俯视图 + 连线**：
- 复用既有板定义（两块板：STM32F103C8T6 蓝药丸 / MSPM0G3507 地猛星，每根引脚有精确坐标）；
- 本步涉及的每根线从板引脚焊盘画一条线，连到图右侧的**模块端子标签**（如「灰度 DIO」「OLED SCL」「电机 AIN1」）；
- 本步的线高亮彩色，工程其余接线若有则淡显（可折叠「显示全部接线」）；
- 端子标签带说明（如「必接」「类型」）。

数据纪律（项目铁律：AI 输出不可信）：
- **图的所有形状、坐标、端子名都由确定性数据渲染**（板定义 + 接线单源），AI 无法画图；
- AI 只在步骤报告里**引用**本步涉及的引脚名/端子名（结构化字段），后端查表校验，非法条目丢弃；校验全丢时回退；
- 接线行数据与 README「引脚接线表」**同源**（同一个数据推导函数），图上不会出现与表格矛盾的线。

退化路径（保证任何情况不比现在差）：
1. 正常：wiring 字段合法 → 画出本步接线图；
2. 无 wiring 字段/全是非法 → **优先按本步资源标定接线图**：任务拆解时 AI 已标的 `resources`（真实引脚名/模块 slug）∩ 工程接线行（快照或 README 兜底，与 README 同源）→ 反推「本步涉及的线」并画接线图（caption 注明「按引脚资源标定」，区别于 AI 引用的本步接线）；`resources` 全是引脚名时逐根引脚命中接线行（每根线接哪个模块端子由工程数据决定，图上有明确端子标签）；
3. 上述反推无行可命中（resources 为供电/板载资源/外设名等无接线行项）→ 按本步资源在板图上高亮相关引脚（资源总览已有同款能力）；
4. 旧目录无接线清单文件：**读取侧从 README「引脚接线表」（与快照同源——README 表由同一推导渲染，解析即恢复）+ 工程上下文 platform + 静态板定义重建接线数据**，走 2；README 无表/上下文缺 platform/板定义缺失 → 按 3；都无 → 只显示原文字（现状行为）。

## 用户故事

1. 作为学生，我每步执行完想在结果面板看到这一步的接线图（板图 + 引脚连到模块端子），以便不用通读长文字就知道该接哪几根线。
2. 作为学生，我想在任务卡「下一步要做」框里看到同一张图，且下方保留原文字，以便卡上对照接线又不丢细节（极性/顺序/注意事项）。
3. 作为学生，我想本步的线用高亮色、其它不相关的线淡显（或不显示），以便聚焦本步。
4. 作为学生，我想图上端子标签直接写「模块+端子名」（灰度 DIO、OLED SCL），引脚用板子丝印名（PA0、PB6），并带必要说明（必接/类型/供电），以便不猜、不翻表。
5. 作为学生，我想电源线（3V3/GND/5V）在图上用不同颜色，以便快速识别供电部分。
6. 作为学生，当接线很多（本步骤涉及十根以上或要看全量）时，我想图能折叠/展开「本步 / 全部接线」，以免图挤成一团。
7. 作为学生，当本轮报告没有接线标注（AI 没给/校验失败/历史目录没有接线文件）时，我想仍能看到有接线关系的图——**按本步资源标定的接线图**（资源引脚 ∩ 工程接线行），接线行可从 README 同源兜底恢复；实在无接线数据时按资源高亮引脚，或至少与现状文字一致，不应报错或空白。
8. 作为用户，我绝不想要 AI 自由画出来的图（形状/坐标幻觉）——图必须由工程数据决定，AI 只能引用名字。
9. 作为开发者，我希望接线行与 README「引脚接线表」/ 报告草稿「引脚分配表」出自同一推导函数，维持「接线单源」，防表格与图漂移。
10. 作为开发者，我希望新协议字段向后兼容：旧任务清单（无 wiring 字段）读取正常、按退化路径处理。
11. 作为学生（辅助），我想每根线上可附简短 note（如「极性注意」），有则显示、无则不占空间。

## 实现决策

- **接线单源落盘**：生成工程时，与 README 同批数据（平台、模块清单、已解析绑定、实例计划）额外落盘一份接线快照文件（如 `.contest_wiring.json`）：内容 = {version, platform, board_id, board（板定义内嵌，含引脚坐标/丝印/固定资源）, rows（= 既有 `_pin_rows` 推导输出的行：模块 slug / 角色 / 生效引脚 / 说明，含多实例通道行）}。**内嵌板定义**使运行期一次读取全齐，不再二次请求。落盘点 = 生成路由写 README 的同一位置。旧目录无此文件 → 后续按退化路径。
- **步骤报告协议扩展**：`StepReport` 增加可选字段 `wiring: [{pin, target, note?}]`（缺省空数组；空 = 本步无物理接线）。语义：本步执行后需要连接的线，「pin」= 板引脚名，「target」= 模块端子/板载资源名。系统提示词约束：只能引用模块接口清单与板定义里的真实引脚/端子名、每根线一条、中文 note 可选。
- **校验（后端纯函数）**：
  - pin 合法 = ∈ 板定义 pins 的 name 集合（含 power/gnd/reset 类引脚，供 3V3/GND/5V 供电线）；
  - target 合法 = ∈ 本工程模块 manifest 端子名（声明 id；label 不同时也接受 label）∪ 板定义 fixed 资源名 ∪ 引脚名自身（板内直连场景）；
  - 逐条校验：非法条目丢弃；剩余 ≥1 条才写入迭代；全丢 = 按空处理（走退化路径）。该函数与 LLM 层解耦，可单测。
- **落盘与读取**：wiring 随步骤报告写入该轮迭代记录（缺省空，旧清单读取兼容零改动）；读取侧条目级容错（坏 JSON → 空，不 500）。
- **前端渲染（fx 纯函数，无副作用）**：新增接线图渲染模块：
  - 板图几何与既有资源总览板图**同常量**（行高/板宽/焊盘坐标换算一致，沿用「两处同常量、交叉同步注释」的既有约定；三处几何常量抽取单源列为范围外）；
  - 画板壳 + 焊盘 + 地标（复用既有画法常量），右侧扩展端子列（每根线一个端子盒：模块名 + 端子名 + note/说明），从引脚焊盘画线到端子盒左侧中点；电源类线用独立配色；highlight 高亮本步线，非高亮淡显；
  - 空态/退化文案（无数据、板定义缺失等），全部输出转义。
- **装配与展示位置**：
  - 结果面板步骤报告块内、任务卡「下一步要做」粘性摘要框内，各渲染同一张图（图文并存：图 + 原 `user_action` 文字）；
  - 数据装配 = 现有任务推进前端已透传 `outputDir`（烧录按钮同款路径）→ 新增读取接线快照的接口 + 任务迭代里的 wiring；
  - 退化顺序：wiring 合法 → 接线图（高亮本步）；wiring 空/校验失败但有接线行（快照或 README 兜底）且 resources ∩ 接线行非空 → 按资源标定接线图；上述失败但任务有 resources → 资源高亮板图（复用资源总览板图渲染器）；都没有 → 纯文字（现状）。
- **API 契约**：新增只读端点，参数 output_dir，返回 {platform, board, rows}；目录无快照 → **读取兜底：解析 README「引脚接线表」（rows 的文本形态，与快照同源）+ `.contest_context.json` 的 platform + 静态板定义 → 返回同形非空载荷**（旧工程数据恢复，不做任何猜测：README 表由同一推导渲染，解析 = 恢复 rows）；无快照且兜底失败（无 README/无法解析/无 context platform/无板定义）→ 200 + 空载荷（前端退化），与既有任务数据读取容错风格一致。
- **展示控制**：默认只画本步高亮线（≤ 图上高度可容纳即全部高亮）；「显示全部接线」折叠开关显示其余线（淡显）。开关状态不持久化（范围外）。

## 测试决策

沿用既有两个测试 seam（工作流：seam 越少越好，不新增）：

- **后端 pytest**（先例：test_readme.py 测引脚表行、test_task_progress.py 测步骤报告/迭代、test_webapp.py 测路由）：
  - 接线行推导与 README「引脚接线表」同源一致（同一输入下 rows 与表格行逐行相等）；
  - README 表解析（工单 05 兜底）：**render_readme 输出 → 解析 → 与 wiring_rows 结构化逐行相等（round-trip）**；无表/表空/坏行/角色 label 拆解/空说明列；
  - 兜底快照重建：无快照目录（README + context platform）→ 非 None 且 rows/board 与生成口径一致；缺 context/缺 README/坏 JSON/未知 platform → None；
  - wiring 校验纯函数：合法全过 / 部分非法丢弃 / 全非法 → 空 / 缺省字段兼容（向后兼容）；
  - 接线快照落盘：生成含引脚模块的工程 → 文件存在、内容字段齐全、board 内嵌、rows 与 README 一致；
  - 读取端点：正常 / 无快照但 README 可兜底（非空）/ 目录无文件 / 快照坏 JSON 四类，均不 500。
- **前端 tests/js**（先例：resource-board.test.mjs、task.test.mjs）：
  - 接线图渲染纯函数：SVG 结构（端子齐全、每根线一条边、高亮类名）、电源线配色、空态/退化输出、全部转义（无未转义注入）；
  - 资源标定反推（工单 05）：resources 引脚名/模块 slug ∩ 接线行 → wiring 引用（去重保序）；空/无匹配 → 空；
  - 任务卡「下一步要做」/ 结果面板报告块在有 wiring、无 wiring（按资源标定 / 无匹配 / 无数据）、无快照三类输入下的渲染结果。
- 不写单测的层：胶水层（generate-tasks.js DOM 接线）——既有惯例，人工冒烟。

## 范围外

- 生成页引脚配置板图（带旋转/点选交互）的几何常量抽取单源（三处「同常量」注释约定维持现状）；
- 让 AI 直接生成图 / SVG / 坐标（违反数据纪律）；
- 接线图手工编辑、导出图片/打印、保存自定义布局；
- 资源总览板图自身的行为改动（本次只读复用其渲染能力与判据）；
- 接线图的生成前预览（生成页板图已有能力，本次不扩）；
- 「显示全部接线」开关状态持久化；
- 依据 main.c 实际使用动态推导接线拓扑（确定性弱，且与接线单源哲学冲突）。

## 布局 v2（工单 06）：两列布线

用户实测反馈（01-05 交付后）：单列端子（全在板右侧）时多根线横穿板图相互缠绕，看不清哪根接哪。要求：**板居中、左右两侧各放模块端子列，端子位置按引脚位置动态生成，避免线的交叉缠绕**。

设计（仍全部由确定性数据推导，数据纪律不变——几何/端子名照旧来自 board + rows，客户端无新数据源）：

- **两列分侧**：焊盘 x=0（板左列）的线 → 左端子列，x=1（右列）→ 右端子列；跨侧线被板图物理隔开，左右互不纠缠。
- **板居中**：板图整体右移 `BOARD_X = TERM_W + TERM_GAP`（=232），左端子列占板左侧 `[0, TERM_W]`，右端子列 `[TERM_R_X, TERM_R_X+TERM_W]`（TERM_R_X = BOARD_X+BOARD_W+TERM_GAP = 716）；viewBox W = TERM_R_X+TERM_W+12 = 936（max-width 由 720 调至 900）。板内既有全部 x 坐标（焊盘中心 150/310、芯片 100、中心 230、排针/地标）统一平移 BOARD_X。
- **端子纵坐标 = 引脚位置**（「按引脚位置灵活生成」）：优先**y 精确对齐焊盘**——端子盒 cy = 焊盘 cy，线为纯水平线（`M 焊盘中心 L 端子缘 cy`），同侧同 y 各占一行互不重叠、零交叉；
- **冲突兜底**：同一焊盘多根线（同 pin 多行，罕见）→ 该侧改**等距布局**：按焊盘 cy 稳定排序，端子盒依次铺在 `TOP_PAD + ROW_H/2 + k*ROW_H`（侧内单调 → 无交叉、盒不重叠），线为连接两点的直线（轻微斜）。两种布局同侧内均保证零交叉。
- **分层**（SVG 元素顺序）：板壳/芯片/地标 → 连线 → 焊盘圆点 + 丝印标签（最上层；标签文字加 `paint-order:stroke` 深底色描边衬底，水平线穿过标签时文字仍可读——线不会压住/覆盖焊盘圆点）。
- 布局为纯函数 `layoutWiring(board, lines)`（输出每线的焊盘坐标、端子盒坐标、path 命令），渲染层只消费其输出——布局规则可单测。

范围外（维持）：折叠开关状态持久化、几何常量抽取单源、交互（点选/拖拽布线）。

## 补充说明

- 数据源落盘优先 / 会话回退是项目既有风格，本 spec 的接线快照与 wiring 字段均随轮次落盘，刷新/历史目录可用；
- 「AI 引用引脚名，图形由数据决定」与项目对 AI 输出的既有处理（清单/接口/引脚名引用 + 校验）一致，不引入新的信任模型。
