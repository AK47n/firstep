# 推荐步骤进度可视化

## Problem Statement

AI 推荐模块是生成流程中又一个长耗时步骤：收敛循环 2-4 轮 × 每轮一次 2-4K token 的 LLM 调用（实测数分钟起步），轮内零事件。前端现状只有按钮静态转圈 + "AI 收敛自检：第 N/4 轮…"一行文字——轮边界之间界面数分钟不变，用户无法判断是正常等待还是卡死（与工单 03 之前母版提炼同款痛点）。

先例就绪：工单 03 已为母版提炼建好完整进度 UI（进度条 + 双计时器 + 日志），且其 spec 的 Out of Scope 当时明确"其他 LLM 调用（模块推荐…）暂不接入，以后接入是顺手的"。后端工单 10 已把推荐收敛轮次经 SSE 进度事件推送（round / converged）——本工单只需前端消费。

## Solution

推荐进度面板：收敛轮次进度条（N/4，提前收敛跳满）+ 双计时器（总用时 / 当前轮已等待，每秒跳动）。轮内 = 单次模型调用、后端发不出事件，计时器是"没卡死"的唯一证明（沿用工单 03「存活证明」决策）。后端零改动。

顺带修复现状两处卡死（与本痛点同源）：`/api/recommend` 的 400（API 未配置等）与断线都会让按钮永远停在"AI 思考中…"——前端没查 `resp.ok`、没查流结束无终态；提炼端点两项都有处理，推荐缺失。

## User Stories

1. 作为用户，我想在点击"让 AI 推荐"后立刻看到进度面板出现（状态 + 计时器起跳），以便知道推荐已开始而不是按钮失灵。
2. 作为用户，我想看到收敛轮次进度（"第 2/4 轮" + 进度条），以便了解分析走到第几轮。
3. 作为用户，我想看到每秒跳动的计时器（总用时 + 当前轮已等待），以便确认推荐没有卡死。
4. 作为用户，我想在提前收敛（第 2 轮就一致）时看到进度跳满，以便知道即将出结果。
5. 作为用户，我想在推荐完成时进度面板消失、结果照常渲染（与现状一致），以便流程不被打断。
6. 作为用户，我想在模型补问时面板收起，回答后重新发起时进度从第 1 轮重新开始，以便补问不污染下一次生命周期。
7. 作为用户，我想在推荐失败（含 API 未配置的 400）时看到中文错误 + 按钮恢复，以便不会永远卡在"思考中"。
8. 作为用户，我想在连接中断时看到提示 + 按钮恢复，以便知道可安全重试（推荐不落任何东西）。

## Implementation Decisions

- **信息源**：只消费现有 `round` / `converged` 事件（工单 10 已就绪，契约在 events.py:28-29 + 契约测试）。**不动后端**——不加轮内子步骤事件：每个子步骤仍是数分钟空窗，事件变密不解决"卡住"疑问，反而动已冻结的 SSE 契约 + 测试。契约冻结是刻意决策，不是能力不足。
- **显示**：轮次进度条（round 事件到 → "第 N/T 轮"，宽度 = N/T；`converged` → 100% 跳满——round_total 是上限非保证，提前收敛就跳，与工单 03 "已读 X/Y"同款诚实）+ 双计时器（总用时从点击起算；"当前轮已等待"在 round / converged 事件到达时重置）。
- **复用**：提炼进度面板同款 CSS 类（`.distill-progress` / `.prog-bar` / `.prog-timers`，index.html:115-134）+ 全局辅助（`fmtClock` / `parseSSE` / `esc`）——同文件全局作用域，直接调用，不复制实现。
- **生命周期**：`done` → 面板收起、结果照常渲染（推荐结果区本就在下方，无需提炼那种"折叠为一行"）；`question` → 面板收起、补问框出现、按钮恢复"让 AI 推荐"，用户回答后 `startRecommend` 重启 = 新生命周期（面板从第 1 轮重新开始）；`error` → 面板收起 + 红字 + 按钮恢复（现有 `showRecommendError`）。
- **卡死修复（同票）**：① fetch 后查 `resp.ok`（400 → 解析 JSON detail → 现有错误路径）——提炼端点有（index.html:1527-1530），推荐缺失；② `parseSSE` 结束仍无终态 → 断线提示"连接中断：本次推荐未完成，可安全重试" + 按钮恢复——提炼端点同款（index.html:1531-1534）。终态（done / question / error）到达时置 `finished` 标记。
- **不做**：取消按钮（刷新 = 安全放弃，推荐无任何副作用）；token 级流式（契约预留扩展位，本次不做）；事件日志（推荐事件 ≤4 条，无价值）；后端任何改动。

## Testing Decisions

- 前端无单测基建（仓库先例：UI 手动验收）。自查可复用工单 03 手法：jsdom 载入整页 + 脚本化假流驱动真实点击流程（`parseSSE` 是纯函数，可 node 直喂 `new Response(new ReadableStream(...))` 构造的假流）。
- 后端零改动：全量 pytest 应保持全绿（验证没碰后端）。
- 真机验收：真实 API 跑 2021F 送药小车（第 2 轮收敛 → 进度条跳满 + 计时器死寂期跳动）；补问路径（找一道模型拿不准的题）；断线（推荐中途杀服务 → 断线提示 + 按钮恢复）；API 未配置 → 400 红字 + 按钮恢复。

## Out of Scope

- 后端事件契约改动（轮内子步骤事件）
- token 级流式
- 取消按钮
- 骨架 / 模块录入校验等其余 LLM 步骤的进度接入（照旧）
