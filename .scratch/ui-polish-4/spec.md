# Spec：卡片折叠 + 赛题一键生成 + 复制输出路径（ui-polish-4）

> 延续 ui-polish 系列迭代。用户要求「思考还应该添加什么然后继续改进」；本轮选三个流程衔接 / 长页面体验价值点（纯前端）。

## 问题陈述

1. 生成页 12 步卡片全纵向堆叠，滚动量大；已完成步骤的信息密度低（用户大多只关心当前步）；
2. 赛题库与生成页流程断裂：看到某道历史赛题想直接做，得记下编号回生成页手动填；
3. 生成完成后拿输出路径（复制给 IDE / 别的工具 / 交接）需手动选中文本复制。

## 方案

### 01. 卡片折叠（长页面减负）

- 每张生成页卡片（含 6.5 实例卡）标题行右侧注入折叠按钮（▾），点击折叠 / 展开该卡；标题行（h2）点击同样 toggle；
- 折叠态 = 卡片只保留标题行（`.card.collapsed > *:not(h2) { display: none }`），完成徽章 `.step-no` 仍在标题行内，状态一目了然；
- 步骤导航底部加「收起已完成 / 全部展开」切换按钮：一键折叠全部已完成卡片（未完成保持展开），再点展开；
- 折叠不持久化（刷新恢复展开）；与现有滚动高亮 / 点击跳转兼容（高度变化由 scroll 监听自动重算）。

### 02. 赛题库「用此题生成」一键跳转

- 赛题库列表每行加「用此题生成」按钮：点击 → 调 `/api/topics/:key` 取题面 → 填入生成页 → 标记第 1 步完成 → 切到生成 tab 并滚到顶部 → toast 提示；
- 复用现有取题面端点与 clearTopicSummary 失效逻辑（题面变了下游全部失效，与新按钮一致）；
- 不动现有「删除」按钮与取题面输入框流程。

### 03. 生成结果卡「复制输出路径」

- 生成完成结果卡「输出目录」行加「复制路径」按钮（生成成功后显示）：点击复制 `res-dir` 全文到剪贴板 + toast「已复制输出路径」。

## 实现决策

- 只改 `src/contest_generator/static/index.html`；后端零改动、API 契约零改动（取题面复用现有端点）。
- 折叠按钮 / 收起已完成按钮由 JS 动态注入（HTML 结构零改动，12 处卡片不逐个编辑）。
- 折叠 CSS 用 `.card.collapsed > *:not(h2)`（直接子元素，h2 保留）；行内 display 元素用 `!important` 压住。
- 新增纯函数：`collapseToggleAll(cards, doneSet, collapse)` 可测逻辑放纯函数（给定卡片数组 + 完成集合 → 折叠/展开哪些）；`topicUsePayload(key)` 意义不大不做，取题面逻辑直接复用现有端点调用。
- 视觉回归：无头 Edge + CDP 截图（折叠态 / 收起已完成 / 赛题库新按钮 / 结果卡按钮）+ 计算样式断言。

## 测试决策

- 新增 `tests/js/card-collapse.test.mjs`（collapseToggleAll 纯函数：已完成折叠 / 未完成保持 / 全展开 / 空集合）；
- `node tests/js/*.test.mjs` + `pytest tests/test_generate_check_contract.py` 全绿；全量 pytest 后台跑一次保底。

## 范围外

- 不做自动折叠（完成即收起）——避免打断用户回看；不做折叠状态持久化；
- 不改后端、不改赛题库数据结构。
