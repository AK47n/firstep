# 引脚类型配色入判据（整个 `--pin-*` 族收口 + 模板变量内联取色入判据 + 亮色成套腿）

> **上游**：`backlog.md` §34 末「本轮量到、明确不做的」第 1 条 + `local-environment.md` §0「留给下一轮的」
> ①：`.role-type` 角色类型标浅色 **3.54**（暗 4.94）——它是 `generate-pins.js` 里**模板变量拼出来的
> 内联取色**，腿⑨ 的正则只收 `color:var(--token)` 字面 ⇒ **这一族的文字色从没被任何对比度判据看过**。
>
> **拍板（2026-10-01，用户，三条）**：
> ① **机制走 C**——**取色还给样式块**（模板变量内联取色改成 `data-pin-type` + 样式块规则），
>    判据回到**已有的腿⑧**（机械面 + token 面的层配方），并给腿⑨ 补一条**正向判据**
>    （`static/js/**` 的内联 `style` 里不许出现 `${…}` 取色）把这道缝焊死；
>    不扩腿⑨ 的认人面（那要守卫去解析 JS 常量表，脆弱），也不做下发式（颜色是纯表现，
>    且下发消不掉"前端仍可自己写死色"这条缝）。
> ② **范围 = 整个 `--pin-*` 族一次收口**——不只是那张标：角色类型标 / 「已绑·现绑」状态文字 /
>    板图焊盘与引脚名 / 图例与菜单色点，两主题全量；文字档 ≥ 4.5、非文字档 ≥ 3:1。
> ③ **立腿**：「**颜色族必须两主题成套**」+ 一份"刻意主题无关"的豁免登记表（双向对账）。
>
> **本轮不发版**（照 §31/§33/§34 的先例，发版另开一轮）。这一批在浅色下**用户看得见**
> （板图引脚名、类型标、状态文字都会变清楚）⇒ 下一版发布说明要点名。

## 问题陈述

`.role-type` 那张标只是**一个症状**。侦察（`.scratch/role-type-recon/`，两支探针可复跑）量到的是
**一整族从没进过判据**：

1. **判据看不见这一族**。角色类型的配色住在 `generate-pins.js` 的 `PIN_TYPE_STYLE` 表里
   （类型 → `[主色令牌, 淡化色令牌]`），渲染时用模板串拼进 `style="color:${st[0]};…"`。
   腿⑨ 的认人正则只认 `color:var(--token)` **字面** ⇒ 这一族的 8 处取色（6 处内联 style +
   2 处 SVG `fill`/`stroke`）**一处都不在判据里**；描边登记簿只把其中两行记成"整圈框"。
   后果与 §34 那条经验同型：**看不见 = 静默不判**。
2. **这一族今天真的坏**（静态现算，几何已被 `contrast-residue/05` 的真像素印证：gpio 浅 3.54 /
   暗 4.94 逐位对上）：

   | 面 | 暗色 | 浅色 |
   |---|---|---|
   | 角色类型标（字色 = 主色 × 自带 dim 底叠 `--panel-2`） | **enc 3.78 / uart 3.93** 不达标，其余 4.94–6.09 | **1.45–3.54，7/7 不达标** |
   | 「已绑 X」「现绑 X」（只有字色，底 = `--panel-2`） | 全过（最低 enc 4.50） | **1.55–4.14，7/7 不达标** |
   | 板图引脚名（`<text fill>`，底 = `--pin-pcb` 叠 `--panel`） | 过 | ≈ 1.5，**几乎看不见** |
   | 图例 / 菜单色点（非文字，要 3:1） | 过 | **spi / exti 1.55、uart 2.67、enc 2.87** 不达标 |

3. **根因两条**：① `--pin-uart/i2c/spi/enc/exti` 五个色是**只有暗色值的字面 hex**，亮色块一个都没覆盖
   （`--pin-gpio/pwm/adc` 派生自语义令牌、有亮色值，但**当文字用**仍然 3.37–3.54——正是
   `light-contrast/02` 那条「主色 ≠ 文字档」的老课）；② 亮色覆盖完整性**没有任何判据**——
   `contrast-residue/03` 只补了 `--pin-fixed-pad` 一个值，边界写进了注释。
4. **"亮色漏覆盖"这条缝的形状已经量清了**：全站 `:root` 114 个令牌、亮色块另定义 75 个；
   按族看，**27 个族两主题成套、7 个族完全不覆盖（全是尺寸/动效类：`--dur-*`/`--ease-*`/`--fs-*`/
   `--header-*`/`--mono`/`--radius-*`/`--space-*`，与主题无关）、部分覆盖的族全站只有 1 个：
   `--pin-*`（亮色只写了 pad / fixed-pad / pcb 三件面，16 个色件靠继承）**。

## 方案

三个面，全部落在既有缝上（不新造第五套做法）：

- **机制面（取色还给样式块）**：把 8 处模板变量取色改成 `data-pin-type` 属性 + `index.html`
  样式块里的规则（按 8 个色族写：`color` / `background` / SVG 的 `fill`、`stroke`）。
  于是判据零新机制：带底规则（类型标）进腿⑧ **机械面**；文字档令牌进腿⑧ **token 面**
  （用**已有的层配方** `基底+叠层` 表达真几何：类型标 = `--panel-2+--pin-X-dim`、
  状态文字 = `--panel-2`、板上引脚名 = `--panel+--pin-pcb`）；色点进 token 面的
  **非文字档**（主色 × `--panel-2`，3:1）。再给**腿⑨ 补一条正向判据**：
  `static/js/**` 的内联 `style="…"` 里出现 `${…}` 取色即红（附一份登记表兜住
  "非令牌的运行时配色"——总览模式的模块配色是 hex 序列，不是令牌）。
- **色值面（`--pin-*` 两主题成套）**：七个色族各补齐**三件套**——主色（非文字：色点 / 描边 /
  焊盘描边）、淡化色（自带底的填充）、**文字档**（`--pin-X-text`，照 `--accent-text` 那一族的先例）。
  亮色块补齐 14 个色件（7 主 + 7 淡），暗色只抬两个不达标的（enc / uart）。
  **"主色 ≠ 文字档"是硬约束**：主色只要非文字 3:1，文字档要 4.5，两者不能互相顶替。
- **判据面（亮色成套立腿）**：新腿判「**颜色令牌所属的族必须在亮色块整族成套定义**」
  （不允许靠继承暗色值）+ 反向（亮色块里定义了但 `:root` 没有 = 畸形）+
  一份 `THEME_INDEPENDENT_FAMILIES` 豁免登记表（前缀 + 中文理由，双向对账）。
  今天盘上**零假阳性**，唯一判红面就是本轮要修的 `--pin-*`。

用户可见的变化**只有一处主题**：浅色主题下引脚配置卡片的配色（类型标、状态文字、板图引脚名、
色点）从"几乎看不见"变成看得清；暗色只动 enc / uart 两处、幅度小。**无交互变化、无文案变化。**

## 用户故事

   以便"这根脚是什么类型"不用眯眼猜。
2. 作为用户（浅色主题），我想要绑完线之后那句「已绑 PA24」在浅色下也看得见，
   以便确认自己刚绑的脚没绑错。
3. 作为用户（浅色主题），我想要板图上已绑引脚的名字在浅色下读得出来，
   以便对着图改线。
4. 作为用户（浅色主题），我想要图例与菜单里的色点在浅色下分得清，
   以便颜色这个身份线索真的起作用。
5. 作为维护者，我想要"颜色从哪来"只有一条路（样式块里的规则），
   以便改一次配色不用在两个语言/两个文件里找同一份表。
6. 作为维护者，我想要"内联 `style` 里拼取色"这件事**当场变红**，
   以便下一处 `${…}` 取色不会又悄悄长出来、又悄悄不被任何判据看见。
7. 作为维护者，我想要这一族的比值**由现算得出**（文字档 4.5 / 非文字档 3:1，两主题各算一遍），
   以便"改了色值但没人重算"这类假绿不再可能。
8. 作为维护者，我想要"某个颜色族在亮色下漏了成员"这件事**有机器判据**，
   以便 `--pin-fixed-pad` 那种"只补一个值"的漏下一次当场红，而不是靠评审的眼睛。
9. 作为维护者，我想要豁免（刻意主题无关的族）**登记在册、带理由、双向对账**，
   以便豁免不会变成"没人知道为什么它不在判据里"。
10. 作为评审者，我想要这一轮的真像素读数**改前/改后两发**、且每格都能对上一个静态格，
    以便"变好了"不是靠人眼看图说的。
11. 作为下一轮接手的人，我想要这批的边界（哪些没做、为什么）写进 `backlog.md` 新一节与本机交接区，

## 实现决策

- **模块**：生成页的引脚渲染簇（取色来源改造）+ 页面样式块（8 个色族的规则 + 令牌三件套）+
  前端守卫（腿⑧ 的登记与格数、腿⑨ 的正向判据）+ Python 口径副本（镜像守卫钉住）+
  真像素量具（只扩配方，不重写）。
- **接口**：被改的接口只有两处——① 渲染侧从"内联 style 拼令牌"改成"挂 `data-pin-type` 属性"
  （DOM 结构与既有选择器 `.pin-role` / `circle[data-pin=…]` **保持不变**，浏览器用例与
  `gen-chain-audit` 脚本仍然认得出）；② 守卫侧的 token 面登记表多一组行（层配方 + 假定底）。
  两处都保持"纯函数 + 可注入参数"的既有形状（红证要喂坏表）。
- **技术澄清**：
  - 徽标的描边走 `border: 1px solid currentColor`（基类一条完整框声明），于是**不必**给 8 个族
    各写一条 `border-color`，描边颜色自动跟着被判过的文字色走；
  - 非文字档的判据口径 = **主色 vs 它所在的那层底**（色点在 `--panel-2` 上，3:1），
    **不是**色点自带底（色点没有自带底）；
  - 「已绑 / 现绑」那两句文字**没有自带底**，底是卡片本身（`--panel-2`）——口径与类型标分开登记；
  - 8 个色族 = gpio / pwm / uart / i2c / spi / enc / adc / exti（14 个引脚类型映射到它们）；
    未知类型保留一个兜底（默认走 accent 那一对，与现状一致）。
- **架构决策**：不新增缝。四个面各自复用既有先例：机械面（同规则 `color × background`）、
  token 面的**层配方**（`基底+叠层`，`code-contrast` 轮立的）、腿⑨ 的登记簿（
  `light-contrast/04` 立的）、真像素量具（`code-contrast/probe-08` + `contrast-residue/probe-09`
  立的）。跨语言镜像守卫同步扩一组。
- **模式变更**：描边登记簿两头都要动——样式块面 **+1**（基类那条完整框）、渲染方面 **−2**
  （那两行内联框改成规则之后不再是渲染方内联框）；腿⑧ 的机械面对数、族面格数、
  渲染方登记条数、token 面行数**每轮现跑**，变了必须解释成"改对了"还是"抽取面坏了"。
- **具体交互**：无 UI 交互变化；DOM 属性多一个 `data-pin-type`（不影响既有选择器与用例）。

## 测试决策

- **什么构成好测试**：判**外部行为**——"浅色下这一族的文字格过不过 4.5、非文字格过不过 3.1
  门槛 3:1"、"内联 `style` 里还有没有模板变量取色"、"颜色族在亮色块是不是整族成套"，
  不判实现细节（选择器怎么写、规则怎么分组）。
- **测试哪些模块**：既有四处，一处都不新增——前端守卫面（腿⑧/⑨）、跨语言镜像面、
  真像素量具面、浏览器门禁（这轮改了 `static/index.html` + `static/js/ui/**`，闸门会自动带上它）。
- **既有先例**：`light-contrast` 轮的"合成红证 + 真文件反证 + 行为向量表"、`border-guard` 轮的
  双腿登记簿双向对账、`contrast-residue` 轮的"读数每轮重跑 / 反证后复原 sha256 一致"、
  `ui-density-sitewide` 的三条纪律（读数每轮重跑 / 浏览器门禁单独跑 / 注释里的数按脚本复算）。
- **判据强度**：每条新判据都要有"注入坏数据就变红"的自检；真文件反证至少覆盖三类注入——
  ① 把某一族的亮色覆盖删掉（亮色成套腿红）、② 把某处内联取色改回 `${…}`（腿⑨ 正向判据红）、
  ③ 把某个文字档令牌的亮色值改回暗色值（token 面红）。
- **每张单的读数**：探针输出落盘到本目录；**读数的时间戳必须晚于最后一次改产品面的时间**。
- **真像素**：改前基线（第一单）与改后复核（收尾单）用**同一套配方**，每格与静态格对账，
  并如实记录"没量到"的格（不许拿"没量到"当通过）。

## 范围外

- **系统性"非文字 3:1"判据**（全站描边 / 图形 / 色点）——本轮只给**引脚这一族**的色点与焊盘描边
  立判据，不给全站立非文字档。
- **叠加态定价**与 **`--accent` 非文字 3:1**（浅 3.42 / 暗 3.11、2.70）——§34 已记明账，本轮不翻案。
- **总览模式的模块配色**（`MODULE_COLORS` 12 色 hex 序列）——它是**运行时按序分配的非令牌配色**，
  本轮只把它登记进腿⑨ 的正向判据豁免（改它属另一件事）。
- **SVG 里 `font-size="11"` 这类属性写法**——不在本轮射程（腿⑤ 只管 `style` 里的 `font-size: Npx`），
  如要收另立。
- **发版**：本轮不发版。
- 库层（`library/**`）、`tools/**`、后端生成链的一切改动。

## 补充说明

- **本轮侦察的两支探针**（都在 `.scratch/role-type-recon/`，可复跑）：
  `probe-01-inventory.py`（内联取色盘点 + 色对两主题现算）、`probe-02-light-coverage.py`
  （亮色覆盖完整性按族盘点）。**票面里每个数都要能用这两支复算**。
- **一条判读纪律**：腿⑧ 机械面的合成基色是 `--panel`，而类型标真实的底是 `--panel-2`
  （卡片底）——两者对同一对色能差 **0.8 左右**（gpio：4.38 vs 3.54）。所以**机械面过线不等于
  真几何过线**，真几何必须由 token 面的层配方兜住（这正是本 spec 把"层配方 + 假定底"
  写进实现决策的原因）。
- **一条命名纪律**：本批一律写全名——「角色类型标 / 状态文字 / 板图引脚名 / 色点」四个面，
  以及「主色 / 淡化色 / 文字档」三件套；不写裸编号（`backlog.md` 说的"另立"指的就是本批）。
