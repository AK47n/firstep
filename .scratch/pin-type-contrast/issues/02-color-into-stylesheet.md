# 02 — 取色还给样式块（类化）+ 腿⑨ 补正向判据

**要做什么：** 把这一族的取色从"模板变量拼进内联 `style`"改成"挂 `data-pin-family` 属性 +
样式块里的规则"，并把"内联 `style` 里拼取色"这件事**立成正向判据**。端到端行为：
**页面上的颜色一个字节都没变**（真像素逐格与 01 基线相同），但取色从此全部落在
腿⑧ 看得见的样式块里，而这族"再长出一处 `${…}` 取色"会当场变红。

**被谁阻塞：** 01（要拿改前基线做"逐位不变"的验收）。

**状态：** resolved（2026-10-01；读数见文末）

## 一、产品面：类化

- [x] 8 处 `${st[0]}` / `${st[1]}` 取色改成 `data-pin-family` 属性（含 SVG 的 `fill` / `stroke`）；
      取值仍是那张表（**表本身保留**——它现在是"类型 → 色族"的唯一出处，不再是"类型 → 颜色"）。
- [x] 样式块里按**色族**写规则（8 个族：gpio / pwm / uart / i2c / spi / enc / adc / exti），
      覆盖 `color` / `background` / SVG 的 `fill`、`stroke`；**未知类型保留兜底**（与现状同色）。
- [x] 角色类型标的描边走基类的 `border: 1px solid currentColor`（一条完整框声明），
      **不给 8 个族各写一条 `border-color`**——描边颜色自动跟着被判过的文字色走。
- [x] DOM 契约不变：`.pin-role` / `circle[data-pin="…"]` / 现有类名与结构保持
      （浏览器用例 `gen-chain-audit` / `module-intro` 都不许改）。

## 二、判据面

- [x] **腿⑨ 新增正向判据**：`static/js/**` 的内联 `style="…"` 里出现 `${…}` 取色
      （`color` / `background` / `background-color` / `border`）即红，报错文案给出出路（"挂属性 + 写进样式块"）。
- [x] 该判据带一份**豁免登记表**（文件 + 锚点 + 中文理由），兜住"非令牌的运行时配色"——
      本仓今天是总览模式的模块配色（`MODULE_COLORS`，12 色 hex 序列，按出现顺序分配）。
      豁免表要**双向对账**（盘上 ⊆ 表 / 表 ⊆ 盘上，锚点过期即红）。
- [x] **描边登记簿两头迁移**：样式块面 **+1**（角色类型标基类那条完整框）、渲染方面 **−2**
      （那两行内联框改成规则之后不再是"渲染方内联框"）；两侧的双向对账都必须转绿。
- [x] 红证：① 把某一处改回 `style="color:${…}"` → 腿⑨ 正向判据红；② 把豁免表里那条删掉 →
      反向对账红（盘上有、表里没有）。两发都要留读数。

## Comments

- **豁免表今天只有 1 条**：总览模式的模块配色（`MODULE_COLORS` 是运行时按序分配的 hex 序列，
  不是令牌）。它是**判据射程外**的东西（没有任何 CSS 令牌可写），登记即诚实。
- **一处口径变化（如实记，今天不可见）**：旧代码对"表外类型"（今天**不存在**这种类型）给的是
  `--accent` **主色**当文字——那个值在浅色下当文字只有 2.99:1（不合 AA）。新写法下：
  类型标落到 `.role-type` 基类兜底（`--accent-text` × `--accent-dim`，两主题都过线）；
  **状态文字**没有基类兜底，会落到 `.role-status` 的 `--muted`（可读，只是不再带类型色）。
  ⇒ 真要支持表外类型，那时再补一条 `.pin-type-text` 基类规则（并挑一个过线的令牌）。
